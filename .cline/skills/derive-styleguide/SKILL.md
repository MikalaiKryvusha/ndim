# /derive-styleguide — стиль владельца, извлечённый из доказательств

Слабая сессия не может УДЕРЖАТЬ стиль владельца в голове — через десять страниц её сносит. Лекарство
никогда не в «постарайся сильнее»: извлеки стиль ОДИН раз из собственного текста владельца, утверди
его и преврати каждое машинно проверяемое правило в строку линтера. «Модель забывает стайлгайд через
десять страниц — линтер не забывает никогда».

**Главное правило: выводи из ОБРАЗЦА, а не из головы.** Каждое утверждение стайлгайда обязано
указывать на доказательство в тексте владельца. Стайлгайд, выдуманный из вкуса, — то же мошенничество,
что выдуманное число.

## Шаг 1. Собрать образец

Спроси у владельца, какие артефакты эталонны (либо возьми объявленные `canonArtifacts` из
`.kaif/kaif.json`). Предпочитай текст, который владелец НАПИСАЛ, тексту, который он лишь принял. Если
образец тонкий (меньше нескольких страниц) — скажи об этом: тонкий образец даёт тонкий свод, и
владелец должен знать, какие правила на скольких доказательствах стоят.

На этом проекте эталон стиля — тексты продукта 1.x (`design/reference-1x/`, `researches/05`–`07`) и
правила текста в `AGENT_GUIDE.md`; они уже фиксируют «Вы», запрет слова «навсегда» и ноль внутреннего
жаргона на лице приложения.

## Шаг 2. Извлечь — с цитатами

Пройди образец и извлеки, каждый пункт С цитатой-примером из текста владельца:

1. **Регистры** — какой голос какому содержанию служит (например, сухой справочный регистр для
   механик, повествовательный — для лора; разделение самого владельца, а не из учебника).
2. **Эталонные примеры** — 3–7 коротких цитат, которые И ЕСТЬ стиль: форма фразы, ритм, как вводятся
   термины, как подаются числа и таблицы.
3. **Словарь: одно понятие — одно слово.** Каждое понятие предметной области сопоставлено с термином
   ВЛАДЕЛЬЦА; каждый синоним, которым владелец НЕ пользуется, идёт в запретный список (дрейф
   синонимов — это и есть то, как гниёт канон).
4. **Конвенции оформления** — заголовки, регистр букв, пунктуация списков, форматы чисел, как
   выкладываются формулы и блоки характеристик.
5. **Антипаттерны** — то, чего текст владельца не делает никогда (слова-наполнители, оговорки,
   маркетинговый тон…), каждый с доказательством «отсутствует в образце / вырезано владельцем в
   коммите X».

## Шаг 3. Разделить правила: линтуемые и суждение

Пометь каждое извлечённое правило:
- **ЛИНТУЕМОЕ** — проверяемое grep-ом или скриптом: запретные синонимы и маркеры-наполнители,
  запрещённые конструкции, «формула без блока „где“», нарушения регистра заголовков, слова-маркеры
  регистра не в том типе документа. Они становятся строками канон-линтера (его шаблон приезжает с
  фреймворком — `.kaif/tools/kaif-canon-lint.mjs`); выпиши их машиночитаемой таблицей
  `шаблон → сообщение`.
- **СУЖДЕНИЕ** — тон, ритм, вкус: остаётся в своде для проходов сильной моделью и вычитки владельцем.
  Никогда не делай вид, что правила-суждения кем-то обеспечены, — прямо скажи, какие из них не
  сторожит ничто.

## Шаг 4. Владелец утверждает — и свод начинает связывать

Заведи свод документом рядом с каноном, которым он правит (например, `design/STYLEGUIDE.md`), с
пометками провенанса, как любой ИИ-текст на территории владельца. Отдай владельцу с ОДНИМ вопросом на
каждый по-настоящему неоднозначный выбор регистра (не викторина — работу сделал ты, он накладывает
вето). После утверждения свод обязателен для каждого будущего письма в этот канон, а линтуемые правила
уходят в линтер в тот же день (правило без стража — это желание, а не правило).

## Заметки

- Довыводи по частям: если владелец написал новое, противоречащее своду, — прав ВЛАДЕЛЕЦ; обнови свод
  и строки его линтера, но никогда не «поправляй» текст владельца.
- Режимы строгости: выводить и обновлять свод — работа сильной модели; ЗАПУСКАТЬ линтер — работа
  любой. В этом разделении и смысл.
- Правило четырёх макетов (`AGENT_GUIDE.md` → «Дизайн») — тот же принцип для визуального: агент не
  решает за владельца, он готовит выбор.
