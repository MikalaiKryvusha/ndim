Здесь рождаются новые измерения: от «в мире вышло вот это» до записи, готовой лечь Николаю на
вычитку. Директория заведена по его слову 2026-08-17: «*давай под разведки и кандидатов заведём
новую директорию, там README напишем, как у нас тут всё заведено и устроено, и туда будешь собирать
тезисные списки с именами кандидатов, и по ним позже будешь там же писать развёрнутые локальные dims
объекты, которые потом будешь скриптами выгружать в базу кандидатов*».

## Зачем это нужно — одной строкой

Пока комнаты не было, завести измерение в 2.0 было **нельзя вовсе**, и мир проходил мимо: слово
владельца — «*сегодня весь мир на хайпе от одиссеи Нолана, а мы такой кусок поисков пропускаем мимо
нас*». Эта мастерская делает пополнение каталога **потоком**, у которого одна ручная точка — его
вычитка.

## 🔴 ГЛАВНОЕ ПРАВИЛО, ради которого всё устроено именно так

**Агент НИКОГДА не заводит измерение сам** (решение владельца, интервью №015, В3 = А). Он доводит
кандидата до карточки и останавливается. Измерение рождается ТОЛЬКО нажатием владельца в панели.

И это не обещание в документе, а механика: у ИИ-агента нет клейма админа, `firestore.rules` не даёт
писать в каталог `dims/` никому, кроме админа, а второго пути записи в каталог не существует —
одобрение зовёт тот же код, что ручная форма.

## Дорога кандидата — четыре шага, и три из них машинные

| # | Шаг | Где живёт | Кто делает |
|---|---|---|---|
| 1 | **Разведка**: что вышло в мире и чего у нас нет | `candidates/scouts/NN_*.md` | машина (`tools/scout-wikidata-candidates.mjs`) |
| 2 | **Развёрнутые объекты**: полная запись со своим описанием | `candidates/batches/NN_*.json` | агент, руками, по фактам реестра |
| 2б | **Приёмка описаний**: объём, строение, заимствование | — | машина (`tools/check-candidate-descriptions.mjs`) |
| 3 | **Выгрузка в очередь** | база: `dim_candidates` | машина (`tools/seed-dim-candidates.mjs`) |
| 4 | 🔑 **Вычитка и одобрение** | панель: `/admin/dims` → «Очередь» | **владелец** |
| 5 | **Возврат на доработку** — если карточка почти хороша | `ownerNote` в базе | **владелец**, читает машина (`tools/read-returned-candidates.mjs`) |

🔄 **Шаги 2б…5 образуют круг, а не прямую.** Возвращённая карточка правится агентом и кладётся
обратно в очередь; замечание владельца при этом сохраняется. Круг стережёт
`tools/verify-candidate-return-loop.mjs` (11 проверок, эмулятор) — без него звено «агент прочитал
замечание» держалось бы на обещании.

## Что лежит в `scouts/` — тезисный список

Один файл на прогон разведки: `NN_<источник>_<тема>.md`. Внутри — таблица «название ru · title en ·
вид · год · известность · идентификатор реестра» и **числа прогона**: сколько найдено, сколько
отсеяла дедупликация, сколько осталось.

**Требования к тезисному списку, каждое оплачено каноном:**

- 🔴 **У каждой строки — РАЗРЕШИМЫЙ идентификатор реестра** (`QID` Wikidata). Основание не вкус, а
  цифры: ссылки, которые модель приводит по памяти, галлюцинируют в 14–95 % случаев
  (`researches/29` §3.4). Строка без идентификатора в список не попадает.
- 🔴 **Дедупликация ЧИСЛОМ, а не на глаз.** Название нормализуется тем же нормализатором, что у
  поиска в продукте (`model/feed.ts` → `normalizeForSearch`: регистр, «ё», дефисы, римские цифры), и
  сверяется с обеими половинами названий всех измерений каталога. Вторая копия правил нормализации
  разъехалась бы с первой на первом же дефисе.
- **Известность названа числом** — сколько языковых разделов Википедии об объекте написали
  (`wikibase:sitelinks`, принятая мера). ⚠️ Это НЕ касса и НЕ хайп: свежий релиз может собирать
  залы и иметь мало разделов, потому что Википедия догоняет медленно. Границы меры называются в
  самом списке, а не подразумеваются.
- **Границы прогона называются вслух:** какие виды объектов искали, какой порог известности, что
  этим порогом отсеклось. Список, у которого не названы границы, читается как «это всё, что есть».

## Что лежит в `batches/` — развёрнутые объекты

Один файл на партию: `NN_<тема>.json`, поле `candidates` — массив записей формы каталога.

```
{ "wikidata": "Q131547207", "sitelinks": 61,
  "title":       { "ru": "…", "en": "…" },     // обязательно ОБА языка
  "description": { "ru": "…", "en": "…" },     // ПИШЕТ АГЕНТ
  "type":        { "ru": "…", "en": "…" },
  "author":      { "ru": "…", "en": "…" },
  "year": "2026",                               // СТРОКА: бывают диапазоны «1966–1969»
  "tags": ["…"],                                // пользовательские теги, по ним ищут люди
  "agentNote": "" }                             // что владельцу проверить; часто пусто
```

**Правила заполнения, и они не косметические:**

- 🔴 **Названия, вид, год, автор, состав — ИЗ РЕЕСТРА по идентификатору**, а не из памяти модели.
  Запрос `wbgetentities`, ссылки разрешаются в имена. Память здесь выдумывает так же, как в фактах.
- 🔴🔴 **ОПИСАНИЕ ПИШЕТ АГЕНТ СВОИМИ СЛОВАМИ по фактам реестра. Текст Википедии не копируется
  никогда.** Это лицензия CC BY-SA и прямой заказ владельца о вычистке заимствований — проект уже
  вычищал 196 таких описаний, и 536 записей до сих пор ждут правки.
- **Оба языка у названия обязательны.** Измерение без `title.ru` или `title.en` сервер синхронизации
  в индекс каталога не берёт («без названия показывать нечего»), то есть его не увидит НИ ОДИН
  человек. Это условие видимости, а не вкус.
- **Год — СТРОКА.** Замер каталога 2026-08-21: диапазон стоит всего у ДВУХ записей из 5121, и обе —
  циклы романов («Тёмные начала» 1995–2000, «Властелин колец» 1954–1955). Строкой поле остаётся
  ради них.
- 🔴 **ГОД СЕРИАЛА — ВСЕГДА ПО ГОДУ ПЕРВОГО СЕЗОНА ИЛИ ПЕРВОЙ СЕРИИ.** Слово владельца 2026-08-21:
  «*год сериала всегда по году первого сезона или первой серии*». Правило описывает то, как каталог
  уже устроен: из 384 записей видов «Телесериал», «Телешоу» и «Интернет-шоу» диапазон не стоит НИ У
  ОДНОЙ. Не «год финала», не «годы показа», не диапазон.
  🔑 **То же правило распространяется на любой объект, выходящий по частям** — эпизодическую
  видеоигру, выпускаемую главами, сериал-антологию, издание с продолжениями: год берётся по
  ПЕРВОМУ выпуску. Пример партии 2: Deltarune стоит `2018` по первой главе, хотя реестр
  перечисляет даты вплоть до 2027 года.
  ⚠️ Не путать с другим случаем: у ФИЛЬМА год берётся по первой дате реестра, и если это
  фестивальная премьера, а широкий прокат позже, расхождение называется в `agentNote`.
- **Расхождение с реестром называется в `agentNote`**, а не сглаживается. Пример из первой партии:
  у «Хамнета» реестр даёт 2025 (премьера на фестивале), широкий прокат — 2026; год взят по реестру,
  а расхождение написано владельцу.
- 🔴 **МЕРА ИЗВЕСТНОСТИ В ОПИСАНИЕ НЕ ПОПАДАЕТ НИКОГДА.** `sitelinks` — служебное число нашей
  разведки, а не факт о произведении. Замер каталога 2026-08-21: записей, где число языковых
  разделов Википедии попало бы в текст описания, — **0 из 5121**. Владелец так не пишет.
  ⚠️ Дефект оплачен: при сборке партий 2 и 3 пишущие субагенты получили `sitelinks` в факт-листе
  и приняли его за факт для текста — фраза «сведения о картине представлены в N языковых разделах
  Википедии» появилась в 30 описаниях из 40 и была вычищена вручную. Число живёт в поле
  `sitelinks`, и только там.
- **`tags` — ПОЛЬЗОВАТЕЛЬСКИЕ теги**, по которым люди ищут. ⛔ Технические теги (`techTags`) сюда не
  пишутся никогда: поле `tags` публичное и едет на страницу каталога. Разбор — словарь продукта
  в `AGENT_GUIDE.md` → «Два рода тегов».

   ✅ Пишем: что это по сути — жанр, форма, тема, среда.

### 🔑 Гарантия — двое ворот, а не абзац в документе

```bash
node tools/measure-catalog-tags.mjs      # перевывести соглашение из каталога
```
→ `candidates/tag-conventions.json` — машиночитаемый источник, который читают приборы.

| Ворота | Что делают |
|---|---|
| приёмка описаний | называет недостающие обязательные теги и предупреждает об именах собственных |
| 🔑 **выгрузка в очередь** | **ОТКАЗЫВАЕТСЯ** класть кандидата без обязательных тегов — код 1, в очередь не попадает ни один |

Вторые ворота важнее первых: приёмку можно забыть запустить, мимо выгрузки кандидат не пройдёт.
⚠️ Ворота **не дописывают теги молча** — тихая дописка сделала бы файл партии и базу разными
правдами. Прибор называет недостающее, правка стоит одной строки.

🔎 **Новый тег берётся из СЛОВАРЯ ВЛАДЕЛЬЦА, а не выдумывается.** Проверить частоту слова по
каталогу — одна команда замера; изобретать свой термин там, где у него уже есть свой, значит дробить
словарь. Полезные числа: «выживание» 103 · «постапокалипсис» 31 · «биография» 151 · «экранизация» 8.

### Что именно закрывает приёмка описаний — и чего она не закрывает

| Проверка | Откуда взялась |
|---|---|
| объём и строение | коридор, выведенный из корпуса владельца |
| заимствование | дословный ряд слов против статьи Википедии |
| зачин | возврат карточки «Обсессия», правило класса |
| внешний авторитет | возврат тринадцати карточек, «класс запрет» |
| следы машинной правки | три обрыва, пережившие зелёный прогон |

🔴 **Урок, оплаченный последним из них.** При автоматической вырезке предложений из готовых
описаний в трёх местах остались обрывки — «*постановок. ; продюсерами*» и дважды висящая кавычка
«*3 апреля 2026 года. ».*». Прогон показывал **✅ ЧИСТО на порванном тексте**, потому что пунктуацию
не мерил никто: прибор удостоверял то, во что не смотрел. Класс общий и стоит того, чтобы его
помнить: **правка ТЕКСТА механизмом обязана иметь проверку СЛЕДОВ этой правки.**

🔴 **И ЧЕТВЁРТЫЙ ОБРЫВ ТОГО ЖЕ КЛАССА НАЙДЕН 2026-08-21 — уже ПОСЛЕ того, как проверку следов
завели.** В английском описании «Дня разоблачения» перечень работ режиссёра начинался обрывком
«*T. the Extra-Terrestrial (1982), Minority Report…*»: механическая нарезка предложений приняла
точку внутри сокращения «E. T.» за конец фразы и разрезала список посередине. Прогон приёмки
показывал ✅ ЧИСТО, потому что образцы следов правки ищут висящую пунктуацию, а здесь пунктуация
цела — порвано СЛОВО. Урок дороже случая: **счёт предложений по точке ломается на сокращениях, и
любая машинная нарезка текста по этому счёту рвёт его в том же месте.** До того как ворота научатся
это ловить, у правила есть дешёвая защита письмом: **в описаниях не пишем сокращений с точками
внутри** — название с инициалами заменяется полным или обходится.

✅ **ТРИ КЛАССА 2026-08-21 ЗАКРЫТЫ МАШИНОЙ 2026-08-22** (dev-3, `tools/measure-prose-gates.mjs`).
Прежняя редакция этой строки гласила «машиной тоже НЕ закрыты» и пережила своё исполнение —
снята. Ворота знают простой слог (расщеплённое сказуемое), суть важнее производства (доля меты) и
называние вместо отнесения. Контракт признаков — `researches/47_candidate_gates_contract.md`.
⚠️ **Но приёмка по-прежнему НЕ закрывает главного: «похоже ли это на мою статью» решает
владелец.** И у самих ворот доля меты порогом пока не красит — он ждёт замера (см. выше). Машина
закрывает проверяемое и говорит об этом вслух — иначе зелёный прогон читался бы как приёмка
владельца.

### Объём и строение — числами

🔄 **КОРИДОР ПЕРЕВЫВЕДЕН 2026-08-21 ПО СЛОВУ ВЛАДЕЛЬЦА.** Дословно: «*900…1400 знаков, 8…14
предложений — это МАЛО!!!! Нужно подробнее!! Читай измерения в БД*», «*например практики танцев,
спорт, секс, игра на музыкальном инструменте, фильмы оригинальной трилогии матрицы — там много
написано*», «*редактируй стилометрию измерений по этим примерам*».

| Мера | Норма | Откуда взята |
|---|---|---|
| Знаков | **1200…2000**, целиться в **1400…1700** | p10…p90 эталонного корпуса владельца (431 запись), медиана 1415 |
| Предложений | **8…18** | тот же корпус: p10 = 7, медиана 9, p90 = 12, максимум 19 |
| Длина предложения | **≈150 знаков** — академический период | средняя по его корпусу: 154 |
| Языков | оба, и **оба полноценные** | английский не короткий пересказ русского |

СРЕДНЕЙ ВСЕГО каталога (1068). Но среднюю тянут вниз массовые виды, а владелец указал на свои
РАЗВЁРНУТЫЕ. Замер 5121 боевой записи 2026-08-21:

| Вид | Записей | Средняя | Медиана | p90 | Максимум |
|---|---|---|---|---|---|
| **Практика** | 228 | **1424** | 1467 | 1720 | 2161 |

### ✅ ПРИЁМ И РЕАКЦИЯ СООБЩЕСТВА — МОЖНО И НУЖНО (слово владельца 2026-08-22)

Похвала, а не замечание, и потому её легко потерять. Владелец **одобрил** абзац о приёме фильма
в карточке «Кобра» и сказал о таком письме дословно:

> «*я сам такое писал, и такое одобряю в описании объектов культуры*»

**Правило:** описание объекта культуры **может и должно** нести то, как объект был ПРИНЯТ — оценки
критиков, отношение публики, место в разговоре о нём. Это часть того, ЧТО объект такое, а не
украшение. Образец — последняя строка «Кобры», которую он и хвалил:

> «*При коммерческом успехе фильм получил резкие отзывы критиков за жёсткость и прямолинейность.*»

🔴 **ГРАНИЦА, БЕЗ КОТОРОЙ ПРАВИЛО СЪЕЛИ БЫ ВОРОТА: реакция сообщества — НЕ производственная
мета.** Приём — это то, что случилось с объектом ПОСЛЕ выхода, у людей; производство — то, как его
делали. Ворота доли меты приём **не штрафуют**, и лексикон приёма («отзывы», «критики», «успех»,
«принят», «сборы») в производственный список не входит. Граница уезжает и в прибор (dev-3):
проверка, считающая похвалу владельца нарушением, — дефект.

⚠️ **Чего это НЕ отменяет:** оценок от себя мы не даём (карточка сообщает, КАК приняли, а не
хорошо ли это), и приём не подменяет содержание — сюжет, герои и проблематика по-прежнему идут
вперёд и занимают основную часть.

📌 **Как это слово чуть не пропало** — знать полезно всей мастерской: кнопка «Одобрить» в
комнате «Измерения» выбрасывает комментарий владельца, а поле `ownerNote` хранит текст ВОЗВРАТА.
Похвала восстановлена из чата, в базу не вернулась. Разбор — `bugs/173`.

⚠️ **Обратная ошибка дороже прямой.** Место, освободившееся от производства, занимает СЮЖЕТ, а не
пустота: коридор 1200…2000 знаков не тронут, и «скупо» мастерская уже оплачивала дважды.

🔑 **Это не отменяет «пять частей», а исправляет их ВЕС.** Порядок частей (ниже) выведен из его
текста о «Матрице», и там самая длинная часть — устройство мира и выбор героя, а производство
укладывается в одно предложение. Агентские партии перевернули пропорцию: обвязка разрослась,
содержание исчезло.

⛔ **Граница, которую нельзя перейти ради этого правила: сюжет НЕ ВЫДУМЫВАЕТСЯ.** Реестр не даёт ни
темы, ни места действия, ни персонажей — пишется подтверждённое, а нехватка называется в
`agentNote`. Выдумка хуже меты: мету владелец сократит, а выдумку он от факта не отличит.

🔎 **И прежде чем объявить, что сюжета нет, — спроси реестр.** У «Дня разоблачения» прежний автор
написал «содержание не раскрывалось» и построил карточку на производстве; в реестре при этом стоят
три темы: НЛО, движение за раскрытие сведений о нём и возможные последствия контакта с внеземной
цивилизацией. Свойства, которые несут содержание: **`P921` тема · `P840` место действия ·
`P674` персонажи · `P144` первоисточник**. Их снимает тот же запрос `wbgetentities`, что и остальные
факты карточки.

### 🔴 ИСТОЧНИК ФАКТОВ — ВЕСЬ ИНТЕРНЕТ, ИЗЛОЖЕНИЕ — ТОЛЬКО СВОЁ (решение владельца 2026-08-22)

правила мастерской столкнулись между собой: «не выдумывай сюжет» + «мета не должна занимать
описание» + «не короче 1200 знаков». Исполнить все три было нечем.

**Что теперь можно и чего нельзя:**

- ✅ **Факт о содержании берётся откуда угодно в сети** — статья, интервью автора, обзор, карточка
  фильмотеки. Реестр остаётся опорой для ПОЛЕЙ карточки (название, вид, год, автор, состав — они
  и дальше снимаются по идентификатору), но описанию он больше не единственный источник.
- ✅ **Факт обязан быть правдивым**, а не правдоподобным. Сомнительное сверяется вторым источником;
  разошлись — берётся то, что подтверждено, а расхождение уезжает в `agentNote`. Полевой пример
  того же дня: у «Обсессии» два источника дали РАЗНЫЕ кассовые сборы, и оба числа просто не
  вошли в описание — касса не нужна тексту настолько, чтобы печатать спорное.
- 🔴 **Изложение — своё, уникальное.** Пересказ близко к тексту источника нарушает то же самое,
  что копипаста: проект уже вычищал 196 заимствованных описаний. Прочитал — закрыл — написал
  своими словами.
- ⛔ **Дословный ряд от 10 слов против ЛЮБОГО источника — дефект**, а не только против Википедии.

⚠️ **Честная граница, и она машинная.** Ворота приёмки сверяют дословный ряд ТОЛЬКО со статьёй
Википедии на том же языке. Другие источники сети машина не проверяет и в обозримом будущем не
будет: их у факта может быть десяток. Значит правило «изложение своё» за пределами Википедии
держится письмом и вычиткой владельца — как и три класса стиля выше. Знать это обязан каждый, кто
здесь пишет: зелёный прогон означает «не совпало с Википедией», а не «текст уникален».

### 🔴 ЖАНР НАЗЫВАЮТ, А НЕ ПРИПИСЫВАЮТ — класс, который прятался в двух замечаниях

> «*"картина совмещает признаки" — какое-то странное формулирование жанра.*»
>
> «*"По жанровой принадлежности лента относится" — высокомерное пафосное обращение к описанию.
> **Мы так не делаем.**»

🔑 **Почему это отдельный класс, а не частный случай слога.** Это та же КОНСТРУКЦИЯ ОТНЕСЕНИЯ, что
запрещена выше в «реестр относит», — она пережила прошлый запрет, потому что из неё убрали
авторитет, а оболочку оставили. Подлежащим стала сама картина: «лента относится к», «картина
принадлежит драматическому кинематографу», «картина совмещает признаки». Прошлый запрет снял слово
«реестр», а снимать надо было конструкцию.

📐 Замер партий 2 и 3: отдельное предложение об отнесении к жанру стоит в **7 карточках из 20**.

🔴 **И почти всегда оно ТАВТОЛОГИЧНО** — жанр уже назван первым предложением. Из «Марти
Великолепного» дословно: «*Американская драматическая комедия 2025 года… Картина принадлежит
драматическому кинематографу и представляет собой американскую драматическую комедию.*» Одно и то
же сказано трижды подряд.

| | Как выглядит |
|---|---|
| ⛔ | «*По жанровой принадлежности лента относится к сверхъестественному хоррору*» |
| ⛔ | «*картина совмещает признаки психологического хоррора, научной фантастики и приключенческого кино*» |
| ✅ | «*Психологический хоррор с приключенческой основой*» — жанр назван первым предложением и больше не повторяется |
| ✅ | отдельного предложения о жанре в описании нет вовсе |

**Ремонт у этого класса свой:** предложение-отнесение не упрощают и не переносят — его УДАЛЯЮТ, а
жанр называют один раз, в первом предложении.

### Пять частей, в этом порядке

Разобрано по его тексту о «Матрице» — это канон, а не вывод агента о нём.

⚖️ **Порядок частей — не их вес.** Части 4 и 5 (устройство мира, герой и его выбор) несут ОСНОВНОЙ
объём описания; части 1–3 (жанр с авторством, состав, выход) — это обвязка, и она короткая. Правило
класса «суть важнее производства» (выше) действует именно здесь: перечень продюсеров, компаний и
прокатных дат по территориям не имеет права весить больше, чем то, что в объекте происходит.

1. **Жанр и авторство с производственной обвязкой**, первым предложением:
   «*Научно-фантастический боевик братьев Вачовски: они же написали сценарий, продюсировал Джоэл
   Сильвер.*»
2. **Состав — отдельным предложением**: «*Играют Киану Ривз, Керри-Энн Мосс, Хьюго Уивинг и Лоренс
   Фишберн.*»
3. **Выход и место в ряду**: «*В прокате США картина с 31 марта 1999 года; с неё началась
   одноимённая медиафраншиза.*»
4. **Устройство мира — развёрнутым академическим периодом**, с причастными оборотами и формальными
   связками: «*реальность, существующая для большинства людей, является в действительности
   симуляцией типа «мозг в колбе» — Матрицей — созданной разумными машинами, чтобы подчинить и
   усмирить человеческое население…*»
5. **Герой и центральный выбор, исход назван прямо**: «*Он выбирает борьбу.*»

🔑 **И его практика, которую стоит повторять:** у частей одной франшизы блок об устройстве мира
повторяется ДОСЛОВНО в каждой записи. Человек, попавший на третью часть из поиска, читает
предпосылку целиком и не идёт искать первую.

### Регистр — что можно и чего нельзя

- ✅ Академический период с причастными и деепричастными оборотами, формальные связки.
- ✅ Факты производства: постановщик, сценарист, продюсер, композитор, состав, год, место в ряду.
- ⛔ **Разговорная связка и впечатление вместо факта.** Из отвергнутой партии: «*Дорога домой длиной
  в десять лет показана как путь человека, который держит слово, данное самому себе*» — это регистр
  эссе, а не справочной статьи.
- ⛔ **Три-четыре предложения вместо статьи.** Сжатие до тезиса и есть то, что владелец назвал
  «скупым объёмом».
- ⛔ **Остановиться на нижней границе коридора.** Нижняя граница — это брак, а не цель. Владелец
  дважды говорил одно и то же слово: «подробнее». Целься в 1400…1700, а не в 1200.
- ⛔ **Зачин с названия объекта:** «*«Обсессия» — американский фильм ужасов…*». Название уже стоит
  в шапке карточки, повторять его в первой строке владелец запретил правилом класса (2026-08-21,
  разобрано разделом выше). Ворота отказывают.
- ⛔ **Приписка к реестру и всякий внешний авторитет:** «*реестр относит*», «*по реестру*», «*the
  registry classifies*». Запрет класса, слово владельца 2026-08-21, разобран разделом выше.
- ⛔ **Пассивное увиливание вместо факта:** «*дата зафиксирована*» вместо «*игра вышла тогда-то*».
  Тот же класс: описание констатирует факт от себя.
- ⛔ **Расщеплённое сказуемое и всякий надутый оборот:** «*производство осуществлено*» вместо
  «*произвела*», «*выход состоялся*» вместо «*вышел*». Запрет класса, слово владельца 2026-08-21
  («*Не усложняй!!!*»), разобран разделом выше. ⚠️ Запрещена надутость оборота, а не длина периода.
- ⛔ **Производственная обвязка вместо содержания.** Продюсеры, компании и перечни прокатных дат,
  занявшие место сюжета, героев и проблематики. Запрет класса того же дня; пропорция и её замер
  (47 % объёма партий 2–3) — разделом выше.
- ⛔ **Отдельное предложение об отнесении к жанру:** «*лента относится к*», «*картина принадлежит
  драматическому кинематографу*», «*совмещает признаки*». Жанр называется один раз, первым
  предложением; предложение-отнесение удаляется целиком.
- ⛔ **Пересказ событий, которых ещё никто не видел.** Девять картин первой партии на момент
  написания в прокат не вышли: описывается ИЗВЕСТНОЕ — постановка, первоисточник, место в ряду.

⚠️ **Отдельная граница, оплаченная разбором:** правила голоса из `AUTHOR_STYLOMETRY.md` писаны для
ЛИЦА ПРОДУКТА (лендинг, блок-дверь), где владелец «идёт как ледокол». **Описание каталога — другой
жанр того же автора**, и перенос витринного регистра сюда был ошибкой первой партии. Класс:
«правило, верное для одного жанра, применено к другому».

### Заимствование меряется машиной, а не обещанием

«Вики-подобно» и «побайтно из вики» разделяет прибор, потому что владелец сам сказал, что в его
старых текстах копипаста есть. Перед выгрузкой партии:

```bash
node tools/check-candidate-descriptions.mjs candidates/batches/NN_*.json
```

Он мерит **объём, число предложений и самый длинный ДОСЛОВНЫЙ РЯД** против статьи Википедии на том
же языке, тем же ядром и тем же порогом (10 слов), что свод каталога. Статья не нашлась —
запись помечается «НЕ ПРОВЕРЕНО» и в «чистые» не попадает никогда.

⚠️ **И честная граница прибора, названная в нём самом:** машина закрывает объём, строение и
заимствование. **«Похоже ли это на мою статью» решает владелец** — прибор этого не проверяет и не
заменяет его вычитку.

## Команды

```bash
# 1. Разведка: что вышло и чего у нас нет
node tools/scout-wikidata-candidates.mjs --year 2026 --min-sitelinks 12
#    → candidates/scouts/NN_*.md  (нужен свежий снимок каталога: fetch-dims-slice --all)

# 2. Развёрнутые объекты пишутся руками агента в candidates/batches/NN_*.json

# 2б. ПРИЁМКА ОПИСАНИЙ — объём, строение и заимствование. Гонится ДО выгрузки
node tools/check-candidate-descriptions.mjs candidates/batches/01_2026_films.json

# 3. Выгрузка в очередь. СУХОЙ ПРОГОН ПО УМОЛЧАНИЮ — пишет только с --apply
node tools/seed-dim-candidates.mjs candidates/batches/01_2026_films.json
node tools/seed-dim-candidates.mjs candidates/batches/01_2026_films.json --apply
node tools/seed-dim-candidates.mjs candidates/batches/01_2026_films.json --contour prod --apply

# 4. Вычитка владельцем: ndimspace.app → Меню → Панель администратора → Менеджер измерений → «Очередь»

# 5. ОБРАТНОЕ ПЛЕЧО: что владелец вернул на доработку и с каким замечанием
node tools/read-returned-candidates.mjs --contour prod
#    → правишь текст в партии → шаг 2б → шаг 3: карточка вернётся в очередь со статусом pending,
#      замечание владельца при этом уцелеет
```

🔑 **Повторный прогон выгрузки безопасен:** идентификатор кандидата выводится из `QID`, поэтому
партия перезаписывает те же документы, а не плодит дубли. **Уже разобранного владельцем прибор не
трогает** — одобренный или отклонённый кандидат в очередь не возвращается, иначе его решение
пришлось бы принимать дважды.

## DONE-тег

Партия помечается `DONE`, когда владелец разобрал **всех** её кандидатов:
`git mv batches/01_2026_films.json batches/01_DONE_2026_films.json`.
Тезисные списки в `scouts/` — **живые справочники**: из одного списка партии берутся месяцами, и
`DONE` они не получают никогда.

## Чего в этой директории НЕТ

- **Методология и разведданные о том, КАК искать** — это `researches/`. Здесь рабочие списки,
  там знание. Первый разбор устройства мастерской живёт прямо в этом README.
- **Развилки владельцу** — только `interviews/`. Вопрос, лежащий в партии, он не увидит.
- **Ни одной записи каталога.** Всё, что здесь лежит, — предложение. Каталог живёт в базе, и
  пишет в него только владелец.
