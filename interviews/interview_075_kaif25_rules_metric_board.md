### В2. Одна метрика доставки — по чему считать, сдвинулась ли работа?

**Адресат ответа:** строка «Метрика доставки» в `MASTER_PLAN.md` и первая строка каждого
закрытия чата.

Как это выглядит на деле:
- Ситуация. За смену закрыты шесть багов и два плана, все проверки зелёные.
- Действие. Агент закрывает чат.
- Результат. Первая строка доклада: «`DELIVERY: вошли и остались 0 → 0; moved by: —; blocker:
  дверь карточки каталога ведёт в стену входа`».
- Проверка. `git log -1 --format=%b` показывает эту строку в теле коммита закрытия.

Формула: метрика обязана считаться уже сегодня и означать ВАШУ приёмку, а не занятость агента.
Исток пришёл к этому после замера «54 честные зелёные сессии сдвинули продукт на 11 из 389».

- **А) (рекомендую) «Вошли и остались»** — сколько аккаунтов создали люди, пришедшие органикой
  (сейчас 0 по замеру воронки в августе). Это прямая приёмка фазы 7 «чтобы вошли». Считать по
  списку аккаунтов Firebase; с приходом «Зрения» (`plans/74`) — автоматически.
- **Б) «Найдены поиском»** — адресов в индексе Яндекса, N из 1051. Считается уже сегодня, но это
  шаг к входу, а не вход.
- **В) «Паритет с 1.x»** — закрытых пунктов фазы 6, N из M. Ваша давняя боль, но приоритет
  уступил воротам по Вашему же решению.

**Ответ:** нужно приложение классифицировать и посчитать по числу механик логически обособленных от друг дружки. Сейчас идей и механик множество. Нужно считать эти механики, насколько они оценочно по 100% шкале завершены, насколько по 100% шкале вплетены и связаны с остальными механиками приложения. Сколько в приложении есть известных дыр, сколько есть противоречий, сколько есть багов. Все эти показатели - это и будет вектор метрики поставки.

### В3. Доска команды — вне git (канон 2.5) или остаётся отслеживаемым файлом?

**Адресат ответа:** `NDIM_WORKTREE_DEV_TEAM_STATUS.md` · инструмент `tools/team-status.mjs` ·
манифест команды, раздел «статус-доска».

Наш тикет `bugs/171` («доска — отслеживаемый файл, дерево грязно по построению») стал каноном:
2.5 держит доску ВНЕ git по умолчанию, а отслеживаемую доску называет опт-аутом, цена которого
записана в конституции. У нас шесть рабочих мест в worktree делят одну доску именно через git.

- **А) (рекомендую) Вывести доску из git.** Один файл по одному абсолютному пути (главная копия),
  инструмент читает его из любого рабочего места; строка в `.gitignore`; снимок доски едет в
  ретроспективу смены. Цена: небольшая правка инструмента и один прогон его самопроверки. Выгода:
  чистые деревья у всех ролей — исчезает класс трения, за который мы сами платили.
- **Б) Оставить в git** и записать опт-аут с его ценой в манифест: «доска — отслеживаемый файл,
  грязное дерево у ролей — норма, ворота чистого дерева её пропускают». Ноль работы сейчас,
  трение остаётся.
