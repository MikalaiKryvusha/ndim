## Шаг 1. Назовите это окно Менеджером

Это окно (главная копия `D:\work\ai_sandbox\ndim`) — и есть Менеджер. Наберите в нём одной
строкой:

```
/rename ndim_manager
```

## Шаг 2. Откройте пять окон ролей (руками — CLI им противопоказан)

**File → Open Folder** (каждая папка — новое окно). Папки — с припиской `ndim_`, чтобы окна
команды отличались в Windows от окон других проектов. ⚠️ Программное открытие окон Менеджером
испытано и ЗАПРЕЩЕНО (`EXP-0179`): команда уходит общему экземпляру VS Code, и тот исполняет
её чужим активным окном — на первом запуске зацепило соседний проект.

| Окно | Папка |
|---|---|
| Дизайнер | `D:\work\ai_sandbox\ndim-team\ndim_designer` |
| QA-инженер | `D:\work\ai_sandbox\ndim-team\ndim_qa` |
| Разработчик 1 | `D:\work\ai_sandbox\ndim-team\ndim_dev1` |
| Разработчик 2 | `D:\work\ai_sandbox\ndim-team\ndim_dev2` |
| Разработчик 3 | `D:\work\ai_sandbox\ndim-team\ndim_dev3` |

⚠️ Окна открываются именно через VS Code (расширение Claude Code 2.1.238). Терминальная команда
`claude` на этой машине пока версии 2.1.232 — у неё на Windows нет связи между сессиями; для
команды она не годится, пока не обновится.

## Шаг 3. В каждом окне — два клика, ноль печатания

Иконка Claude в боковой панели → выберите **усилия размышления MAX** (модель Opus 5 уже
предзадана конфигом рабочего места — `.claude/settings.local.json` пишет инструмент `create`;
только гляньте, что встала). **Печатать ничего не нужно** (Ваша правка на первом запуске
2026-08-21, проверено живьём): открытая панель сама регистрирует сессию, Менеджер видит её в
списке, присылает инструктаж — и это сообщение будит роль. Роль по инструктажу читает манифест,
объявляется на статус-доске и докладывает Менеджеру; имена сессий остаются автоматическими
(они начинаются с имени папки — `ndim-dev1-…`), точные адреса Менеджер вписывает в постановки.

⚠️ Перед запуском убедитесь, что имя `ndim_manager` носит ровно ОДИН чат — новый Менеджер.
Прежний припаркованный чат Менеджера переименуйте (`/rename ndim_manager_old`) или закройте:
двойник имени перехватывает доклады ролей (прожито на первом запуске).

## Шаг 4. Напишите Менеджеру — и команда пойдёт

Как только окна открыты, напишите Менеджеру в этом окне, что делать команде, — например:

```
Команда открыта. Запускай: раздай задачи по текущему беклогу.
```

Менеджер разошлёт задачи по манифесту (постановка: что · зачем · критерии готово · где · что не
трогать · когда и куда отчитаться) и будет вести конвейер: работа в ветке роли → вердикт QA →
мерж в main.

## Что уже проверено без Вас (репетиция 2026-08-21, протокол — `qa/team-rehearsal.md`)

- Сообщения ходят в обе стороны, постановка доставляется мгновенно.
- Статус-доска и замок стенда работают из рабочих мест ролей.
- Полный конвейер прожит: постановка → коммит в ветку роли → мерж Менеджером → перезапуск ветки.
- Найденный на репетиции дефект (отчёт ушёл сессии чужого проекта при смерти адресата) вылечен
  правилами 2 и 9 манифеста.

## Если что-то не так

- Роль не видит доску или замок → она обязана звать инструмент по абсолютному пути:
  `node D:\work\ai_sandbox\ndim\tools\team-status.mjs …` — это написано в манифесте.
- Сообщение не дошло → посмотрите строку роли на доске (`NDIM_WORKTREE_DEV_TEAM_STATUS.md`) —
  результат работы всегда лежит в ветке и на доске, даже когда сообщение потерялось.
- Окно закрылось/зависло → просто откройте папку роли заново и повторите две строки шага 3:
  ветка роли хранит все коммиты, ничего не теряется.
