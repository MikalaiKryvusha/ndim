## Зачем это нужно от Вас, а не от меня

Доступ к данным Search Console выдаёт **не облако, а сама консоль**. Ролей Google Cloud, которые
открывали бы эти данные, не существует: API пускает только того, кто числится пользователем ресурса
в самой Search Console, — а добавить туда адрес может лишь человек с правами владельца ресурса.
Это Вы.

## Часть 1 — добавить аккаунт в Search Console (~2 минуты) 🔴 ГЛАВНОЕ

1. Откройте **https://search.google.com/search-console** под аккаунтом `kotkrinik@gmail.com`.
2. В левом верхнем углу выберите ресурс **`ndimspace.app`** (он у нас доменный — одно добавление
   покроет и `/ru`, и `/en`, и поддомены сразу).
3. В левой колонке внизу нажмите **«Настройки»**.
4. Откройте **«Пользователи и разрешения»**.
5. Нажмите синюю кнопку **«Добавить пользователя»**.
6. В поле адреса вставьте **ровно эту строку**:

   ```
   ndim-console-reader@ndim-space.iam.gserviceaccount.com
   ```

7. Уровень разрешений выберите **«Полный доступ»**.

   Почему не «Владелец»: владельческий уровень нужен только чтобы **менять** ресурс — подавать карту
   сайта, править настройки. Миссия только читает, и лишнее право здесь — лишний риск.
   Почему не «Ограниченный»: он показывает не всё, и часть метрик просто не приедет.

8. Нажмите **«Добавить»**.

> права собственности»**, в списке подтверждённых владельцев нажмите **«Добавить владельца»** и

## Часть 2 — выдать две роли аккаунту выгрузки (~1 минута)

Это нужно для второй половины дела — чтобы Search Console сама каждый день складывала данные в
BigQuery и они хранились без срока (зачем — часть 3).

Я эту команду выполнить не могу: правку прав доступа мне заблокировал предохранитель моего
инструментария, и обходить его я не стал. **Вставьте в PowerShell две команды по очереди:**

```powershell
gcloud projects add-iam-policy-binding ndim-space --member="serviceAccount:search-console-data-export@system.gserviceaccount.com" --role="roles/bigquery.jobUser"
```

```powershell
gcloud projects add-iam-policy-binding ndim-space --member="serviceAccount:search-console-data-export@system.gserviceaccount.com" --role="roles/bigquery.dataEditor"
```

Каждая должна закончиться выводом обновлённой политики без слова `ERROR`.

> Адрес `search-console-data-export@system.gserviceaccount.com` — это аккаунт **самого Google**, не
> наш. Роли выдаются ему, чтобы он имел право писать в наш BigQuery. Так это и описано в
> документации Google.

## Часть 3 — включить массовую выгрузку в BigQuery (~2 минуты)

**Зачем, коротко.** Search Console хранит историю **16 месяцев** и прошлое не восстанавливает.
Каждый день без выгрузки — это день, который через 16 месяцев исчезнет навсегда. Выгрузка копит
данные у нас и снимает эти часы с нашей шеи. Прошлые 16 месяцев API отдаст в любой момент, а вот
суточная детализация с сегодняшнего дня копится только у того, кто выгрузку уже включил, —
**поэтому эта часть важнее части 1 по срочности, хотя и меньше по смыслу.**

1. Search Console → тот же ресурс `ndimspace.app` → **«Настройки»**.
2. Откройте **«Массовый экспорт данных»**.
3. **Идентификатор проекта Cloud:** `ndim-space`
4. **Название набора данных:** `searchconsole` (это значение по умолчанию, менять не нужно)
5. **Расположение набора данных:** **EU** — рекомендую именно его: наши данные и так живут в
   Европе (боевая база в `eur3`), и держать выгрузку рядом честнее по приватности.
   🔴 Выбирается **один раз**: сменить расположение потом можно только удалив набор и начав заново.
6. Нажмите **«Продолжить»** и подтвердите.

Первая выгрузка приедет в течение суток, не сразу.

> **Про деньги, чтобы не было сюрприза.** Место в BigQuery платное. При наших нынешних числах это
> единицы мегабайт в сутки — расход, который на счёте будет незаметен, но он не нулевой, и Вы о нём
> предупреждены.
