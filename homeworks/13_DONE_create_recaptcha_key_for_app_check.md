## Зачем

Ваше обязательство из интервью №009: «*App Check — включу сам… без него широкая гостевая
дверь становится приглашением накрутить воронку*». Фаза 3 подключает App Check в **режиме
наблюдения**: ни один запрос не блокируется, консоль копит доли запросов «с токеном / без
токена». Код в приложении уже стоит за предохранителями и ждёт только ключа.

**Принуждение этой домашкой НЕ включается.** Оно — отдельный шаг после наблюдения, включу его
я сам (решение №009 отдано агенту, оно обратимо переключателем), и перед ним отдельно
подготовлю боевые смоуки двери.

## Почему это не может сделать агент

Ключи reCAPTCHA создаются только руками в админке Google — у неё нет API (разведка
2026-08-21). Нужен классический **v3**, не Enterprise: Enterprise заводится по API, но тянет
включение биллинг-поверхности — против Вашего условия держаться бесплатных планов.

## Что сделать

1. Открыть **https://www.google.com/recaptcha/admin/create** (под аккаунтом проекта).
2. Заполнить:
   - **Label:** `NDim Space`
   - **Тип:** **reCAPTCHA v3** (score based)
   - **Domains:** `ndimspace.app` и `www.ndimspace.app`
3. Создать. Получите две строки: **Site key** (публичная) и **Secret key** (секретная).
4. **Site key** пришлите мне в чат — он публичный по устройству, как и весь веб-конфиг: лежит
   в бандле у каждого посетителя. Я впишу его в `src/lib/firebase.ts` и выкачу штатной дверью.
5. **Secret key** внесите в консоль Firebase, мне его присылать не нужно:
   **https://console.firebase.google.com/project/ndim-space/appcheck** → вкладка **Apps** →
   приложение web «NDim Space» → провайдер **reCAPTCHA v3** → вставить секрет → сохранить.

## Альтернатива, если удобнее без консоли Firebase

Положите секрет в `.env` строкой `NDIM_RECAPTCHA_SECRET=<секрет>` (Ваше же правило: ключи
живут только в окружении) — тогда регистрацию провайдера в App Check я проведу сам по REST,
а строку из `.env` потом можно удалить: после регистрации секрет хранится у Firebase.

## Как агент поймёт, что готово

Впишу сайт-ключ, выкачу дверью (стейдж → бой), и в консоли **App Check → Metrics** начнут
копиться запросы «Verified» — это первая половина ворот наблюдения. Вторая — «доля без
токена стабилизировалась» — вопрос нескольких дней, и только после неё придёт черёд
принуждения.

## Честное предупреждение о лице продукта

Условия reCAPTCHA требуют либо бейдж в углу страницы, либо строку атрибуции («protected by
reCAPTCHA» со ссылками на политику Google). Строка мелкая, но это лицо продукта: при вписании
ключа покажу варианты размещения — сам ставить не буду.
