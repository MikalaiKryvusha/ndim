# План 31 — ЭПИК `ideas/29`, ФАЗА 1: экономный индекс каталога

> **Третья ступень лестницы `/plan-epic`** — операционный план **только этой фазы**.
> План фазы 2 пишется, когда закроется фаза 1 (с её уроками внутри), а не заранее.

> **Доказательная база:** `researches/29` §2.3, §2.4, §2.5, §2.6, §3.7.
> **Статус:** 🔵 открыт, разблокирован · решений владельца НЕ требует · клиент НЕ трогаем.

## Цель фазы

Сделать так, чтобы **добавление одного измерения стоило одной-двух операций Firestore, а не 5111
чтений**, и чтобы обслуживание индекса перестало молча терять данные. Это техническое предусловие
всего остального эпика: пока пересборка индекса стоит как весь каталог и стирает поля, любой код,
создающий измерения, строится на песке.

Попутно закрывается открытый `bugs/106` — правка живёт в той же функции, и чинить её отдельным
заходом значит платить за пересборку боевого образа дважды.

## Критерии «готово»

1. Добавление измерения в каталог **не вызывает полного перечитывания каталога** — доказано
   прибором «до/после» в числах операций.
2. Документ каталога без поля `title` **не вводит вычислитель в вечную пересборку** — доказано
   воспроизведением на стенде до фикса и его отсутствием после.
3. Полная пересборка (аварийный путь) **сохраняет поля записи, которых не знает** — доказано
   тестом, красным на сегодняшнем коде.
4. `space/stats.dims` равно числу записей индекса; диаметр Пространства при 5111 измерениях
   равен **714,9** (`bugs/106`).
5. Страж фазы **красный на сегодняшнем коде** и доказан ≥2 мутациями.
6. `npm test`, `npm run test:calc`, `npm run test:rules` — зелёные.
7. Пара «истина ↔ зеркало» вписана в реестр `AGENT_GUIDE` с однострочной командой проверки.

## Чего эта фаза НЕ делает

- **Не строит панель и не пишет ни строки клиента.** Инкрементальная запись со стороны панели
  приезжает в фазе 4 вместе со своим единственным потребителем — формой создания (YAGNI).
- **Не меняет поведение экранов** «Измерения» и «Пространство» — числа обязаны остаться теми же,
  кроме исправленного `dims` (5112 → 5111) и диаметра (715 → 714,9).
- **Не выкатывает.** Правка живёт в образе сервера синхронизации; пересборка и выкат — рука
  владельца (`npm run calc:image`).

## Шаги

### Шаг 0 — Замер ДО кода (прибор, не страж)

> ⚓ Якорь метаплана: «Обезвредить **мину `title`** … 5111 чтений на каждом рабочем цикле при
> бесплатной суточной квоте 50 000».

Без этого замера доказать, что фикс что-то починил, будет нечем (`EXP-0070`: проверка, которую
нельзя провалить, ничего не проверяет).

- [ ] Написать `tools/measure-dims-index.mjs` — **прибор**: печатает по кругам, сколько документов
      каталога читает один цикл вычислителя и была ли пересборка индекса.
- [ ] **Воспроизвести мину `title` на стенде:** положить в каталог документ с полем `name` и БЕЗ
      `title`, прогнать два цикла подряд, показать, что запись «индекс каталога пересобран»
      появляется **каждый раз**. Ожидание по коду: `indexed` навсегда на единицу меньше
      `dimsCount - 1`, условие возврата (`index.mjs:355`) не выполняется никогда.
      🔴 Если воспроизвести НЕ удалось — остановиться и переписать гипотезу, а не «чинить на всякий
      случай»: `researches/29` §2.3 помечен `[NOT-TESTED]` честно.
- [ ] **Замерить цену добавления одного измерения** сегодня: сколько чтений от появления документа
      до его появления в индексе.
- [ ] **Проверить находку §2.6** (виджет «Сегодня» не видит новых измерений в бою): запрос
      `catalog.where('created', '>=', …)` (`index.mjs:321`) ищет ПЛОСКОЕ поле, а боевые документы
      несут `time.created`. Подтвердить чтением боя прибором `probe-prod-stats` (только чтение,
      разрешение — интервью №013 В2 = Б) либо арифметикой по миграции.
- [ ] Подтвердилось — **завести баг-документы** (`/report-bug`) до фикса, а не после.

**Проверка наблюдением:** в чате и в документе фазы стоят ЧИСЛА «до» — сколько чтений, сколько
пересборок на два цикла. Без чисел шаг не закрыт.

### Шаг 1 — 🔴 Стенд врёт формой данных, и это чинится ПЕРВЫМ

> ⚓ Якорь метаплана: «Проверить находку §2.6: ищет ли вычислитель новые измерения по полю,
> которого в бою нет».

`tools/seed-dev.mjs:297` кладёт измерения с **плоским** `created`, а бой несёт `time.created`
(Timestamp). Значит запрос вычислителя на стенде работает, а в бою не находит ничего **никогда** —
и ни один существующий тест этого увидеть не может, потому что все они смотрят на стендовую форму.

- [ ] Сделать сид **честным**: часть измерений — в боевой форме `time.created`, часть — в
      стендовой (обе формы живут в реальности, `feed.ts:227` знает обе).
- [ ] Убедиться, что после правки сида **существующие тесты `test:calc` краснеют или остаются
      зелёными по ПРАВИЛЬНОЙ причине** — и объяснить в коммите, какой именно (правка тестовых
      фикстур без обоснования = фрод по умолчанию, `AGENT_GUIDE` → «Коммиты»).

**Проверка наблюдением:** прогон `npm run test:calc` до и после правки сида; в коммите — блок
обоснования.

### Шаг 2 — Страж ДО фикса

> ⚓ Якорь метаплана: «страж … **красный на сегодняшнем коде**, зелёный на новом, доказан
> ≥2 мутациями».

- [ ] `tools/verify-dims-index.mjs` стережёт четыре вещи:
      1. **добавили измерение → оно в индексе, и полной пересборки НЕ было** (счёт чтений);
      2. **документ без `title` не вызывает пересборку на каждом цикле** (два цикла подряд — одна
         запись в логе, а не две);
      3. **пересборка сохраняет незнакомые поля записи** (положить в запись индекса постороннее
         поле, вызвать аварийную пересборку, убедиться, что поле живо) — это требование `ideas/28`
         про счётчики популярности;
      4. **`space/stats.dims` == числу записей индекса**, и диаметр при 5111 равен 714,9.
- [ ] Прогнать страж на **сегодняшнем** коде: он обязан покраснеть минимум по пунктам 1, 2 и 4.
      Зелёный страж до фикса = страж-украшение, шаг не закрыт.

**Проверка наблюдением:** число провалов «до» записано в этот документ.

### Шаг 3 — Фикс: сторож свежести перестаёт врать

> ⚓ Якорь метаплана: «Полная пересборка становится аварийным путём».

Сегодня свежесть индекса определяется вычитанием магической единицы
(`index.mjs:355` — `indexed === dimsCount - 1`), и любая аномалия каталога превращается в вечный
цикл пересборок.

- [ ] Записывать при сборке индекса **отметку сборки** отдельным полем документа `dims/dims_list`
      (не внутри JSON-строки: `merge` на уровне поля её сохранит) — сколько документов каталога
      было на момент сборки и когда.
- [ ] Свежесть определять **сравнением с этой отметкой**, а не вычитанием константы. Документ без
      `title` тогда перестаёт быть вечным поводом: числа сходятся с тем, что было при сборке.
- [ ] Число служебных документов вынести **именованной константой** со списком идентификаторов —
      магических чисел в проекте не держим (`AGENT_GUIDE` → «Стиль кода»).
- [ ] Расхождение «документов каталога больше, чем записей индекса» **логировать
      предупреждением с числом** — мина обязана быть видна, а не молчать.

### Шаг 4 — Фикс: дельта вместо полной пересборки

> ⚓ Якорь метаплана: «**Инкрементальное обновление**: … одно чтение + одна запись вместо
> 5111 чтений».

- [ ] Обычный путь: дочитывать **только изменившиеся документы** каталога (рекомендация —
      запрос по времени правки, `time.updated`, покрывающий и создание, и редактирование) и
      дописывать их записи в индекс.
- [ ] Полная пересборка остаётся **аварийным** путём: индекс пуст, битый или число записей
      уменьшилось (удаление измерения дельтой не ловится — это честная граница приёма).
- [ ] Слияние — **на уровне ключей записи**, а не подстановкой новой строки целиком: поля, которых
      обновление не знает, обязаны выжить (требование `ideas/28`, иначе первая же пересборка сотрёт
      5111 счётчиков популярности).
- [ ] ⚠️ Проверить, что запрос по вложенному полю **не требует составного индекса**
      (`firestore.indexes.json` сегодня пуст осознанно); понадобился — добавить туда со строкой
      комментария, как принято в этом файле.

### Шаг 5 — Фикс `bugs/106`: число измерений рождается в одном месте

> ⚓ Якорь метаплана: «`bugs/106` … фикс живёт в той же функции — чинить отдельно значит платить
> за выкат образа дважды».

- [ ] Взять кандидата №2 из документа бага: **`dims` для статистики считать по индексу**, а не по
      числу документов коллекции. Тогда «сколько измерений» и «что показано на экране „Измерения“»
      — одно число по построению, и дрейфу пары неоткуда взяться.
- [ ] ⚠️ Сторожу свежести (шаг 3) по-прежнему нужны ОБА числа — их нельзя схлопывать в одно.
- [ ] Отметить в `bugs/106` шаги 1 и 2 как исполненные; шаг 3 (переписать снимки дней с отметкой
      правки — решение владельца, интервью №014 В2=В) — **отдельный разовый инструмент**, он
      пишет в бой и запускается только с явного слова владельца ПОСЛЕ выката этой фазы.

### Шаг 6 — Реестр пар «истина ↔ зеркало»

> ⚓ Якорь метаплана: «пара … вписана в реестр `AGENT_GUIDE` с однострочной командой проверки».

- [ ] Вписать в `AGENT_GUIDE` → «Реестр пар»: `dims/{id}` → `dims/dims_list` → `space/stats.dims`,
      с однострочной командой проверки. Пара рождается в этой фазе — значит и строка в реестре
      обязана появиться сегодня, а не после первой потери.

### Шаг 7 — Доказательство и сдача

- [ ] Страж шага 2 — **зелёный**, доказан ≥2 мутациями (например: вернуть вычитание единицы →
      покраснеет пункт 2; заменить слияние на подстановку строки → покраснеет пункт 3).
- [ ] `npm test` · `npm run test:calc` · `npm run test:rules` — зелёные. ⚠️ `test:calc` не гонять

- [ ] Прибор шага 0 прогнан **после** фикса: числа «до/после» стоят рядом в этом документе.
- [ ] `/fable-judge` по фазе — прежде чем объявить её закрытой.
- [ ] 🔧 **За владельцем:** пересборка образа `npm run calc:image` и выкат. Агент не выкатывает.

## Проверка наблюдением — чем именно судим

| Что | Чем меряем | Что считается успехом |
|---|---|---|
| цена добавления измерения | `tools/measure-dims-index.mjs` | «до» — полный проход каталога; «после» — единицы операций |
| мина `title` | два цикла на стенде с документом без `title` | «до» — две пересборки; «после» — ни одной |
| сохранность чужих полей | страж, пункт 3 | постороннее поле записи живо после аварийной пересборки |
| `bugs/106` | страж, пункт 4 | `dims` = записей индекса; диаметр 714,9 |
| честность стенда | форма `created` в сиде | обе формы присутствуют |

## Риски этой фазы

| Риск | Симптом, по которому узнаем | Что делаем |
|---|---|---|
| Мина не воспроизведётся | два цикла, одна пересборка | остановиться, переписать гипотезу (§2.3 честно помечен `[NOT-TESTED]`) |
| Запрос по вложенному полю потребует составного индекса | отказ Firestore с текстом про индекс | добавить в `firestore.indexes.json` с комментарием |
| Правка сида погасит существующие тесты | красный `test:calc` | разобрать КАЖДЫЙ провал: «тест стерёг правду» или «тест стерёг стендовую выдумку» |
| Дельта пропустит удаление измерения | число записей уменьшилось | аварийная полная пересборка — принятая граница, назвать её вслух |
| Правка не доедет до боя | бой продолжает показывать 5112 | выкат — рука владельца; отметить в `STATUS.md` как ожидающее |
