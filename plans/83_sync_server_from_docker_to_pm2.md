## Три дефекта, найденные по дороге

1. 🔴 **Образ боя был собран из НЕСОХРАНЁННОГО дерева.** `builtAt` 2026-08-15T20:08:49Z — на семь
   минут раньше коммита `f6a0c14`, поэтому номер сборки 31 принадлежал предыдущему коммиту, а код
   внутри был уже новее. **Номер сборки врал три недели.** Теперь номер и дата берутся из git
   замороженной копии и сойтись обязаны всегда.
2. 🔴 **Боевая команда в шапке `Dockerfile` сегодня НЕ РАБОТАЕТ.** Она не подаёт
   `FIRESTORE_DATABASE_ID`, а базы `(default)` в боевом проекте нет вовсе (замер: `5 NOT_FOUND`).
   Кто пошёл бы «по документации» — получил бы отказ и не понял почему.
3. 🔴 **PM2 запускал бы службу Node 22.6** (он стоит под nvm), а сервер синхронизации импортирует
   ядро похожести исходником `.ts` и требует ≥ 23.6. Молчаливое падение на первом импорте.
   Лечится дважды: `interpreter` в конфиге и сверка версии в самом приборе.

## Откат

Владелец возвращает гипервизор (`bcdedit /set hypervisorlaunchtype auto` + перезагрузка), поднимает
Docker Desktop — и старый путь цел: образ собирается `npm run sync:image`, запускается командой из
шапки `Dockerfile` **плюс** `-e FIRESTORE_DATABASE_ID=ndim-db-prod`. Перед этим погасить службу:
`pm2 delete ndim-server-prod && pm2 save`, иначе два сервера будут считать одно и то же.

## Решения, принятые без владельца

1. **Бой запущен кодом `f6a0c14`, а не текущим деревом.** Довод: переезд и выкат трёх недель
   бэкенда — два разных изменения, и смешать их значит остаться без ответа на вопрос «что
   сломалось». Отменяется его словом в любую минуту.
2. **Номер сборки и дата теперь берутся из коммита** (31 → 32, дата сдвинулась на 7 минут).
   Довод: у родного запуска сборки нет, и коммит — единственный честный источник.
3. **Проект и имя базы берутся из `lib/contours.mjs`, а не из `.env`.** Владелец предложил `.env`;
   довод против назван ему в чате и ждёт его слова: `.env` вне git, поэтому расхождение с
   `contours.mjs` случилось бы молча, а цена — боевой ключ в чужой базе.
