## Вектор цели (Achieve)

Боль: каждая сессия перечитывает девять документов ядра целиком, и четыре из них перегружены — руководство
агента втрое длиннее бюджета; сессия тратит контекст на историю вместо правил. KAIF 2.7 сделал бюджет дверью
в закрытии чата; владелец велел делать, как регламентирует KAIF. Цель: `node .kaif/kaif-core.mjs check
--gate-budgets` выходит кодом 0, и НИ ОДНА строка не потеряна — всё вынесенное лежит дословно по адресу,
который называет сама дверь, а в ядре на его месте стоит указатель.

## Критерии приёмки

1. Проверка: `node .kaif/kaif-core.mjs check --gate-budgets` → код 0 (замер до: код 1, четыре строки —
   `AGENT_GUIDE` 2706 / 1200 · `STATUS` 415 / 200 · `MASTER_PLAN` 704 / 300 · `TESTING_FRAMEWORK` 555 / 300).
2. Ничего не потеряно: перепись кириллицы по четырём документам + адресам выноса до и после — сумма не
   убывает; каждый вынесенный блок находится дословно по адресу (`git diff --word-diff` показывает перенос, а
   не переписывание).
3. Ни один бюджет не поднят (`DOC_BUDGETS` в `.kaif/kaif-core.mjs` не тронут).
4. Правила, которые агент обязан держать при входе, остались в ядре: в каждом вынесенном блоке ядра стоит
   строка-указатель «полностью — <адрес>», и `/resume` открывает ядро целиком (`node tools/verify-resume-covers-core.mjs`).
5. Ворота проекта зелёные: `npm run guards`, `npm run questions`, `npm run kaif:check`.

## Адреса выноса (их называет сама дверь)

- `STATUS.md` → летопись `PROJECT_HISTORY.md` (закрытые эстафеты — дословно, стрижка бонсая).
- `MASTER_PLAN.md` · `TESTING_FRAMEWORK.md` · `AGENT_GUIDE.md` → летопись `PROJECT_HISTORY.md` ·
  `researches/` · файл домашних правил (ярус 4 таксономии, `AGENT_GUIDE.md` → «Таксономия документов»).

## Шаги

- [ ] **Ш0. Опись.** По каждому документу — таблица разделов с числом строк и классом: *правило* (остаётся
      в ядре, сжимается только повтором) · *история повода* (разбор инцидента, «оплачено…», цитаты поля →
      летопись) · *справочник* (реестр приборов стенда, словарь, реестр пар → файл домашних правил или
      `researches/`). Опись — файл в `researches/`, до первого переноса.
- [ ] **Ш1. `STATUS.md`** — стрижка бонсая по канону `/end-chat-soft` (самое дешёвое, ~215 строк).
- [ ] **Ш2. `TESTING_FRAMEWORK.md`** — истории правил 8–10 и полевые разборы → летопись/`researches/`, правила
      остаются.
- [ ] **Ш3. `MASTER_PLAN.md`** — блоки ревизий 2026-08-01…09-12 и детальные замеры фаз → летопись; журнал
      решений остаётся (он и есть «почему»).
- [ ] **Ш4. `AGENT_GUIDE.md`** — самое крупное (≈1 500 строк сверх бюджета): реестр приборов стенда,
      досье окружения, словарь продукта и правила текста → файл домашних правил; истории поводов → летопись.
      `FORK:` имя и место файла домашних правил — сверить с поставкой KAIF (ярус 4) до переноса.
- [ ] **Ш5.** Критерии 1–5, отчёт о прогоне дверей и переписи.

## Риски

- **Высокий:** правило уезжает вместе с историей, и следующая сессия его не видит — критерий 4 (указатель в
  ядре на каждом выносе) и опись Ш0 до переноса.
- **Средний:** ссылки `AGENT_GUIDE.md` → «<раздел>» в навыках и документах указывают на вынесенный раздел —
  грепом по названиям разделов перед каждым выносом, указатель на новом месте.
