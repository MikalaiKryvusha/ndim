# План 66 — ЭПИК: команда разработки NDim Space из ИИ-агентов на git worktree

> **Исходящее:** локальные канон-документы `NDIM_WORKTREE_DEV_TEAM_MANIFEST.md` и
> `NDIM_WORKTREE_DEV_TEAM_STATUS.md` · врезка в `AGENT_GUIDE.md` (командный git-режим) ·
> домашка владельцу на первый запуск

**Вектор цели** (из `ideas/40`, словами владельца): организовать работу над NDim Space в
параллель — командой ИИ-агентов по ролям (Менеджер · Дизайнер · QA · Разработчики 1–3), каждая
роль в своей ветке worktree и своём окне VS Code, связь через сообщения, синхронизация через два
новых локальных канон-документа. Подготовить команду к первому запуску: Николай открывает окна и
пишет Менеджеру — Менеджер запускает команду рассылкой задач.

**Критерии приёмки эпика** (все проверяются наблюдением на первом запуске):

1. Владелец открывает окна ролей ПО ДОМАШКЕ (готовые команды копипастой), ни одного шага «разберись сам».
2. Каждая роль стартует со своим именем-адресом, читает манифест и объявляет себя строкой в
   статус-таблице.
3. Сообщение Менеджера доходит каждой роли; ответ роли доходит Менеджеру (замер живьём).
4. Тестовая задача проходит ПОЛНЫЙ конвейер: постановка → работа в ветке роли → вердикт QA →
   мерж Менеджером в `main` (EXP-0176: конвейер до продукта, не «сдал — покатим потом»).
5. Ни один синглтон машины (стенд/порты/докер/бой) не тронут двумя ролями одновременно — замок
   тяжёлых прогонов работает.
6. Канон цел: `npm run kaif:check` зелёный, вера-строка стоит в обоих новых документах,
   `verify-sync-server-name` зелёный.

## Чего эпик НЕ делает (названо, чтобы не расползтись)

- Не трогает продукт NDim Space — ни одной строки кода приложения; команда строится, чтобы
  дальше СТРОИТЬ продукт.
- Не выбирает модели/тарифы окон — это рука владельца при открытии окон.
- Не автоматизирует найм/увольнение ролей (расширение парка разработчиков — следующая идея).
- Не заменяет STATUS.md проекта: эстафета сессий во времени остаётся как была; статус-таблица —
  синхронизация ролей в моменте.
- Не строит демон-оркестратор поверх сессий: оркестратор — Менеджер-сессия, живой агент по
  манифесту (Оккам; `researches/44` §2).
