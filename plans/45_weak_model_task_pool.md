## Формат «план для строгого исполнителя» — чем он отличается от обычного

Слабая модель хороша ровно в том, в чём слаба сильная дисциплина: она НЕ импровизирует. План
для неё пишется так, чтобы импровизация не понадобилась ни в одном шаге:

1. **Шаги мелкие, каждый с командой проверки и признаком «готово».** Не «сделай форму», а
   «создай файл X с полями списка Y; готово = команда Z печатает …».
2. **Всё решённое названо в плане** (файлы, имена, границы значений) — исполнитель не выбирает.
3. **Всё нерешённое помечено `STOP-ASK`** — исполнитель останавливается и спрашивает, а не
   догадывается. Провал слабой модели — сигнал о недостающем ограждении в плане, не «модель
   тупая» (рамка безвинна, канон KAIF).
4. **Проверка встроена в шаг, а не в конец:** страж/тест называется в том же шаге, что и код;
   мутация — с ожидаемым числом падений.
5. **Капканы проекта процитированы прямо в шаге**, где они стреляют (не ссылкой «см. опыт»):
   слабая сессия исполняет вставленную команду и игнорирует эссе (правило Repro из
   `EXPERIENCE.md`).
6. **Канон-минимум сессии исполнителя:** `STATUS.md` → свой план → цитируемые в плане срезы.
   Полный `/resume`-проход обязателен и для неё.

Образец формата — **`plans/44`** (фаза 4 админ-эпика, написан в этой форме).

## Что слабой модели НЕ дают (граница пула — жёсткая)

- **Решения вкуса и видения:** макеты, тексты лица продукта, состав страниц, приоритеты —
  только сильная модель + владелец (правило четырёх макетов, `AUTHOR_STYLOMETRY`).
- **Выкаты в бой и необратимые правки данных** — AUTH владельца, и исполняет их сессия,
  способная оценить нештатное (деплой, прополки, миграции).
- **Диагностику неворспроизведённых багов** — «три попытки → /bug-research» слабой модели
  недоступен по построению; ей дают баги только с готовой процедурой замера.
- **Написание планов для самой себя** — план без разведки был бы фикцией; планы пишет
  сильная модель по свежему чтению кода.

## Как пополнять пул (регламент для сильной модели)

Закрывая заход, спроси: «какой следующий кусок ИСПОЛНИМ строго по бумаге?» Если есть — напиши
план в формате выше и добавь строку в реестр. Если для куска нужна разведка — сделай разведку
сейчас (пока контекст горячий), а план оставь готовым. Задание без готового плана в пул не
кладётся — «понятно описаны и легки в исполнении» и есть определение пула (слово владельца).
