## Шаг 0 — перечень снят с ПРАВИЛ, а не с памяти (2026-08-01)

Это и есть тот самый «явный перечень до кода». Источник — `firestore.rules` и `storage.rules`,
прочитанные построчно.

### Что человек удаляет САМ, мгновенно

| Что | Где | Правило разрешает |
|---|---|---|
| Корневой документ | `users/{uid}` | `allow read, write: if isSelf` ✓ |
| Бакеты профиля | `users/{uid}/profile/{bucketId}` | ✓ (подколлекция — поштучно) |
| Свои группы и их состав | `users/{uid}/groups/{g}` + `/members/{m}` | ✓ (две вложенности — поштучно) |
| Подсказки аудитории | `users/{uid}/audience/{viewerUid}` | ✓ поштучно |
| Дружбы | `friendships/{pairId}`, где он `a` или `b` | `allow delete: if participant()` ✓ |
| Точка | `points/{uid}` | `allow delete: if isSelf` ✓ |
| Оценки по Измерениям | `points/{uid}/dims/{dimId}` | ✓ поштучно |
| Фотография | Storage `users/{uid}/avatar/avatar.webp` | ✓ владелец пути |
| Учётная запись | Firebase Auth | `deleteUser` ✓ |

⚠️ **Firestore не удаляет подколлекции вместе с документом.** Четыре подколлекции выше
вычищаются поштучно, батчами, с честной обработкой обрыва посередине.

### 🔴 Что человек удалить НЕ МОЖЕТ — и это шире, чем предполагал ответ В3

| Что | Почему нельзя | Кто вычистит |
|---|---|---|
| **Свой** `relations/{uid}` | `allow write: if false` — клиенту запись запрещена ПОЛНОСТЬЮ | сервер синхронизации |
| Он в **чужих** топах `relations/{другой}` | чужой документ | сервер синхронизации |
| Его членство в **чужих** группах `users/{другой}/groups/*/members/{uid}` | чужой документ | ⚠️ **никто** — вопрос ниже |
| Подсказка аудитории у **другого** `users/{другой}/audience/{uid}` | чужой документ | ⚠️ **никто** — вопрос ниже |
| Его **предложения измерений** `suggestions/{id}` с полем `authorUid` | `allow update, delete: if isAdmin()` | ⚠️ **никто** — вопрос ниже |

🔴 **Ответ В3 покрывал только чужие топы.** Три строки со знаком ⚠️ в нём не рассматривались —
их нашла эта разведка. Обещание «все её данные будут безвозвратно удалены» их пока НЕ покрывает.

## ✅ Вопрос В11 — ОТВЕТ ПОЛУЧЕН 2026-08-01: **А**

ухода автора. ✅ Сделано — `cleanupDeletedPeople()` в вычислителе, 9 тестов, доказан мутацией.

## Критерии «готово»

1. Виджет **«Удаление аккаунта»** — во всю панель (4 шага), последним; **содержимое ≤620px**
   (`EXP-0110`: виджет тянем, содержимое ограничиваем).
2. Подтверждение — **ввод своей почты в поле + повторный вход** (В2 = А).
3. Порядок необратим и правилен: **Storage → Firestore → `deleteUser`**. Не удалилось —
   **учётную запись не трогаем** и честно говорим (обратно дефекту 1.x).
4. Текст предупреждения — **дословно 1.x**, со словом «безвозвратно» (В4 = А).
5. Публичная страница «Удалить аккаунт», доступная **без входа** (В6 = А).
6. Страж, доказанный мутацией с **названными адресатами**.
7. `/fable-judge`.

## Шаги

- [x] **А1. Модуль удаления** `deleteAccount()`: перечень выше, батчами, с остановкой на первой
      неудаче и внятным отчётом, что осталось.
- [x] **А2. 🔴 `deleteUser` — ТОЛЬКО последним.** «Deletes and signs out the user»: после него
      правила человека не пустят, и остатки станут неудаляемыми навсегда.
- [x] **Б1. Виджет** по утверждённому макету: свёрнутый вид (одна строка + обычная кнопка),
      развёрнутый (перечень потерь КОНКРЕТИКОЙ — «Ваш NDim ID и N оценок», «фотографию»,
      «связи с N людьми»), поле почты, красная кнопка **только на финальном шаге** (GOV.UK).
- [x] **Б2. Кнопки-глаголы, без умолчания в фокусе** (NN/g): Enter не должен удалять аккаунт.
- [x] **Б3. Честно сказать про сутки** (В3): «Из чужих списков связей Вы исчезнете в течение суток».
- [x] **В1. Сервер синхронизации** — `cleanupDeletedPeople()` в ночном проходе: свой топ, остатки дерева, членства и подсказки в ЧУЖИХ деревьях, обезличивание предложений. **9 тестов**, доказан мутацией (убираем за всеми → краснеет ровно асимметрия «за живым не убирают»).
- [x] **Г1. Публичная страница «Удалить аккаунт»** — маршрут, доступный без входа; `noindex`
      НЕ ставить (Google Play требует, чтобы её можно было найти).

      🔴 **Это ДВЕРЬ, а не инструкция** (поправка владельца 2026-08-01: «Почему "Как" удалить
      аккаунт? Зачем КАК?»). Требование звучит как *«a way to **request** that their data be
      deleted»* — то есть место, где удаляют, а не текст о том, как найти кнопку. Инструкцию
      ищет тот, кому не дали кнопку; правильный ответ — дать кнопку.

      Устройство: одна строка о том, что произойдёт → вошедшему **сразу шаг подтверждения**
      (то же поле почты, что в виджете) → не вошедшему сначала вход (ссылка или Google), и
      тем же движением дальше. Никаких «перейдите в Профиль → Управление аккаунтом»: человек
      пришёл сюда именно потому, что приложения у него может уже не быть.
- [x] **Д1. Страж** `tools/verify-account-delete.mjs` — **22 проверки**: было-что-удалять ·
      удаление проходит · оценок, бакетов, фотографии нет · неверная почта не удаляет ·
      до подтверждения не удалено.
  - [ ] ↳ **не проверено:** вход той же почтой создаёт ПУСТОЙ новый аккаунт · «никто не может
        удалить чужое» (это тест ПРАВИЛ, его дом — `npm run test:rules`) · сбой посреди каскада
        не оставляет человека без входа.
- [x] **Д2. Мутация (а)** — `deleteUser` в начало → покраснели ровно «каскад дошёл до конца» и
      все пять проверок «ПОСЛЕ». Прогнана, адресаты названы.
  - [ ] ↳ **не прогнаны:** (б) снять требование ввода почты; (в) оборвать каскад на середине —
        для (в) нужен способ заставить удаление данных упасть, и его ещё надо придумать.
