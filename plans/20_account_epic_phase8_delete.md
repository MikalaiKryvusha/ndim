> **Якорь метаплана** (цитата): «**Фаза 8 — Удаление аккаунта.** Самая дорогая при ошибке и потому

## Шаг 0 — перечень снят с ПРАВИЛ, а не с памяти (2026-08-01)

Это и есть тот самый «явный перечень до кода». Источник — `firestore.rules` и `storage.rules`,
прочитанные построчно.

### Что человек удаляет САМ, мгновенно

| Что | Где | Правило разрешает |
|---|---|---|
| Корневой документ | `users/{uid}` | `allow read, write: if isSelf` ✓ |
| Бакеты профиля | `users/{uid}/profile/{bucketId}` | ✓ (подколлекция — поштучно) |
| Свои группы и их состав | `users/{uid}/groups/{g}` + `/members/{m}` | ✓ (две вложенности — поштучно) |
| Подсказки аудитории | `users/{uid}/audience/{viewerUid}` | ✓ поштучно |
| Дружбы | `friendships/{pairId}`, где он `a` или `b` | `allow delete: if participant()` ✓ |
| Точка | `points/{uid}` | `allow delete: if isSelf` ✓ |
| Оценки по Измерениям | `points/{uid}/dims/{dimId}` | ✓ поштучно |
| Фотография | Storage `users/{uid}/avatar/avatar.webp` | ✓ владелец пути |
| Учётная запись | Firebase Auth | `deleteUser` ✓ |

⚠️ **Firestore не удаляет подколлекции вместе с документом.** Четыре подколлекции выше
вычищаются поштучно, батчами, с честной обработкой обрыва посередине.

### 🔴 Что человек удалить НЕ МОЖЕТ — и это шире, чем предполагал ответ В3

| Что | Почему нельзя | Кто вычистит |
|---|---|---|
| **Свой** `relations/{uid}` | `allow write: if false` — клиенту запись запрещена ПОЛНОСТЬЮ | сервер синхронизации |
| Он в **чужих** топах `relations/{другой}` | чужой документ | сервер синхронизации |
| Его членство в **чужих** группах `users/{другой}/groups/*/members/{uid}` | чужой документ | ⚠️ **никто** — вопрос ниже |
| Подсказка аудитории у **другого** `users/{другой}/audience/{uid}` | чужой документ | ⚠️ **никто** — вопрос ниже |
| Его **предложения измерений** `suggestions/{id}` с полем `authorUid` | `allow update, delete: if isAdmin()` | ⚠️ **никто** — вопрос ниже |

🔴 **Ответ В3 покрывал только чужие топы.** Три строки со знаком ⚠️ в нём не рассматривались —
их нашла эта разведка. Обещание «все её данные будут безвозвратно удалены» их пока НЕ покрывает.

## ❓ Вопрос владельцу (В11) — до реализации

**Что делать со следами, которые не удаляет ни человек, ни сервер связей?**

- **А) (рекомендуется) Научить суточный проход сервера синхронизации** вычищать за удалённым всё:
  свой и чужие `relations`, членство в чужих группах, подсказки аудитории, а `suggestions`
  **обезличивать** (стереть `authorUid`, оставить текст: предложение измерения полезно
  Пространству и после ухода автора).
  *Цена:* работа в сервере синхронизации; следы живут до суток.
- **Б) Обезличивать всё, включая предложения — то есть удалять и их.**
  *Цена:* Пространство теряет предложенные измерения, а их писали люди.
- **В) Оставить как есть** и честно назвать это в политике (Google Play прямо допускает: данные,
  удерживаемые по легитимным причинам, надо раскрыть человеку).
  *Цена:* обещание «все данные» становится неполным, а это ровно то, за что взялись.

## Критерии «готово»

1. Виджет **«Удаление аккаунта»** — во всю панель (4 шага), последним; **содержимое ≤620px**
   (`EXP-0110`: виджет тянем, содержимое ограничиваем).
2. Подтверждение — **ввод своей почты в поле + повторный вход** (В2 = А).
3. Порядок необратим и правилен: **Storage → Firestore → `deleteUser`**. Не удалилось —
   **учётную запись не трогаем** и честно говорим (обратно дефекту 1.x).
4. Текст предупреждения — **дословно 1.x**, со словом «безвозвратно» (В4 = А).
5. Публичная страница «Как удалить аккаунт», доступная **без входа** (В6 = А).
6. Страж, доказанный мутацией с **названными адресатами**.
7. `/fable-judge`.

## Шаги

- [ ] **А1. Модуль удаления** `deleteAccount()`: перечень выше, батчами, с остановкой на первой
      неудаче и внятным отчётом, что осталось.
- [ ] **А2. 🔴 `deleteUser` — ТОЛЬКО последним.** «Deletes and signs out the user»: после него
      правила человека не пустят, и остатки станут неудаляемыми навсегда.
- [ ] **Б1. Виджет** по утверждённому макету: свёрнутый вид (одна строка + обычная кнопка),
      развёрнутый (перечень потерь КОНКРЕТИКОЙ — «Ваш NDim ID и N оценок», «фотографию»,
      «связи с N людьми»), поле почты, красная кнопка **только на финальном шаге** (GOV.UK).
- [ ] **Б2. Кнопки-глаголы, без умолчания в фокусе** (NN/g): Enter не должен удалять аккаунт.
- [ ] **Б3. Честно сказать про сутки** (В3): «Из чужих списков связей Вы исчезнете в течение суток».
- [ ] **В1. Сервер синхронизации** — по ответу В11.
- [ ] **Г1. Публичная страница** «Как удалить аккаунт» (маршрут без входа, `noindex` НЕ ставить:
      Google Play требует, чтобы её можно было найти).
- [ ] **Д1. Страж** `tools/verify-account-delete.mjs` на стенде: удаление проходит · вход той же
      почтой создаёт ПУСТОЙ новый аккаунт · оценок, бакетов, фотографии нет · **никто не может
      удалить чужое** (тест правил) · сбой посреди каскада НЕ оставляет человека без входа.
- [ ] **Д2. Мутации с адресатами:** (а) переставить `deleteUser` в начало → краснеет «остатки
      удалены»; (б) снять требование ввода почты → краснеет проверка подтверждения;
      (в) оборвать каскад на середине → краснеет «учётная запись цела».

## Риски

| Риск | Как гасим |
|---|---|
| 🔴 **Человек теряет доступ, а данные остаются** (дефект 1.x: ошибки глушились, `deleteUser` шёл дальше) | А2 + мутация (в): порядок и остановка на первой неудаче стерегутся машиной |
| 🔴 **Обещание «все данные» окажется ложью** | Шаг 0 назвал ВСЁ, включая три строки, которых не было в В3; В11 закрывает их сознательно |
| **Enter удаляет аккаунт** | Б2 |
| **Красная кнопка висит на экране постоянно** и притупляет внимание | Б1: красная только на финальном шаге |
| **Страж «зелёный», потому что удалять было нечего** | Страж обязан СНАЧАЛА создать труд (оценки, фото, дружбу), а потом удалять |
