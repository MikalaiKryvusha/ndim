## Цель (вектор)

Человек из поиска, нажавший на карточке «Оцените, чтобы найти людей, кто думает, как Вы»,
оказывается в продукте гостем — без единой формы по дороге. Та же механика, что у моста
лендинга (`/profile?guest=1`), на настоящей поверхности притока — 10 222 карточках.

## ⛔ Инвариант владельца — КАРТОЧКУ НЕ ОБЕДНЯТЬ

Его слово (№050, чат): «*чтобы не получилось, что этим макетом обедним наши уже сделанные
двери*». Макет — эскиз ОДНОГО блока, а не всей страницы: «〈сокращено〉» в нём — приём рисунка, не
замысел продукта. В бою карточка остаётся ПОЛНОЙ, меняется только низ блока двери
(кнопка → звёзды + панель). Что обязано остаться нетронутым, по живой структуре страницы:
шапка с языками и «Войти» · ссылка в хаб вида · заголовок + оригинальное название · досье
целиком (оценка/«Ещё без голосов», Вид, Год, Автор, Место в своём виде, Теги) · **полное
описание объекта** (канон мастерской 900–1400 знаков) · тексты двери (doorTitle +
doorVoted/doorNoVotes — слова владельца) · «Похожие по каталогу» · подвал. Приёмка Ш4
включает diff секций «до/после»: исчезнувшая секция = красный.

## Критерии приёмки

1. Клик по двери карточки в БОЮ → человек внутри гостем; форм — ноль (живой прогон + кадры).
2. Живая сессия уважается: вошедший человек по той же двери попадает в свой профиль, гостя
   ему не заводят (канон `bugs/95` — дверь `?guest=1` это уже умеет).
3. Счётчик `door_click` (фаза 1 `plans/74`) в бою ненулевой в первую же неделю.
4. Вес карточки не вырос сверх допуска стража `verify-catalog-hubs`; пререндер целостен.
5. `bugs/201` уезжает тем же выкатом (правка «30 дней» → срок из `GUEST_TTL_DAYS`).

## 🔬 Разведка исполнения (сессия 40, 2026-08-28) — читать ДО первой строки кода

1. 🔴🔴 **Карточки собраны с `csr = false`** (`dimension/[slug]/+page.server.ts:71`) —
   клиентского JS у них НЕТ ВООБЩЕ, и это решение куплено замером (там же, строки 55–70:
   минус 10 222 файла `__data.json` ≈ 41 МБ на релиз; страница без бандла фреймворка).
   ⛔ **НЕ включать `csr = true` «чтобы заработали звёзды»** — это откат оплаченной
   оптимизации на всей SEO-поверхности (замер по build/: страница Теста с гидрацией несёт
   25 модульных ссылок, карточка — 4).
2. ✅ **Выбранная архитектура — «ванильный остров»:** звёзды и панель уже в пререндеренном
   HTML (панель скрыта классом); маленький инлайн-скрипт (ванильный, ~1–2 КБ) вешает
   обработчики; при ПЕРВОМ касании динамически грузится «движок двери» — отдельный чанк,
   собираемый вторым входом Vite из тех же исходников (`test-engine.ts` →
   `saveTestRating`: слой данных чист от `$app/*` и Svelte — проверено грепом импортов).
   Так карточка остаётся без фреймворка, а Firebase грузится только тому, кто тронул звёзды.
3. **Движок уже существует и доказан боем:** `src/lib/data/test-engine.ts` →
   `saveTestRating(lang, dimId, value)` — «первая оценка = вход»: рождает гостя, заводит
   пространство, пишет НАСТОЯЩУЮ оценку тем же `saveRating`, шаг воронки. В бою на страницах
   Теста с 2026-08-14. Не переизобретать.
4. **Звёздный ряд — канон продукта:** 11 позиций 0…10 С ЦИФРАМИ (память владельца: звёзды

   цифр) — исполнение следует канону жеста, композиция Д3 не меняется.
5. **Гонка «коснулся → сразу нажал кнопку»:** сохранение асинхронно (рождение гостя +
   Firebase-чанк — секунды). Кнопка «Войти в Пространство» обязана ДОЖДАТЬСЯ обещания записи

## Риски

- **Наплыв гостей = наплыв точек:** каждый гость — полноправная точка на 7 дней; успех двери
  приближает потолок сервера синхронизации (`MASTER_PLAN` фаза 4, риск роста). Лечение по
  канону: замер до оптимизации — счётчики фазы 1 `plans/74` и есть замер.
- **Информационный интент:** часть пришедших хочет «plot summary», а не знакомств; дверь
  обязана звать, но не обманывать — тексты не трогаем, обещание («найти людей») уже честное.
- **Кэш карточек:** страницы пререндерены и кешируются; после выката проверить свежесть
  отдаваемого HTML (`verify-prod-cache`, `bugs/124`).
