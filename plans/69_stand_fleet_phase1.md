### Шаг 3 — конфиг эмуляторов слота: `firebase.<слот>.json`

- [ ] Генератор: читает `firebase.json`, подменяет ТОЛЬКО секцию `emulators`, пишет

- [ ] Файлы слотов — в `.gitignore` (машинерия рабочего места, как `dims-build.json`).
- [ ] Детерминизм: повторный прогон на неизменённом `firebase.json` даёт побайтово тот же файл

- **Проверка:** сгенерировать дважды, `fc` без различий · `firebase emulators:exec -c` встаёт.
- **Признак «готово»:** слот 1 поднимается своим конфигом, слот 0 — штатным, одновременно.

### Шаг 4 — `npm run stand` на портах слота + лимит «≤ 3»

- [ ] Обёртка запуска (`tools/stand-launch.mjs`): слот → конфиг → `emulators:exec -c` → внутри

      🔴 `--strictPort` обязателен: без него vite тихо переезжает на соседний порт, и роль
      начинает смотреть чужой сайт.
- [ ] **Проверка лимита при старте** — решение владельца «3 стенда»: посчитать занятые

      Дёшево и механически, а не правилом в документе.
- [ ] `package.json`: `stand` зовёт обёртку. Прежнее поведение в главной копии (слот 0) обязано
      остаться байт-в-байт тем же.
- **Проверка:** `npm run stand` в двух worktree разом; оба отвечают; третий — встаёт; четвёртый —
      отказ с текстом.
- **Признак «готово»:** роль поднимает стенд БЕЗ правки конфигов руками (критерий 2 эпика).

## Ворота фазы

1. Замер шага 1 заполнен числами ОБОИХ прогонов (с игрой и без), вердикт назван.
2. Три стенда живут одновременно; все три отвечают; данные независимы — доказано чтением.
3. Роль поднимает стенд без правки конфигов руками.
4. Четвёртый стенд получает отказ (лимит владельца исполнен механикой).
5. `npm test` · `npm run check` · `typecheck` · `verify-dimension-pages` · `verify-catalog-hubs` —
   зелёные; вес бандла в норме.
6. Пять мутаций прогнаны, адресаты названы заранее, после отката — ноль.

## Риски

| Риск | Уровень | План |
|---|---|---|
| Замер упрётся в потолок фиксации | **высокий** | это НЕ провал фазы, а её результат: числа → Менеджер → владелец (его «если что»). Работа по слотам продолжается, лимит просто окажется ниже трёх |
| Правка `src/lib/firebase.ts` заденет боевой контур | средний | вход в эмуляторы только через `isStand()`; умолчания равны нынешним литералам; проверка весом бандла до/после |
| Гашение стенда на Windows не убивает дерево | средний | капкан от `dev-1`, подтверждён QA дважды: гасить `taskkill /PID <корень> /T /F` и ПРОВЕРЯТЬ порты; держателя искать по `OwningProcess` порта, не маской (`EXP-0181`) |
| Приборы фазы 3 покраснеют на слоте ≠ 0 | средний | ожидаемо и названо: они ещё на литералах. Фаза 1 сдаётся на слоте 0 и на слоте 1; красное на слоте 1 у приборов хвоста — не дефект фазы |
| Долгий замок стенда мешает команде | средний | один заход вместо трёх, предупреждение на доске и сообщением; отдать по первому слову между поднятиями |
| Смешение предметов суда в одной ветке | низкий | план — документ, код фазы начинается ПОСЛЕ мержа правки звёзд (граница поставлена Менеджером) |
