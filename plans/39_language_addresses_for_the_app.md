## 🔴 Главный риск фазы, и он не технический

**11 публичных адресов УЖЕ проиндексированы** — документы открыты поиску с 2026-08-01, корень и
раньше. Переезд без переадресации выбрасывает всё, что они заработали, и отдаёт роботу 404.

**Значит 301-переадресация со старых адресов на `/ru/…` — не улучшение, а обязательная часть
работы.** Она делается в `firebase.json` и кода не требует.

⚠️ **И ловушка внутри ловушки:** правило `/menu/:rest*` заденет и `/menu` — а это ЛИЧНЫЙ экран
приложения под `noindex`, и уводить его на `/ru/menu` нельзя, там сломается навигация. Правила
обязаны быть поимённые, а не по маске.

**Одиннадцать адресов, которые предстоит развести — поимённо, чтобы ни один не потерялся:**

```
/                    /menu/terms       /menu/about     /menu/support
/delete-account      /menu/privacy     /menu/author    /menu/donate
                     /menu/disclaimer                  /menu/share
                     /menu/manual
```

⚠️ **Чего в этом списке НЕТ и что трогать нельзя:** `/menu` (личный экран, `noindex`), `/profile`,
`/relations`, `/dims`, `/space`, `/account`, `/auth/action`. Список публичных берётся из карты
сайта, а не пишется по памяти, — иначе личный экран уедет под языковой адрес и откроется поиску.

🔴 **Одного числа снять не могу:** сколько из этих адресов реально в индексе Google. Это видно
только в Search Console под входом владельца. Замер после фазы обязан сравниваться с ним, поэтому
число просится в `homeworks/09` — владелец увидит его сегодня вечером.

### Шаг 1 — Общий модуль языка

Один модуль на весь проект, по образцу того, что уже сделано для темы (`src/lib/ui/theme.svelte.ts`).

- **На публичных адресах источник истины — АДРЕС.** Память браузера правит только там, где адрес
  языка не задаёт (за стеной входа).
- 🔴 **Мост «адрес → память»:** публичный адрес ЗАПИСЫВАЕТ язык в память. Иначе человек, пришедший
  с `/ru/`, проваливается в английское приложение — это ломается не у робота, а у ЧЕЛОВЕКА.
- Инлайн-скрипт `app.html` перестаёт слепо перезаписывать `lang` на языковых адресах.
- Каркас рассчитан на **N языков**, а не на два: «в будущем добавим ещё языков» — слово владельца.

**Ворота:** ни одного прямого `localStorage.getItem('ndim-lang')` вне модуля (страж грепом,
сегодня их 14).

### Шаг 2 — Маршруты: `[lang=lang]` для публичного, корень отдельно

- Публичные страницы переезжают под `src/routes/[lang=lang]/…` — ограничитель параметра уже есть
  (`src/params/lang.ts`), каталог по нему уже живёт.
- **Личные экраны НЕ трогаются вовсе:** `/profile`, `/relations`, `/dims`, `/space`, `/account`,
  `/menu`, `/auth/action` остаются на своих адресах под `noindex`. Языковых адресов за стеной входа
  нет и не будет.
- **Корень `/`** становится крошечной страницей-распознавателем: `noindex`, без содержания,
  инлайн-скрипт читает память и язык браузера и делает `location.replace()` на `/ru/` или `/en/`.
  Это дословно то, что описал владелец в ответе Р5.

⚠️ **Почему `[lang=lang]`, а не `[[lang]]`.** Необязательный параметр оставил бы живым и `/menu/terms`
без языка — то есть третий адрес того же содержания, дубль для поиска. Обязательный параметр плюс
переадресация со старых адресов даёт ровно два адреса на документ.

### Шаг 3 — 🔴 Переадресация со старых адресов (обязательна, делается ДО выката)

В `firebase.json`, цель `landing`, поимённо на каждый из 11 адресов:

```
{ "source": "/menu/terms", "destination": "/ru/menu/terms", "type": 301 }
```

**Куда вести:** на **русскую** версию — это язык, на котором они были проиндексированы. Робот
дальше сам найдёт английскую по `hreflang`.

⛔ **Не писать маску `/menu/:rest*`** — она заденет личный экран `/menu`.

### Шаг 4 — `hreflang`, `canonical`, карта сайта

- Двусторонний `hreflang` с самоссылкой на КАЖДОЙ паре плюс `x-default` на английский.
  Механика уже написана и работает в каталоге — переиспользовать, а не изобретать.
- `canonical` каждой страницы — на свой языковой адрес.
- Карта сайта: 11 × 2 + 10 222 = **10 244** адреса. Генератор уже собирает список из источников.

### Шаг 5 — Стражи

| Страж | Что ловит |
|---|---|
| Грепом | `localStorage.getItem('ndim-lang')` вне модуля языка |

| По `build/` | `hreflang` двусторонний, самоссылка есть, `x-default` объявлен |

### Шаг 6 — Приёмка

🔴 **Главная проверка фазы — не робот, а ЧЕЛОВЕК** (`plans/24` §5.4): человек с `ru` в памяти
браузера открывает английский адрес и **остаётся на английском**; перейдя оттуда внутрь приложения,
видит **тот же** язык. Живой Chrome, обе темы, две ширины, скриншоты.

## Критерии «готово»

1. Каждая публичная страница доступна на двух языках, `hreflang` двусторонний, `x-default` на
   английский.
2. **Ни один старый адрес не отвечает 404** — все одиннадцать дают 301.
3. Корень не участвует в поиске и уводит человека на его язык.
4. Личные экраны не сдвинулись и остались под `noindex`.
5. Ни одного прямого чтения памяти языка вне модуля.
6. Человек с «неправильной» памятью остаётся на языке АДРЕСА — проверено живым Chrome.
7. Карта сайта содержит 10 244 адреса.
8. `npm test` · `npm run check` · `npm run e2e` · стражи каталога — зелёные.
