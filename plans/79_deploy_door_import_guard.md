## Цель одной строкой

Импорт `tools/deploy.mjs` не исполняет НИЧЕГО (ни сети, ни сборки, ни выката) — при этом
поведение двери как CLI не меняется ни на байт наблюдаемого контракта.

## Почему это отдельная порция Менеджера, а не минутная правка

Дверь выката — самая опасная точка проекта (`bugs/124`: смесь сборок роняла бой у всех).
27 операторов верхнего уровня переезжают под `main()` — правка механическая, но цена ошибки
боевая, поэтому: исполняет Менеджер (дверь — его зона по манифесту) · судит QA · выкат после
неё идёт только через полный штатный цикл.

## Шаги

1. **Замер ДО:** список верхнеуровневых операторов поимённо (что именно исполняется при
   импорте сегодня) — фиксируется в этом плане перед правкой.
2. **Правка:** операторы под `main()`, входной предохранитель «запущен или подключён» по
   канону `ideas/43` (образец — team-status.mjs после №16).
3. **Проверки, все обязательны:**
   - `node tools/deploy.mjs --selftest` — 8/8, как до правки;
   - `npm run deploy -- --gate-only` — замок отвечает, ничего не выкатывая;
   - проба импорта: файл с заведомо ложным утверждением, импортирующий дверь, ЧЕСТНО
     красный (класс «фабрика ложнозелёного», №16), и импорт не делает ни одного fetch
     (замер, не заявление);
   - `verify-import-safety`: deploy.mjs уходит из реестра отсрочек — строка отсрочки
     краснеет сама («вылечен — строку снять»), снять её тем же коммитом.
4. **Суд QA** (порция маленькая, но дверь — судится всегда).
5. Ближайший штатный выкат после мержа — обычной дверью, с обычным смоуком; отдельного
   «проверочного» выката НЕ делается (нечего катить — поведение CLI не менялось).

## Наблюдаемый критерий приёмки

Импорт двери из постороннего файла: ноль сетевых обращений, ноль побочных действий, чужой
код возврата цел. CLI-путь: `--selftest` 8/8 и `--gate-only` отвечают как до правки.
Реестр отсрочек verify-import-safety больше не содержит deploy.mjs.
