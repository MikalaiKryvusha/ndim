## Вектор цели

Корень `ndimspace.app/` перестаёт быть распознавателем языка под `noindex` и становится
**главной с содержанием** — макет **V5**, собранный владельцем 2026-09-05 из V4 и V3.

Слово-заказ дословно: «*и принято, берем в работу, делай, кати на стейдж, тестируй*».

**Что считается сделанным:** человек, открывший корень, видит страницу на обоих языках, может
войти гостем одной кнопкой и уйти в каталог по живой ссылке; робот получает индексируемую
главную; вход по ссылке из письма работает как прежде.

## Решения агента (мои, не его) — названы, чтобы он мог отвести

1. **`x-default` остаётся английским.** Довод «корень теперь двуязычен и он лучший x-default»
   существует (`design/root-minilanding-implementation-notes.md` §6.1), но это ЕГО решение
   (№010 Р5), и агент его не отменяет. Вынесено ему вопросом.
2. **`csr = false` остаётся.** На странице только ссылки; тема переключается инлайн-скриптом
   `app.html` без бандла. Корень остаётся мгновенным.
3. **Счётчика `door_click` на корне не будет в этой работе.** С `csr = false` его негде повесить,
   а тянуть бандл ради счётчика — плата, которой заказ не просил. Отдельной задачей.
4. **В полосе 6 объектов, музыка не берётся.** Причина не косметическая и записана раньше
   (макет, 2026-08-29): под музыку у мастерской нет проверенных правил, и ставить на ЛИЦО двери
   вид, за который мы не отвечаем, нельзя. Шесть видов дают ровно ту сетку 3×2, которую он
   утвердил.

## Шаги

- [ ] **Ш1 · Страница.** `src/routes/+page.svelte` переписывается в V5. Из распознавателя
      остаётся ТОЛЬКО ветка письма (`mode=signIn` + `oobCode` → `/profile`), и она остаётся
      первой. Языковой увод, `noindex` и `<noscript>` снимаются.
- [ ] **Ш2 · Данные.** `src/routes/+page.server.ts`: числа из `$lib/data/metrics`, полоса из
      `catalog-source` (правило `EXP-0136`: каталог только на сервере).

      JSON-LD — тем же блоком, что на языковых главных.
- [ ] **Ш4 · Страж языка.** `tools/verify-lang-module.mjs`: у корня остаётся одно плечо ПИСЬМО.
      Правка проверки объясняется в коммите (иначе фрод по канону).
- [ ] **Ш5 · Канон.** `plans/39` шаг 2 приводится в соответствие: языкового увода больше нет.
- [ ] **Ш6 · Sitemap.** Корень попадает в карту сайта.
- [ ] **Ш7 · Свежесть чисел.** `node tools/snapshot-landing-metric.mjs` перед выкатом.
- [ ] **Ш8 · Ворота.** `npm run check` · `npm test` · `npm run test:tools` · `npm run guards`.
- [ ] **Ш9 · Стейдж.** Выкат и смоук: обе темы, три ширины, консоль чиста, ссылки живые.
- [ ] **Ш10 · Доклад владельцу** кадрами со стейджа.

## Проверка наблюдением — чем доказывается каждый шаг

| Что | Чем меряется |
|---|---|
| Корень индексируем | в HTML корня нет `noindex`; `bugs/203` получает строку замера |
| Письмо не сломано | прибор открывает `/?mode=signIn&oobCode=X` и видит `/profile` с целым query |
| Языкового увода нет | прибор открывает `/` с `ndim-lang=ru` в памяти и ОСТАЁТСЯ на корне |
| Числа живые | значения на странице совпадают с `landing-metric.ts`, а не с литералом |
| Полоса живая | шесть ссылок ведут на существующие `/ru/dimension/<slug>` и отдают 200 |
| Кнопка держит две строки | замер `getClientRects()` на 390 · 1024 · 1440 |
| Двуязычные пары разнесены | ни одной строки вида «Русское · English» в разметке корня |
| Консоль чиста | ноль ошибок на стейдже под обеими темами |

## Риски

1. **Ссылка из письма.** Самый дорогой контракт страницы. Ветка `oobCode` остаётся ПЕРВОЙ и
   получает собственный прибор — иначе класс 2026-07-12 повторяется.
2. **Каталог в бандле.** 17,5 МБ уедут в клиент, если тронуть `catalog-source` из
   универсального `load` (`EXP-0136`). Только `+page.server.ts`.
3. **Снимок чисел протухает.** У корня появляется тот же контракт свежести, что у лендинга
   (`bugs/81`): снимок берётся ПЕРЕД выкатом.
4. **Первый объект хаба в бою может оказаться неудачным лицом.** В макете полоса собрана из
   фикстуры. Смотреть живой прогон на стейдже глазами до боя.
