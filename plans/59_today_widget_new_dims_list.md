## Заказ владельца — дословно

> «*вот тут хорошо было бы писать тип, название, год. И каждый добавленный пункт было бы хорошо в

> высоте растягивающимся, но после достижения предела растяжения — внутри него появляется скрол,
> и можно новости скролить прямо внутри виджета.*»

## Как это выглядит сегодня — снято по коду, а не по памяти

Одна сплошная строка: «Появилось **11 новых измерений**: «Одиссея», «Человек-паук: Новый день»,
«Проект «Конец света»», …» — имена через запятую, без вида и года, всё в один абзац.

| Слой | Файл | Что там сейчас |
|---|---|---|
| Payload | `sync-server/index.mjs:595` | `newDims.set(dim.id, { id, title })` — **только имя** |
| Модель | `src/lib/model/stats.ts:37` | `interface NewDim { id, title }` |
| Событие | `stats.ts:396` | `{ kind: 'dims', delta, total, names }` |
| Отрисовка | `src/routes/space/+page.svelte:304` | имена склеиваются запятыми в один поток `Seg[]` |

🔴 **Отсюда главное следствие для порядка работ: вид и год В ПАВЛОАДЕ НЕТ ВООБЩЕ.** Приложение их
не «забыло показать» — оно их не получает. Значит первый шаг лежит на сервере синхронизации, и
пока он не выкачен, любая правка вёрстки покажет пустоту.

⚠️ **И вторая цена, которую надо знать заранее:** событие живёт в `space/stats`, документе, который
читают ВСЕ вошедшие. Добавляя поля, мы утяжеляем его для каждого чтения — поэтому шаг 1 несёт
потолок числа записей, а не «сколько будет».

## Вектор цели

Человек, открывший «Пространство», за один взгляд понимает, ЧТО именно появилось в Пространстве за
сутки: каждый объект отдельной строкой, с видом и годом. Список любой длины помещается в виджет,
не разрывая сетку экрана.

## Критерии «готово»

1. Каждое новое измерение — **отдельный пункт** маркированного списка.
2. В пункте стоят **вид · название · год**; отсутствующий год не оставляет пустых скобок.
3. Виджет растёт по высоте до предела, дальше — **прокрутка внутри него**, а не рост наружу.
4. Сетка виджетов (`ideas/24`) не ломается ни на 390, ни на 1440.
5. Оба языка равнозначны: список читается по-русски и по-английски.
6. Каждый шаг доказан прибором, пишущий — ещё и мутацией.

## Шаг 1 — Павлоад: сервер синхронизации отдаёт вид и год 🔲

**Что делаем.** `sync-server/index.mjs` кладёт в `newDims` ещё два поля:

```js
newDims.set(dim.id, { id: dim.id, title, type: dim.data().type ?? null, year: dim.data().year ?? null });
```

- [ ] `stats.ts` → `interface NewDim` получает `type: Localized | null` и `year: string | null`.
- [ ] 🔴 **Потолок числа записей.** Сегодня в `newDims` уходят ВСЕ измерения суток. Одиннадцать
      записей это ~1 КБ, сто — уже заметно, а документ читает каждый вошедший. Ставим предел
      **20 записей** и отдаём `total` отдельно: виджет честно скажет «и ещё 15».
- [ ] ⚠️ Правило «без названия — не новость» (строка 594) НЕ трогаем: оно оплачено падением всей
      пакетной записи цикла (`bugs/109`). Вид и год такого предохранителя не требуют — их
      отсутствие законно, поэтому `?? null`, а не пропуск записи.

**Моя проверка.** Тест в наборе сервера синхронизации: цикл кладёт вид и год · запись без года
даёт `null` и не роняет батч · при 25 новых измерениях в документе ровно 20 записей и `total: 25`.
**Мутация:** отдать `undefined` вместо `null` → тест обязан покраснеть (Firestore отвергает
`undefined`, и это ровно тот класс, что уронил цикл в `bugs/109`).

## Шаг 2 — Формат пункта: вид · название · год 🔲

**Что делаем.** Чистая функция в `src/lib/model/stats.ts` (или рядом с ней):
`newDimLine(dim, lang) → { kind, name, year }`.

- [ ] Год берётся строкой (у восьми боевых записей это диапазон «1966–1969»).
- [ ] Года нет → пункт без скобок вовсе. Пустые скобки «(—)» — визуальный мусор.
- [ ] Вида нет → пункт без вида, название остаётся первым.
- [ ] Название в кавычках-лапках, как везде в продукте.
- [ ] 🔴 **Название НЕ ОБРЕЗАЕТСЯ** — закон владельца 2026-08-14. Пункт растёт по высоте.

**Моя проверка.** Юнит-тесты на все четыре комбинации (есть/нет вида × есть/нет года) плюс
диапазон лет. Чистая — значит её достаёт `node --test` без браузера.

## Шаг 3 — Маркированный список в виджете 🔲

**Что делаем.** Событие `dims` перестаёт быть одним потоком `Seg[]` и получает СВОЮ разметку:
заголовок «Появилось 11 новых измерений» и под ним `<ul>` с пунктами.

- [ ] Остальные события виджета («Сегодня») формат НЕ меняют: правка адресная.
- [ ] Маркер — точка, отступ по сетке продукта.
- [ ] Пункт не является ссылкой: страницы измерения внутри приложения нет, а вести из личного
      экрана на публичную страницу — отдельное решение владельца, не побочный эффект правки.

**Моя проверка.** Расширить `verify-ideas24` (виджетная сетка): у события `dims` ровно N пунктов
`<li>`, в каждом вид и год, ни одного обрезанного названия. **Мутация:** вернуть склейку запятыми
→ проверка краснеет.

## Шаг 4 — Предел высоты и прокрутка ВНУТРИ виджета 🔲

**Что делаем.** Список получает `max-height` и `overflow-y: auto`.

- [ ] Предел назначается **замером, а не на глаз**: высота виджета не должна ломать колонку сетки
      `ideas/24` на 390 и на 1440. Снять прибором на 5, 11 и 30 пунктах.
- [x] ✅ **РАЗВИЛКА ЗАКРЫТА ВЛАДЕЛЬЦЕМ 2026-08-18 (интервью №039, В3 = A + B): ОБА признака.**
      Затухание у нижней кромки **И** видимая полоса прокрутки внутри виджета.
      🔴 Из этого следует работа, которой в плане не было: полосу придётся рисовать СВОЮ
      (`::-webkit-scrollbar` + `scrollbar-width`/`scrollbar-color`), потому что на телефоне
      система прячет системную полосу до момента прокрутки — а владелец просил видимую. Проверять
      на 390 обязательно: там это не косметика, а собственно исполнение его решения.
      ⚠️ Затухание не должно съедать последнюю строку: градиент кладём поверх, а не в поток.
- [ ] `overscroll-behavior: contain` — прокрутка внутри виджета не должна утаскивать страницу.
      ⚠️ Смежное с `verify-ptr`: жест обновления страницы отбирается своим правилом, и эти два
      механизма обязаны ужиться — проверять вместе.

**Моя проверка.** Прогон живым браузером: при 30 пунктах высота виджета не превышает предела,
внутри есть прокрутка, страница при этом НЕ едет; при 3 пунктах прокрутки нет вовсе (иначе
пустая полоса у короткого списка). Обе темы × 390/1440, кадры.
