## Мины, названные ЗАРАНЕЕ и НЕ подлежащие переоткрытию

Обе названы мной же в `plans/69` и подтверждены Менеджером в постановке. Здесь они не
обсуждаются — здесь они умирают или замеряются.

1. 🔴 **`reuseExistingServer: true`.** `node_modules/playwright/lib/runner/index.js:821–832`:
   `return` при живом сервере стоит ВЫШЕ `launchProcess`, а наш `command` — это
   `npm run build && npm run preview` ОДНОЙ строкой. Значит при чужом живом preview не
   запускается не только сервер — **не запускается СБОРКА**, и прогон судит артефакт, которого
   правка роли не касалась. Лечение — `false`: Playwright тогда бросает громкую ошибку с именем
   порта. ⛔ Это решение фазы, а не развилка.
2. ⛔ **Потолок воркеров СЧИТАТЬ ЗАМЕРОМ, А НЕ НАЗНАЧАТЬ.** `workers` в конфиге не задан,
   умолчание Playwright — `"50%"` (8 воркеров на роль на этой машине). Три роли разом — 24
   контекста Chromium плюс три `vite build`. **Фаза 2 не ставит `workers` в конфиг.** Она снимает
   числа и записывает их; назначение потолка — предмет следующей фазы или отдельного решения,
   опертого на эти числа.

## Шаги

### Шаг 1 — ОДИН источник портов vite: конфиг выводит слот сам

**Якорь:** «*`vite preview`/`dev` на портах слота*».

- [ ] `vite.config.ts` импортирует `slotOf`/`portsFor` из `tools/lib/stand-slot.mjs` и выводит слот
      **из имени своего каталога** (`import.meta.url`, а не `process.cwd()`: конфиг обязан знать
      своё рабочее место независимо от того, откуда его позвали).
- [ ] Явный слот парка — переменной `STAND_SLOT` (её уже ставит `tools/stand-launch.mjs --slot`).
      Это ЕДИНСТВЕННОЕ исключение и оно названо: флаг существует ради проверяемости парка из
      одного рабочего места.
- [ ] `server: { port, strictPort: true }` и `preview: { port, strictPort: true }` — порты слота.
- [ ] Порты эмуляторов слота уезжают в артефакт из ЭТОГО ЖЕ места (`VITE_STAND_*` до загрузки
      окружения Vite), а не из обёртки запуска.

🔑 **Почему одно место, а не два.** Разведка требовала, чтобы `webServer.command` нёс окружение
слота в ОБЕ половины — и в `build`, и в `preview`. Требование верное, но оно ДИСЦИПЛИНАРНОЕ: его
исполняет тот, кто помнит. Если слот выводит сам конфиг, нести нечего: **любая** сборка из этого
рабочего места запекает свой слот, включая ту, которую поднимает Playwright, и включая ту, которую
кто-то запустит руками. Мина умирает по построению — ровно то, чего требует якорь.

⚠️ **Слот 0 обязан остаться байт-в-байт прежним:** порты слота 0 равны сегодняшним литералам
(4173 · 5173), а дверь выката (`tools/deploy.mjs`) передаёт `--port 4173` явным флагом — флаг
сильнее конфига. Главная копия не замечает фазы вовсе.

- **Признак «готово»:** `npm run preview` в моём каталоге слушает **4213**, а не 4173 · сборка БЕЗ
  всякого окружения несёт в чанке `q('8221', 8181)` (греп артефакта) · слот 0 даёт прежние числа.

## Риски

- 🔴 **Правка `vite.config.ts` задевает ВСЕ сборки проекта, включая боевую.** Смягчение:
  порты слота 0 равны сегодняшним литералам; дверь выката передаёт порт явным флагом; ветка
  `isStand()` (хост `localhost`) отделяет стенд от боя по построению. Контроль — сборка в главной
  копии не меняется по поведению, и это проверяется, а не предполагается.
- ⚠️ **`reuseExistingServer: false` сделает красными прогоны, которые раньше молча проходили** —
  у того, кто держит свой вчерашний preview. Это не регрессия, а обнажившийся отказ (`EXP-0091`),
  и отказ называет порт.
- ⚠️ **Замер занимает весь парк.** Соседи в это время без стенда. Смягчение: один заход,
  предупреждение команды сообщением, уборка с контролем возврата.
- ⚠️ **Три `vite dev` из одного рабочего места делят `.svelte-kit/`.** В фазе 1 два лишних dev
  так уже поднимались, но замер А поднимает ТРИ ПОЛНЫХ стенда — если общий каталог даст сбой, это
  результат замера, а не его провал: он записывается как найденная граница парка.

## Чего фаза НЕ делает

- Не чинит хвост из 42 приборов с литеральным адресом и не пишет стража литералов — это фаза 3.
- Не трогает `tools/deploy.mjs`, боевые и стейдж-ресурсы, контейнеры сервера синхронизации.
- Не назначает потолок воркеров (только меряет) и не расширяет файл подкачки.
- Не правит `storage.cors.json` (боевой файл, правка = выкат, решение Менеджера — названо
  `plans/69` §5.3 и остаётся открытым вопросом к нему).
- Не сшивает канон под парк (манифест, `AGENT_GUIDE`, досье окружения) — это фаза 4.
