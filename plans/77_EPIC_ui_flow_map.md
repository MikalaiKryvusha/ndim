## Вектор цели

Владелец открывает ОДНУ страницу и видит с высоты всё приложение: экраны рядом, стрелки
связей, логические флоу — «понимание устройства UI/UX приложения» (его слова). Рядом — почин
дизайн-системы: библиотека переиспользуемых компонентов.

## Критерии приёмки эпика

1. Инструмент выбран ВЛАДЕЛЬЦЕМ из кандидатов разведки (страница вычитки), развёрнут
   self-hosted/локально, открывается у него в браузере.
2. Развёртка покрывает ВСЕ живые экраны продукта (сверка с `qa/JOURNEYS.md` — ни один путь
   карты не остаётся без экранов на схеме); связи — стрелками; флоу читаются без пояснений.
3. Владелец подтверждает словом: «вижу устройство UI/UX с высоты» (приёмка — его глаза,
   это и есть заказ).
4. Библиотека компонентов начата: повторяемые элементы (кнопки, карточки, панели, нав-рельс)
   выделены как переиспользуемые, названы по словарю продукта.
5. Регламент свежести назван: как развёртка живёт дальше (кто и когда добавляет новый экран;
   «мертвеющая схема» хуже отсутствующей).

## Риски, названные заранее

- **Инструмент-склад:** self-hosted сервис без бэкапа = схема живёт на одном диске.
  Экспорт/бэкап — ось разведки Ф0, не послесловие.
- **Схема-мертвец:** развёртка, не вписанная в процесс (новый экран → новый кадр на схеме),
  устареет за месяц. Критерий 5 обязателен.
- **Подмена заказа:** владельцу нужен ВИД СВЕРХУ, а не перерисовка приложения в векторе.
  Скриншоты живых экранов — законный материал Ф2; перерисовка компонентов — только в Ф3 и
  только переиспользуемых.
