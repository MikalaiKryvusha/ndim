## 🔴 Ворота в этом окне НЕ РАСТУТ — и это меняет форму приёмки

Заказ предполагал «эволюцию guards по шагам как приёмку каждого шага». Замер отвечает иначе:

```bash
for b in 51676fd f683f48 c27cbb6 e5f093d 192133c f405258; do
  git diff --name-only main..."$b" -- tools/guards.mjs | wc -l; done
# 0 0 0 0 0 0
```

**Ни одна ветка очереди не трогает `tools/guards.mjs`.** Состав ворот остаётся **13** от первого
шага до последнего — в отличие от окна смены 10, где он рос 7 → 13 и служил приёмкой сам по себе.

Это НЕ ослабление: ворота подхватывают новое сами, потому что первая строка состава — глоб
`tools/*.test.mjs`. Растёт не число ворот, а число проверок внутри них: мастерская привозит шесть
новых файлов тестов приборов, dev-1 и dev-3 — по одному. Поэтому контроль шага — **числа
`npm run test:tools`**, а не длина списка стражей. Приёмка, привязанная к длине списка, в этом

## Механика окна — та же, что доказана сменой 10

`main` живёт в главной копии Менеджера, и git не отдаёт одну ветку двум worktree
