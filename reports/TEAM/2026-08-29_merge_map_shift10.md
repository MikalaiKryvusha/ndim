## Как карта построена — чтобы её можно было перепроверить, а не поверить

Очередь смоделирована ЦЕЛИКОМ и ПО ПОРЯДКУ, а не каждая порция против `main` по отдельности.
Разница существенная: конфликт шага 7 существует только потому, что шаг 1 уже лёг. Модель
строится так (рабочее дерево не трогается, коммиты не создаются в ветке):

```bash
# один шаг очереди
git merge-tree --write-tree <текущее>  <голова порции>   # печатает дерево + конфликты
git commit-tree <дерево> -p <текущее> -p <голова> -m sim  # виртуальная голова для следующего шага
```

Прогон целиком — `mergemap.mjs` в скретчпаде смены; повторяется одной командой и даёт таблицу ниже.

## Конфликты — по одному на файл, с планом решения

### `EXPERIENCE.md` — шаги 2, 3, 4, 5, 6, 7 (ШЕСТЬ РАЗ ПОДРЯД)

Один и тот же файл конфликтует на каждом шаге, кроме первого и последнего. Причина не в людях, а
в конвенции: новые уроки дописываются В НАЧАЛО файла, и любые две ветки, писавшие уроки
параллельно, спорят за одни и те же первые строки. При шести рабочих копиях это гарантия, а не
случайность.

**План решения — один на все шесть шагов, механический:**
1. Берутся ОБЕ стороны целиком. Ни одна запись не выбрасывается: журнал — летопись, а не мнение.
2. Порядок восстанавливается хронологический (новое сверху) по дате в шапке каждой записи.
3. Дубли снимаются только при ПОЛНОМ совпадении смысла и с оговоркой в теле оставшейся записи
   (прецедент: снятие дубля `EXP-NEW` в `df43109` у QA).
4. Нумерация — ниже отдельным разделом.

⚠️ Проверка после каждого решения: `npm run guards` содержит стража целостности текста
(`verify-text-integrity.mjs`), который краснеет на оставленных маркерах конфликта. То есть
недорешённый конфликт этого файла ловится механически, а не глазами.

### `tools/guards.mjs` — шаг 7 (перепись dev-3)

Обе стороны дописывают в массив `GUARDS`: моя — три строки после шага 6, dev-3 — строку

## Правило окна — и почему карта его инструмент

**Сначала ВСЕ мержи, потом стейдж, потом бой.** Расписка стейджа привязана к коммиту, и каждый
мерж делает её негодной. Карта позволяет пройти все восемь шагов подряд, не останавливаясь на
размышление, и выйти на стейдж один раз.

⛔ **Мержей не делал и не делаю до слова владельца (интервью №059 В1).** Всё выше — предпросмотр:
рабочее дерево чисто, `git status` пуст, ни одна ветка не сдвинута.
