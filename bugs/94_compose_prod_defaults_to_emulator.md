# Bug 94 — боевой запуск по инструкции самого compose-файла подключает «прод» к эмулятору

**Статус:** 🔴 OPEN · **Когда/контекст:** найден 2026-07-31 аудитом Fable 5 после сессий слабых
моделей (ревизия кода + состязательная проверка) · **Серьёзность:** major

## Симптом

Владелец запускает боевой режим ровно так, как велит инструкция в шапке
`calculator/docker-compose.yml` (строки 10–11): задаёт `FIREBASE_PROJECT_ID=ndim-space` и
`GOOGLE_APPLICATION_CREDENTIALS` и делает `docker compose up`. Ожидаемое: сервер синхронизации
ходит в боевой Firestore. Наблюдаемое бы:

- если стенд с эмулятором поднят — «боевой» контейнер **молча пишет топы похожести в пустую
  дев-базу эмулятора**, боевой Firestore не синхронизируется вовсе;
- если эмулятор погашен — каждый цикл падает с ошибкой соединения; боевой экран «Пространство»
  показывает «Не отвечает», Связи людей застывают.

Ни одна из веток не сообщает честно, что «бой» подключён не туда.

## Воспроизведение (детерминированное)

1. Положить ключ в `calculator/secrets/sa.json` (как велит шапка файла).
2. `FIREBASE_PROJECT_ID=ndim-space GOOGLE_APPLICATION_CREDENTIALS=/secrets/sa.json docker compose -f calculator/docker-compose.yml up -d --build`
3. `docker inspect` контейнера: `FIRESTORE_EMULATOR_HOST=host.docker.internal:8181` присутствует.
4. Admin SDK при наличии `FIRESTORE_EMULATOR_HOST` ходит в эмулятор независимо от ключа —
   дальше по состоянию эмулятора одна из двух веток симптома выше.

Попытка снять переменную окружением (`FIRESTORE_EMULATOR_HOST=`) не помогает: синтаксис `:-`
подставляет дефолт и при **пустой** переменной.

## Криминалистика

Мина — `calculator/docker-compose.yml:24`:

```yaml
FIREBASE_PROJECT_ID: ${FIREBASE_PROJECT_ID:-demo-ndim-dev}
FIRESTORE_EMULATOR_HOST: ${FIRESTORE_EMULATOR_HOST:-host.docker.internal:8181}
```

А инструкция боевого режима в шапке **этого же файла** (строки 9–11) велит задать только две
переменные — про эмулятор ни слова:

```
# ...положить ключ сервисного аккаунта в calculator/secrets/sa.json ... и запустить:
#   FIREBASE_PROJECT_ID=ndim-space GOOGLE_APPLICATION_CREDENTIALS=/secrets/sa.json \
#     docker compose -f calculator/docker-compose.yml up -d --build
```

Страж в `calculator/index.mjs:164` однонаправленный — добавляет эмулятор для `demo-*`, но
комбинацию `ndim-space` + эмулятор не запрещает:

```js
if (projectId.startsWith('demo-') && !process.env.FIRESTORE_EMULATOR_HOST) {
  process.env.FIRESTORE_EMULATOR_HOST = '127.0.0.1:8181';
}
```

Строка 665 комбинацию лишь логирует: `` log(`старт: проект ${projectId}, эмулятор: ...`) ``.

Состязательная проверка закрыла линии опровержения:

1. **«Окружением можно снять»** — нет: `:-` в compose подставляет дефолт и при пустой переменной.
2. **«Страж в коде спасёт»** — нет: он работает только для `demo-*` (см. цитату выше).
3. **«Это теория»** — нет: `researches/14_kaif_for_weak_models_report.md:102-104` фиксирует ровно
   этот отказ как факт живой сессии — «compose-дефолт вообще целится в эмулятор… слепой перевыкат
   по документации отправил бы боевой сервер в несуществующий эмулятор»; спасла ручная сверка
   `docker inspect`, а не какой-либо страж. После этого compose-файл не правился (git log), бага
   заведено не было, решения владельца «оставить как есть» нет.

Смягчение (не опровержение): канонический боевой путь — `plans/04:119-126` и шапка Dockerfile
(`docker run` без compose, безопасно), `AGENT_GUIDE:458` отсылает к Dockerfile. Это снижает
вероятность, но мина в шапке compose остаётся взведённой и уже почти сработала.

## Корневая причина

Compose-файл писался под дев-стенд: дефолты `demo-ndim-dev` + `host.docker.internal:8181` удобны
локально. Инструкцию «для боя» дописали в шапку того же файла, не заметив, что эмуляторный дефолт
переезжает и в бой, а синтаксис `:-` делает его несбрасываемым через окружение. Класс дефекта —
**инструкция/гейт, которой верят слепо, ведёт не туда** (родственник `bugs/71`).

## План фикса

Двухслойное лечение класса, не экземпляра — всё `[NOT-TESTED]`:

1. `[NOT-TESTED]` Убрать эмуляторный дефолт из `docker-compose.yml`; стендовое значение переезжает
   в `docker-compose.override.yml` (compose подхватывает его автоматически только локально) либо
   задаётся явно в командах стенда.
2. `[NOT-TESTED]` Двусторонний страж в `calculator/index.mjs`: комбинация «проект `ndim-space` +
   `FIRESTORE_EMULATOR_HOST`» = немедленное падение при старте с внятным текстом; спасение через
   явный `NDIM_ALLOW_EMULATOR=1` для осознанных случаев.
3. `[NOT-TESTED]` Мутация для проверки стража: запуск с `ndim-space` + эмулятором **обязан упасть**.
4. `[NOT-TESTED]` Переписать инструкцию в шапке compose честной (или указать канонический путь
   через `docker run` из `plans/04`).
