# Bug 53 — Меню: сегмент «Тема» показывает «Светлая», когда применена тёмная

**Статус:** 🔴 OPEN (воспроизводится детерминированно) · **Когда/контекст:** 2026-07-27, найден
попутно при замене иконок (`bugs/17`) · **Кто чинит:** агент сам, решения владельца не требует

## Симптом

На `/menu` при тёмной теме документ действительно тёмный (`<html data-theme="dark">`, фон тёмный),
но в карточке «Вид» подсвечена кнопка **«Светлая»**, а иконка строки показывает **солнце**.
То есть переключатель врёт о текущем состоянии.

Дефект **не новый**: `class:on={theme === 'light'}` стоял и раньше. Его просто не было видно,
пока иконкой темы был статичный знак `☾` — он выглядел одинаково при любой теме. Живая иконка
(луна/солнце) из `bugs/17` рассинхрон обнажила.

## Воспроизведение (детерминированное)

```bash
npm run build
npx vite preview --port 4173
```

Playwright, контекст с `localStorage['ndim-theme'] = 'dark'` до загрузки:

```js
await page.addInitScript(() => localStorage.setItem('ndim-theme', 'dark'));
await page.goto('http://127.0.0.1:4173/menu');
await page.evaluate(() => document.documentElement.getAttribute('data-theme')); // 'dark'  ✔
await page.locator('.seg button.on').last().innerText();                        // 'Светлая' ✘
```

Воспроизводится на **обеих** ширинах (390 и 1440). При светлой теме всё согласовано.

## Криминалистика

- `src/app.html:14-17` — инлайн-скрипт до отрисовки читает `ndim-theme` и ставит `data-theme`.
  На момент гидрации атрибут уже правильный (проверено: `data-theme` = `dark`).
- `src/routes/menu/+page.svelte:41` — `let theme = $state<'light'|'dark'>('light')`, то есть
  **начальное значение зашито светлым**; `:55` в `onMount` читает `data-theme`; `:58-61`
  MutationObserver следит за дальнейшими сменами.
- Значит либо присваивание в `onMount` не доезжает до уже гидрированной разметки, либо
  разметка, отрисованная пререндером со светлой темой, не пересобирается по этому состоянию.
  Родственный класс — EXP-0049 («две ловушки Svelte 5» при работе с состоянием шапки).

## Гипотезы (по убыванию правдоподобия)

1. **Пререндер + гидрация:** страница пререндерена при `theme='light'`, и присваивание в
   `onMount` происходит после гидрации, но `class:on` не переприменяется к уже существующему DOM.
   Проверить: тот же ли эффект у сегмента «Язык» (он инициализируется так же, из localStorage).
2. **Гонка порядка:** значение читается раньше, чем атрибут доступен компоненту.
   Слабее: тест показывает, что атрибут стоит верный ещё до гидрации.
3. Состояние читается, но перекрывается повторной инициализацией ниже по `onMount`.

**Правильное лекарство скорее всего одно на класс:** тему нельзя держать локальным `$state`
каждого экрана (сейчас она объявлена в `menu`, в `AppBar` и на лендинге раздельно) — источник
истины должен быть один, и читаться он должен из `data-theme`/`localStorage` **при инициализации**,
а не в `onMount`. Это же снимет и дублирование `setTheme` в трёх местах.

## План проверки

Страж на согласованность: `data-theme` документа == активная кнопка сегмента, обе темы × 390/1440.
Готовый код проверки лежит в истории `tools/verify-icons.mjs` (был временно добавлен туда, когда
дефект поймали, и вынесен сюда, чтобы прогон иконок стерёг только иконки). Проверить стража на
сломанной версии обязательно.
