## Симптом

Одна и та же команда `npm test` в двух рабочих копиях одного коммита даёт РАЗНОЕ число тестов, и
обе объявляют себя зелёными:

| где | вывод |
|---|---|
| копия разработчика | `tests 322 · pass 322 · fail 0` |
| свежий worktree QA | `tests 318 · pass 318 · fail 0` |

Ни строки «пропущено», ни предупреждения: `skipped 0` в обоих случаях. Прогон на 4 теста короче
выглядит ТОЧНО так же успешно, как полный.

## Причина — условное объявление вместо объявленного пропуска

`src/lib/content/catalog-neighbours.test.ts:127` и `src/lib/content/catalog-hub.test.ts:267`:

```js
const BUILD = new URL('./dims-build.json', import.meta.url);
const full = existsSync(BUILD) ? (JSON.parse(readFileSync(BUILD, 'utf8')) as NeighbourItem[]) : null;

if (full) {
  test('боевой каталог: соседи есть у КАЖДОГО объекта, и их ровно восемь', () => { … });
  test('боевой каталог: сосед НИКОГДА не из чужого вида — слияние видов запрещено', () => { … });
}
```

`src/lib/content/dims-build.json` — артефакт сборки и он в `.gitignore` (строка 67). В свежем
worktree его нет, `if (full)` ложно, и четыре теста (по два в каждом файле) **не объявляются
вовсе**. `node --test` не может сообщить о том, чего ему не объявили.

Проверено числом: объявлений `test(` в `src/**/*.test.ts` — **322**; прогнано — **318**.
Расхождение целиком приходится на эти два файла (по 2 в каждом), остальные 18 файлов сходятся
один-в-один.

## Чем это опасно

Пропадают самые дорогие проверки набора — те, что судят каталог из 5 111 объектов («у КАЖДОГО
объекта ровно восемь соседей», «сосед никогда не из чужого вида»). Их и писали ради боя, а не
ради фикстуры из девяти строк — так сказано в их же комментарии. Сессия в чистом worktree
(а команда worktree — это ровно такие сессии) получает зелёный прогон БЕЗ них и не узнаёт об
этом. Это тот же класс, за который в проекте уже платили: проверка, которая молча не выполняется,
неотличима от выполненной.

## Воспроизведение (30 секунд)

```
rm -f src/lib/content/dims-build.json   # или просто взять свежий worktree
npm test                                # tests 318, skipped 0
npm run build                           # артефакт появляется
npm test                                # tests 322, skipped 0
```

## Критерий приёмки починки (что будет ВИДНО работающим)

1. Без `dims-build.json` тесты **объявляются** и печатаются как ПРОПУЩЕННЫЕ с причиной:
   `test('боевой каталог: …', { skip: 'нет src/lib/content/dims-build.json — сначала npm run build' }, …)`.
2. Общее число тестов не зависит от наличия артефакта: `tests 322` в обоих случаях, а разница
   видна в строке `skipped` (0 или 4).
3. Прогон в чистом worktree печатает причину пропуска ВСЛУХ — сессия не может принять неполный
   набор за полный.
4. Проверка починки — мутацией окружения, а не кода: удалить артефакт, прогнать, увидеть
   `skipped 4` и причину; вернуть, прогнать, увидеть `skipped 0`.
