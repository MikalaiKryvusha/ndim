# Баг 130 — отпечаток базы считает каталог ДВАЖДЫ: сводка врёт, квота горит

> **Заведён:** 2026-08-15 · **Нашёл:** агент (разведка перед наполнением стейджа) ·
> **Статус:** ✅ ПОЧИНЕН 2026-08-15 21:5x, доказан 2 мутациями · **Серьёзность:** ложное число в
> критерии приёмки миграции + 10 % суточной квоты чтений на каждый прогон ·
> **Родитель:** `plans/53_EPIC_stage_environment.md` фаза 0

## Симптом

`tools/migrate/db-fingerprint.mjs` рапортует в сводке `counts`:

```
dims/*   10224
```

Реальных документов каталога в бою — **5112** (`bugs/106`: 5111 измерений + служебный
`dims_list`). Число завышено ровно вдвое.

Заголовочное число отпечатка при этом **верное**: `documents: 11266`. Врёт только разбивка по
коллекциям — и именно она переписана в план.

## Чем это уже навредило

1. 🔴 **Ложное число уехало в `plans/53` ДВАЖДЫ** — в инвентарь фазы 0 (`| dims/* | 10 224 |`) и
   в таблицу правил переноса зарубки (`dims/* (10 224) | как есть`). Инвентарь объявлен ожиданием
   для критерия **П1 «ни один документ людей не потерян»**. Сессия, наполняющая стейдж или
   мигрирующая бой, увидела бы 5112 против ожидаемых 10 224 и прочитала бы это как потерю половины
   каталога.
2. 🔴 **Таблица инвентаря в `plans/53` противоречит сама себе:** сумма её строк даёт 16 378, а
   итог подписан «**ВСЕГО 11 266**». Расхождение — ровно 5112, то есть та же двойная порция.
3. 💸 **Каждый прогон жжёт лишние 5112 чтений.** Прибор честно печатает `reads: 16378`, но 5112 из
   них — повторное чтение уже прочитанного. Бесплатная квота — 50 000 чтений в сутки на проект;
   за 2026-08-15 израсходовано ≈ 44 000. Лишние 10 % квоты тратятся в единственной работе, где
   владелец сказал «*права на ошибку у нас нет*».

## Воспроизведение (детерминированное, БЕЗ обращения к бою)

Отпечаток уже снят и лежит на диске — дефект воспроизводится по файлу, чтений не стоит:

```bash
node -e "
const j=JSON.parse(require('fs').readFileSync('test-results/db-fingerprint/ndim-space--default.json','utf8'));
const p=Object.keys(j.docs);
console.log('real dims/{id}      :', p.filter(x=>/^dims\/[^/]+$/.test(x)).length);   // 5112

console.log('documents (correct) :', j.documents);                                   // 11266
console.log('counts sum == reads :', Object.values(j.counts).reduce((a,b)=>a+b,0), j.reads);
"
```

## Криминалистика

| Проверка | Значение |
|---|---|
| `dims/{id}` в дедуплицированной карте `docs` | **5112** |
| `counts['dims/*']` в сводке | **10224** |
| `completenessProbe` → `dims.total` | **5112** (сам прибор знает правду в другом своём поле) |
| `points/{uid}/dims/{dimId}` | 4066 (не задвоено) |
| `documents` / размер карты `docs` | 11266 / 11266 (верно) |
| `reads` | 16378 = 11266 + **5112** |

Сходимость точная: избыток чтений равен ровно числу документов корневого каталога.

## Корневая причина

`collectionGroup(name)` в Firestore матчит **каждую** коллекцию с этим именем — включая
**КОРНЕВУЮ**. У нас имя `dims` носят две разные вещи: корневой каталог измерений `dims/{dimId}` и
подколлекция оценок `points/{uid}/dims/{dimId}`. Прибор читает обе, и корневую — дважды:

```js
// ── 1. Корневые коллекции целиком ───────────────  (db-fingerprint.mjs:137)
for (const collection of roots) {
  const snapshot = await collection.get();          // dims → 5112 документов
  ...
}

// ── 2. Подколлекции — запросами по группе ───────  (db-fingerprint.mjs:145)
for (const name of KNOWN_SUBCOLLECTIONS) {          // 'dims' в списке
  const snapshot = await db.collectionGroup(name).get();  // 5112 КОРНЕВЫХ + 4066 оценок
  ...
}
```

`record()` (строка 117) кладёт документ в `Map` по пути — и **карта дедуплицирует**, поэтому
`documents` уцелел. А счётчик строкой ниже инкрементируется **на каждый вызов**, не глядя, видел ли
он этот путь раньше:

```js
function record(path, data) {
  docs.set(path, hashOf(data));                     // дедуплицирует — число 11266 спаслось
  ...
  counts.set(template, (counts.get(template) ?? 0) + 1);   // НЕ дедуплицирует — отсюда 10224
}
```

🔑 **Класс дефекта:** *два представления одних данных, из которых дедуплицирует только одно.*
Заголовочное число верно, разбивка врёт — и в план уехала именно разбивка. Тот же класс, что
`bugs/106` (`space/stats.dims` считался по документам коллекции и давал 5112 против 5111 индекса):
у величины оказалось два источника, и разошлись они молча.

## План фикса

1. **Не читать корневую коллекцию, чьё имя есть в `KNOWN_SUBCOLLECTIONS`** — групповой запрос
   шага 2 возвращает её сам (это доказано замером: 10 224 = 2 × 5112 достижимо, только если группа
   вернула все 5112 корневых). Экономит 5112 чтений и убирает задвоение у источника, а не
   заплаткой на счётчике.
2. `record()` делает счётчик **идемпотентным по пути** — второй пояс: чтобы будущее совпадение имён
   (например, подколлекция `days` и одноимённая корневая) не вернуло тот же класс молча.
3. **Страж, доказанный мутацией:** на синтетической базе эмулятора завести корневую `dims` и
   `points/{uid}/dims/{id}`, снять отпечаток и потребовать `counts['dims/*'] === число корневых`.
   Мутация — вернуть чтение корневой коллекции; проверка обязана покраснеть.
4. **Пересчитать `counts` из уже снятой карты `docs`** — бесплатно, без единого чтения боя — и
   исправить оба места в `plans/53` плюс строку инвентаря.

## ✅ СТАТУС: DONE (2026-08-15, вечер)

**Фикс — два пояса, каждый доказан отдельной мутацией:**

1. **У источника:** шаг 1 не читает корневую коллекцию, чьё имя есть в `KNOWN_SUBCOLLECTIONS`, —
   групповой запрос шага 2 возвращает её сам. Убирает и задвоение, и лишние чтения.
2. **Второй пояс:** `record()` инкрементирует счётчик **идемпотентно по пути**. Он не нужен для
   сегодняшнего дефекта, но ловит будущее совпадение имён, если пояс 1 забудут.

**Страж:** `tools/migrate/verify-fingerprint.mjs` — 6 проверок на эмуляторе, **боевых чтений 0**.
Фикстура воспроизводит саму коллизию имён: корневой `dims` (7) + `points/{uid}/dims` (10, разложены
неравномерно 6/4). Числа выбраны РАЗНЫМИ и некратными нарочно — при 10 и 10 задвоение дало бы 20 и
выглядело бы правдоподобно. Внутри есть контроль прибора (`EXP-0082`): пустая фикстура иначе
красила бы «0 === 0» зелёным четырежды.

**Замер мутациями:**

| Мутация | Провалов | Что покраснело |
|---|---|---|
| Обе половины сняты (= код, который был в бою) | **3** | `counts['dims/*'] = 14` (2 × 7) · сумма 32 ≠ documents 25 · reads 32 ≠ 25 |
| Снят только пропуск корня (счётчик жив) | **1** | reads 32 ≠ 25 — сводка честна, но чтения горят |
| Фикс целиком | **0** | — |

🔑 Первая мутация — точная миниатюра боя: `counts` задвоился ровно вдвое, сумма разошлась с итогом,
а `documents` **остался верным**. Именно поэтому дефект прожил незамеченным: смотрели на
заголовочное число, а в план переписали разбивку.

**Замер на бою (пересчёт из уже снятой карты `docs`, 0 чтений):** `dims/*` = **5112**,
сумма всех строк = **11 266** = `documents`. Сходится.

**Цена прогона упала:** 16 378 → 11 266 чтений (**−5 112**). При суточной квоте 50 000 это
возвращает 10 % бюджета в работу, где 2026-08-15 уже было израсходовано ≈ 44 000.

## Решения, принятые без владельца

- **Пропуск корневой коллекции вместо заплатки на счётчике.** Заплатка починила бы сводку и
  оставила бы гореть 5112 чтений — то есть половину дефекта, причём ту, что стоит денег.
- **Оставлен и второй пояс** (идемпотентный счётчик), хотя после пояса 1 он избыточен: коллизия
  имён — свойство МОДЕЛИ, а не этой ошибки, и следующая пара одноимённых коллекций появится без
  предупреждения.
- **Отпечаток боя НЕ переснимался.** Верная сводка пересчитана из уже сохранённой карты путей —
  это те же данные и ноль чтений. Пересъёмка стоила бы 11 266 чтений ради числа, которое уже есть.
