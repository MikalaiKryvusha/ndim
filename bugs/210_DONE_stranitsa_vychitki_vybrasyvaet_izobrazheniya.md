## Симптом

Интервью №055 (выбор макета двери корня из четырёх) поднято контуром
(`node tools/review.mjs open interviews/interview_055_root_door_mockup_choice.md`).
Страж самодостаточности документ ПРОПУСТИЛ, страница поднялась и позвала владельца —
но все четыре markdown-изображения (`![V1 светлая](../test-results/root-door-mockups/…png)`
и родня) в HTML не приехали. Владелец получил вопрос «какой вариант берём» без единого
кадра вариантов.

## Замер (2026-08-28 ~18:0x, прибор — HTTP-чтение поднятой страницы)

```
Invoke-WebRequest http://127.0.0.1:51005/ → длина HTML: 30 782 · тегов <img>: 0
```

В исходном md — 4 изображения (`![V1…]`, `![V2…]`, `![V3…]`, `![V4…]`), файлы на диске
ЕСТЬ (`test-results/root-door-mockups/`, 24 кадра). 4 в источнике → 0 у глаз.

## Почему это класс, а не мелочь

Страж содержимого контура ловит **текстовые** отсылки наружу (мою же «В1 выше» в В3 он
поймал этим же вечером — страница отказалась подниматься), но НЕ ловит потерю
**изображений** при рендере: «есть в md» и «дошло до глаз владельца» — разные факты, а
проверяется только первый. Это дыра ровно в том месте, ради которого контур существует:
«Подавать, а не называть» (EXP-0125). Вопрос о ВИЗУАЛЬНОМ выборе без картинок — худший
случай класса: страница формально поднята, фактически пуста.

## Обход, применённый немедленно

Интерактивный макет открыт владельцу напрямую из main:
`design/root-door-mockups.html` (переключатели вариант × ширина × тема) — он и есть
рабочий артефакт выбора. Страница вопросов оставлена поднятой для записи ответов.

## Гипотеза причины (не вскрыта кодом — вскрыть при фиксе)

Markdown-рендерер `tools/review.mjs` не поддерживает синтаксис `![alt](path)` (вырезает
или не распознаёт). Проверить также: даже если тег появится, отдаст ли встроенный сервер
файлы ВНЕ каталога документа (`../test-results/…`) — вероятно, нужен либо статический
маршрут, либо встраивание data-URI (второе честнее: `render` обязан давать
самодостаточный офлайн-файл, значит data-URI нужен обоим путям).

## Наблюдаемый критерий приёмки фикса

1. Страница №055, поднятая контуром, несёт **4 изображения**, каждое читается из HTML
   (data-URI ненулевой длины ЛИБО HTTP 200 с ненулевым телом).
2. **Страж краснеет на потере:** в md есть `![…](…)`, а в HTML `<img>` нет или файл не
   читается → страница ОТКАЗЫВАЕТСЯ подниматься с именем пропавшего файла (как уже
   отказывается на текстовой отсылке наружу).
3. Мутационная проба: битый путь к картинке в копии документа → отказ с именем файла;
   возврат пути → страница поднимается, изображения на месте.
4. `node tools/review.mjs --selftest` зелёный.

## Починка — 2026-08-28, тем же днём

Причин оказалось ДВЕ, и обе были нужны для симптома:

1. **Рендерер не знал синтаксиса изображения.** `inline()` (`tools/lib/review-core.mjs`)
   превращал в ссылку только `[подпись](файл)`; `![подпись](кадр.png)` оставался текстом и до
   встраивателя не доезжал. Вылечено: изображение приводится к ссылке дом-конвенции, дальше
   конвейер вшивает файл data-URI, как и раньше.
2. **Пути разрешались от корня проекта, а не от документа.** `../test-results/…` из
   `interviews/` уезжал ВЫШЕ корня → `existsSync` ложь → тихая подпись «нет файла».
   Вылечено: `resolveAsset` пробует каталог документа, затем корень (`tools/review.mjs`);
   внешние адреса (`http…`) остаются ссылками.
3. **Тихая деградация заменена отказом.** Третий предполёт `preflightAssets` в `open` и
   `render`: страница со ссылкой на несуществующий файл НЕ ПОДНИМАЕТСЯ и называет каждый
   пропавший файл поимённо — как уже делает страж самодостаточности.

## Замеры приёмки — по критериям из шапки, все четыре

| Критерий | Замер |
|---|---|
| 1. №055 несёт 4 изображения | `render` №055: **тегов img 4 · data-URI png 4 · «нет файла» 0** |
| 2. Страж краснеет на потере | копия №055 с битым путём: **⛔ СТРАНИЦА НЕ ПОДНЯТА**, каждый файл назван, код возврата 1, html НЕ создан |
| 3. Мутационная проба | битый путь → отказ с именем; возврат пути (живой №055) → 4/4 вшиты |
| 4. Самотест | `node tools/review.mjs --selftest` → «самотест ядра чист» (+3 новых случая на `inline()`) |
