## Симптом

В **35 описаниях каталога из 5121** есть слова, набранные ДВУМЯ алфавитами встык, без разделителя:
кириллическое слово с латинской буквой-двойником внутри или на конце. Глазом такое слово
неотличимо от правильного — буквы `а`·`a`, `е`·`e`, `о`·`o`, `с`·`c`, `р`·`p` выглядят одинаково.

Все 31 слово (замер по живому каталогу):

```
Алексe ×5 · Лукасe ×2 · Аксумa ×3 · Криспa · Секторa · Эрикасонa · Лукасa · братa · Джекa ·
Хартa · Станa · Доранa · Кротa · Саровa · искусствa · Озунa · Рафтo · Ингo · Эуфемиo ·
Монтеcом · автoфагии · кабdriver · немецкийpoque
```

Отдельно — четыре, где смешение может быть АВТОРСКОЙ стилизацией, и их надо не чинить, а
спросить: `Zемфира` (певица так пишет своё имя), `ДжаZ`, `Animalизм`, `РOUNDS`, `ЭNaMi`,
`Нikolaj`, `Грanny`, `Сagal`. ⚠️ Разделять эти два списка обязан человек, а не прибор.

## Чем это плохо

1. **Это публичный текст.** Описания едут на 10 222 страницы каталога, которые читают люди и
   роботы поиска — то есть на главную поверхность притока проекта.
2. **Поиск в продукте по такому слову не сработает.** `model/feed.ts` → `normalizeForSearch`
   приводит регистр, «ё», дефисы и римские цифры, но букву-двойник не знает: «Алексe» и «Алексе»
   для него разные строки.
3. **Класс молчаливый.** Ни один существующий страж проекта этого не ловит, и глаз не ловит тоже.

## Воспроизведение (детерминированное, без сети)

```bash
node --input-type=module -e "
import {readFileSync} from 'node:fs';
const dims = JSON.parse(readFileSync('src/lib/content/dims-build.json','utf8'));
const ВСТЫК = /[\p{Script=Latin}][\p{Script=Cyrillic}]|[\p{Script=Cyrillic}][\p{Script=Latin}]/u;
const слова = (t) => String(t ?? '').split(/[\s,;:!?()«»\"„“]+/u).filter(Boolean);
let карточек = 0; const найдено = new Map();
for (const d of dims) {
  const t = d.description?.ru; if (!t) continue;
  const hit = слова(t).filter((w) => ВСТЫК.test(w));
  if (hit.length) { карточек++; for (const h of hit) найдено.set(h, (найдено.get(h) ?? 0) + 1); }
}
console.log('карточек ' + карточек + ' · слов ' + найдено.size);
console.log([...найдено.entries()].sort((a,b)=>b[1]-a[1]).map(([w,c])=>c+'×'+w).join(' · '));
"
```

Ожидается: **карточек 35 · слов 31**.

## Корневая причина / гипотезы

Не установлена, и гадать не надо — её назовёт распределение. Ранжированные гипотезы:
1. **Раскладка при ручной правке.** Хвостовое `a`/`e`/`o` в русских словах (`братa`, `Джекa`,
   `Хартa`, `искусствa`) — подпись переключения раскладки на последней букве.
2. **Копирование из смешанного источника** (статья, где имя набрано латиницей).
3. **Машинная генерация описания** — тогда класс будет расти с каждой партией.

🔑 Различить дёшево: посмотреть, в каких описаниях они живут — старых (наследие) или
переписанных недавно; и есть ли такие слова в АНГЛИЙСКИХ описаниях (обратная сторона класса).
Этот замер я НЕ делал — называю его, а не выдаю за сделанный.

## План фикса

1. Разделить два списка глазами: настоящие опечатки против авторских стилизаций
   (`Zемфира` — имя, которое так и пишется; трогать нельзя).
2. Починить опечатки правкой данных — теми же приборами, что правят описания каталога.
   ⛔ НЕ автозаменой всех латинских двойников подряд: она сломает стилизации и латинские имена.
3. Завести страж класса по `dims-build.json` и поставить его в ряд с прочими стражами каталога —
   иначе класс вернётся с ближайшей партией. Механизм у проекта уже есть: `mixedScriptWords` из
   `tools/check-candidate-descriptions.mjs` (`ndim_dev3`, `6e7d1eb`) ловит ровно это; страж
   каталога — его второе применение, к УЖЕ ВЫКАЧЕННЫМ данным, а не к кандидатам.

**Фикс принят, когда (наблюдаемо):**
· *Scale* — число описаний каталога со смешением алфавитов встык · *Meter* — прогон из раздела
«Воспроизведение» · *Target* — **0**, при явном списке разрешённых авторских стилизаций рядом;
· страж класса стоит в реестре «Испытательный стенд» и доказан мутацией (посадить `Алексe` в
чистое описание — обязан покраснеть и НАЗВАТЬ карточку);
· контроль в обратную сторону: `Zемфира` и прочие утверждённые стилизации прогон НЕ красят.
