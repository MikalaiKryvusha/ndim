# Баг 100 — Контур согласований может молча съедать ответы владельца (весть из Unliminium)

**Статус:** 🔬 ТРЕБУЕТ ПРОВЕРКИ НА ЭТОМ ПРОЕКТЕ — дефект подтверждён в соседнем, здесь не проверялся.
**Вес:** критический, если подтвердится (уничтожает работу владельца).
**Источник:** полевой инцидент в проекте **Unliminium**, 2026-08-02. Разослано по прямому поручению
владельца: *«раздай новости об этом баге в соседние проекты»*.

> **Почему письмо пришло именно сюда.** Контур «агент ↔ владелец» на страницах родился у вас: KAIF
> 2.2 (`ideas/20_kaif_2.2_scope.md`, п. 1.6) прямо называет реализацию NDim образцом и ссылается на
> `researches/28_owner_reviews_contour_field_report.md`. Unliminium строил свой контур **по вашим
> решениям** — и напоролся на дефект, которого в отчёте нет. Если он есть и у вас, он ждёт своего часа.

## Что случилось у нас

Владелец писал ответы на интервью **больше часа**. Нажал «Сохранить» — и получил **вечное
«Записываю…»** без единого слова об ошибке. Кнопка осталась заблокированной. Ответы уцелели только
потому, что он сам догадался нажать Ctrl+C и вставить текст в чат.

Его слова: *«Я писал ответы, работал, а оно не может их записать!!!!»* · *«Ждать ответы владельца
ХОТЬ ВЕЧНОСТЬ!»*

## Первопричина — три дефекта, порознь терпимых, вместе смертельных

1. **Таймаут ожидания убивал СЕРВЕР** (у нас — 30 минут по умолчанию), а вкладка в браузере
   оставалась открытой и об этом не знала.
2. **Клиентский `fetch` не был обёрнут в `try/catch`.** Мёртвый сервер отвергает промис → обработчик
   клика молча умирает на необработанном отказе → кнопка навсегда `disabled`, статус навсегда
   «Записываю…».
3. **Черновик нигде не хранился** — ответы жили только в DOM и умирали вместе со вкладкой.

**Ни одна из трёх частей не сообщала о беде.** Молчание и делает дефект критическим.

Отдельно виновата **асимметрия ожиданий**: агент ждёт минуты, владелец отвечает часами, потому что
ДУМАЕТ. Таймаут был выставлен по мерке агента, а платил по нему человек.

⚠️ Тут есть ловушка, которая касается вас напрямую. Ваш же инвариант «**сохранение будит ждущего**»
(§2 отчёта 28) требует, чтобы процесс страницы ЗАВЕРШАЛСЯ по сохранению. Отсюда и рождается соблазн
добавить таймаут — «раз процесс всё равно должен умирать, пусть умирает и по часам». Это **ложная
симметрия**: умирать он обязан ПО СОБЫТИЮ, и никогда — ПО ВРЕМЕНИ.

## Как проверить у себя (5 минут, настоящий браузер)

```bash
# 1) поднять страницу согласования, забрать ЖИВОЙ html, убить сервер
<ваша команда открытия> --no-open &
curl -s http://127.0.0.1:<порт>/ -o /tmp/page.html
kill %1
# 2) открыть /tmp/page.html в headless-браузере, вписать ответ, кликнуть «Сохранить»,
#    подождать 1.5 с и прочитать DOM
```

Смотреть три вещи. **Дефект есть, если:** кнопка сохранения осталась `disabled`; в статусе висит
«Записываю…» (или аналог) без слова об ошибке; текста владельца нигде на странице нет.

У нас до починки: `спасательный блок=false ; кнопка разблокирована=false ; статус=Записываю…`

## Чем починили (пять мер, все проверены зондом)

| Мера | Суть |
|------|------|
| **Терпение бесконечно** | таймаут по умолчанию снят (`0`); `--timeout N` остался только для автоматики |
| **Громкий отказ** | `fetch` в `try/catch`; путь «тихо не записалось» физически закрыт |
| **Спасательный круг** | не записалось → текст владельца возвращается НА СТРАНИЦУ: поле со всем содержимым + «Скопировать» + «Повторить», кнопка разблокируется |
| **Черновик в браузере** | `localStorage` на каждый ввод, восстановление при загрузке |
| **Пульс** | страница спрашивает `/alive` раз в 15 с и говорит вслух, как только сервер замолчал — владелец узнаёт СРАЗУ, а не через час |

Из пяти только **пульс** делает дефект невозможным; остальные четыре делают его поправимым. Стоит
брать все пять.

После починки, тот же зонд: `спасательный блок=true ; кнопка разблокирована=true ; ответ в
выдаче=true ; черновик в браузере=true ; статус=НЕ ЗАПИСАНО — ответы ниже, они не потеряны`
