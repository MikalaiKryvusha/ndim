## Диагностика — все замеры 2026-08-28 ~15:50, прибор curl

| Проверка | Результат |
|---|---|
| Главная `/` как YandexBot | **HTTP 200**, 0.46 s |
| Главная `/` обычным UA | HTTP 200, 0.21 s |
| `robots.txt` | чист: `User-agent: * / Disallow:` (пусто) + sitemap |
| Удалённая карточка Финиста как YandexBot | HTTP 200 |
| `https://www.` и `http://` | оба 301 → `https://ndimspace.app/` (правильно) |
| `/ru`, `/en`, карточки | меты `robots` НЕТ, canonical на месте |
| sitemap.xml | 10 460 страниц |
| **Корень `/`** | 🔴 **`<meta name="robots" content="noindex"/>`** |

Снаружи хост здоров: коды 200, редиректы зеркал правильные, robots чист. Единственный красный
факт — **мета `noindex` на корне**, и он НЕ дефект кода: это исполнение решения владельца
(интервью №010 Р5 = В; `plans/39`): лендинги живут на `/ru` и `/en`, «ни один не сидит на голом
корне», корень — JS-распознаватель языка (`src/routes/+page.svelte:64`), в поиске не участвует —
«цена названа и принята».

## Почему Google растёт, а Яндекс казнит — одна и та же мета, разные судьи

- **Google** оценивает страницы по отдельности: корень noindex — ну и ладно, ходит по sitemap,
  индексирует `/ru`, `/en` и карточки. Показы ×30 за месяц (аудит 2026-08-28).
- **Яндекс** считает главную страницу лицом ХОСТА. Недоступная главная — сигнал качества всему
  сайту («Главная страница сайта недоступна для робота» — формулировка их же дайджеста), и
  дальше его алгоритм малоценности (широко известный как «МПК») выкидывает внутренние страницы
  пачками. −100% страниц в поиске при живом самом сайте — типичная картина именно этого класса.

Класс дефекта: **«решение, оптимальное под одного судью, наказано другим судьёй»**. Решение
№010 Р5 принималось с ценой «корень не в поиске» — но цена оказалась не «минус одна страница»,
а «минус доверие Яндекса ко всему хосту». Цена выросла ПОСЛЕ принятия решения — значит, решение
законно перевзвесить, и это право владельца, не агента.

## Лечение причины — ✅ ВЫБРАНО ВЛАДЕЛЬЦЕМ: вариант А (интервью №052, В1 = А, 2026-08-28 16:24)

**Корень становится видимой страницей-дверью:** `noindex` снимается; на странице — название,
одна строка о Пространстве, две большие кнопки «Русский»/«English»; JS-распознаватель языка
и контракт писем (`mode=signIn&oobCode` → `/profile`) остаются как есть — человек страницы
по-прежнему не видит. Лендинги `/ru`,`/en`, карточки, sitemap не трогаются. Тексты двери —
на вычитку владельцу ДО выката. Путь: 4 макета (Дизайнер) → выбор владельца → код → стейдж →
бой → повторная отправка главной в переобход. Исторические варианты решения (для контекста):

- **А. Серверный 301 с корня на `/en`** (redirect в `firebase.json` вместо JS-распознавателя).
  Яндекс понимает «главная = редирект» и берёт целевую. Цена: распознавание языка по браузеру
  на корне умирает — русский человек, набравший голый домен, попадёт на `/en` (в шапке есть
  переключатель). Контракт писем (`mode=signIn&oobCode` → `/profile`) обязан пережить редирект —
  проверить, что hosting-redirect не съедает query.
- **Б. Корень — настоящая страница x-default без `noindex`**: лёгкий выбор языка (две больших
  двери RU/EN) + hreflang. Яндекс получает живую главную, Google — x-default. Цена: правка
  №010 Р5 «ни один не сидит на голом корне» смягчается до «лендинги на префиксах, корень —
  дверь»; плюс дизайн-работа (4 макета).
- **В. Ничего не менять, только переобход**: слабо — Яндекс продолжит считать главную
  недоступной, класс вернётся.

⚠️ Что бы ни выбрали — Google-динамику (×30) не рисковать: `/ru`, `/en`, карточки, sitemap не
трогаются ни в одном варианте.
