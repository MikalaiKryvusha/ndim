# Bug 89 — автовход стенда подменял живую сессию, и вход по почтовой ссылке был непроверяем

**Статус:** ✅ ПОЧИНЕНО 2026-07-30 · **Когда/контекст:** охота на родню вакуумной проверки из
`EXP-0087` — прямая просьба эстафеты предыдущей сессии · **Тип:** дефект испытательного стенда,
делавший целый класс проверок вакуумным (плюс три давно красных проверки в `verify-bugs08`)

## Симптом

Проверка «человек вошёл ИМЕННО как X» на стенде **не могла покраснеть никогда**. Прошлая сессия
поймала это на `bugs/84` (мутация «выбрасываем намерение» дала 54 зелёных и 2 провала, оба на
консоли) и оставила предупреждение в `STATUS.md`. Оно оправдалось: ровно так же был устроен
`tools/verify-bugs08.mjs`.

## Причина — в продукте, а не в страже

`src/lib/data/profile.ts` → `currentSession()`, ветка стенда заканчивалась строкой:

```ts
return signInDev();   // безусловно
```

То есть **на любом голом адресе стенд входил `dev@ndim.space`, ВЫТЕСНЯЯ живую сессию**. Следствия:

- вход по почтовой ссылке был принципиально **ненаблюдаем**: сработал он или нет, следующая
  навигация возвращала dev-пользователя;
- вход **НОВИЧКА** (гость → свой аккаунт по ссылке на новую почту) молча подменялся dev-аккаунтом
  за его спиной — то есть страж проверял не тот сценарий, который заявлял.

## Лечение

```ts
const existing = await waitForSession();
if (existing !== null && !existing.isAnonymous) return existing.uid;
return signInDev();
```

Живая сессия НАСТОЯЩЕГО аккаунта уважается; автовход остаётся тому, у кого сессии нет вовсе.

**Что сознательно НЕ изменилось:** анонимная сессия «настоящим аккаунтом» не считается — гость
ходит по продукту через дверь `?as=guest`, а голый адрес по-прежнему отдаёт dev-пользователя. От
этого зависят существующие стражи, и менять им землю под ногами без причины нельзя.

**Проверено:** `verify-bug84` **58/0**, `verify-bug87` **60/0**, `verify-plan08` 17/0 (`--quick`),
`verify-ideas18` зелёный — правка двери никого не задела.

**Мутация:** вернул безусловный `signInDev()` → новая проверка личности покраснела
(«показано: dev@ndim.space, ожидалось: newbie-…@test.dev»). До правки продукта такой мутации не
существовало вовсе: краснеть было нечему.

## 🔴 Худшая находка: страж `verify-bugs08` был красным ДАВНО и молча

Его не гоняли месяцами, и он сгнил в трёх местах разом:

| Что | Почему это плохо |
|---|---|
| **`check(имя, true)`** — три проверки зелёные ПО НАПИСАНИЮ (после `waitForURL`/`waitFor`) | «Доказательством» служило то, что ожидание не бросило исключение. Сломайся продукт — прогон падает НЕОБРАБОТАННЫМ исключением, и итог «провалов: N» не печатается вовсе |
| **Ширина шапки/панели** требовала ровно 390 и 800px | `scrollbar-gutter: stable` (`bugs/59`, решение владельца) резервирует ~15px ещё с июля: «во всю ширину» это 375 и 785. Страж краснел на ИСПРАВНОМ продукте — сравнивать надо с шириной РАСКЛАДКИ (`document.body.clientWidth`) |
| **Селектор кнопки** «Сохранить результаты» | Кнопка называется «Сохранить мои результаты» с `bugs/84` (В4=А, две двери). Прогон падал исключением на середине |
| **Ожидание почты** в «Меню» по `.card` | `.card` есть в пререндеренном «Манифесте» и находится раньше данных аккаунта: первая редакция моей же проверки читала пустоту. Ждать надо ИМЕННО почту |

Все четыре исправлены; страж — **ВСЁ ЗЕЛЁНОЕ**.

## Чего НЕ делать

- **Не лечить вакуумную проверку внутри стража**, если её вакуумной сделало удобство стенда:
  подкручивание проверки оставит корень на месте, и следующая проверка того же класса родится
  такой же.
- **Не писать `check(имя, true)`.** Если утверждение доказывается ожиданием — сравни результат
  ожидания, а не факт его завершения.
- **Не сравнивать геометрию с шириной вьюпорта** — только с шириной раскладки (`bugs/59`).
- **Не считать анонимную сессию настоящим аккаунтом** в ветке стенда: на «голый адрес = dev@»
  опираются `verify-ideas18`, `verify-plan08`, `verify-ptr` и другие.
