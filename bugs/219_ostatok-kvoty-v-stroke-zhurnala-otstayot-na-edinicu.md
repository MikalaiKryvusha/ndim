# Баг NEW — остаток квоты в строке журнала отстаёт на единицу: прибор печатает 1 там, где Яндекс отдаёт 0

> **Создан:** 2026-08-29, смена 9, dev-3 · **Родитель:** `bugs/203` (инцидент Яндекса), первая
> машинная подача переобхода · **Статус:** 🔧 ФИКС И ЕГО ЮНИТ **В СТВОЛЕ**; ЖИВОЙ ПРИЁМКИ НЕ БЫЛО —
> DONE не ставится (сверено 2026-08-30, dev-1) · **Исходящее:** строка журнала `bugs/203` за 2026-08-29 несёт СВЕРЕННОЕ число, а не
> печатное — расхождение названо там же

## Симптом

Первый настоящий прогон машинной подачи (`node tools/yandex-recrawl.mjs --apply …`, 2026-08-29)
завершился и напечатал в готовой строке для журнала:

```
✅ ПОДАЧА ЗАВЕРШЕНА: принято 150 · пропущено 0 · отказов 0
   остаток очереди 1051 · остаток квоты 1

СТРОКА ДЛЯ bugs/203 (скопировать в журнал подач):
- **2026-08-29** — отправлено **150** · остаток очереди **1051** · остаток квоты 1
```

Повторный опрос Вебмастера тем же прибором сразу после прогона (сухой, ничего не шлёт) дал:

```
квота:      суточная 150 · остаток 0
к отправке: 0 (ограничитель — квота исчерпана)
```

**Остаток квоты 1 против остатка квоты 0.** Разница на единицу, и в ту сторону, что читается как
«ещё один адрес можно послать», когда послать нельзя.

## Чего этот баг НЕ означает — и это важнее самого бага

⚠️ **Адрес НЕ потерян, подача исправна.** Сходится всё, что имеет цену:

| Что | Число | Чем подтверждено |
|---|---|---|
| принято прибором | 150 | 150 ответов с кодом 202 (`outcome: accepted`) |
| израсходовано квоты | 150 | `daily_quota` 150 − `quota_remainder` 0 = 150, живой опрос ПОСЛЕ |
| строк в журнале | 150 | `recrawl-sent.txt`, дубликатов 0 |
| остаток очереди | 1051 | 1201 − 150, посчитано прибором из файлов |

Портится **только отчётное число остатка квоты**. Поэтому баг заведён как дефект отчёта, а не как
дефект подачи, и порция уже подана — переигрывать нечего.

## Причина — прочитана в коде, не угадана

`tools/yandex-recrawl.mjs` ведёт `quotaLeft` так:

```js
let quotaLeft = quotaRemainder;                 // взято ДО цикла, из GET /recrawl/quota
…
if (result.outcome === 'accepted') {
    accepted += 1;
    if (result.quotaRemainder !== null) quotaLeft = result.quotaRemainder;   // ← из ответа 202
}
```

То есть в строку журнала уезжает `quota_remainder` из **последнего 202-ответа**. Контракт API
(`researches/56` §3.5) обещает, что остаток приезжает с каждым ответом, — и он приезжает; но
Яндекс отдаёт его **ДО списания того самого вызова, который отвечает**. На 150-м адресе он честно
сообщает «до этой подачи оставался 1», прибор записывает это как «осталось 1», а осталось уже 0.

🔑 **Класс дефекта — тот же, что у `bugs/215`, только зеркальный.** Там снимок перезаписывал день
числом, которого не проверил; здесь строка журнала утверждает состояние ПОСЛЕ действия числом,
снятым ДО него. Общее одно: **отчёт о необратимом действии построен на попутном числе, а не на
замере.** Попутное число дешевле, и ровно поэтому его берут.

## Лечение — кандидат, не решение

Простейшее по Оккаму: после цикла спросить остаток ещё раз — `GET /recrawl/quota` — и печатать
замеренное, а не накопленное. Один лишний читающий вызов на весь прогон; читающий вызов квоты
разрешён явно (`lib/yandex-webmaster.mjs`: «это вопрос "сколько можно", а не действие»).

Поле `quota_remainder` из 202-ответов при этом стоит НЕ выбрасывать, а оставить для остановки на
лету, — но в журнал оно уезжать перестанет.

⚠️ **Юнит обязателен, и он именно на форму строки, а не на сеть:** `ledgerLine()` — чистая функция
в `tools/lib/yandex-recrawl-core.mjs`, и её вход должен прийти от замера. Правка без юнита была бы
«фиксом в кредит» (класс, названный на смене 8).

## Приёмка

Следующий прогон `--apply` печатает остаток квоты, совпадающий с тем, что отдаёт немедленный
сухой прогон после него. Сегодняшнее расхождение 1/0 — эталонный случай для проверки.

## 🔧 СВЕРКА 2026-08-30 (dev-1, смена 14) — ФИКС НАЙДЕН В СТВОЛЕ, НО БАГ НЕ ЗАКРЫТ

Шапка говорила «ФИКС НЕ НАЧАТ». Это неправда с некоторого дня: **лечение написано, и написано
ровно то, которое этот документ предлагал кандидатом.**

```bash
git grep -n "settleQuotaLeft" main -- tools/lib/yandex-recrawl-core.mjs tools/yandex-recrawl.mjs
node --test tools/yandex-recrawl.test.mjs      # 43/43
```

· `settleQuotaLeft()` — `tools/lib/yandex-recrawl-core.mjs:110`, чистая функция;
· зовётся в `tools/yandex-recrawl.mjs` ПОСЛЕ цикла, поверх свежего `GET /recrawl/quota`, и её
  значение уезжает и в консоль, и в `ledgerLine()` — то есть попутное число в журнал больше не идёт;
· замер не приехал → число НАЗЫВАЕТСЯ попутным (`settled.measured === false` печатает предупреждение),
  а не выдаётся за замер;
· юнит требуемого рода есть и он на ФОРМУ, а не на сеть — включая ловушку `measured || fallback`,
  которая выбросила бы валидный ноль: `assert.equal(settleQuotaLeft({ measured: 0, fromLastResponse: 7 }).value, 0)`.

### ⛔ ПОЧЕМУ ЭТО ВСЁ РАВНО НЕ `DONE`

🔑 **Разница между этим багом и тремя закрытыми сегодня — в предмете наблюдения, а не в
