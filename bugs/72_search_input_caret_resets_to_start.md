# Bug 72 — Поиск измерений: каретка в поле сбрасывается в начало, текст вводится задом наперёд

**Статус:** 🔬 ВОСПРОИЗВЕДЁН на стенде, причина НЕ найдена — нужен отдельный заход
(кандидат в `/bug-research`) · **Заведён:** 2026-07-28 агентом, попутно при работе над
`ideas/20` · **Кто чинит:** агент сам (решения владельца не требует)

## Симптом

В поле поиска на «Измерениях» посимвольный ввод даёт **перевёрнутую строку**: человек
печатает «Кошки» — в поле оказывается «икшоК». Каждая следующая буква вставляется в
позицию 0, потому что каретка после каждой буквы возвращается в начало.

Последствие для человека прямое: поиск по набранному тексту ничего не находит.

## Криминалистика (снято 2026-07-28, стенд `npm run stand`, Playwright/Chromium)

**Воспроизводимость: 5 из 5** при посимвольном вводе с задержкой 60 мс.

Трасса события `input` (каждая строка — одно нажатие):

```
{"value":"К","caret":0,"sameNode":true,"focused":true}
{"value":"оК","caret":0,"sameNode":true,"focused":true}
{"value":"шоК","caret":0,"sameNode":true,"focused":true}
```

`caret: 0` уже ПОСЛЕ вставки первой буквы — то есть каретка не «уезжает потом», а не
продвигается вовсе.

## Двери 1 и 3 ЗАКРЫТЫ — замер 2026-07-29 `[TESTED: 2026-07-29 · node tools/probe-bug72.mjs на стенде, дев :5173 и прод-сборка :4173]`

```bash
npm run stand                                   # эмуляторы + сид + дев на :5173
npx vite preview --port 4173                    # ТА ЖЕ сборка, что едет в бой
PROBE_BASE=http://localhost:5173 node tools/probe-bug72.mjs
PROBE_BASE=http://localhost:4173 node tools/probe-bug72.mjs
```

Сравнение возможно потому, что `isStand()` (`src/lib/firebase.ts:46`) определяет стенд **по
hostname `localhost`**, а не по режиму сборки: продакшен-сборка на preview идёт в те же эмуляторы
и так же сама входит пользователем стенда. То есть отличается ровно одно — dev против прод-сборки.

| Проверка | vite dev :5173 | прод-сборка :4173 |
|---|---|---|
| ввод по буквам, клавиатурные события | **«икшоК»** ❌ | **«икшоК»** ❌ |
| ввод по буквам, `insertText` в обход клавиатуры | **«икшоК»** ❌ | **«икшоК»** ❌ |
| контроль: голый `<input>` на ЭТОЙ ЖЕ странице | «Кошки» ✅ | «Кошки» ✅ |
| `direction` / `unicode-bidi` / `writing-mode` по всем 8 предкам | всё `ltr` / `normal` | всё `ltr` / `normal` |

### Что это даёт

1. ✅ **Дверь 1 закрыта — это НЕ артефакт `vite dev` / HMR.** Дефект живёт на той же сборке, что
   едет в бой, побуквенно одинаково. Главный вопрос документа снят: чинить придётся по-настоящему.
2. ✅ **Дверь 3 закрыта** — направление текста ни при чём: ни один из 8 предков не задаёт `rtl`
   или нестандартный `unicode-bidi`. Последний оставшийся класс причин исключён наблюдением.
3. ✅ **Дверь 2 закрыта наполовину, и это самое ценное.** Два РАЗНЫХ пути ввода (клавиатурные
   события и `insertText`, который их обходит, — так работают вставка и IME) дают один и тот же
   реверс. Значит дело не в способе ввода.
4. 🔥 **Новая улика, которой в документе не было: голый `<input>`, вставленный в DOM ЭТОЙ ЖЕ
   страницы, печатается верно.** Прошлый контрольный опыт делался на `about:blank` и доказывал
   только исправность инструмента. Теперь исключены ВСЯ страница целиком: глобальные слушатели,
   стили документа, шрифты, тема, роутер. Виноват **сам компонент поля поиска**, а не окружение.

### Что осталось (следующие двери, сузились)

1. **Разметка поля осмотрена (`+page.svelte:1017-1024`) и оказалась ОБЫКНОВЕННОЙ:**
   `<input class="search" type="search" enterkeyhint="search" bind:value={search}>` внутри
   `<form onsubmit={submitSearch}>`, плюс `bind:this`. Ни `oninput`, ни одностороннего
   `value={…}`, ни `{#key}`. Значит подозреваемых осталось двое: **кто ещё пишет в переменную
   `search`** (искать присваивания и `$effect`, её задевающие) и **сама пара
   `bind:value` + `type="search"` в Svelte 5**. Прошлые опыты снимали присваивания
   `value` через подмену сеттера ПРОТОТИПА — а Svelte 5 может писать значение иначе (свойство на
   самом элементе, атрибут, `defaultValue`); подмену стоит повторить на САМОМ элементе, а не на
   прототипе.
2. **Живая клавиатура человека** (CDP-порт 9222, память `browse-live-1x-in-owner-browser`) —
   осталась непроверенной; после п. 4 выше её приоритет упал, но опровергнуть «оба синтетических
   пути врут одинаково» она всё ещё может.
