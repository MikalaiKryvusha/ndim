# Bug 72 — Поиск измерений: каретка в поле сбрасывается в начало, текст вводится задом наперёд

**Статус:** 🔬 ВОСПРОИЗВЕДЁН на стенде, причина НЕ найдена — нужен отдельный заход
(кандидат в `/bug-research`) · **Заведён:** 2026-07-28 агентом, попутно при работе над
`ideas/20` · **Кто чинит:** агент сам (решения владельца не требует)

## Симптом

В поле поиска на «Измерениях» посимвольный ввод даёт **перевёрнутую строку**: человек
печатает «Кошки» — в поле оказывается «икшоК». Каждая следующая буква вставляется в
позицию 0, потому что каретка после каждой буквы возвращается в начало.

Последствие для человека прямое: поиск по набранному тексту ничего не находит.

## Криминалистика (снято 2026-07-28, стенд `npm run stand`, Playwright/Chromium)

**Воспроизводимость: 5 из 5** при посимвольном вводе с задержкой 60 мс.

Что уже проверено и ОТВЕРГНУТО как причина:

| Новый `$effect` сброса запроса | эффект временно убран, 3 прогона | ❌ не влияет (и с ним 3 из 3 чисто в другой оснастке) |

Трасса события `input` (каждая строка — одно нажатие):

```
{"value":"К","caret":0,"sameNode":true,"focused":true}
{"value":"оК","caret":0,"sameNode":true,"focused":true}
{"value":"шоК","caret":0,"sameNode":true,"focused":true}
```

`caret: 0` уже ПОСЛЕ вставки первой буквы — то есть каретка не «уезжает потом», а не
продвигается вовсе.

## Что осталось непроверенным (следующие двери)

1. **Бой.** На `ndimspace.app` опыт невозможен без входа: гостю поле поиска не отдаётся.
   Проверить под логином владельца или на собранном приложении с доступом к базе —
   **первый вопрос: боевой это дефект или артефакт dev-режима (vite dev / HMR)**.
2. **Живой человек vs синтетический ввод.** Playwright вводит символы через CDP
   `Input.insertText`. Проверить настоящей клавиатурой в живом Chrome (CDP-порт 9222,
   память `browse-live-1x-in-owner-browser`) — совпадает ли поведение.
3. **Свойство самого поля.** Снять computed `direction` / `unicode-bidi` у `input.search`
   и её предков: единственный класс причин, оставшийся неисключённым.

Дефект существует независимо от работы над явным вводом (доказано прогоном на HEAD), а

отправку страж делает через `fill()`.
