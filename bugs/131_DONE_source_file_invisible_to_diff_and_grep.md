# Баг 131 — сырой байт NUL в исходнике делает файл невидимым для diff и grep

> **Заведён:** 2026-08-15 · **Нашёл:** агент (попытка вычитать собственный фикс `bugs/130`) ·
> **Статус:** ✅ ПОЧИНЕН 2026-08-15, доказан эталоном хешей + прогоном стража ·
> **Серьёзность:** правки прибора, судящего сохранность данных людей, структурно невычитываемы ·
> **Родитель:** `bugs/130`

## Симптом

```
$ git diff --stat tools/migrate/db-fingerprint.mjs
 tools/migrate/db-fingerprint.mjs | Bin 15356 -> 17381 bytes

$ grep -n "GOOGLE_APPLICATION_CREDENTIALS" tools/migrate/db-fingerprint.mjs
Binary file tools/migrate/db-fingerprint.mjs matches
```

Файл — обычный `.mjs` на UTF-8, без BOM. Но и git, и ripgrep считают его **бинарным**: дифф не
показывается никогда, содержимое не грепается никогда.

## Как нашёлся

Не поиском. Я починил `bugs/130` и пошёл вычитать собственный дифф перед коммитом — по правилу
гигиены «`git diff --stat` перед КАЖДЫМ коммитом». Диффа не оказалось.

🔑 **И это же — ответ на вопрос, почему `bugs/130` прожил незамеченным.** Прибор писался, правился
и принимался в файле, который **нельзя было ни продиффить, ни грепнуть**. Ревью этого инструмента
было структурно невозможным, а не пропущенным по невнимательности.

## Корневая причина

В `canonical()` пять шаблонных строк несут **сырой байт `U+0000`** как метку типа:

```js
if (typeof value.toMillis === 'function') return `<NUL>ts:${value.toMillis()}`;
```

Замысел здравый: префикс, который не может совпасть с настоящим строковым значением, — иначе
документ со строкой `"ts:123"` дал бы тот же хеш, что отметка времени. Ошибка не в идее, а в
**написании**: метка вписана сырым байтом вместо escape-последовательности. И git, и grep объявляют
файл бинарным по первому же NUL — это их штатное правило определения двоичных данных, а не сбой.

## Фикс

Пять сырых NUL → escape `\u0000`. **Строка в рантайме та же**, поэтому ни один уже снятый отпечаток
не обесценился:

```
строки идентичны : true
хеш escape       : 3fbbd03b0909e86f
хеш сырого NUL   : 3fbbd03b0909e86f
```

Правка сделана файловым инструментом (канон «текст едет через файлы»), длина файла выросла ровно на
`5 × 5 = 25` байт — сходится с числом замен.

**Проверка наблюдением:** страж `tools/migrate/verify-fingerprint.mjs` после правки — **6/0**;
`grep` теперь показывает все пять строк; git отдаёт текстовый дифф.

## TWINS

`TWINS: искал сырые управляющие байты (NUL и C0 вне \t\n\r) во ВСЕХ 990 отслеживаемых текстовых
файлах репозитория скриптом — найден 1: сам `db-fingerprint.mjs`. Других мест нет.`

То есть это единичный случай, а не класс. Отдельного стража не завожу сознательно: цена — ещё один
прогон в каждом ритуале ради дефекта, встретившегося один раз за 990 файлов; дешёвая проверка
записана строкой в этом документе и повторяется одной командой:

```bash
node -e "const{execSync}=require('child_process'),fs=require('fs');let n=0;
for(const f of execSync('git ls-files',{encoding:'utf8'}).split('\n').filter(Boolean)){
 if(/\.(png|jpg|ico|woff2?|ttf|pdf|zip|gz|bundle|keystore)$/i.test(f))continue;
 const b=fs.readFileSync(f);for(const c of b)if(c===0||(c>0&&c<9)||(c>13&&c<32)){console.log(f);n++;break}}
console.log('файлов с управляющими байтами:',n)"
```

## Решения, принятые без владельца

- **Оставлена сама идея NUL-префикса.** Она верна: разделяет метку типа и данные надёжнее любого
  печатного префикса. Менялось только написание.
- **Страж не заводится.** Один случай на 990 файлов — Оккам: команда в документе дешевле прогона
  в ритуале. Если класс повторится, решение пересматривается.
