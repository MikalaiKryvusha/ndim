# Bug 50 — Поиск измерений ищет только то, что уже подгружено в браузер

**Статус:** 🔴 OPEN ·
**Источник:** слово владельца, чат 2026-07-26 (дословно):

> «сломался поиск измерений. В старом НДим я вводил название измерения - и оно находило
> его среди всех измерений пространства. Сейчас не находит, словно оно ищет только в том
> скоупе, который подгружен в браузере - это неприемлемо. Есть dims_list - по ним можно
> искать что угодно»

## Симптом

На `/dims` человек вводит название измерения, которое **точно есть** в Пространстве, —
экран отвечает «Ничего не найдено». Находятся только те измерения, чьи карточки уже
показаны на экране: первые ~12 из ленты «Все» плюс уже раскрытые карточки вкладки
«Мой NDim ID». Чем меньше человек пролистал — тем меньше ищется. Поиск по каталогу из
5111 измерений фактически не существует.

Диагноз владельца — точный: ищется ровно «тот скоуп, который подгружен в браузере».

## Воспроизведение (детерминированное)

1. Открыть `/dims` вошедшим человеком, **не прокручивая ленту**.
2. Взять любое измерение, которого нет в первых 12 карточках (например, из хвоста
   каталога — его id виден в `dims/dims_list`).
3. Ввести его название в строку поиска.
4. **Ожидаемо (канон 1.x):** карточка измерения показана.
   **Фактически:** «Ничего не найдено».
5. Контрольная проверка: прокрутить ленту до этой карточки, затем ввести тот же запрос —
   измерение находится. Это и доказывает, что фильтруется загруженное, а не каталог.

## Причина (найдена в коде, не гипотеза)

[src/routes/dims/+page.svelte:317-331](src/routes/dims/+page.svelte#L317-L331):

```ts
if (search.trim() !== '') {
  // Ищем среди уже загруженных карточек (обеих вкладок) — каталог целиком не читаем.
  const ids = new Set(searchIndex(data.index, search));
  const pool = new Map<string, DimCard>();
  for (const card of shown) pool.set(card.id, card);
  for (const [id, card] of mineCards) pool.set(id, card);
  return [...pool.values()].filter((card) => ids.has(card.id));
}
```

`searchIndex` (`src/lib/model/feed.ts:86`) отрабатывает **правильно**: он ищет по
`dims/dims_list`, то есть по всем 5111 измерениям, и возвращает найденные id. Но
результат используется лишь как **фильтр** по `pool` — карточкам, уже лежащим в памяти
вкладки. Найденное, но не загруженное, молча выпадает: id есть, карточки нет, показывать
нечего.

Ошибка допущена под флагом экономии запросов (комментарий в строке 322). Экономия понята
неверно: **1.x за найденными карточками ходил в базу** — просто не за всем каталогом, а
за ≤20 найденными документами. Дорого читать 5111 документов; читать 20 по точному
попаданию — это и есть канон.

Побочно: ветка «Ничего не найдено» ([+page.svelte:522](src/routes/dims/+page.svelte#L522))
делает утверждение о **каталоге**, имея данные только о загруженном срезе, — витрина врёт
(канон EXP-0033: у витрины нет права на «что-нибудь»).

## Канон 1.x (снят с живого кода, `ndim_old/public/scripts/app.js`)

`doSearchDims()` (строки 9131–9230) — ровно та схема, которой у нас нет:

1. **Поиск по локальному `all_dims_list`** (= документ `dims/dims_list`, весь каталог) —
   функция `searchInJson` (9026).
2. **Ограничение 20 результатов** + тост: «По Вашему запросу найдено очень много
   измерений. Будут показаны только первые 20 совпадений. Пожалуйста, уточните Ваш запрос
   для более точного поиска.» / «Too many dimensions were found by your query…».
3. **Затем догрузка найденных из базы**: `getDoc(doc(db, "dims", ndim_id))` по каждому
   найденному id, снапшот кладётся в `dims_cache_map`, из него рисуется обычная карточка.
4. **Лоадер на время поиска** (`search_page_content_loader`).
5. Пусто → тост «Ничего не найдено 😔» / «Nothing found 😔».

Кроме того, 1.x сортировал выдачу **по релевантности**: `lengthDiff` = |длина названия −
длина запроса|, по возрастанию — точное короткое совпадение выше длинного (9039–9047).

И нормализовал строку — `normalizeStringForSearch` (9052–9077), обе стороны сравнения:

- римские цифры I…XV → арабские;
- нижний регистр;
- **«ё» → «е»**;
- дефис/тире между символами → пробел; дефис с пробелами вокруг — удаляется;
- всё, кроме букв, цифр и пробелов, — удаляется (кавычки, точки, скобки);
- схлопывание пробелов.

Наш `searchIndex` не делает ничего из этого: сырое `.toLowerCase().includes()` по
склейке `ru + ' ' + en`. Значит, помимо главного дефекта, **не находятся**: «звездные
войны» → «Звёздные войны», «человек паук» → «Человек-паук», «алхимик» → «„Алхимик“»
с кавычками, «Рокки 4» → «Рокки IV». Для каталога, который люди набивали руками, это
не мелочь.

Дополнительно: склейка `ru + ' ' + en` даёт ложные совпадения на стыке языков (запрос,
попадающий на хвост русского имени и начало английского). Мелочь, но чинится тем же
проходом — сравнивать имена по отдельности.

## План фикса

**Ядро (`src/lib/model/feed.ts`) — чистые функции, покрываются юнит-тестами:**

- [ ] `normalizeForSearch(input)` — перенос правил 1.x дословно (римские цифры, регистр,
      ё→е, дефисы, только буквы/цифры/пробелы, схлопывание).
- [ ] `searchIndex` переписать: нормализовать запрос и **каждое имя отдельно** (ru и en),
      сортировать по `lengthDiff`, вернуть **все** попадания (обрезание — задача экрана,
      чтобы функция оставалась честной и тестируемой).
- [ ] Константа `SEARCH_RESULT_LIMIT = 20` — канон 1.x.

**Экран (`src/routes/dims/+page.svelte`):**

- [ ] Поиск больше **не фильтрует `pool`**, а строит собственный список: id из
      `searchIndex` → `loadDimCards(первые 20)` → карточки (кеш `dims.ts` уже есть, второй
      раз то же измерение не читается).
- [ ] Debounce ввода (~250 мс), чтобы посимвольный ввод не гнал запросы: в 1.x поиск
      запускался по кнопке-лупе и Enter, у нас — по мере ввода, и без задержки это те же
      деньги, ради которых всё и затевалось.
- [ ] Лоадер `Loading.svelte` на время догрузки (карточка загрузки уже каноничная, bugs/21).
- [ ] «Ничего не найдено» показывать **только когда поиск действительно завершён и пуст**,
      а не «пока не загрузилось».
- [ ] Больше 20 совпадений — сказать честно («показаны первые 20, уточните запрос»),
      текст из 1.x.

**Чего НЕ делать:** не читать коллекцию `dims` целиком, не заводить внешний поисковый
сервис, не трогать сервер синхронизации, правила и модель данных. Цена фикса — ≤20 чтений
на поиск, и только когда человек ищет.

## План проверки

- [ ] Юнит на `normalizeForSearch`: ё/е, дефис-тире, кавычки и скобки, римские цифры,
      регистр, схлопывание пробелов.
- [ ] Юнит на `searchIndex`: находит измерение, которого **нет** среди загруженных
      (главный страж этого бага); порядок по релевантности; пустой запрос → пусто;
      нет ложного совпадения на стыке ru/en.
- [ ] e2e на стенде: открыть `/dims` **без прокрутки**, искать измерение из хвоста
      каталога → карточка на экране. Мутация: вернуть фильтр по `pool` — тест обязан
      упасть.
- [ ] QA-прогон живым Chrome (ворота сдачи, `plans/06`): обе темы × 390/1440, скриншоты,
      консоль чиста; проверить счётчик чтений (в консоли — что ищем ≤20 документов, а не
      каталог).
