# Bug NEW — потерянный домен `ndim.app` три месяца оставался разрешённым для входа в наш проект

**Статус:** ✅ ИСПРАВЛЕНО В БОЮ 2026-09-19 23:3x +03:00 — домен удалён из разрешённых (консоль Firebase, в браузере
владельца по его слову «*сделай оба через браузер*»), сверено чтением настройки через API; страж класса —
`tools/verify-auth-domains.mjs` · **Тяжесть:** S1 — брешь в авторизации: чужой домен мог входить в наш проект от
имени наших людей · **Заведён:** 2026-09-19 23:5x +03:00, агент — найден при чтении настроек входа gcloud по заказу
владельца «*проверить авторизацию через Google*» ·
**Родня:** `bugs/NEW_google_signin_newcomer_lands_on_load_error.md` (та же работа) · журнал решений `MASTER_PLAN.md`,
2026-07-11 (домен `ndim.app` перехвачен 2026-06-20 владельцем `ndim.me`)

## Симптом

В разрешённых домены входа Firebase Auth проекта `ndim-space` стоял `ndim.app` — домен, который проект ПОТЕРЯЛ
20 июня 2026 и который принадлежит другому человеку. Замер 2026-09-19 22:1x, чтение через gcloud:

```
authorizedDomains: localhost, ndim-space.firebaseapp.com, ndim-space.web.app, 127.0.0.1,
                   ndim.app, ndim-space--landing-3jvzs4cd.web.app, ndimspace.app, www.ndimspace.app
```

## Чем это опасно

Разрешённый домен — это список тех адресов, со страниц которых Firebase соглашается вести вход в наш проект.
Владелец `ndim.app` мог поставить у себя страницу с нашим публичным веб-конфигом (он по устройству лежит в бандле
у каждого) и кнопкой «Войти через Google». Человек увидел бы настоящий экран Google, вошёл бы — и токен нашего
проекта на ЕГО аккаунт оказался бы у чужой страницы, то есть чужой код получил бы право читать и писать данные
этого человека в нашей базе. Плюс само имя `ndim.app` выглядит для человека нашим.

⚠️ Названо честно: следов такой страницы никто не искал и не замерял — опасность в возможности, а не в замеренном
случае.

## Причина

Домен попал в список, когда `ndim.app` был нашим (весна 2026). Потеря домена (20 июня) была записана в журнал
решений мастер-плана, но список разрешённых доменов Firebase этим никто не пересмотрел: он живёт в консоли, а не
в репозитории, и ни один прибор проекта его не читал. Класс: **настройка вне кода, о которой никто не спрашивает.**

## Фикс

1. Домен удалён из списка в консоли Firebase (диалог «Remove authorized domain… Domain ndim.app» → Remove).
2. Сверено независимо, чтением `admin/v2/projects/ndim-space/config` через gcloud: `ndim.app` в списке нет, остальные
   семь доменов на месте.
3. Страж класса — `node tools/verify-auth-domains.mjs`: читает список у Firebase и краснеет на КАЖДОМ домене, которого
   нет в объявленном составе (состав — в самом приборе, с причиной у каждой строки).

TWINS: искал «настройка контура вне кода, которую никто не читает» — разрешённые домены входа (этот баг) · адреса
возврата клиента OAuth (проверяются тем же прибором нечем: публичного API нет, поэтому в приборе объявлена ГРАНИЦА) ·
шаблоны писем Firebase (`EXP-0042`, наследие 1.x — не проверяется ничем) · настройки проекта PostHog (запись сессии
включена на стороне проекта, шапка `analytics.ts`). Прочие в этой работе не искались.

## Решения, принятые без владельца

- `[AI]` Состав разрешённых доменов в страже объявлен по факту сегодняшнего списка (семь строк) с причиной у каждой;
  канал предпросмотра `ndim-space--landing-3jvzs4cd.web.app` оставлен как наш, хотя он мёртв, — удаление мёртвых
  строк не входило в заказ и требует его слова.
