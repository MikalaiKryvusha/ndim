## Симптом

`npm run build` падает на последнем шаге пререндера:

```
Error: The following routes were marked as prerenderable, but were not prerendered
because they were not found while crawling your app:
  - /[lang=lang]/catalog/[kind=kind]/[page=page]
See the `handleUnseenRoutes` option …
```

Код выхода ненулевой, каталога `build/` не остаётся вовсе.

## Кого это останавливает — цена, а не неудобство

- **`npm run build`** в любом рабочем каталоге без боевого доступа к каталогу измерений;
- **`npm run e2e`** — стенд Playwright собирает боевой артефакт и гоняет браузер по нему;
- **стражи, судящие по собранному сайту**: `verify-product-vocabulary`, `verify-catalog-hubs`,
  `verify-test-pages`, `verify-tier2-prefetch` — все начинаются с «нет каталога build/»;
- **ворота Smoke двери выката** (`npm run deploy`) — они гоняют набор по собранному артефакту.

🔴 **Это бьёт по КАЖДОЙ роли команды `NDIM_WORKTREE_DEV_TEAM`.** Пять рабочих каталогов ролей —
свежие worktree, и ни в одном из них полного каталога нет и быть не может: он не в git.

## Криминалистика

### Замер 1 — дефект НЕ внесён работой по `plans/67`

Сборка прогнана на коммите `99c4ad7` (дерево ДО первой строки моей работы) — падает **тем же
сообщением и на том же маршруте**. То есть это состояние, унаследованное рабочим каталогом, а не
регрессия фазы 5.

### Замер 2 — причина

Каталог измерений в проекте живёт двумя файлами (`src/lib/content/dims-source.ts`, шапка):

| Файл | Что в нём | В git? |
|---|---|---|
| `dims-build.json` | весь каталог, 5111 записей, 16,7 МБ | ❌ `.gitignore:67`, пишется `tools/fetch-dims-slice.mjs --all` шагом выката |
| `dims-slice.json` | **50 записей**, запасной срез | ✅ лежит в git |

Замер файлов рабочего каталога: `dims-build.json` — **нет**; `dims-slice.json` — есть, 174 822
байта. Значит сборка идёт на срезе, и это штатный, задуманный режим.

**На срезе из 50 записей ни один вид каталога не набирает второй страницы.** Это не рассуждение:
сборка печатает причину сама, своими же строками — вот они, из живого прогона 2026-08-21:

```
[catalog] индекс каталога: 50 объектов · источник: запасной срез
[catalog] 14 первых страниц хабов · источник: запасной срез
[catalog] 0 страниц хабов со второй и дальше
[dimension] 100 страниц (50 × 2 яз.) · источник: запасной срез
```

**Ноль** — это и есть дефект в одном числе. `entries()` маршрута `[page=page]` возвращает пустой
список (`hubPageEntries()` считает страницы по данным), маршрут не пререндерится ни разу — и
SvelteKit объявляет его «не найденным при обходе». Ограничитель `src/params/page.ts` при этом
исправен: он и должен отвергать `…/1`, к падению он отношения не имеет.

Для сравнения, числа полного каталога названы в шапке самого маршрута: Movie 46 · Video game 20 ·
TV Series 6 · Novel 3 · Practice 3 · Music Artist 3 · Book 1 = **82 адреса на язык**. То есть на
боевых данных маршрут обходится и падения нет — дефект живёт ровно в запасном режиме.

### Что изменилось, если раньше собиралось

Сам маршрут и запасной срез существуют давно, а сборка на срезе задумана рабочей — это сказано в
шапке `dims-source.ts` дословно: «*без него `npm run build` из чистого клона падал бы, а собирать
сайт должно быть можно без сети и без боевого доступа*». Значит поведение сменил не наш код:
`handleUnseenRoutes` — настройка пререндера SvelteKit (в проекте **2.69.2**), и непререндеренный
маршрут в ней стал **ошибкой**, а не предупреждением, как было раньше. `vite.config.ts` секции
`prerender` не содержит вовсе, то есть живёт на умолчании.

⚠️ Граница этого разбора, названная честно: замера «на какой именно версии Kit поведение
сменилось» я не делал — вывод сделан из того, что настройка существует, а конфиг её не задаёт.
Прежде чем опираться на срок, его надо снять с релизных заметок Kit.

## Направление починки (не выполнено — решение за Менеджером)

Настройка `handleUnseenRoutes` принимает функцию, а не только режим. Отсюда лечение, которое НЕ
слепит ворота:

- на **срезе** (`DIMS_SOURCE === 'запасной срез'`) непререндеренный маршрут пагинации каталога —
  ожидаемое следствие малых данных, ему место в предупреждении;
- на **полном каталоге** тот же маршрут, оставшийся необойдённым, — настоящая авария, и она
  обязана ронять сборку.

⛔ **Чего делать НЕ надо:** ставить `handleUnseenRoutes: 'warn'` глобально. Это гасит сигнал и на
боевой сборке — то есть меняет падающую сборку на молча неполный выкат, а такой обмен этот проект
уже оплачивал (`bugs/124`: смесь сборок уехала в бой при зелёных приборах).

## Обход, которым можно жить прямо сейчас

Живой Chrome поднимается `npm run dev` / `npm run stand` — они не пререндерят и падению не
подвержены. Не работают только пути, которым нужен собранный артефакт (список выше).

## ✅ Починка и её доказательство

**Что сделано** (`827a363`, `vite.config.ts`, рука Менеджера): `handleUnseenRoutes` задан
ФУНКЦИЕЙ, а не режимом. Прощается **ровно один** маршрут и **только** когда каталог собран из
запасного среза — имя маршрута вынесено в константу `CATALOG_PAGED_ROUTE`. Любой другой
необойдённый маршрут роняет сборку и на срезе тоже; на полном каталоге падение сохраняется для
всех, включая этот. ⛔ Глобальный `'warn'`, названный выше запрещённым, не применён.

### Две ветки доказательства — их нельзя проверить в одной среде

Дефект живёт в РЕЖИМЕ СРЕЗА, а исправность строгого режима — в среде с полным каталогом. Одна
машина обе стороны показать не может, поэтому доказательство разделено по рукам:

| Ветка | Кто | Среда | Наблюдение |
|---|---|---|---|
| полный каталог по-прежнему строг | Менеджер | главная копия, полный `dims-build.json` | сборка `main` зелёная, 1 м 14 с |
| срез больше не роняет сборку | dev-1 | worktree `ndim_dev1`, только `dims-slice.json` | код выхода **0**, предупреждение вместо падения |

Наблюдение ветки среза, дословно из прогона 2026-08-21:

```
[catalog] индекс каталога: 50 объектов · источник: запасной срез
[catalog] 14 первых страниц хабов · источник: запасной срез
[dimension] 100 страниц (50 × 2 яз.) · источник: запасной срез

[prerender] запасной срез каталога: маршрут /[lang=lang]/catalog/[kind=kind]/[page=page]
не набрал ни одной страницы — это норма среза; на полном каталоге он обязателен (bugs/160)
  ✔ done
```

### Мутация — прощение АДРЕСНО, а не «сойдёт что угодно»

Зелёная сборка сама по себе не отличает «прощаем один маршрут» от «прощаем всё». Адресат объявлен
ДО прогона: подменяем значение `CATALOG_PAGED_ROUTE` (дописываем знак) — настоящий необойдённый
маршрут перестаёт совпадать с прощаемым, и сборка **обязана упасть, назвав его имя**.

| Состояние конфига | Код выхода | Маршрут назван в выводе |
|---|---|---|
| мутант (константа подменена) | **1** | ✅ да — `/[lang=lang]/catalog/[kind=kind]/[page=page]` |
| возврат к `827a363` | **0** | предупреждение вместо падения |

Контроль возврата: `git diff --stat vite.config.ts` пуст — конфиг восстановлен побайтово.

⚠️ **Оговорка о собственном приборе, чтобы число не соврало следующему.** Первый заход мутации
напечатал «предупреждения нет» на ИСПРАВНОМ конфиге — и это был дефект ЗАМЕРА, а не продукта:
`execSync` при успехе возвращает только stdout, а предупреждение идёт в **stderr**. Перепрогон с
обоими потоками: stdout — 0 совпадений, stderr — 1. Судить о сборке по одному потоку нельзя.
