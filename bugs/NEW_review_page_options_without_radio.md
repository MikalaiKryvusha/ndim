# Bug NEW — страница вычитки подняла вопрос с вариантами без кнопок выбора: варианты абзацами «**А) …**» не узнаются

**Статус:** 🔴 OPEN · **Тяжесть:** S1 — пострадало доверие владельца, ответ пришлось писать текстом ·
**Когда/контекст:** 2026-09-25 23:18, интервью №098 «Тест на совместимость для двоих»; нашёл владелец.

## Симптом

Слово владельца на странице, дословно: «*Г, но какого хуя ты опять радиокнопки забыл сделать? у тебя опять баг у этом
контуре блядском!*».

В интервью №098 оба вопроса несли варианты «А)…Д)», но страница показала только поле текста — кнопок выбора не было.
Владелец ответил текстом.

## Корневая причина

`tools/lib/review-core.mjs` узнаёт вариант только по пункту СПИСКА (`OPTION_START`: строка «`- **А) …**`»). Агент
(Менеджер) записал варианты абзацами «`**А) V1 …**`» — так же, как в №097. Разбор вернул 0 вариантов, и страница честно
нарисовала поле текста. Предполётная проверка (`preflight`, `lintSelfContained`) вопрос с вариантами-абзацами НЕ отказала —
класс «страница выглядит целой, а выбора нет» прошёл до владельца.

## План фикса (dev-1, контур вычитки)

1. Разбор узнаёт обе формы варианта: пункт списка и абзац, открывающийся «**А)**»…«**Е)**» (и латиницей A–F).
2. Предполётная проверка: вопрос, в котором есть строки вида «**Б)**» / «Б)» в начале, а разбор вернул меньше двух
   вариантов, — страница НЕ поднимается, код 1, называет вопрос и строку.
3. Юниты на обе формы (включая №097 и №098 как живые фикстуры) + мутант «абзац не узнаётся» → красный адресно.
4. Живой проход: страница №098 (копия в тестовой папке) показывает кнопки у В1 и В2.

## Решения, принятые без владельца

`[AI]` Лечение — в разборе (обе формы) И в предполётной проверке; одна из двух половин оставила бы класс открытым.
