# Bug 76 — «Как меня видят»: оверлей без записи в истории, системная «Назад» уносит из приложения

**Статус:** ✅ DONE — закрыт 2026-07-29 · шапка догнала 2026-08-29 · **Когда/контекст:** 2026-07-29, волна владельца `ideas/21` (п. 3)

## Симптом

Слово владельца дословно:

> с «Как меня видят» навигация работает некорректно, закрыло приложение, словно родительский
> Профиль не был в стеке навигации.

## Замер / воспроизведение

**Живого замера по этому пункту нет.** Прибор волны (`tools/probe-ideas21.mjs`,
`test-results/ideas21/report.txt`) п. 3 не снимал — в отчёте измерены пп. 1, 2, 4, 5, 6, 7, 9, 10,
11, 14, 15, 16. Чисел вставлять неоткуда: **[NOT-TESTED]**.

Что доказано **кодом** (это сильнее, чем «иногда»): обработчика «Назад» у окна нет вовсе, значит
системная «Назад» **никогда** его не закроет — ни разу, ни при каких условиях.

Что кодом доказать **нельзя** — глубину стека в момент инцидента: она зависит от того, как владелец
вошёл. Отсюда два исхода одного дефекта (формулировка сверки разведки):

- в стеке есть предыдущая запись приложения → «Назад» уводит на **другой маршрут**, компонент
  профиля размонтируется и окно исчезает вместе с ним; для человека это «выкинуло с экрана», а не
  «закрылось окно»;
- записи нет (свежая вкладка, вход по ссылке из письма) → закрывается **контейнер** — ровно то, что
  владелец и описал словами «закрыло приложение».

Воспроизведение, которое надо снять до кода (владелец — QA, канон `plans/06`):

1. открыть `/profile` в свежей вкладке;
2. снять `history.length` — ожидание **1**;
3. нажать «Как меня видят»;
4. нажать системную «Назад» (Android) или краевой жест.

Ожидание владельца: возврат в профиль. Ожидание по коду: уход из приложения.

## Причина

«Как меня видят» — **не маршрут и не модалка платформы**, а булев флаг компонента профиля.

- `src/routes/profile/+page.svelte:62` — `let seeMeOpen = $state(false);`
- `src/routes/profile/+page.svelte:980` — открытие:
  `<button type="button" class="btn ghost" onclick={() => (seeMeOpen = true)}>{t.seeMe[lang]}</button>`
- `src/routes/profile/+page.svelte:64-72` — блокировка прокрутки подложки
  (`document.body.style.overflow = 'hidden'` с восстановлением в теле `$effect`), то есть ведёт себя
  как лайтбокс;
- `src/routes/profile/+page.svelte:1062` — `{#if seeMeOpen && data}`, слой рисуется полноэкранным:
- `src/routes/profile/+page.svelte:1122-1125` —
  `.seeme { position: fixed; inset: 0; z-index: 70; background: var(--bg); overflow-y: auto; }`
  со своей прибитой шапкой (`.seeme-head`, 1126-1130) и стрелкой «Назад» (`.back-btn`, 1065);
- закрывается ровно двумя способами: `onclick={() => (seeMeOpen = false)}` (`:1065`) и Escape
  (`:779` — `if (seeMeOpen && event.key === 'Escape') seeMeOpen = false;`).

**Ни одной записи в историю при открытии не делается.** По всему `src/` `history.pushState` не
встречается ни разу, обработчика `popstate` нет ни одного; единственный вызов истории —
`history.replaceState(null, '', '/profile')` в почтовом флоу (`src/routes/profile/+page.svelte:232`),
а `replaceState` записей **не добавляет** (проверено грепом по `src/` при сверке разведки и повторно
при заведении этого документа — ноль вхождений `pushState`/`popstate`).

Отсюда наблюдение владельца: экран **выглядит** дочерней страницей (полный экран, заголовок, стрелка
«Назад» — тот же вид, что у настоящих дочерних маршрутов `src/routes/menu/{about,author,donate,
manifesto,share,support,[slug]}`), но **в стеке навигации его нет**. Системная «Назад» и краевой жест
обращаются к истории браузера, а не к оверлею.

### Ворота намерения (`BUG_FIXING_FRAMEWORK`, шаг 4)

`INTENT:` код закрывает окно только экранной кнопкой и Escape (`:1065`, `:779`); владелец ожидает,
что системная «Назад» вернёт в профиль; **спецификация лежит в самом коде** —
`src/routes/profile/+page.svelte:58-59`:

> `// Вкладки «Личное/Видимость» упразднены (слово владельца 2026-07-27): предпросмотр`
> `// аудиторий — не таба, а ОКНО за кнопкой «Как меня видят»; «Назад» возвращает в профиль.`

То есть Y (владелец) = Z (спецификация) ≠ X (код): требование «"Назад" возвращает в профиль» было
записано, но реализовано только как **экранная** кнопка. Это не спор о замысле — это недоделка.

### Близнецы (класс, а не экземпляр)

Тот же приём — полноэкранный слой без записи в историю — в проекте не единичен:

- `src/lib/ui/Avatar.svelte:38` — `let open = $state(false);` (лайтбокс фото);
- `src/lib/ui/ChapterNav.svelte:135-137` — `.backdrop { position: fixed; inset: 0; z-index: 40; }`
  (панель глав с подложкой).

`TWINS: искал полноэкранный слой, управляемый локальным булевым состоянием без записи в историю —
найдено 2 других места: src/lib/ui/Avatar.svelte:38, src/lib/ui/ChapterNav.svelte:135-137.`
Чинить их или оставить — решается вместе с выбором варианта ниже, но заявлять «класс закрыт», починив
одно окно, нельзя.

## Что делать

Дальше — две формы лечения. Разведка рекомендует **А**; **Б** добавлен при заведении документа как
штатная альтернатива, потому что он один закрывает и близнецов.

**Вариант А — настоящий дочерний маршрут** (рекомендация разведки, Оккам). Сделать окно маршрутом по
образцу `src/routes/menu/*`, которые в продукте уже есть и выглядят ровно так же. Тогда «Назад»
работает бесплатно, без своего `pushState`/`popstate`. Цена: состояние (`data`, выбранная аудитория
`previewKey`) должно пережить переход, а вид экрана — не измениться ни на пиксель. Побочный эффект:
у окна появляется собственный URL — оно становится открываемым по ссылке и переживает перезагрузку.

роутер — свой `popstate` не пишется. API в установленной версии есть: `@sveltejs/kit` **2.69.2**,
экспорт `pushState` подтверждён в `node_modules/@sveltejs/kit/src/runtime/app/navigation.js`.
Гипотеза уровня API: **на этом коде не проверено** — ни одного применения в проекте нет.

3. Затем пройти близнецов по списку `TWINS` — починить или явно перечислить в этом документе с

4. Экранную кнопку «Назад» (`:1065`) и Escape (`:779`) **оставить** — они не конфликтуют с системной,

5. Проверить снятие блокировки прокрутки: при закрытии через историю `$effect` (`:64-72`) обязан

## Чего НЕ делать

- **Не вешать глобальный перехват `popstate` на всё приложение ради одного окна** (прямая заметка
  разведки): при трёх похожих оверлеях это быстро превратится в самодельный роутер поверх штатного.
- Не закрывать окно по эвристикам (`blur`, `visibilitychange`, таймеры) — это лечение симптома, а
  причина в отсутствии записи в истории.
- Не менять **вид** окна: он утверждён (слово владельца 2026-07-27), меняется только его место в
  стеке навигации.
- Не считать пункт закрытым по одному экрану: без прохода по `TWINS` класс останется открытым, и
  владелец сам скажет «и с фото то же самое».

## Нужно ли решение владельца

**Нет.** Разведка: `АВТОНОМИЯ: АГЕНТ_САМ` — «макетов это не требует: вид экрана уже утверждён и не
меняется, меняется только его место в стеке навигации».

Единственный триггер, при котором нужно спросить: если выбранный вариант **меняет то, что владелец
видит** — например, вариант А выводит в адресную строку новый URL и делает окно открываемым по
ссылке. Если при работе окажется, что это заметно на лице приложения, — короткий вопрос владельцу
(`/interview`), а не самостоятельное решение. Толкование «"не таба, а ОКНО" — про способ входа
(кнопка → окно), а не про URL» — это **чтение агента, у владельца не проверено**.

## ✅ STATUS: DONE (2026-07-29)

**Фикс — вариант Б: штатное неглубокое маршрутирование SvelteKit** (`pushState` из
`$app/navigation` + `page.state` из `$app/state`). Адрес не меняется, окно остаётся окном, но
получает запись в истории, и «Назад» обслуживает **настоящий роутер** — своего `popstate` в
приложении не появилось.

Почему Б, а не А (отдельный маршрут): Б **масштабируется на класс**. Полноэкранных слоёв в
проекте три (это окно, лайтбокс фото `Avatar.svelte`, панель глав `ChapterNav.svelte`), и для
лайтбокса собственный URL выглядел бы натянуто. Заодно не пришлось тащить состояние (`data`,
`previewKey`) через переход и не изменился ни один пиксель утверждённого вида.

**Точка закрытия теперь ОДНА** — `history.back()`. Экранная стрелка и Escape зовут её же:
состояние окна выведено из истории (`$derived(page.state.seeMe === true)`), а не хранится
отдельным флагом, поэтому разъехаться с историей ему физически негде.

Тип признака объявлен в `src/app.d.ts` → `App.PageState` с инструкцией для будущих слоёв:
добавлять признак сюда, а не заводить свой перехват `popstate`.

## Решения, принятые без владельца

1. **Вариант Б вместо А** — по критерию «что масштабируется на класс» (обоснование выше).
   Побочный эффект варианта А, от которого отказались: у окна появился бы собственный URL, то
   есть оно стало бы открываемым по ссылке и переживало бы перезагрузку. Это изменение продукта,
   а не починка дефекта, — поэтому не делалось.

   осталась бы «лишняя» запись, и «Назад» пришлось бы жать дважды.
3. **Близнецы не тронуты** (см. выше) — решение оставлено владельцу.
