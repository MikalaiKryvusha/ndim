# Bug 164 — два доказанных прибора разметки не гоняет ни один страж и не называет ни один реестр

**Статус:** ✅ ЗАКРЫТ 2026-08-22
**Версия/сборка:** ветка `ndim_dev3` @ 507cfd4 · найдено на `main` @ 3662525 (прибор пришёл с ним)
**Когда/контекст:** 2026-08-22, суд QA над сдачей dev-3 (`plans/58` шаг 1, починка слияния тегов)

> Находка не блокирует сдачу dev-3 — она о ПРОЦЕССЕ, а не о его коде. Заведена отдельно, чтобы
> вердикт не смешивал две разные вещи.

## Симптом

У прибора разметки тегов жизненного цикла есть два доказанных проверочных артефакта:

| Артефакт | Что доказывает | Чем запускается СЕГОДНЯ |
|---|---|---|
| `tools/tag-dims-approval.test.mjs` | **29** юнитов чистого ядра (классификация, слияние тегов по осям, указатель кандидатов, предохранитель утечки) | ничем |
| `tools/verify-tag-dims-approval.mjs` | стендовый страж на живой базе: отказ · сухой прогон · мутация порога · запись · идемпотентность | ничем |

Ни один npm-скрипт их не зовёт, ни одна строка реестра их не называет. Работа сделана, доказана
мутациями — и невидима для любого будущего прогона.

## Воспроизведение (детерминированное)

```bash
node -e "const s=require('./package.json').scripts; for(const k in s) console.log(k, s[k])" | grep tag-dims
# пусто

grep -n "tag-dims-approval" AGENT_GUIDE.md STATUS.md
# пусто — ни в таблице «Испытательный стенд», ни в «Стражи, которые надо держать зелёными»
```

## Криминалистика

- `npm test` = `node --test "src/**/*.test.ts"` — покрывает **только** `src/`. Файлов `tools/*.test.mjs`
  в проекте ровно **один**, и он вне охвата.
- Для сравнения, чужие семьи тестов охвачены: `sync-server/*.test.mjs` (14 файлов) → `npm run test:sync`;
  `tests/rules/*.test.ts` (2 файла) → `npm run test:rules`.
- Команда запуска юнитов существует, но живёт **комментарием в шапке самого прибора**
  (`tools/tag-dims-approval.mjs:35`) — то есть держится на памяти того, кто откроет файл.
- Оба артефакта прогнаны мной вручную при суде и **зелёные**: юниты 29/29, стендовый страж все
  проверки. Дефект не в них, а в том, что их запуск не механизирован.

## Корневая причина

Прибор родился вне трёх существующих семей тестов (`src/` · `sync-server/` · `tests/rules/`), и
для него не завели ни четвёртой семьи, ни строки реестра. Класс известен и уже оплачен проектом:
`EXP-0104` / `AGENT_GUIDE.md` → `verify-ideas24` — «*страж существовал с 31.07 и не был записан
никуда, то есть не запускался никем — самая дешёвая форма потери уже оплаченной работы*».

## Честная граница находки

**Это ОДИН случай, а не класс.** Замер: файлов `tools/*.test.mjs` в проекте ровно один, и это он.
Обобщать до «тесты приборов у нас не гоняются» оснований нет — обобщение было бы утверждением
о поиске, а не о мире (`EXP-0165`).

## План фикса

1. Охватить семью одним скриптом — `"test:tools": "node --test \"tools/*.test.mjs\""` в
   `package.json`. Дёшево, и новый прибор попадает под охват сам, без правки скрипта.
2. Строку в реестр «Испытательный стенд» (`AGENT_GUIDE.md`) на **оба** артефакта, с числами
   (29 юнитов · стендовый страж, 5 блоков) и пометкой, что стенд нужен только второму.
3. Строку в «Стражи, которые надо держать зелёными» (`STATUS.md`).
4. ⚠️ Порядок предпочтений канона (`AGENT_GUIDE.md` → «Журнал опыта»): первое — убрать ловушку
   (шаг 1, охват скриптом), и только потом запись. Шаги 2–3 — реестр для человека, они шаг 1 не
   заменяют.

## Чей это долг

Прибор пришёл в `main` до сдачи dev-3; его сдача семью лишь расширила (19 → 29 юнитов).
Владельца долга назначает Менеджер — это не блокер ни одной ветки.
