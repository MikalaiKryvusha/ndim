# Bug 92 — точка, у которой удалили все оценки, навсегда хранит старый топ в relations

**Статус:** 🔴 OPEN · **Когда/контекст:** найден 2026-07-31 аудитом Fable 5 после сессий слабых
моделей (ревизия кода + состязательная проверка) · **Серьёзность:** major

## Симптом

Человек крестиками удаляет ВСЕ свои оценки измерений. Ожидаемое: экран «Связи» и виджет
«Мои связи» честно пустеют — топ считался из оценок, оценок больше нет. Наблюдаемое бы:
он **бессрочно** видит полный старый топ, посчитанный из уже не существующих оценок, причём
виджет-сводка показывает эти устаревшие похожести со **свежим** `lastSync` — выглядит как
только что пересчитанная истина. У остальных людей он из топов исчезает ближайшим ночным
полным проходом, а его собственный документ `relations/{uid}` не лечится никогда — пока он
не поставит хотя бы одну новую оценку.

## Воспроизведение (детерминированное)

1. Иметь точку с оценками и непустым топом в `relations/{uid}` (экран «Связи» показывает людей).
2. Крестиками удалить все свои оценки; последняя тоже уходит через `removeRating` — стража
   «нельзя удалить последнюю» нет ни в данных, ни в UI (`dims/+page.svelte:644`, меню
   «Убрать мою оценку»). Каждое удаление ставит `dirty`.
3. Дождаться цикла сервера синхронизации: `dirty` снят, `lastSync` свежий.
4. Открыть «Связи»: полный старый топ на месте. Ночной полный проход — то же самое.

## Криминалистика

Сердце дефекта — `calculator/index.mjs:560`, цикл пересчёта топов:

```js
for (const [uid, point] of pointsCache) {
  if (Object.keys(point.ratings).length === 0) continue;
  ...
  const fingerprint = topFingerprint(top);
  const changed = writtenTops.get(uid) !== fingerprint;
  if (changed && (fullPass || readySet.has(uid))) {
    writes.push((batch) =>
      batch.set(db.doc(`relations/${uid}`), { computedAt: now, version: RELATIONS_VERSION, top }),
```

`continue` выбрасывает опустевшую точку **до** diff и записи. А следом (строки 581–585) `dirty`
снимается со всех готовых точек **безусловно**:

```js
for (const uid of readyUids) {
  const firstSeen = pointsCache.get(uid)?.firstSeen ?? now;
  writes.push((batch) =>
    batch.set(db.doc(`points/${uid}`), { dirty: false, lastSync: now, firstSeen }, { merge: true }),
```

Линии опровержения, закрытые состязательной проверкой:

- **«Последнюю оценку удалить нельзя»** — можно: `removeRating` (`src/lib/data/profile.ts:273`)
  удаляет любую оценку без проверки остатка, `dirty` ставится.
- **«Точка не дочитается»** — дочитается: она в `ready`, дельта-чтение кладёт её в кэш с
  `ratings = {}` (`calculator/index.mjs:534`), после чего строка 560 её пропускает.
- **«Ночной проход вылечит»** — нет: полный проход исполняет тот же цикл с тем же `continue`,
  а `delete` для `relations` есть только у осиротевших гостей (строка 406).
- **«Экран сам заметит»** — нет: `fetchRelations` (`src/lib/data/relations.ts:79–110`) читает
  `relations/{uid}` и рисует топ без сверки с собственными оценками человека.
- **«Это чей-то осознанный выбор»** — упоминаний сценария в `bugs/`, `ideas/`, `interviews/`,
  `plans/` нет; тесты (`full_pass.test.mjs`) покрывают обратный случай «пустой топ → честный»,
  но не «честный → должен опустеть».

Асимметрия реальна: у остальных `computeRelation` с пустыми `ratings` даёт `null`
(`similarity.ts:115`), поэтому из чужих топов опустевший исчезает.

## Корневая причина

Регрессия инварианта после рефакторинга экономии. В первой версии сервера синхронизации
(коммит `0154051`) `continue` был безобиден: все топы переписывались каждый цикл, и опустевшая
точка просто получила бы пустую запись следующей записью соседа. Рефакторинг `ba7a9fd`
(`ideas/14`, запись только изменившимся по fingerprint) сделал запись условной, а ветку
«точка опустела» никто не перевёл на новый контракт: она перестала доходить до diff вовсе.
Это не решение владельца, а дыра, открывшаяся сменой стратегии записи.

## План фикса

Опустевшая точка обязана проходить через diff и запись, как все остальные:

1. Убрать `continue` для пустых `ratings`; считать такой точке **честный пустой топ**
   (`top: []`) и дать diff-записи затереть устаревший `relations/{uid}`. [NOT-TESTED]
2. Альтернатива — удалять документ целиком: `fetchRelations` при отсутствии документа
   возвращает `null` (строка 82), что похоже на штатное «связей ещё нет», но перед выбором
   этого варианта сверить, как `null` рисует экран «Связи» и виджет-сводка. [NOT-TESTED]
3. Проверить побочные ветки цикла: `checked`, `similarities` и статистика Пространства не
   должны испортиться от точки с нулём оценок (гипотеза: пустой топ ничего не добавит,
   но это надо увидеть, а не предположить). [NOT-TESTED]
4. Снятие `dirty` оставить только **после** записи топа этой точки.
5. Тест в calc-сюиту: «точка с топом → все оценки удалены → relations пуст/удалён» —
   обратный к существующему «пустой → честный» в `full_pass.test.mjs`. [NOT-TESTED]
