# Bug 71 — `kaif:check` краснеет на переводах строк Windows, а не на содержании

**Статус:** ✅ ПОЧИНЕН 2026-07-28 (проверен мутацией) ·
**Когда/контекст:** найден при финальной регрессии сессии багов 68/69/70

## Симптом

`npm run kaif:check` — **обязательный гейт перед каждым push** (`AGENT_GUIDE` → «Git-процесс»)
— выдал 15 ошибок:

```
✖ .claude/skills/resume/SKILL.md: нет YAML-фронтматтера
✖ .claude/skills/pause/SKILL.md: нет YAML-фронтматтера
… ещё 13
```

Фронтматтер был на месте у всех пятнадцати. Первые байты файла: `2D 2D 2D 0D 0A` — то есть
`---\r\n`.

## Причина

`tools/03-kaif-verify.mjs` ищет фронтматтер регекспом `/^---\n([\s\S]*?)\n---/` — требует LF.
Проект живёт на Windows с `core.autocrlf`, git отдаёт рабочую копию с CRLF, и `---\r\n` под
регексп не подходит. Проверка падала на ПЕРЕВОДАХ СТРОК, а не на содержании файла.

Почему всплыло только сейчас: 2026-07-28 гейт был зелёным сразу после обновления KAIF 1.6 → 2.0
(файлы лежали такими, какими их написала машинерия обновления, — с LF), и покраснел позже, когда
git «потрогал» их при чекауте. Красными оказались ровно те 15 скиллов, которые переписало
обновление.

**Это не регрессия текущей сессии:** ни один из трёх коммитов (bugs/70, 69, 68) не касается
`.claude/skills/` и `tools/03-kaif-verify.mjs`.

## Фикс

`tools/03-kaif-verify.mjs`: чтение нормализует переводы строк —
`readFileSync(p, 'utf8').replace(/\r\n/g, '\n')`. Одна строка, лечит весь класс: тому же
регекспному риску подвержены и другие проверки файла.

## Проверка

`npm run kaif:check` — зелёный (28 скиллов, 1 ожидаемое предупреждение про `.private/`).
**Мутация — гейт по-прежнему стережёт содержимое, а не молчит:** `name: resume` → `name: resumeX`
даёт `✖ name «resumeX» ≠ имени папки «resume»`; после возврата файла снова зелено. Попутно
выяснилось, что гейт ловит и BOM (файл, записанный PowerShell с `-Encoding utf8`, не проходит
проверку фронтматтера) — это правильное поведение, оставлено как есть.

## Почему это важнее одной строки кода

Гейт, обязательный перед push, начал блокировать работу по причине, не имеющей отношения к его
предмету. Следующая сессия, увидев 15 «ошибок» в файлах, которых она не трогала, с высокой
вероятностью решит пропустить гейт — а стережёт он утечку секретов и ПДн (`bugs/01`, `bugs/03`,
утечка здесь уже случалась однажды). Гейт, который агент учится обходить, хуже отсутствующего.

## Решения, принятые без владельца

- **Чинил инструмент, а не файлы.** Альтернатива — привести 15 скиллов к LF (`.gitattributes`)
  — лечит симптом на одной машине и оставляет мину для любого Windows-чекаута.
- **Находка отправлена вверх по течению:** дописана в `researches/16` (отчёт для агента-разработчика
  KAIF) как находка **K6** с рекомендацией поискать тот же класс во всех регекспах машинерии,
  привязанных к `\n`.
