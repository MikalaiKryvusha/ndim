# Bug 88 — тёплая лента «Измерений» выбрасывается на каждом возврате: `$state` сравнивается с сырым объектом

**Статус:** ✅ ПОЧИНЕНО 2026-07-30 · **Когда/контекст:** найден 2026-07-30 стражем `plans/08`
(память вида, ответ владельца В11=А), пока мерили, почему прокрутку некуда возвращать ·
**Тип:** дефект реактивности, тихо отменявший половину `ideas/18`

## Симптом

Замер на стенде (`test-results/plan08/probe-warm-feed3.mjs`): лента «Измерений» долистана до
**44 карточек** (весь неоценённый каталог стенда), уход на «Пространство», возврат:

```
трасса возврата (кадр → карточек): [{"f":0,"n":0},{"f":1,"n":44},{"f":15,"n":12}]
```

То есть лента **восстанавливается правильно** (44 карточки на первом же кадре — это работает
`ideas/18`), а через 14 кадров **выбрасывается** и добирается заново одной порцией — 12.
Заодно пересобирается очередь, а она случайная (`Math.random` в `src/lib/model/feed.ts`), —
то есть порядок карточек под руками у человека **меняется**.

Это ровно то, на что жаловался владелец в п. 1 волны `ideas/21` («загружаются по-новой»), но
причина **другая, чем считалось**: `bugs/74` часть А винит инвалидацию кэша своей же оценкой, а
здесь лента терялась **без единой оценки**, при живом и честном кэше.

## Причина — доказана инструментом, а не рассуждением

`src/routes/dims/+page.svelte`, `loadScreen()`:

```ts
const rebuilt = screen !== data;   // ← ВСЕГДА true
```

Временный лог в продукте на стенде напечатал:

```
[DBG08] loadScreen: rebuilt= true  warm= true  warmShown= 44  shown= 44
        | screen===warm: true | screen===$snapshot(data): false | dataIsProxy: true
```

Читается так:

- `screen === warm` — **истинно**: кэш отдал ТОТ ЖЕ объект, свежесть работает как задумано;
- `dataIsProxy` — **истинно**: `let data = $state<DimsScreenData|null>(warm ?? null)` в Svelte 5
  заворачивает объект в **глубокий прокси**;
- значит `screen !== data` — сырой объект против своего же прокси — **истинно всегда**, и ветка
  «экран пересобран заново» (`queue = [...screen.feed]; shown = []`) исполняется на КАЖДОМ
  возврате.

Тонкость, из-за которой дефект прожил незамеченным: `$state.snapshot(data)` тоже не равен
`screen` — снимок это глубокая копия. Тождество прокси не восстанавливается никаким сравнением
«снаружи», поэтому и лечится не сравнение, а тип состояния.

**Почему страж `ideas/18` был зелёным.** `tools/verify-ideas18.mjs` считает две вещи: чтения
документов и карточку «Загрузка». Обе оставались правильными! Карточки 12-й порции уже лежат в
`cache` модуля `dims.ts`, поэтому пересборка стоила **0 чтений**, а `stand` был `'ready'` с
первого кадра, поэтому лоадера не было. Страж охранял ЦЕНУ захода и не охранял **длину ленты** —
её никто не мерил до `plans/08`.

## Лечение

`src/routes/dims/+page.svelte:91` — `$state` → **`$state.raw`**:

```ts
let data = $state.raw<DimsScreenData | null>(warm ?? null);
```

`$state.raw` держит ССЫЛКУ: реактивность даёт присваивание (`data = screen`), а тождество
остаётся тождеством. Данные экрана неизменяемы по объявлению (все поля `readonly`, в коде нет ни
одной правки на месте — проверено грепом), поэтому глубокая реактивность им не нужна вовсе; на
индексе из 5111 измерений она была ещё и дорогой.

**Проверено на стенде после фикса:** `[{"f":0,"n":44}]` — 44 карточки с нулевого кадра, ни одного
кадра со сброшенной лентой.

## Радиус класса — где ещё то же самое

Сравнение `$state`-значения с сырым объектом по тождеству — ловушка на весь проект. Обход
2026-07-30:

| Место | Есть ли дефект |
|---|---|
| `src/routes/dims/+page.svelte` `data` | **был, починен** (`$state.raw`) |
| `src/routes/relations/+page.svelte:48` `data` | нет: тождество нигде не сравнивается (`data = loaded` без ветвления). Прокси здесь — только лишняя работа на 250 карточках |
| `src/routes/space/+page.svelte`, `/profile` | нет: сравнений по тождеству нет |

Правило на будущее (в `EXPERIENCE.md` как EXP-0088): **если значение состояния сравнивается по
тождеству с тем, что пришло извне (кэш, загрузчик, сеть), — это `$state.raw`, а не `$state`.**

## Проверка

Стражем `tools/verify-plan08.mjs`: проверка «содержимого после возврата не меньше»
(`было 44, стало 12` до фикса — она и вскрыла дефект). Отдельного стража не заводим: длина ленты
после возврата — часть приёмки памяти вида, и держать её в двух местах значило бы две правды.
