# Bug 65 — лайтбокс фото не накрывает полосу под скролбар (15px справа)

**Статус:** 🔬 ИССЛЕДОВАНО, не починено — нужен взгляд владельца на десктопе
**Версия/сборка:** 2.0 · **Когда/контекст:** 2026-07-27, найден QA-прогоном волны 11 при работе
над `ideas/17` (шапка V3-А); к самой шапке отношения не имеет — существовал до неё.

## Симптом

Полноэкранный просмотр фото (`.lightbox`, `position: fixed; inset: 0`, портал в `body`) накрывает
**раскладку**, а не всё окно: справа остаётся полоса шириной полосы прокрутки, где виден фон
страницы. Замер живым Chrome: вьюпорт 390×740 → оверлей **375×740**.

Высота верна, ширина меньше на 15px — ровно на `scrollbar-gutter: stable`, который был введён
`bugs/59` («скролбар двигает приложение в сторону»). То есть это **побочный эффект правильного
фикса**: с зарезервированной полосой прокрутки `inset: 0` физически не может накрыть её.

## Воспроизведение (детерминированное)

```bash
npm run stand
node tools/verify-batch4.mjs      # раздел «bugs/36 · лайтбокс фото на «Связях»»
```
Проверка «оверлей накрывает ВЕСЬ вьюпорт» краснела на 375 против 390. **Проверено на базе до
работы над шапкой (`git stash push src`) — провал тот же, значит дефект не новый.**

## Криминалистика

- `src/lib/ui/Avatar.svelte:127-140` — `.lightbox { position: fixed; inset: 0; }`
- `src/routes/+layout.svelte` — `:global(html) { scrollbar-gutter: stable; }` (bugs/59)
- замер: `boundingBox → {x:0, y:0, width:375, height:740}` при `viewportSize → 390×740`

## Насколько это дефект

- **На телефоне — почти наверняка нет:** там полосы прокрутки наложенные (overlay), гуттер не
  отнимает ширину.
- **На десктопе — видимая светлая полоска справа** при открытом фото в тёмной подложке. Это
  косметика, но именно того класса, который владелец ловит глазом.

## Гипотезы фикса (не применять без слова владельца)

1. `width: 100vw` вместо `inset: 0` по горизонтали — накроет и гуттер, но `100vw` на странице с
   полосой прокрутки даёт горизонтальный перелив: рискуем вернуть **bugs/59**. Проверять замером.
2. Скролл-лок лайтбокса (он уже есть) может убирать полосу прокрутки — тогда достаточно, чтобы на
   время просмотра гуттер не резервировался (`scrollbar-gutter: auto` на `html` под класс блокировки).
3. Ничего не делать и закрыть как «осознанно»: цена — светлая полоска 15px справа на десктопе.

## Решения, принятые без владельца

- **Страж в `tools/verify-batch4.mjs` приведён к правде, а не к желаемому:** он сравнивал ширину
  оверлея с шириной ВЬЮПОРТА, а фиксированный слой по построению накрывает РАСКЛАДКУ. Проверка
  теперь сверяет оверлей с шириной раскладки и ссылается на этот баг, чтобы находка не растворилась
  в зелёном прогоне.
