# Bug 74 — «Измерения» открываются холодными: кэш гасит своя же оценка и pull-to-refresh, прокрутка не хранится

**Статус:** 🔴 ОТКРЫТ · **Когда/контекст:** 2026-07-29, волна владельца `ideas/21` (п. 1)

## Симптом

Слово владельца дословно:

> при переключении на Измерения, они загружаются по-новой, не работает кеш и сохранение страницы
> на той позиции скрола, на какой её оставили при навигации.

*(в оригинале «Изменения» — опечатка, речь про экран «Измерения»)*

Внутри одного предложения — **две независимые поломки**: (А) экран перечитывается с нуля,
(Б) экран открывается сверху.

## Замер / воспроизведение

**Часть Б измерена живым браузером** (`tools/probe-ideas21.mjs`, стенд `http://localhost:5173`,
`test-results/ideas21/report.txt:21-30`):

| Экран | Ушёл с позиции | Вернулся на | Ждали |
|---|---|---|---|
| «Измерения» | 900 | **0** | 900 |
| «Связи» | 72 | **0** | 72 |
| «Пространство» | 900 | **0** | 900 |

То есть память прокрутки не теряется «иногда» — её нет вовсе, и не только на «Измерениях».
Консоль при этом чиста.

**Часть А живым замером НЕ снята** — прибор волны её не проверял. Она доказана по коду
(разведка `test-results/ideas21/recon.txt`, секция «=== ПУНКТ 1 ===», вердикт
`ПОДТВЕРЖДЁН_КОДОМ`). Воспроизведение для ручной проверки:

1. Открыть «Измерения», дождаться ленты, уйти на «Профиль», вернуться — экран тёплый (кэш работает).
2. Поставить **любую свою оценку** на «Измерениях», уйти на «Профиль», вернуться —
   карточка «Загрузка», лента пересобрана и перетасована заново.
3. Либо: потянуть pull-to-refresh **на любом из четырёх главных экранов** и перейти на
   «Измерения» — тот же холодный заход.

## Причина

### А) Кэш есть, но его гасят два штатных действия

**1. Ключи экрана лежат под чужим префиксом.** `src/lib/data/cache.ts:101` —
`dimsScreen: 'ratings:screen'`, `cache.ts:103` — `dimsShown: 'ratings:shown'`. Инвалидация
работает **по началу ключа**, `cache.ts:191`:

```ts
if (key === prefix || key.startsWith(prefix)) store.delete(key);
```

Поэтому `afterMyRatingChanged()` (`src/lib/data/profile.ts:227-231`, внутри `invalidate(KEYS.ratings)`
на строке 229) сносит **и мои оценки, и собранный экран**. Зовётся она из `saveRating`
(`profile.ts:208`) и `removeRating` (`profile.ts:218`), а «Измерения» используют именно её —
`src/lib/data/dims.ts:180`:

```ts
export { saveRating, removeRating } from './profile.ts';
```

вызов — `src/routes/dims/+page.svelte:508` (`await saveRating(uid, dimId, value)` внутри `commit()`).

Что происходит на следующем заходе (`src/routes/dims/+page.svelte:82-85`):

```ts
const warm = peekDimsScreen();
const warmShown = warm ? peekDimCards(peekShownFeed() ?? []) : [];
let stand = $state<…>(warm ? 'ready' : 'connecting');
```

`warm === undefined` → `stand = 'connecting'` → карточка «Загрузка»; `warmShown = []` → лента
пуста; `loadMyRatings` заново читает всю коллекцию (`dims.ts:87`,
`getDocs(collection(db(), 'points', uid, 'dims'))` — платно по документу), а `loadDimsScreen`
пересобирает ленту `buildUnratedFeed` (`dims.ts:142`), которая тасует через `Math.random`
(`src/lib/model/feed.ts:63-70`). Отсюда и ощущение «загрузилось по-новой»: не только спиннер,
но и **другой порядок карточек**.

**Усиление:** после оценки экран не перечитывается на месте — `commit()`
(`dims/+page.svelte:499-536`) правит только локальные `ratings` / `queue` / `shown` и `loadScreen`
не зовёт. Значит кэш остаётся пустым ровно до следующего захода.

**2. Pull-to-refresh гасит то же самое глобально.** `src/lib/data/refresh.svelte.ts:75-80` —
`invalidateAll()` сносит `relations` + `space` + `ratings` + `profile`, а перечитывает
`refreshNow` только **текущий** экран (`refresh.svelte.ts:97`, `await reload()`). Жест висит на
всех четырёх главных экранах: `dims/+page.svelte:992`, `profile/+page.svelte:792`,
`relations/+page.svelte:258`, `space/+page.svelte:351`. Потянул вниз на «Профиле» — «Измерения»
обречены на холодный заход.

**Поведение закреплено стражем:** `tools/verify-ideas18.mjs:280` —

```js
check('после МОЕЙ оценки «Измерения» перечитываются', backToDims.db > 0, `обращений: ${backToDims.db}`);
```

То есть сегодняшнее поведение — не случайность, а **действующий контракт** `ideas/18` и интервью
№005 В4 (`FRESH.mine` / `FRESH.server` = `Infinity`, `cache.ts:55-77`). См. «⛔ Ждёт владельца».

### Б) Позиции прокрутки между заходами на /dims нет вовсе

Единственная память — `src/routes/dims/+page.svelte:664`:

```ts
const tabScroll: Record<Tab, number> = { all: 0, mine: 0 };
```

Это обычная переменная **внутри компонента**: уход с маршрута её уничтожает. Плюс
`let tab = $state<Tab>('all')` (`dims/+page.svelte:92`) — возврат всегда открывает вкладку «Все».
Общая механика (снимок вида на навигации) разбирается в **`plans/08`** по п. 9 волны —
здесь её не дублируем.

### Оговорки сверки (перенесены из разведки честно)

- **СВЕРКА: подтверждено** — все строки на месте, цитаты из `cache.ts:101/103/191`,
  `profile.ts:208/227-231`, `refresh.svelte.ts:75-80/97`, `dims/+page.svelte:82/84/85/92/248-250/664`,
  `dims.ts:87/142/160-167/180`, `verify-ideas18.mjs:280` совпали дословно, включая номера строк.
- **СВЕРКА (неточность, вывод не меняет):** формулировка «сносит разом и список „докуда долистал“»
  верна лишь на миг. `$effect` на `dims/+page.svelte:248-250`
  (`if (stand === 'ready') rememberShownFeed(shown.map(...))`) перезапишет `ratings:shown` сразу же,
  как только `shown` изменится после оценки (`dims:534`). Но прочитан этот список всё равно не
  будет: `warmShown` игнорирует его при `warm === undefined` (`dims:84`). Итог тот же — холодный экран.
- **СВЕРКА (неточность):** «485 платных чтений» — число из данных владельца, **кодом не доказано**.
  Доказан механизм (`getDocs` коллекции, `dims.ts:87`), не объём. Реальную цену холодного захода
  никто не мерил — это **не проверено**.
- **СВЕРКА:** более простой причины не нашлось. Кэш не гасится ничем побочным: `own(uid)` чистит
  только при смене uid (`cache.ts:120-125`), таймеров уборки нет сознательно (`cache.ts:26-32`).

## Что делать

Часть А — **только после ответа владельца** (раздел ниже). Если ответ будет «разводим ключи»:

1. Увести `dimsScreen` и `dimsShown` из-под префикса `ratings` в `src/lib/data/cache.ts:99-108`
   (например `dims:screen` / `dims:shown`) — вместе с комментарием, который сегодня объясняет
   обратное («Под префиксом `ratings`: моя оценка делает его несвежим»).
2. Гасить экран прицельно там, где он **действительно** протух: смена uid, явный pull-to-refresh
   на самих «Измерениях», отмена оценки (пересборка очереди, `dims.ts:160-167`). Моя оценка меняет
   ленту ровно на одну карточку, и её `commit()` уже убирает локально сам
   (`dims/+page.svelte:531-534`).
3. Переписать страж `tools/verify-ideas18.mjs:277-281` под новый контракт **и** поправить
   `ideas/18` — иначе зелёный страж будет защищать отменённое решение.
4. Pull-to-refresh: сузить `invalidateAll()` до данных текущего экрана либо перечитывать всё,
   что погасили. Жест владельцем утверждён (интервью №006) — трогать сам жест нельзя, речь только
   о радиусе поражения. **Развилку выносим владельцу тем же вопросом.**

Часть Б — **не чинить здесь**. Она закрывается общей механикой памяти вида из `plans/08`
(п. 9 волны): снимок `scrollY` по маршруту на `beforeNavigate` / возврат на `afterNavigate`, плюс
вопрос, помнить ли вкладку «Все / Мой NDim ID». Этот баг закроется только когда обе части сойдутся.

## Проверка

Каким наблюдением судим, что починено:

1. **Часть А, оценка.** Открыть «Измерения», поставить оценку, уйти на «Профиль», вернуться:
   карточки «Загрузка» нет, `stand === 'ready'` с первого кадра, порядок оставшихся карточек тот же,
   что был до оценки, оценённая карточка из ленты ушла.
2. **Часть А, pull-to-refresh.** Потянуть вниз на «Профиле», перейти на «Измерения»: экран тёплый.
   Потянуть вниз **на самих «Измерениях»**: экран перечитывается (жест обязан работать —
   интервью №006).
3. **Часть Б.** Повторить замер прибора: уйти с «Измерений» с позиции 900 → вернуться на 900
   (сейчас 0, `report.txt:22-24`).
4. **Счётчик обращений к базе.** Прогон с тем же счётчиком, что в `tools/verify-ideas18.mjs`:
   после моей оценки возврат на «Измерения» даёт `db === 0` (сегодня страж требует `> 0` — строку
   придётся переписать вместе с контрактом).

**Чем доказать сам страж (мутация).** Новый `tools/verify-bug74.mjs` обязан быть прогнан на
сломанном коде и **упасть**:

- мутант 1: вернуть `dimsScreen` под префикс `ratings` в `cache.ts:101` → проверка 1 краснеет;
- мутант 2: вернуть `invalidate(KEYS.ratings)` в `invalidateAll()` → проверка 2 краснеет;
- мутант 3: снять восстановление прокрутки → проверка 3 краснеет.

Без падения на мутанте страж считается недоказанным (`TESTING_FRAMEWORK.md`).

## Чего НЕ делать

- **Не «чинить» кэш дописыванием значений руками.** `cache.ts:182-193` и `researches/17` §2.4
  прямо про это: помечаем и перечитываем, а не правим содержимое кэша на месте.
- **Не отключать pull-to-refresh ради тёплого старта** — жест утверждён владельцем в интервью №006.
  Речь только о радиусе инвалидации, не о самом жесте.
- **Не менять контракт `ideas/18` молча.** Зелёный `tools/verify-ideas18.mjs` сегодня защищает
  ровно текущее поведение; правка кода без правки `ideas/18` и стража даст либо красный страж,
  либо страж, охраняющий отменённое решение.
- **Не решать часть Б здесь.** Локальный костыль в `dims/+page.svelte` продублирует механику,
  которую `plans/08` заводит на все экраны сразу (у владельца п. 9 — «ни на одной странице»).
- **Не полагаться на число «485 чтений»** — оно из наблюдений владельца, кодом не подтверждено.
