## Вывод-вперёд

`tools/verify-probe-mark.mjs` следит, чтобы каждый браузерный прибор, способный дойти до живого
контура, метил свои сессии — иначе наши прогоны считаются людьми и пачкают воронку (`bugs/202`).

🔴 **Но прибор, у которого метку УБРАЛИ, не краснеет — он исчезает из корпуса.** Страж остаётся
зелёным, а число осмотренных молча уменьшается на единицу. Комментарий в коде обещает
обратное: «*Правило простое и не расширяет корпус: **опт-ин необратим**. Прибор, однажды взявший
помощник, судится на ПОЛНОТУ*». Опт-ин обратим удалением одной строки.

## Криминалистика — мутация и контроль, оба на живом дереве

Признак корпуса (`isLiveBrowserProbe`, строки 57–74):

```js
const drivesBrowser = /chromium\.launch\(/.test(source);
const reachesLive = /ndimspace\.app/.test(source) || /ndim-stage\.web\.app/.test(source) || /lib\/contours\.mjs/.test(source);
const knowsMark  = /lib\/probe-mark\.mjs/.test(source);
return drivesBrowser && (reachesLive || knowsMark);
```

Прибор без живого адреса В ТЕКСТЕ попадает в корпус **только через `knowsMark`**. Убрал метку —
`knowsMark` ложь, `reachesLive` ложь, прибор перестал быть «живым» и не судится вовсе.

| мутация (снят импорт `probe-mark`) | осмотрено | вердикт стража |
|---|---:|---|
| `smoke.mjs` (живого адреса в тексте НЕТ) | **15 → 14** | ✅ зелёный, код 0 — 🔴 **дефект** |
| `probe-test-pages-live.mjs` (живой адрес ЕСТЬ) — контроль | 15 | ❌ красный, прибор назван, код 1 ✅ |

Контроль обязателен и приведён намеренно: **для 12 приборов из 15 страж работает верно.**
Слепое пятно ровно у тех, кого держит только собственная метка.

⚠️ Контроль попадания снят по ПРЕДМЕТУ ЧТЕНИЯ, а не по факту правки файла (`EXP-0198`): перед
каждым прогоном печаталось, что видит сам признак стража (`/lib\/probe-mark\.mjs/.test(source)`)
— `true` до, `false` после.

## Радиус поражения — поимённо, признаком САМОГО стража

Замер моим зондом, повторяющим предикаты стража дословно (число сошлось с его собственным: 15):

| прибор | живой адрес в тексте | держится только меткой |
|---|---|---|
| **`smoke.mjs`** | НЕТ | 🔴 ДА |
| **`probe-bridge.mjs`** | НЕТ | 🔴 ДА |
| **`verify-funnel-v2.mjs`** | НЕТ | 🔴 ДА |
| остальные 12 | есть | — |

🔑 **Тяжесть определяется именно этими тремя, а не их числом.** `smoke.mjs` — тот самый прибор,
чьи прогоны и загрязнили воронку (`bugs/202`: «гостевые всплески совпадают с днями выкатов —
свои же смоуки»). `verify-funnel-v2.mjs` — приёмка самой воронки. То есть без охраны остались
ровно те, ради которых страж заведён.

## Почему зелёный тут особенно опасен

У воронки нет громких отказов: `track()` глотает ошибку намеренно. Страж заведён, чтобы поломка
не давала **тихий ноль**. Здесь он сам даёт тихий зелёный — то же самое свойство этажом выше.
Единственный видимый след — число «осмотрено 15», но его не с чем сравнить: ожидаемого значения
нигде нет, и «14» читается как норма.

⚠️ Контроль на ПОЛНУЮ слепоту у стража есть и работает (`judged === 0` → «признак сломан»).
Не защищено именно ЧАСТИЧНОЕ усыхание корпуса.

## Воспроизведение (детерминированное)

```bash
node tools/verify-probe-mark.mjs            # ✅ «осмотрено 15», код 0
# снять строку импорта probe-mark из tools/smoke.mjs, затем:
node tools/verify-probe-mark.mjs            # ✅ «осмотрено 14», код 0 ← дефект
# то же с tools/probe-test-pages-live.mjs:
node tools/verify-probe-mark.mjs            # ❌ красный, прибор назван, код 1 ← контроль
```

## Наблюдаемый критерий приёмки фикса

- [ ] Снятие метки с `smoke.mjs`, `probe-bridge.mjs` или `verify-funnel-v2.mjs` даёт **красный
      прогон с именем прибора**, а не молчаливое уменьшение счёта.
- [ ] Страж сравнивает число осмотренных с **объявленным ожиданием** (якорь в коде либо
      поимённый список опт-ина), и расхождение краснеет само.
- [ ] Контроль на месте: у прибора с живым адресом снятие метки по-прежнему краснеет (не
      сломать работающие 12, чиня 3).
- [ ] Доказано мутацией НА КАЖДОМ из трёх приборов, а не на одном.

## Гипотезы лечения (ранжированы)

1. **Дешёвая и точная.** Поимённый список опт-ина в самом страже — те три прибора, что живого
   адреса не держат, перечислены с причиной. Список маленький, закрытый и краснеющий: прибор из
   списка без метки — нарушение. Ровно та форма, которую страж УЖЕ применяет к себе (`SELF`).
2. **Механическая.** Считать «живым» и прибор, принимающий `--base`/`PROBE_BASE`: это и есть
   способ дойти до живого контура рукой, названный в комментарии самого стража как повод
   завести третью половину признака. Тогда корпус перестаёт зависеть от метки вовсе.
3. ⛔ **Чего делать НЕ надо:** расширять корпус до всех браузерных приборов. Автор отверг это
   осознанно и прав: прогон на `localhost` пишет в эмулятор, которого никто не читает.

## Решения, принятые без владельца

Одно: считать это дефектом, а не замечанием. Основание — свойство «опт-ин необратим» записано в
код как обоснование решения №5 сдачи («полнота держится машиной, а не списком»), и оно неверно;
решение остаётся правильным, но опирается на гарантию, которой нет.
