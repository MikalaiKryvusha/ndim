## Симптом

`node tools/week-number.mjs --week 2026-09-21` печатает «окно 2026-09-21 … 2026-09-28 (UTC)». Границы строятся строкой из
`Date.toISOString()` (`week-number.mjs:46–51`) и передаются в запрос как `toDateTime({from})` БЕЗ пояса (`:66–76`), а HogQL
читает строку без пояса в поясе ПРОЕКТА PostHog (+03:00). Фактическое окно — неделя по московскому времени, с понедельника
00:00 +03:00 (= воскресенье 21:00 UTC), а не по UTC, как напечатано.

## Криминалистика (замер 2026-09-25 10:12)

HogQL `SELECT toString(toTimeZone(toDateTime('2026-09-25 05:40:00'), 'UTC'))` → `2026-09-25 02:40:00`: строка без пояса
прочитана как +03:00. Тот же сдвиг поймал суд №2 в разовой сверке сессии (окно «UTC 05:40–07:00» оказалось 05:40–07:00 +03:00).

## Что неверно и что — нет

- **Неверна подпись** «(UTC)» в выводе прибора и в отчёте `qa/reports/2026-09-25_week-number.md`, если он её повторяет.
- **Числа, вероятно, те, что нужны владельцу:** неделя по его часам. Решение — какую неделю считать (по Москве или по UTC) —
  инженерное; лечение `[AI]`-предложение: передавать пояс явно (`toDateTime({from}, 'Europe/Moscow')`) и печатать «+03:00».

INTENT: код передаёт границы `toDateTime({from})` без пояса и печатает «(UTC)»; ожидание — окно названо тем поясом, в
котором считается; спецификация — документация PostHog: «*Date literals parse in your project's timezone, not UTC …
For an absolute instant, pass the timezone explicitly*» (posthog.com/docs/sql/expressions). Расходились подпись и запрос.

- `tools/week-number.mjs`: неделя — понедельник 00:00 +03:00; каждая граница `toDateTime({x}, 'Europe/Moscow')`,
  календарный день возврата `toDate(toTimeZone(…, 'Europe/Moscow'))`; подпись «… 00:00 +03:00 (Москва)». **Контроль
  пояса в каждом прогоне:** тот же запрос возвращает начало окна в UTC, прибор сравнивает МОМЕНТ со своим расчётом и
  краснеет «окно названо неверно». Неделя по умолчанию — по московскому календарю.
- `tools/lib/posthog.mjs` — лечение по форме для всех приборов: `toDateTime({параметр})` и `toDateTime('литерал')` без
  пояса отказываются ДО сети.

  прогоном Менеджера и вылечен сверкой моментов; фикстура юнита теперь — дословный живой ответ.

## Решения, принятые без владельца

- `[AI]` Неделя считается по Москве, а не по UTC — прежний запрос уже читался в поясе проекта +03:00, и числа, которые
  владелец видел, были московскими; правка подписи, а не смена окна (числа ДО = ПОСЛЕ, отчёт прогона).
- `[AI]` Календарный день возврата тоже назван явно по Москве (раньше — неявно по поясу проекта).
- `[AI]` Отказ голой границе в общем помощнике (FORK в шапке блока `tools/lib/posthog.mjs`, consulted — документация
  PostHog): по слову Менеджера «на твоё усмотрение, с FORK-строкой».
- `[AI]` Контроль пояса встроен в сам запрос прибора (одна колонка, без отдельного прибора и без стража в воротах).
