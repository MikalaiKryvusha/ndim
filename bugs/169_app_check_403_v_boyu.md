# Bug 169 — App Check в бою отдаёт 403: наблюдение не работает, консоль шумит у каждого

**Статус:** 🟡 СИМПТОМ СНЯТ (App Check выключен предохранителем), ПРИЧИНА НЕ УСТРАНЕНА ·
**Заведён:** 2026-08-22, Менеджером · **Нашла:** дверь выката (`verify-prod-signed-in`) ·
**Родитель:** `plans/22` фаза 3 · **Требует:** руки владельца в консоли Firebase

## Симптом

Первый боевой выкат с врезкой App Check (ночь 2026-08-22) прошёл дверь до смоука под сессией —
и смоук покраснел на единственной проверке: **«консоль чиста за весь проход»**, обе ширины,
обе темы.

```
❌ [390-light]  консоль чиста — Failed to load resource: status 403  (×3)
❌ [1440-dark] консоль чиста — Failed to load resource: status 403  (×1)
```

Остальные 22 проверки из 24 — зелёные: приложение стартовало, вход прошёл, «Профиль» показал
содержимое человека, все пять экранов отрисовались, `TypeError` нет, «Как меня видят» и возврат
работают.

## Адрес отказа — назван зондом, а не догадкой

🔴 **Прибор смоука печатает голое «403» без адреса.** По такому сообщению чинить нечего, поэтому
адрес снят отдельным читающим зондом (три страницы боя, все ответы ≥ 400):

```
403     fetch  content-firebaseappcheck.googleapis.com/v1/projects/ndim-space/apps/
               1:1077558742259:web:0de996aa7f186d7d13bb86:exchangeRecaptchaV3Token   ×2
FAILED  fetch  www.google.com/recaptcha/api2/clr                                     ×2
```

То есть обмен токена reCAPTCHA v3 на токен App Check **отказан сервером**, а вспомогательный
запрос самой reCAPTCHA не доезжает вовсе.

## Что сломано, а что НЕ сломано — граница названа честно

| | |
|---|---|
| ❌ **Сломано** | НАБЛЮДЕНИЕ — то единственное, ради чего врезка ставилась. Токенов нет, доли «с токеном / без» копить не из чего. Плюс 403 в консоли у КАЖДОГО живого человека на каждой загрузке |
| ✅ **Не сломано** | Продукт. Принуждение не включено (решение №009 — сначала наблюдение), поэтому отказ обмена ничего не блокирует: вход, содержимое, все пять экранов зелёные в смоуке |

## Причина — гипотеза, и она НЕ проверена

Отказ приходит со стороны Firebase, а не из нашего кода: ключ подставлен верный, врезка стоит
до первых запросов данных, контур боевой. Наиболее вероятное — **регистрация провайдера
reCAPTCHA v3 для этого приложения не действует**: ключ создан владельцем 2026-08-21
(`homeworks/13`), провайдер регистрировался по REST, и в `STATUS.md` рядом с этим стоит
пометка про TTL в один день.

⛔ **Проверить это агент не может:** нужна консоль Firebase владельца. Гипотеза записана
гипотезой и в вину коду не ставится.

## Что сделано ночью

**Симптом снят штатным предохранителем модуля:** `APP_CHECK_SITE_KEY = ''` в
`src/lib/firebase.ts`, и `maybeInitAppCheck` выходит первой же строкой. Бой возвращён ровно в то
состояние, в котором жил вчера.

Размен назван явно: оставить 403 в консоли у живых людей ради **неработающего** наблюдения —
плохая сделка. Выключение обратимо одной строкой, и она названа в комментарии рядом.

## Как вернуть

1. Владелец проверяет в консоли Firebase, что провайдер reCAPTCHA v3 зарегистрирован для
   приложения `1:1077558742259:web:0de996aa7f186d7d13bb86` и секрет действует.
2. Агент возвращает ключ `'6LftspEtAAAAAF7FP29ls_2OaGOglMT3F9wjrjlj'` в константу.
3. Выкат — и **дверь проверит сама**: тот же смоук покраснеет снова, если обмен по-прежнему
   отказан. Ворота, поймавшие дефект один раз, поймают его и во второй.

## Отдельный дефект, вскрытый попутно

🔴 **Смоук под сессией печатает «403» без адреса.** Сообщение `Failed to load resource: the
server responded with a status of 403 ()` — это всё, что видит тот, кто читает вывод двери.
Найти виновника удалось только отдельным зондом, написанным на месте.

Лечение дешёвое: подписаться на `page.on('response')` и печатать в отчёте адрес, код и тип
ресурса для каждого ответа ≥ 400. Тогда красная строка двери сразу называет, что чинить.
Исполнитель — QA (его прибор). Заводится отдельной строкой в его очередь, а не отдельным
документом: это правка одного прибора, а не класс.

## Решения, принятые без владельца

1. **App Check выключен без его слова.** Довод: врезка не работала (наблюдение мертво), а
   вредила видимо (403 у каждого). Выключение возвращает бой во вчерашнее состояние и
   обратимо одной строкой. Владелец спал; будить его ради отката к вчерашнему — цена выше
   пользы.
2. **Ключ оставлен в комментарии, а не удалён.** Это публичный ключ сайта reCAPTCHA (не секрет);
   удалить его значило бы заставить владельца искать его заново.
