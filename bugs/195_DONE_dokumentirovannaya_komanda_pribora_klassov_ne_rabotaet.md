# Bug NEW — документированная команда прибора классов владельца не работает: файл съедается разбором флага

**Статус:** ✅ ЗАКРЫТ 2026-08-23 (Менеджер, сессия 38) · **Заведён:** 2026-08-23, QA (смена 6) ·
**Нашла:** суд ветки `ndim_designer`, срез `4fb41f6` · **Прибор:**
`tools/check-owner-classes.mjs:243` · **Родитель:** `candidates/owner-critical-notes-2026-08-22.md`
· **Исходящее:** —

## Симптом

Шапка прибора документирует запуск:

```
node tools/check-owner-classes.mjs candidates/batches/06_*.json [--today 2026-08-22]
```

Так он не запускается **никогда**. Прогон по любой партии без `--today`:

```
Укажи файл партии: node tools/check-owner-classes.mjs candidates/batches/06_*.json
EXIT=2
```

Работает **только** форма с флагом — то есть ровно та, которая в шапке помечена
необязательной квадратными скобками.

## Криминалистика

`tools/check-owner-classes.mjs:240–243`:

```js
const todayArg = argv.indexOf('--today');
const today = todayArg >= 0 ? argv[todayArg + 1] : new Date().toISOString().slice(0, 10);
// значение флага не должно уехать в список файлов
const files = argv.filter((a, i) => !a.startsWith('--') && i !== todayArg + 1);
```

`indexOf` не нашёл флага → `todayArg = -1` → `todayArg + 1 = 0` → условие превращается в
`i !== 0` и вычёркивает **первый аргумент, то есть сам файл партии**.

Строка написана против настоящей беды («значение флага уехало в список файлов, прибор падает на
`2026-08-22` как на файле») и в присутствии флага работает верно. В его отсутствие она съедает
предмет — потому что `-1 + 1` попадает ровно в первый элемент, а не в «никуда».

### Воспроизведение — без файлов и без прибора

```
node -e "const a=['x.json'];const t=a.indexOf('--today');console.log(a.filter((v,i)=>!v.startsWith('--')&&i!==t+1))"
→ []
```

С флагом: `['x.json','--today','2026-08-23']` → `['x.json']`. Разница воспроизводится каждый раз.

## Почему это не мелочь

Прибор — единственная машина, судящая карточки по шестнадцати классам владельца, и он мерило
партии 6 и работ Дизайнера. Тот, кто запустит его документированной командой, получит **код 2 и
пустой прогон**. Код 2 отличается от «нарушений нет» (код 0) и от «нарушения есть» (код 1) — но
в конвейере, который смотрит только на «ноль или не ноль», пустой прогон читается как отказ, а
привычка добавлять `--today` появляется у того, кто уже споткнулся. Класс тот же, что смена
ловила четырежды: **проверка, которую в написанном виде никто не может исполнить.**

## Лечение

Считать `-1` отсутствием, а не индексом:

```js
const skip = todayArg >= 0 ? todayArg + 1 : -1;
const files = argv.filter((a, i) => !a.startsWith('--') && i !== skip);
```

🔴 **Проверить починку ОБЕИМИ формами, и обе — прогоном, а не чтением:**
· без `--today` — прибор обязан отработать и назвать число карточек;
· с `--today 2026-08-23` — то же число, и значение флага НЕ должно попасть в список файлов.
Случай в набор — **парой**: проверка «флаг не уезжает в файлы» одна была бы зелёной и на текущей
редакции; различает эти поведения только пара.

## Чего делать НЕ надо

- ⛔ Не «чинить» шапку, дописав `--today` в документированную команду: это спрячет дефект,
  оставив прибор с ловушкой для следующего.

## Закрытие — 2026-08-23

Индекс значения флага больше не существует, когда флага нет: `valueIndex = todayArg >= 0 ? todayArg + 1 : -1`.
Документированная форма запуска работает:

```
$ node tools/check-owner-classes.mjs candidates/batches/06_2026_films_series_games.json
=== 13 карточек, сегодня 2026-08-23 · нарушений найдено: 0
```

🔑 **Вместе с этим закрыт второй дефект той же строки, который документ не называл:** «сегодня»
бралось как `new Date().toISOString().slice(0, 10)`, то есть в UTC. Вечером по местному времени
прибор судил ЗАВТРАШНИМ днём, ночью — вчерашним, и у объекта, вышедшего сегодня, вердикт «вышел
или ещё нет» переворачивался. Дата собирается из `getFullYear`/`getMonth`/`getDate`.

Повод для правки — правило владельца 2026-08-23: «*на момент написания проверить локальное время
машины ОБЯЗАТЕЛЬНО!!!!*». Правило записано в `candidates/README.md` → «Часы машины», урок —
`EXPERIENCE.md` EXP-0208.
