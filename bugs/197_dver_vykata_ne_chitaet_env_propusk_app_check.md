# Bug 197 — дверь выката в бой не читает `.env`: пропуск App Check лежит на месте и не доезжает до прибора

**Статус:** 🔴 ОТКРЫТ · **Заведён:** 2026-08-23, Менеджер (сессия 38) ·
**Нашёл:** боевой выкат `npm run deploy` из чистой оболочки ·
**Прибор:** `tools/lib/app-check-debug.mjs:33` · **Родитель:** `bugs/169`, интервью №046

## Симптом

Единственная дверь выката (`npm run deploy`) доходит до ПОСЛЕДНЕГО шага — смоука под сессией —
и падает, хотя пропуск заведён и лежит в `.env`:

```
▶ БОЙ https://ndimspace.app · light 390×844
Error: нет пропуска App Check: переменная NDIM_APP_CHECK_DEBUG_TOKEN пуста.
    at grantAppCheckDebug (tools/lib/app-check-debug.mjs:52:13)
🔴 ШАГ ПРОВАЛЕН: 🔑 СМОУК ПОД СЕССИЕЙ — вход и все экраны. Выкат остановлен.
```

🔴 **Цена момента: хостинг УЖЕ обновлён.** Шаги «выкат в БОЙ», «замер попадания в контур»,
«заголовки кеширования» и «переадресации живы» прошли зелёными ДО падения. То есть бой получил
новую сборку, а проверка под сессией не состоялась — ровно то состояние, которое дверь
существует, чтобы не допускать.

## Криминалистика

`tools/lib/app-check-debug.mjs:32–35`:

```js
export function debugToken() {
  const value = process.env[DEBUG_TOKEN_VAR]?.trim();
  return value ? value : null;
}
```

Значение берётся из `process.env`, **а `.env` в этот процесс никто не читает.** Загрузчик
`tools/lib/env.mjs` в проекте есть и работает, но его зовут ровно двое:
`tools/lib/credentials.mjs` и `tools/probe-search-console.mjs`. Ни `verify-prod-signed-in.mjs`,
ни `app-check-debug.mjs` его не импортируют.

Проверяется одной строкой:

```
$ node -e "console.log(process.env.NDIM_APP_CHECK_DEBUG_TOKEN ? 'ЕСТЬ' : 'нет')"
нет
$ grep -c NDIM_APP_CHECK_DEBUG_TOKEN .env
1
```

Переменная в файле есть. В процессе её нет.

## Почему это не всплывало раньше

Шапка `app-check-debug.mjs` объявляет: «Значение живёт ТОЛЬКО в `.env`». Замысел верный, и
`bugs/169` закрывался именно так. Но прибор читает не файл, а окружение — и прогон проходил
только там, где переменную задали руками в оболочке (`$env:NDIM_APP_CHECK_DEBUG_TOKEN = …`).

🔑 **Класс дефекта: дверь зависит от НЕНАПИСАННОГО ручного шага.** Пока тот, кто её открывает,
знает про экспорт, дверь выглядит исправной; на чистой оболочке она не проходит собственный
последний рубеж. Это тот же класс, что «зелёное на непроверенном»: правило существует, механизма
под ним нет.

## Лечение

`debugToken()` зовёт `loadEnv()` — ровно тем же приёмом, что `credentials.mjs:32`. Загрузчик
идемпотентен и НЕ перезаписывает уже заданные переменные, поэтому явный `$env:X` в оболочке
по-прежнему побеждает файл.

⛔ **Чего лечение НЕ делает:** не ослабляет требование пропуска. Отсутствие токена на боевом
контуре по-прежнему роняет прибор — иначе прогон дал бы 403 и красную «консоль чиста» по ложной
причине (`bugs/169`).

## Наблюдаемая приёмка

`node -e "import('./tools/lib/app-check-debug.mjs').then(m => console.log(m.debugToken() ? 'ЕСТЬ' : 'нет'))"`
из чистой оболочки печатает `ЕСТЬ`, и боевой выкат доходит до вердиктов смоука.
