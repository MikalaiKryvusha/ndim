## Симптом

`node tools/read-funnel-days.mjs --contour prod` 2026-09-08: за **6 и 7 сентября ни одной строки**,
за 5 сентября `landing_view` = **0** при `guest_start` = 3. Колонки `door_click` нет вовсе.
До выката главной V5 (2026-09-05 17:20) `landing_view` шёл ровно, по 1–8 в день.

## Причина — чтением кода, а не догадкой

Счётчик `landing_view` зовётся **из одного места**: `src/routes/[lang=lang]/+page.svelte:137`,
и только для тех, у кого нет сессии.

До V5 корень был распознавателем языка: он уводил каждого на `/ru` или `/en`, то есть **любой
пришедший на `ndimspace.app` попадал на страницу, где счёт есть**.

`plans/81` сделал корень самой главной и увод убрал (страж языка даже перевёрнут — он теперь
требует ОТСУТСТВИЯ увода). Считать на корне некому и нечем:

- `src/routes/+page.server.ts:29` — `csr = false`. Клиентского кода на корне нет вовсе;
- `src/routes/+page.svelte` не импортирует ни `track`, ни что-либо из воронки (проверено списком
  импортов) — там только `site`, `langs`, `catalog-hub`, `dim-jsonld`, `format`, `Brand`, `Icon`.

**Итого: человек, пришедший из поиска на `/`, невидим для воронки целиком** — ни прихода, ни
единого шага. А корень теперь индексируем и лежит в sitemap, то есть доля таких людей будет расти.

## Почему это дороже, чем кажется

Это бьёт прямо в приоритет 0 (`GOAL.md`, слово владельца 2026-09-05: «*вход в продукт почти
нулевой… это приоритет номер 0*»). Вся работа половины «чтобы вошли» принимается ЧИСЛАМИ воронки —
и главная, лицо этой работы, из этих чисел выпала. `plans/82` тоже нечем будет принять: его
критерий приёмки — рост входа, а начало пути не считается.

⚠️ И отдельно: **два дня без единой строки нельзя прочитать как «никто не приходил»**. Дней с
нулём событий в ряду и раньше хватало (03 и 04 сентября пустые), но теперь тишина неотличима от
слепоты. Ряд перестал отвечать на вопрос, ради которого заведён.

## Чего НЕ делать

⛔ **Не включать `csr = true` на корне ради счётчика.** Корень пререндерен намеренно (`plans/81`),
и гидратация всей главной ради одного события — цена, несоразмерная выгоде. Тот же запрет стоит у
двери карточки (`plans/75`: «`csr = true` не включать — остров»).

## Направление лечения (не начато, решения владельца не требует)

Островом или инлайн-скриптом, как уже сделано на корне для маркера сессии (`bugs/08.1`, хотфикс
`bc3407f`): корень УЖЕ несёт инлайн-скрипт, который читает `localStorage` и уводит вошедшего.
Счёт `landing_view` для остающегося — соседняя строка в том же месте, без гидратации.

⚠️ Условие счёта обязано остаться прежним: вошедший в `landing_view` не попадает (`bugs/08.1`,
довод в `plans/74`). На корне это тот же признак — маркер `ndim-session`.

## Фикс (2026-09-12) — по решению владельца №078 В1 = Г

**Решение, дословно:** «*только аналитикой постхог, мы свою БД фаерстор не грузим запросами*».
Значит на корне нет шага своей воронки (`track()`/Firestore не трогаются), есть одно событие в
PostHog. Ряд `space/funnel/days` для прихода на корень остаётся пустым НАВСЕГДА — по слову
владельца, а не по дефекту; приход на главную читается из PostHog (`$pathname = /`,
`$lib = ndim-root-inline`).

**Форма.** `src/lib/data/analytics.ts` → `rootLandingViewScript()` собирает инлайн-строку из
констант модуля (ключ, адрес `POSTHOG_CAPTURE_URL` = `/i/v0/e/`, таблица хостов
`contourHostMap()`, метка `PROBE_MARK`, зеркало маркера сессии); `src/routes/+page.svelte`
врезает её в `<svelte:head>` отдельным IIFE ПОСЛЕ двери письма, со своим `try` и своей проверкой
маркера — ровно по правилу из «Направления лечения» выше. Страница по-прежнему без единого файла
кода (`csr = false`), SDK не грузится. Транспорт проверен живьём до кода: преполёт CORS 200,
POST `text/plain` → `{"status":"Ok"}`.

**Кто не считается:** маркер сессии (вошедший и гость) · `mode=signIn&oobCode` (письмо) ·
метка прибора `ndim-probe` · хост вне таблицы (стенд, чужой).

**Проверки, приехавшие с фиксом:** юниты — строка исполняется в стенде-заглушке (`new Function`
с подставленными `location`, хранилищами, `fetch`), 10 случаев; e2e `e2e/root-landing-view.spec.ts`
— сборка открывается под боевым и стейджевым именем перехватом маршрута, PostHog заглушен,
6 случаев × 2 ширины; набор — `qa/suites/root-landing-view.md`; отчёт — `qa/reports/2026-09-12_root-landing-view.md`.

**Приёмка, поправка к пункту 2 выше:** механическая защита от повтора теперь ЕСТЬ, и она
названа — e2e-кейс «бой: ровно одно landing_view» краснеет при снятой врезке (доказано
мутацией 2026-09-12: снята строка `{@html LANDING_VIEW}` → 2 адресных красных). Прежняя
честная строка «защиты нет» этим закрыта.

**TWINS:** искал другие страницы с `csr = false`, куда человек приходит из поиска и где счёт
шага воронки отсутствует, — карточки каталога (`dimension/[slug]`) и хабы: там счёт на показе
снят РЕШЕНИЕМ (`plans/75` п.7, число просмотров отдаёт Search Console), близнецом дефекта не
является. Семейство «Тест» — под `csr`, считает SDK. Итого близнецов: нет.

## Дополнение 2026-09-12 — робот не считается (найдено прогулкой по слову владельца)

Владелец (интервью №081 В1 = Б): «*сам сходи на стейдж, походи по нему, даже несколько раз, и
сам посмотри аналитику*». Прогулка шестью свежими контекстами показала: события корня доезжали
(7 из 7), события SDK с лендинга `/ru` и от гостя — нет. Разделяющие замеры (25 с окно, режим
`__posthog_debug`, подсмотренный таймер очереди, скрытые признаки робота по одному): SDK
исправен — он отсеивает роботов `isLikelyBot` (`webdriver` · user agent · `userAgentData.brands`),
и headless Chromium — робот по всем трём («HeadlessChrome» в brands даже при подменённом user
agent). Со скрытыми признаками SDK отправил `POST /e/` через 3,9 с.

**Следствие для строки корня:** она роботов не отсеивала — считала бы Googlebot и любой
краулер с исполнением JS, и критерий приёмки «сопоставимо с кликами Search Console» плыл бы.
Строка перенесена в `src/lib/data/root-landing-view.ts` и отсеивает роботов тем же признаком и
тем же списком (`DEFAULT_BLOCKED_UA_STRS` из `@posthog/core`, импорт). Модуль импортирует
только корень (сервер), чанк аналитики не тяжелеет. Юнит ГЛ-15 (мутация «снят webdriver» →
красный), e2e — кейс робота как контроль, прибор слоя С приходит человеком.
