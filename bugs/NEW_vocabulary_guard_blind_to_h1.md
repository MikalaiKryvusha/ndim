## Симптом

`tools/verify-product-vocabulary.mjs` объявляет предметом суда «видимый текст СОБРАННОГО сайта —
ровно то, что читает человек». **Заголовки `h1` в этот предмет не входят ни на одной странице.**

Функция `stripData` вырезает `<h1>…</h1>` из КАЖДОЙ страницы до поиска. На карточке каталога это
верно: там `h1` — название объекта культуры, то есть данные владельца, а не наш текст. На всех
остальных страницах `h1` — **наш текст**: заголовок лендинга, заголовки документов «Меню»,
заголовки семейства «Тест», заголовки хабов каталога.

Замер по свежей сборке: **216 заголовков `h1` на 221 странице вне каталога** невидимы стражу.

## Воспроизведение (детерминированное)

```bash
npm run build
node tools/verify-product-vocabulary.mjs          # ✅ проверок 7 · провалов 0
```

Мутация 1 — запрещённые слова ВНУТРИ `h1` (подстановка печатает дельту байт, попадание
подтверждается грепом ПОСЛЕ правки):

```
build/ru/menu/manual.html
  было:  <h1 class="svelte-18sjm5y">Руководство пользователя</h1>
  стало: <h1 class="svelte-18sjm5y">Руководство пользователя: оси и axes</h1>

node tools/verify-product-vocabulary.mjs          # ✅ проверок 7 · провалов 0   ← ДЕФЕКТ
```

Мутация 2 (контроль) — ТЕ ЖЕ два слова вне `h1`, на ТОЙ ЖЕ странице, обычным абзацем:

```
node tools/verify-product-vocabulary.mjs          # ❌ проверок 7 · провалов 1
  · ru\menu\manual.html — ось/оси — говорим «измерение» (нашлось: оси)
  · ru\menu\manual.html — axis/axes — говорим «dimension» (нашлось: axes)
```

## Криминалистика — двусторонняя мутация, попадание доказано в обе стороны

Обе подстановки проверены на факт применения (класс `EXP-0180` / `EXP-0189`: молча не легшая
мутация красит зелёным непроведённую проверку). Дельта байт печаталась, наличие и отсутствие
строки подтверждалось грепом после каждой правки, откат тоже.

| Куда посажены слова `оси` и `axes` | Файл | Страж | Что это доказывает |
|---|---|---|---|
| внутрь `<h1>` | `build/ru/menu/manual.html` | ✅ 7 · провалов **0** | слепое пятно настоящее |
| в обычный абзац той же страницы | тот же файл | ❌ 7 · провалов **1**, оба правила названы | прибор исправен и различает |
| откат обеих | тот же файл | ✅ 7 · провалов **0** | сборка восстановлена, следов нет |

Различающий опыт чистый: изменилось РОВНО место слова — файл и слова те же, вердикт
противоположный. Чтения регулярки было бы недостаточно; заявление уронено наблюдением.

## Корневая причина

Вырез `h1` задумывался для страницы каталога и применён ко всему сайту. В шапке `stripData`
названы поводы каждого выреза, и все они каталожные: «описание», «карточка-досье», «заголовки с
названием объекта», ранжированный список хаба, хвост индекса. Признака «эта страница — карточка
каталога» вырез не спрашивает, хотя сам страж такой признак уже вычисляет строкой ниже:

```js
const isCatalog = (f) => f.includes(`${sep}dimension${sep}`);
```

То есть лечение лежит в самом файле и стоит одной передачи признака в `stripData`.

## Второй, меньший дефект того же прибора — обещание шире проверки

Шапка списка `BANNED` гласит: «Каждая строка — из колонки „НИКОГДА не пишем“ канона. Добавляешь
слово в словарь — добавь и сюда, иначе правило снова станет пожеланием».

**Механизировано четыре строки колонки из десяти.** Не механизированы: `платформа` / `приложение`
как имя · `совместимость` · `рейтинг` / `лайки` как имя звёзд · `наш рейтинг` / `средняя оценка`
как имя NDSR · `пересчитано топов` · `жив` / `alive` / `up` как состояние сервера · «измерения
придумывает сообщество».

⚠️ **И это НЕ значит, что их надо добавить.** Замер по той же сборке (судейский зонд, обе
языковые половины) даёт ровно два непустых попадания, и оба законные:

| Строка канона | Где встретилось | Вердикт |
|---|---|---|
| `совместимость` / `compatibility` | лендинг: «настоящая совместимость» / `truly compatible`; семейство «Тест»: «Тест на совместимость» / `Compatibility test` | **законно оба раза.** Лендинг — строка владельца из 1.x, оставлена дословно: агент дважды предлагал её заменить, владелец дважды вернул свою («оставляем», 2026-08-02). Цена названа в `plans/29` §3а и принята им сознательно — комментарий источника говорит прямо: «Это НЕ недосмотр» (`src/lib/content/landing-copy.ts`). «Тест на совместимость» — имя страницы, интервью №028 В2 = А (`src/lib/content/test-copy.ts`) |
| `платформа` / `platform` | подвал лендинга, оба языка: «Пространство NDim · открытая платформа, сделанная с заботой о людях» | **в букве правила:** канон запрещает `платформа` **как имя**, а здесь имя названо первым и `платформа` стоит приложением к нему. Единственное место на сайте; обоснования рядом с ним, в отличие от предыдущей строки, НЕ записано |

Проверено и то, что могло бы показаться нарушением, а им не является:
`matches` на английских страницах «Теста» означает **совпадения** (русская половина говорит
«совпадения»), а не `Связи`; канон запрещает кальку `матч` / `мэтч` как имя `Связей`.
`like` в 47 попаданиях — английский предлог и глагол («people who are genuinely like you»), а не
существительное «лайки»; это шум моего зонда, а не продукта.

Добавь кто-нибудь `совместимость` в `BANNED` «по канону» — страж покраснел бы на утверждённом
владельцем тексте лендинга. Это ровно класс, уже оплаченный «Калькулятором любви» (интервью
№028): страж краснел на четырёх выкаченных страницах **не на жаргоне**.

**Поэтому дефект здесь не «мало правил», а МОЛЧАНИЕ о границе:** файл обещает зеркалить колонку и
не говорит, какие строки оставлены прозой и почему. Следующий агент прочтёт обещание и поверит.

## План фикса

1. Передать `stripData` признак каталожной страницы; каталожные вырезы (включая `h1`) применять
   ТОЛЬКО к карточке каталога. Прочие 221 страница судятся целиком, вместе с `h1`.
2. Доказать правку **мутацией в обе стороны**: на некаталожной странице `h1` обязан краснеть, на
   каталожной — оставаться зелёным, иначе вернётся ложная тревога на «Ось зла» в названии фильма.
3. Дописать в шапку `BANNED` честную границу: какие строки колонки механизированы, какие
   оставлены прозой и по какой причине (утверждённые владельцем сочетания дали бы ложную
   тревогу), со ссылкой на замер этого документа.
4. Обновить строку прибора в реестре «Испытательный стенд» `AGENT_GUIDE.md` новым числом проверок.

⛔ **Чего НЕ делать:** не добавлять `совместимость` и `платформа` в `BANNED` — замер выше говорит,
что это покрасит исправный продукт и утверждённый владельцем текст.

**Фикс принят, когда (наблюдаемо):**

- *Scale* — число заголовков `h1` вне каталога, попадающих под суд · *Meter* — прогон
  `node tools/verify-product-vocabulary.mjs` по свежей `npm run build` плюс мутация из раздела
  «Воспроизведение» · *Target* — **216 из 216**: мутация в `h1` некаталожной страницы даёт
  провалов ≥ 1 и НАЗЫВАЕТ страницу;
- мутация того же слова в `h1` **каталожной** страницы оставляет прогон зелёным — ложная тревога
  на данные владельца не вернулась;
- прогон на чистой сборке остаётся ✅, и число проверенных страниц не убыло против 302.

## Решения, принятые без владельца

Лечения не применял — документ фиксирует находку и замер. Вывод «`платформа` в подвале лендинга
стоит в букве правила» вынесен как НАБЛЮДЕНИЕ для владельца через Менеджера, а не как вердикт:
это его текст и его витрина, и решение о нём принадлежит ему.
