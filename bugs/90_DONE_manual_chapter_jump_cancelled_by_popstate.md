# Bug 90 — тап по главе руководства никуда не везёт: платформа отменяет переход на popstate

**Статус:** ✅ ПОЧИНЕНО 2026-07-30 · **Когда/контекст:** найден при ревизии давно не гонявшихся
стражей (урок `EXP-0090`) · **Тип:** регрессия от В12б, видимая человеку

## Симптом

В руководстве (`/menu/manual`) человек открывает панель глав, жмёт «Напутствие» — панель
схлопывается, и **он остаётся на месте**. Ни к главе, ни куда-либо ещё.

Замер (`test-results/plan08/probe-manual.mjs`, собранный сайт): высота документа **13 956px**,
`scrollY` через 200/600/1200/2500 мс после тапа — **0, 0, 0, 0**.

Поймано стражем `tools/verify-manual-v1.mjs` — **12 провалов** (3 проверки × 4 комбинации темы и
ширины): «тап по главе везёт к ней — scrollY: 0», «финальная сеть во вьюпорте после перехода»,
«внизу документа активна последняя глава».

## Причина

Регрессия появилась вместе с **В12б** (интервью №007: «навигация должна быть честной, фиксим») —
панель глав получила запись истории, чтобы её закрывала системная «Назад» (`bugs/76`, близнецы).
Закрытие — это `history.back()`, то есть **popstate**. А SvelteKit на popstate **восстанавливает
прокрутку той записи истории** — ту, что была в момент ОТКРЫТИЯ панели, обычно 0.

Порядок в `src/lib/ui/ChapterNav.svelte` был такой:

```ts
function go(id: string): void {
  document.getElementById(id)?.scrollIntoView({ behavior: 'smooth', … }); // 1. поехали
  closePanel();                                                          // 2. history.back()
}
```

Шаг 2 отменял шаг 1: плавный переход только начался, и восстановление позиции платформой вернуло
человека наверх. На телефоне это выглядит как «кнопка не работает».

Это тот же класс, что описан в разведке `plans/08`: **программная прокрутка воюет с
платформенной**, и выигрывает та, что случилась позже.

## Лечение

Едем к главе, КОГДА ПАНЕЛЬ УЖЕ ЗАКРЫЛАСЬ:

```ts
let pendingChapter: string | null = null;

$effect(() => {
  if (open || pendingChapter === null) return;
  const id = pendingChapter;
  pendingChapter = null;
  requestAnimationFrame(() => requestAnimationFrame(() => {
    document.getElementById(id)?.scrollIntoView({ behavior: MOTION.base ? 'smooth' : 'auto', block: 'start' });
  }));
});

function go(id: string): void {
  if (!open) { /* … просто едем … */ return; }
  pendingChapter = id;
  closePanel();
}
```

**Два факта, добытых замером, а не рассуждением** (оба стоят в комментарии к коду):

1. **`afterNavigate` для этого НЕ ГОДИТСЯ.** На неглубоком маршрутировании (`pushState` +
   `history.back()`) он **не вызывается вовсе** — временный лог показал ровно одно срабатывание,
   при монтировании компонента. Первая редакция фикса была построена на нём и не работала.
2. **Двух кадров ожидания достаточно, и они не суеверие:** восстановление позиции платформой
   прилетает следующим кадром после popstate. С двумя кадрами трасса даёт
   `+0 мс → 0 · +150 мс → 384 · +500 мс → 8569 · +1000 мс → 12 485` — плавный ход к главе жив.

Своего слушателя `popstate` не заводим: это прямой запрет `bugs/76` (самодельный роутер поверх
штатного). Слушаем СОСТОЯНИЕ (`open`), а не событие.

## Проверка

`node tools/verify-manual-v1.mjs` (собранный сайт: `npm run build` +
`npx vite preview --port 4173 --strictPort`) — **все проверки зелёные**; до фикса **12 провалов**.

**Мутантом служит сам дефект:** вернуть `scrollIntoView` перед `closePanel()` — страж обязан
покраснеть на тех же трёх проверках. Прогон «до» снят и записан выше, поэтому отдельная мутация
не нужна (приём `bugs/70`: «мутантом был сам дефект»).

## Почему дефект дожил до сегодня

`verify-manual-v1` не гоняли с тех пор, как В12б добавил панели запись истории. Это и есть урок
`EXP-0090`: **страж, который никто не запускает, гниёт вместе с продуктом.** В той же ревизии
нашлись и другие сгнившие стражи (`verify-bugs08`, `verify-bug42`).
