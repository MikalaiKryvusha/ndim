## Приёмка

- Ситуация. Цикл службы не завершается дольше 600 секунд.
- Действие. Сторожевой таймер фиксирует превышение предела.
- Результат. Процесс завершается с кодом 1, PM2 запускает новый процесс, а следующий завершённый цикл записывает свежее сердцебиение.
- Проверка. `node --test sync-server/cycle_watchdog.test.mjs` проходит 2 теста; после боевого перезапуска `node tools/read-server-pulse.mjs --contour prod` завершается кодом 0 и печатает `ЖИВ`.

3. До фикса сторож отсутствует, и тест падает на импорте; после фикса проверка получает ошибку превышения предела и один вызов аварийного завершения.

Ручной `pm2 restart ndim-server-prod` оживил службу: полный проход прошёл за 8,6 секунды, следующее сердцебиение записано `2026-11-24T13:33:48.282Z`, прибор пульса вернул код 0.

## Корневая причина / Гипотезы

Подтверждённая ближайшая причина длительного простоя — в `sync-server/index.mjs` служебный цикл защищён только флагом `cycleInFlight`. Пока `await runCycle()` не завершится, флаг остаётся `true`; у ожидания нет предельного срока. PM2 видит живой процесс и потому не перезапускает его.

Какой именно `await` внутри `runCycle()` завис 2026-11-23, установить по имеющемуся логу нельзя: промежуточные операции цикла не логируются, а стека зависшего promise после перезапуска больше нет. Дефект Firestore или сети не утверждается без доказательства. Фикс закрывает бесконечную потерю следующих циклов при любом таком зависании.

## План фикса

1. Добавить сторож `runCycleWithWatchdog` с пределом `SYNC_CYCLE_TIMEOUT_SECONDS`, по умолчанию 600 секунд.
2. При превышении предела записать ошибку и завершить процесс кодом 1. Просто снять `cycleInFlight` нельзя: старый цикл продолжил бы работать параллельно с новым и разорвал бы кэш процесса.
3. Дать PM2 выполнить уже настроенный `autorestart`; успешный новый процесс повторит просроченный полный проход по сохранённой в базе отметке.
4. Доказать тест красным на версии без сторожа, затем зелёным на фиксе; прогнать весь набор `test:sync`, сборку и живой пульс после выката только этого фикса в замороженную копию.

**Фикс принят, когда (наблюдаемо):** тест зависшего цикла вызывает аварийное завершение один раз; тест обычного цикла не вызывает его; боевой сервер на новом коммите завершает полный проход и даёт свежие сердцебиения в двух последовательных проверках с интервалом больше 60 секунд.

TWINS: искал `cycleInFlight`, `await runCycle()` и `setInterval(` по `sync-server/*.mjs` в основном и боевом деревьях — других независимых реализаций нет; обе копии относятся к одному исходнику и получат один фикс. Единственный служебный `setInterval` принадлежит этому циклу; таймеры переподъёма подписки эскорта используют `setTimeout` и не удерживают флаг занятости.

## Решения, принятые без владельца

- Предел 600 секунд: текущий полный проход на 336 точках занял 8,6 секунды, поэтому предел оставляет большой запас росту и всё же ограничивает простой примерно десятью минутами вместо суток.
- При таймауте процесс завершается, а не запускает следующий цикл поверх старого: сохраняется инвариант отсутствия пересекающихся циклов.
- В бой переносится только этот фикс поверх `35b950f1`, без более новых изменений основного дерева, среди которых есть удаление гостевых аккаунтов.
