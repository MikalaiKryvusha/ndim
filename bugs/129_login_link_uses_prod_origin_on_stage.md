# Баг 129 — на стейдже не войти: ссылка в письме строится из БОЕВОГО домена

> **Заведён:** 2026-08-15 · **Нашёл:** ВЛАДЕЛЕЦ (живая попытка войти на стейдже) ·
> **Статус:** ✅ ПОЧИНЕН 2026-08-15, проверен наблюдением · **Серьёзность:** вход не работает ·
> **Родитель:** `plans/53_EPIC_stage_environment.md` фаза 1

## Симптом

На `https://ndim-stage.web.app/profile` владелец ввёл почту, нажал «Получить ссылку для входа» и
получил **«Не удалось создать аккаунт. Пожалуйста, попробуйте ещё раз.»**

## Причина

```js
function loginLinkOrigin(): string {
  return isStand() ? location.origin : SITE_ORIGIN;   // SITE_ORIGIN = https://ndimspace.app
}
```

Правило читалось как «**всё, что не стенд, — это бой**», и до 2026-08-15 оно было верным: контуров
было ровно два. С появлением третьего оно стало ложным: приложение стейджа просит Firebase отправить
ссылку с `continueUrl` на `ndimspace.app`, а этого домена **нет в authorized domains** проекта
`ndim-stage`. Firebase отказывает, `classify()` не знает такого кода и кладёт его в общую корзину
`unknown` — человек читает «не удалось создать аккаунт», хотя дело не в аккаунте вовсе.

🔑 **В бою дефекта нет и не было:** там канонический домен и есть свой, он разрешён, и путь работает
у 94 живых людей. Дефект родился вместе с третьим контуром — то есть его внёс агент в тот же день.

## Лечение

Условие теперь называет **дом**, а не отсутствие стенда:

```js
return isStand() || isStage() ? location.origin : SITE_ORIGIN;
```

Канонический домен принадлежит бою; у остальных контуров дом — их собственный origin.

## TWINS — обход класса «ссылка из боевого домена»

Искал: `SITE_ORIGIN` во всём `src/`. Найдено **19 мест**, и они делятся на две группы с разной
судьбой — это и есть разбор класса, а не одна строка:

| Группа | Места | Вердикт |
|---|---|---|
| **Метаданные для роботов** — `canonical`, `hreflang`, `x-default`, `sitemap.xml`, JSON-LD | `DocShell.svelte`, `[lang]/+page.svelte`, `catalog-source.ts`, `sitemap.xml/+server.ts`, страницы `dimension`, `test`, `tests`, `delete-account` | ✅ **Оставлено намеренно.** Их работа — указывать на боевой дом всегда; на стейдже они безвредны, потому что контур закрыт `X-Robots-Tag: noindex` целиком (`verify-stage-noindex`) |
| **Действующие ссылки** | `account.ts` (ссылка входа) | 🔴 **починено** |
| | `menu/+page.svelte` «скопировать ссылку», `menu/share` «поделиться» | ✅ **Оставлено намеренно.** Человек делится ПРОДУКТОМ, а не песочницей: копировать со стейджа адрес стейджа было бы хуже, а не лучше |

То есть класс закрыт по списку: одно место починено, восемнадцать осмотрены и оставлены с
названной причиной.

## Проверка наблюдением

`node tools/probe-stage-signin.mjs` — прибор проходит путь человека на живом стейдже:
до починки владелец видел отказ; после — **0 неудачных запросов к Firebase, 0 ошибок консоли**.

⚠️ Первая редакция прибора искала поле почты сразу и падала по таймауту **на исправном продукте**:
поле раскрывается вторым шагом, после «войти по ссылке на почту». Прибор, врущий о продукте, —
это `EXP-0082` в чистом виде; поправлено вместе с багом.

## Чему учит

**Условие вида «всё, что не X, — это Y» живёт ровно до появления Z.** Оно не ошибка в момент
написания — оно становится ошибкой позже, молча, и ломает то, что раньше работало. При добавлении
третьего чего-либо (контура, языка, роли, темы) обход обязан идти не по новому коду, а по СТАРЫМ
бинарным развилкам: их формулировка и есть список мест, где появление третьего сломает продукт.
