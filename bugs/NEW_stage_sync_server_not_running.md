# Bug NEW — на стейдже не работает сервер синхронизации с 2026-09-13: Связи на стейдже не считаются

**Статус:** 🔴 OPEN · **Тяжесть:** S2 — потерян прогон (первый заход НЛ-16 дал «Связей нет» при исправном продукте) ·
**Когда/контекст:** 2026-09-25 16:25, ручной прогон новой V1 главной на стейдже (`plans/106` Д11,
`qa/reports/2026-09-25_new-landing-v1.md`).

## Симптом

Гость стейджа ставит оценки, проходит мост — и за 180 с документ `relations/{uid}` не появляется. Экран «Связи» гостя
показывает «рассчитываются» бесконечно. Живой процесс сервера синхронизации на машине один — боевой
(`run-sync-server.mjs --contour prod`).

## Воспроизведение

1. `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -match 'run-sync-server' }` —
   строки с `--contour stage` нет.
2. Любой прогон пути «оценки → Связи» на `ndim-stage.web.app` — Связи не появляются.

## Криминалистика

Журнал временного запуска 2026-09-25 16:25 (`node tools/run-sync-server.mjs --contour stage`):
`последний ночной проход был 2026-09-13T07:00:12.683Z` — стейдж жил без сервера синхронизации 12 дней. С поднятым
сервером Связи гостя появились через 89 с (окно новичка) и 7 с (второй гость), 23 человека.

## Корневая причина / Гипотезы

Сервер стейджа не стоит службой: боевой переехал на PM2 2026-09-08, стейдж под PM2 — работа порции 2 `plans/85`
(«стейдж под PM2»), не сделана. Последний ночной проход 13.09 — вероятно, последний ручной запуск.

## План фикса

Решение — поставить сервер стейджа службой PM2 (`plans/85`, порция «стейдж под PM2»), как бой. Решение о постоянном
процессе на машине владельца — его (машина одна, игры, ресурсы). До того: каждый прогон «Связей» на стейдже поднимает
сервер на время прогона командой выше и гасит по командной строке `--contour stage`.
