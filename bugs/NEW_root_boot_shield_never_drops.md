## Симптом

`ndimspace.app` у владельца: знак, «Пространство NDim», кольцо, через 15 секунд — «Загрузка
выполняется необычно долго. Попробуйте перезагрузить страницу». Перезагрузка не помогает. У агента
в свежем браузере — исправная главная V5 с содержанием.

## Причина — воспроизведено зондом, не догадкой

Инлайн-скрипт `src/app.html` поднимает загрузочный щит (`html[data-booting]`, `bugs/40`) на корне и
на лендинге, если в `localStorage` лежит маркер `ndim-session` — то есть у ВСЯКОГО, кто хоть раз
входил, гостем тоже. Опускает щит ровно одно место — `endBoot()` из `src/lib/data/session.ts`,
которое до V5 звал лендинг: корень уводил всех на `/ru`, лендинг решал «сессия есть → внутрь /
нет → опустить щит». `plans/81` сделал корень страницей с содержанием и увод убрал, а `endBoot()`
на корне никто не позвал. Щит висит до потолка 15 с и дальше показывает совет перезагрузить.

Зонд на бою (Playwright, 2026-09-05 17:36): свежий контекст → щит `display:none`, ошибок 0; контекст
с живой гостевой сессией → `data-booting` стоит через 2, 6 и 12 секунд, адрес `/`. Стейдж свежим
контекстом — исправен. Ровно поэтому **все проверки были зелёными**: смоуки, e2e и приёмка агента
ходят свежими контекстами без маркера сессии, а у владельца маркер есть всегда.

Кэш и куки браузера не при чём: корень отдаётся с `Cache-Control: no-cache`, живой HTML новый.

## Лечение

Первый заход — `onMount` с `hasSession()` по образцу лендинга — НЕ СРАБОТАЛ на стенде (щит стоял
15 с): корень живёт без гидратации (`csr = false`), `onMount` там не исполняется никогда. Это
поймано зондом, а не глазом, — второй заход уже по устройству страницы.

`src/routes/+page.svelte`, инлайн-скрипт (тот же, что разбирает ссылку из письма): после ветки
письма — если в `localStorage` лежит маркер `ndim-session`, `location.replace('/profile')`. Это тот
же признак, по которому `app.html` поднял щит, и та же дверь, куда лендинг уводил вошедшего
(`APP_URL`, bugs/08.1): щит держится до ухода, кадра главной человек не видит. Маркер без живой
сессии приводит на экран входа, а не на вечный экран. Без маркера щит не поднимается, главная
видна сразу.

## Проверка

- [ ] стенд: маркер без сессии → щит опущен, главная видна; гостевая сессия → увод в `/profile`;
- [ ] `e2e/root.spec.ts` — у корня появился первый e2e: содержание + поиск открыт + маркер сессии
      без сессии опускает щит (фикстура доказывает, что щит был поднят);
- [ ] стейдж дверью → бой дверью → зонд с гостевой сессией на бою: щит опущен либо увод внутрь.

## Урок (в `EXPERIENCE.md`)

Проверка «свежим контекстом» слепа к состоянию, которое есть у КАЖДОГО настоящего человека:
маркер сессии, память темы и языка, живая сессия. Смоук боя обязан иметь хотя бы один проход с
маркером сессии на публичных страницах — иначе дверь зелёная, а владелец видит вечную загрузку.
