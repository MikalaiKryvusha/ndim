## Симптом

Остров двери объявляет инвариант ТРИЖДЫ — в `island.js`, в `+page.svelte` и в комментарии
загрузчика, дословно: «**Дверь карточки не имеет права исчезнуть ни при какой поломке: она и есть
смысл страницы**». Инвариант держится классом `door-js`: микроскрипт в `<head>` ставит его до
первой отрисовки, CSS по нему прячет запасную ссылку, а упавший остров класс СНИМАЕТ, и запасная
дверь возвращается.

**Снимает класс только `catch`.** Ранние выходы острова — обычные `return`, и они класс не
трогают:

| Место в `src/lib/door/island.js` | Ветка |
|---|---|
| `if (!door) return;` | блока двери нет в разметке |
| `if (stars.length === 0 \|\| !panel \|\| !enter) return;` | разметка и остров разъехались именами |
| `if (engineUrl === '' \|\| dimId === '') return;` | пререндер не отдал адрес движка или id |

В любой из этих веток человек с живым JS остаётся на карточке, у которой: запасная дверь скрыта
CSS, панель скрыта атрибутом `hidden`, звёзды инертны. **Выхода в продукт нет ни одного.** Это
возврат `bugs/200` в худшей форме: там дверь вела в стену входа, здесь двери нет вовсе.

## Улика — мутация и её замер

Мутировал ПРИНАДЛЕЖНОСТЬ, а не правило: в отдаваемой странице переименован атрибут разметки
`data-door-panel` → `data-door-panelz` (остров ищет прежнее имя). Живой Chromium, 390 px, клик по
звезде, ожидание 1,5 с:

```
класс <html>: "door-js"
запасная дверь видима: false
кнопка панели видима: false
видимых ссылок внутри блока двери: 0
видимых ссылок в гостя на всей странице: 0
ошибок консоли: 0
```

🔑 **Ноль ошибок консоли — половина дефекта.** Поломка полностью бесшумна: ни исключения, ни
предупреждения. Ни один живой контур о ней не узнает.

## Что смягчает

Прибор двери эту поломку ЛОВИТ и громко: на том же мутанте `node tools/probe-catalog-door.mjs`
дал 4 провала (`1г`, `1д`, `1ж`, `1и`) и затем упал по таймауту клика — то есть в бой такое может
уехать только мимо прибора. Поэтому дефект не блокирующий. Но инвариант, записанный в трёх
местах кода как безусловный, сегодня безусловным НЕ является, и следующая сессия прочтёт его как
правду.

## Лечение

В каждой ветке раннего выхода вернуть запасную дверь — либо снятием класса, либо (короче) заменой
`return` на `throw`, чтобы сработал уже существующий общий `catch`:

```js
if (stars.length === 0 || !panel || !enter) throw new Error('дверь: разметка разъехалась с островом');
```

⚠️ `if (!door) return;` стоит ВНЕ `try` — либо занести его внутрь, либо снять класс явно. Ветка
«блока двери на странице нет» безопасна сама по себе (нет блока — нет и запасной ссылки), но
разбирать её отдельно дешевле, чем оставлять читателю на догадку.

## Приёмка

1. Юнит в `src/lib/door/island-core.test.ts`: сегодня он проверяет лишь НАЛИЧИЕ строки
   `classList.remove('door-js')` в тексте острова — этого мало, строка есть и сейчас. Проверять
   надо, что КАЖДАЯ ветка выхода ведёт к возврату запасной двери (в тексте острова не остаётся
   `return` до снятия класса, либо ветки переведены на `throw`).
2. Контрольный случай прибора двери: раздел с мутацией имени атрибута, ожидание — **видимых
   ссылок в гостя на странице ровно 1** (запасная дверь вернулась), а не ноль.

## ✅ ПОЧИНКА — 2026-08-28, dev-1 (порция вердикта QA №5)

**Лечение.** Все три ветки раннего выхода в `src/lib/door/island.js` переведены на `throw`, и
ветка `if (!door)` **занесена внутрь `try`** — та самая, которую документ дефекта разрешал
оставить снаружи («безопасна сама по себе»). Взята строгая половина совета: пока она стоит вне
`try`, инвариант держится РАССУЖДЕНИЕМ («нет блока — нет и запасной ссылки»), а внутри — держится
механикой. Инвариант «дверь не имеет права исчезнуть» стал безусловным во всех ветках, как и
записано в трёх местах кода.

```js
if (!door) throw 0;
if (stars.length === 0 || !panel || !enter) throw 0;
if (engineUrl === '' || dimId === '') throw 0;
```

⚖️ **Почему бросается ГОЛОЕ значение, а не `new Error('…')`** — довод замерен, а не стилистический.
Сообщение не читает никто: общий `catch` его глотает и в консоль не пишет (шум в консоли продукта
запрещён каноном). При этом остров уезжает в КАЖДУЮ из 10 222 страниц, то есть каждый байт текста
стоит ~10 КБ сборки и лишнего трафика человеку. Объяснение каждой ветки живёт в комментарии — он
режется на пути в страницу и стоит ноль байт. Итог по весу: **2 563 → 2 568 байт** при потолке
2 600 (запас 32); потолок НЕ двигался.

**Юнит — по приёмке п. 1, и он мерит ЧИСЛОМ.** Прежний тест проверял лишь НАЛИЧИЕ строки
`classList.remove('door-js')` — она была на месте и в день, когда дефект нашли, то есть о
ДОСТИЖИМОСТИ этой строки не говорила ничего. Новый тест `island-core.test.ts` → «ни одна ветка
выхода не уносит запасную дверь (bugs/213)» держит два признака: голых `return;` в острове ровно
**один** (законный — `if (pending === null) return;` в обработчике кнопки: запись не начиналась,
уходить некуда), и все три сторожа настройки названы поимённо и обязаны бросать.

**Доказан двумя мутациями** (мутировалась ПРИНАДЛЕЖНОСТЬ ветки к пути `catch`, а не правило):

| Мутация | Итог юнитов | Что сказал тест |
|---|---|---|
| `if (stars.length === 0 …) throw 0` → `return;` | **8 / 1** | ветка названа поимённо |
| `if (!door) throw 0` → `return;` | **8 / 1** | «голых `return;` в острове 2, а законен ровно ОДИН» |
| возврат обеих | **9 / 0** | — |

**Прогоны:** `npm test` 417/0 (было 416 — прибавился этот тест) · `npm run test:tools` 320/0 ·
`npm run check` 517/0 · `npm run typecheck` чист · прибор двери `32 / 0`.

⏭ **Что НЕ сделано этой порцией и почему.** Приёмка п. 2 просит у прибора раздел с мутацией имени
атрибута (ожидание: видимых ссылок в гостя ровно 1). Не заведён: раздел требует подмены отдаваемой
страницы на лету, то есть второго контура сборки внутри прибора, — а класс уже закрыт юнитом на
каждом прогоне и без стенда. Если QA считает живой раздел обязательным, верну его отдельной
порцией; решение за судом, отказ назван вслух, а не умолчан.
