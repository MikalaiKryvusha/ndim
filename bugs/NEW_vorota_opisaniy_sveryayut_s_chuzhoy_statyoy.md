## Симптом одной строкой

Ворота печатают `✅ чисто · ряд N сл.` и считают запись сверенной, когда сверяли её с **чужой
статьёй Википедии** — иногда вовсе о другом объекте.

## Воспроизведение — одна команда

```bash
node tools/check-candidate-descriptions.mjs candidates/batches/05_2026_films_and_games.json
```

Итог прогона 2026-08-22 по полной партии 5: `сверено с Википедией: 47 · 🔴 НЕ ПРОВЕРЕНО: 1`.
На деле **семь половин из двадцати четырёх**, писанных в эту смену, сверены не с той статьёй —
и все семь на русской стороне:

| Карточка | Половина | С чем сверяли на самом деле | Что должно было быть | Вердикт прибора |
|---|---|---|---|---|
| Voicemails for Isabelle | ru | **«Робинсон, Ник»** (биография актёра) | статьи нет вовсе | ✅ чисто |
| Husbands in Action | ru | **«Ли Да-хи»** (биография актрисы) | статьи нет вовсе | ✅ чисто |
| Сначала дамы | ru | **«Прикосновение (фильм, 1992)»** | статьи нет вовсе | ✅ чисто |
| Meccha Chameleon | ru | **«Big Walk»** (другая игра) | «Meccha Chameleon» — статья ЕСТЬ | ✅ чисто |
| Star Fox | ru | **«Star Fox»** (франшиза) | «Star Fox (игра, 2026)» | ✅ чисто |
| Lego Batman: Legacy… | ru | **«Бэтмен»** (франшиза) | своя статья ЕСТЬ | ✅ чисто |
| Paralives | ru | **ничего — поиск вернул пустоту** | «Paralives» — статья ЕСТЬ | ⏭ не проверено |

🔴 **У дефекта ДВЕ стороны, и вторая нашлась только на второй порции.** Прибор не просто
подсовывает чужую статью, когда своей нет, — он **пропускает свою, когда она есть**: у
«Paralives» русская статья существует, а полнотекстовый поиск по запросу
`Paralives Видеоигра 2026` не вернул ничего. Прибор написал честное «не проверено» по
случайности, а не потому, что проверять было нечего.

🔑 И вот что это значит для доверия к числу в подвале отчёта: **единственное `НЕ ПРОВЕРЕНО: 1`
за весь прогон стоит на карточке, у которой статья ЕСТЬ**, а три карточки, у которых её
действительно нет, попали в «сверено». Число внизу отчёта не описывает реальность ни в одну
сторону.

Чем снято поимённо (тот же запрос, что строит прибор):

```bash
curl -s "https://ru.wikipedia.org/w/api.php?action=query&list=search&srlimit=1&format=json&srsearch=Voicemails%20for%20Isabelle%20%D0%A4%D0%B8%D0%BB%D1%8C%D0%BC%202026"
# → "Робинсон, Ник"
```

## Причина — в коде, и она в трёх строках

`tools/check-candidate-descriptions.mjs:242…252`, функция `articleText`:

```js
const search = await api(lang, { action: 'query', list: 'search',
  srsearch: `${title} ${kind} ${year}`.trim(), srlimit: '1' });
const hit = search?.query?.search?.[0]?.title;
if (!hit) return null;
```

Берётся **первое попадание полнотекстового поиска, и никто не проверяет, что оно об этом
объекте.** Полнотекстовый поиск почти всегда что-нибудь находит: слова «Фильм» и «2026» есть в
тысячах статей, а имена актёров из названия ведут прямо на их биографии.

🔑 **Собственный комментарий прибора обещает ровно то, чего он не делает:**

> «*Запрос строится из названия, вида и года — без них поиск сваливается на однофамильцев, и мы
> сверяли бы текст с чужой статьёй.*»

Вид и год **не спасают** — они и притягивают чужие статьи.

## Второе следствие, которое дороже первого

Ветка «НЕ ПРОВЕРЕНО» **срабатывает не на том.** Она смотрит на ПУСТОТУ ВЫДАЧИ, а не на
отсутствие статьи — то есть отвечает на вопрос «нашёл ли поиск хоть что-нибудь», а канон
мастерской спрашивает у неё совсем другое:

> `candidates/README.md`: «*Статья не нашлась — запись помечается «НЕ ПРОВЕРЕНО» и в «чистые» не
> попадает никогда*»

Два вопроса совпадают только случайно. За полный прогон партии 5 они не совпали ни разу:
`НЕ ПРОВЕРЕНО: 1` стоит на карточке, у которой статья ЕСТЬ, а три карточки без статьи попали в
`сверено: 47`. Ошибка при этом невидима — в подвале отчёта печатается ровное число, и читается
оно как «всё сверено».

## Предлагаемое лечение (решать разработчику)

1. **Сначала прямое попадание по заголовку**, а не поиск: `titles=<название>` + `redirects=1`.
   Статья есть — сверяем её, вопрос закрыт.
2. 🆕 **Прямое попадание закрывает и вторую сторону дефекта** — «Paralives» находится по
   заголовку мгновенно, хотя полнотекстовый поиск его теряет. Это не два лечения, а одно.
3. **Поиск — только запасным путём, и его попадание проверяется:** заголовок статьи, очищенный от
   служебного различителя в скобках, обязан совпасть с названием карточки. Не совпал — `null`,
   то есть честное «НЕ ПРОВЕРЕНО».
4. 🔑 **Самотест обязан содержать РУССКИЙ вход** — `AGENT_GUIDE.md` → «САМОТЕСТ РУССКОЙ ПРОВЕРКИ
   ИДЁТ НА РУССКОМ ОБРАЗЦЕ». Все семь промахов здесь — на русской половине, ни одного на английской.
5. **Мутация, которая обязана уронить починку:** подсунуть карточку с названием, которого в
   Википедии нет («Voicemails for Isabelle» на русском годится как живой образец) — прибор обязан
   напечатать `НЕ ПРОВЕРЕНО`, а не `✅ чисто`. Второй образец, обязательный: «Paralives» на
   русском — прибор обязан НАЙТИ статью, а не написать «не проверено».
