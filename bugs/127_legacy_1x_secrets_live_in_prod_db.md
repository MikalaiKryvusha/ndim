# Баг 127 — в боевой базе живут 331 секретный ключ 1.x, о которых код 2.0 не знает

> **Заведён:** 2026-08-15 · **Автор находки:** агент (прибор `tools/migrate/db-fingerprint.mjs`,
> первый прогон) · **Родитель:** `plans/53_EPIC_stage_environment.md` фаза 0 ·
> **Статус:** 🔴 открыт, НЕ починен · **Серьёзность:** приватность / гигиена данных ·
> **Исходящее:** судьба пласта — решение владельца, задаётся после переезда баз

## Симптом

Прибор отпечатка базы, написанный ради миграции, отказался считать отпечаток полным: в боевой базе
нашлась подколлекция, которой нет ни в `firestore.rules`, ни в `src/lib/model/schema.ts`, ни в
одном инструменте 2.0.

```
users/{uid}/privat/{uid}   —  331 документ
   uid              string(28)   непустой у всех 331
   privat_data      object       ПУСТОЙ у всех 331   ({})
   user_secret_key  string(30)   НЕПУСТОЙ у всех 331
```

Замер: `node tools/migrate/probe-collection-group.mjs privat` (только чтение, значений не печатает).

## Почему это дефект, а не «просто наследие»

1. **`researches/02` утверждал обратное, и это уже стоило слепого пятна.** Там записано:
   «`users/{userId}/privat/{id}` — приватные данные. **Не используется** (заглушка)» и отдельным
   пунктом «мёртвая подколлекция-заглушка». Вывод был сделан ЧТЕНИЕМ КОДА 1.x. Замер уточнил:
   заглушка `privat_data` действительно пуста у всех, **а секретные ключи живые** — 331 непустая
   строка в 30 знаков.
   🔑 Класс тот же, что у `bugs/108` и `bugs/109`: **1.x знал о поле, 2.0 его не узнал.**
2. **Правила 2.0 её не описывают вовсе.** Данные закрыты только финальным `match /{document=**}
   { allow read, write: if false; }` — то есть клиент не прочтёт (проверено: неаутентифицированный
   REST даёт 403), но защита держится на умолчании, а не на осознанном правиле. Admin SDK
   (вычислитель) правила обходит по устройству.
3. **Секрет без хозяина — это долг.** Никто в 2.0 не знает, что этот ключ означает, кто его выдал и
   что он открывает. Пока это не выяснено, каждая копия базы копирует 331 неизвестный секрет.

## Что уже сделано

- ✅ Подколлекция внесена в `KNOWN_SUBCOLLECTIONS` прибора отпечатка — иначе миграция потеряла бы
  331 документ молча.
- ✅ Отпечаток боя снят полностью: **11 266 документов**.
- ✅ Проверено, что клиент её не читает (403 на REST без входа).

## Что решено по ней в рамках миграции (`plans/53`)

- **В бой она переезжает КАК ЕСТЬ.** Принцип фазы 3: *миграция ничего не чистит* — иначе критерий
  П1 («ни один документ не потерян», сверка 100 %) не может быть выполнен по определению, а именно
  он воплощает слово владельца «права на ошибку у нас нет».
- **В стейдж она НЕ едет вовсе.** Обезличиватель выбрасывает подколлекцию целиком: 331 секретный
  ключ в песочнице, которую мы ломаем нарочно, не нужен ни в каком виде.

## Что осталось выяснить (после переезда, отдельной работой)

- Что такое `user_secret_key` в 1.x: где выдавался, что открывал, жив ли механизм. Источник —
  приватный `MikalaiKryvusha/ndim-old` (разведка по коду, не по памяти).
- Если механизм мёртв — пласт удаляется целиком, и это улучшение приватности.
- Если жив — ему нужно явное правило в `firestore.rules`, а не защита умолчанием.
