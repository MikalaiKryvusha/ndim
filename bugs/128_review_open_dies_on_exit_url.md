# Баг 128 — дверь вычитки умирает сразу после открытия браузера: в `process.exit()` уезжает адрес

> **Заведён:** 2026-08-15 · **Нашёл:** ВЛАДЕЛЕЦ (прислал кадр `ERR_CONNECTION_REFUSED`) ·
> **Статус:** ✅ ПОЧИНЕН 2026-08-15, проверен наблюдением · **Серьёзность:** контур владельца ·
> **Родитель:** — · **Исходящее:** —

## Симптом (глазами владельца)

Агент поднял страницу вычитки (`npm run review -- open homeworks/11…`). Браузер открылся — и
показал **«Не удаётся открыть эту страницу · 127.0.0.1 отказано в подключении ·
ERR_CONNECTION_REFUSED»**. Владелец прислал кадр.

В консоли агента при этом:

```
TypeError [ERR_INVALID_ARG_TYPE]: The "code" argument must be of type number.
    Received type string ('http://127.0.0.1:58239/')
    at process.exit (node:internal/process/per_thread:231:24)
    at file:///D:/work/ai_sandbox/ndim/tools/review.mjs:1351:29
```

## Причина

Расхождение контракта между функцией и её вызывающим кодом:

- `cmdOpen()` при успехе возвращает **адрес поднятой страницы** — строку (`review.mjs:1060`);
- вызывающий код считал, что успех — это `undefined`:
  `return code === undefined ? null : code;` — и строка адреса уезжала дальше как код возврата;
- `process.exit('http://127.0.0.1:58239/')` роняет Node.

Порядок событий и объясняет коварство: браузер открывается на строке 1045, **до** возврата, —
поэтому вкладка успевает появиться, а сервер умирает через миг. Владелец видит открытое окно с
ошибкой соединения, то есть симптом выглядит как «страница не поднялась», хотя она поднималась.

## Лечение

`review.mjs`, разбор результата `open`: проверяется **ТИП**, а не частное значение.

```js
return typeof result === 'number' ? result : null;
```

Контракт назван прямо в комментарии: **число = отказ предполёта; всё прочее = сервер жив**, выход
произойдёт после записи решения. Проверка по типу не сломается, если `cmdOpen` когда-нибудь начнёт
возвращать что-то третье.

## Проверка наблюдением

Прогон после правки: страница поднялась, адрес напечатан, и **прибор постучался в неё HTTP-запросом
— 200, 24 978 байт**. Это и есть доказательство: прежде процесс до ответа не доживал.

## Чему учит

🔑 **Строка, отданная как код возврата, — целый класс.** Тот же самый разбор `review.mjs` уже нёс
защиту от него у соседней команды: у `render` стоит комментарий «`?? 0` пропустил бы строку пути
прямиком в `process.exit`». То есть класс был **известен и обезврежен в одной ветке из двух** —
а во второй остался жить.

Отсюда практическое следствие для правок такого рода: обезвредив ловушку в одной ветке разбора,
пройди **все** ветки того же разбора — они почти всегда писались одной рукой и в один час
(«дефекты кучкуются», `TESTING_FRAMEWORK.md` принцип 4; проверка близнецов `BUG_FIXING_FRAMEWORK`).

⚠️ И отдельно: страж контура (`verify-bug110`, `verify-owner-reviews`) этого не поймал, потому что
проверяет ЗАПИСЬ РЕШЕНИЯ, а не то, что сервер переживает собственный запуск. Класс «процесс умер
после того, как браузер открылся» виден только тому, кто **стучится в поднятый адрес**.
