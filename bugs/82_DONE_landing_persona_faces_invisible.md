## Причина

Видимость трёх лиц карты висит на ОДНОМ событии без запасного пути, и это признано в самом коде.

**1. Стиль прячет лица с первого кадра** — `src/lib/ui/SimilarityDemo.svelte:378–384`:

```css
/* Лицо в точке карты — та же готовность, что и в кружках карточек (bugs/69):
   место держит круг персонажа, лицо проявляется скачанным. */
svg image { opacity: 0; transition: opacity var(--motion-base) var(--motion-ease); }
svg image:global(.ok) { opacity: 1; }
```

В собранном CSS ровно это же (`build/_app/immutable/assets/2.BoXxwve1.css`). Так и задумано:
прозрачность задаётся стилем, чтобы действовать до гидрации (`bugs/69`, `ready.ts:10–13`).

**2. Класс `ok` вешает единственный механизм** — `use:ready` на SVG-картинке
(`src/lib/ui/SimilarityDemo.svelte:190–195`):

```svelte
<image use:ready href={avatarFace(pt.p.id)} … clip-path="url(#demo-face-clip)" />
```

**3. У SVG-картинки в `ready` нет быстрого пути «уже загружена»** — `src/lib/ui/ready.ts:30–41`:

```ts
// Пререндер + гидрация: к моменту действия картинка из кэша может быть уже загружена —
// тогда событие `load` не сыграет никогда (класс EXP-0049). У SVG-картинки нет
// `complete`/`naturalWidth`, ей остаётся только событие.
if (node instanceof HTMLImageElement && node.complete && node.naturalWidth > 0) { reveal(); return; }
node.addEventListener('load', reveal, { once: true });
node.addEventListener('error', reveal, { once: true });
```

Комментарий прямо признаёт дыру: HTML-картинку страхует проверка `complete && naturalWidth`
(:33), SVG-картинке «остаётся только событие» (:32).

**4. Страница пререндерена, а лица грузятся жадно.** В `build/index.html` три
`<image href="/img/personas/alice_face.png" …>` (и `max_`, `nastya_`) стоят с первого байта —
проверено grep'ом. Гидрацию при этом тормозят 15 `modulepreload`-модулей (тот же файл), а
картинки весят 148–173 КБ (`static/img/personas/`: 147 705 / 160 438 / 172 908 Б). Кружки
карточек в такой гонке не страдают: они `loading="lazy"` (`SimilarityDemo.svelte:216`) и у них
есть быстрый путь `:33`.

**Итого:** любой сценарий, где `load` отыграл до того, как действие подписалось, оставляет лица
прозрачными НАВСЕГДА — восстановиться нечем. Замер показывает, что на стенде это происходит
всегда, а не иногда.

**Что причиной НЕ является (закрыто разведкой и замером):**

- «`SVGImageElement` в каком-то браузере не отдаёт `load` вовсе» — опровергнуто кодом проекта:
  `tools/verify-bug69.mjs:68` («SVG `<image>`: помечаем по событию `load`, оно у `SVGImageElement`
  есть») и мутационный прогон в `bugs/69` (вернули `opacity: 1` SVG-лицам → 41 кадр «на горячую»,
  то есть байты засчитались). Не тратить попытки на эту ветку.
- «Файлов нет / не раздаются» — на стенде закрыто замером (см. выше). **На бою не проверено**
  (см. шаг 1 плана).

## ✅ STATUS: DONE (2026-07-29)

**Фикс:** `src/lib/ui/ready.ts` — общий приём готовности графики научился отвечать на вопрос
«картинка уже загружена?» для **SVG-картинки**, у которой нет `complete`. Спрашивается не
элемент, а **кэш браузера**: служебная `new Image()` на тот же адрес. У лежащей в кэше
`complete` истинно сразу; если нет — она догрузится вместе с настоящей и разбудит нас
событием. Сети это не стоит ничего (второй запрос на тот же URL обслуживается из кэша).

**Почему дефект был именно у SVG:** лендинг **пререндерен**. Разметка приезжает готовым HTML,
браузер начинает грузить картинку при разборе, `load` проходит задолго до гидратации — а
`use:ready` вешает слушателя уже после. У HTML-картинки эту дыру закрывала ветка
`complete && naturalWidth > 0`; у SVG закрывать было нечем.

**Замер до и после** (`node tools/probe-ideas21.mjs`, живой браузер):

| | класс `ok` | `opacity` |
|---|---|---|
| до | `false` у всех трёх | `0` |
| после | `true` у всех трёх | `1` |

Кадр карты смотрен глазами (`test-results/ideas21/11-map-after.png`): Алиса, Настя и Макс на
месте, с лицами.

### Страж расширен, потому что был зелёным на дефекте

`tools/verify-bug69.mjs` **не мог** увидеть этот дефект — и это важнее самого бага:

1. **Он придерживал графику роутом на 700 мс.** Задержка сама лечила симптом на время замера:
   картинка приходила после гидратации, `load` играл, лицо проявлялось. Добавлен второй проход
   **«быстро»** — без задержки, поверх прогретого кэша (реальный случай человека).
2. **Главная проверка структурно слепа к этому классу.** Невидимая картинка не может дать кадр
   «видима без байтов»; чем хуже дефект, тем зеленее страж. Добавлена обратная проверка:
   **доехала — обязана проявиться**.
3. **`hasBytes` у SVG опирался на то же событие `load`**, что и сам баг, — прибор повторял
   ошибку продукта. Переведён на **Resource Timing**, который помнит загрузку независимо от
   момента подписки (и ровно это обещал комментарий в шапке, а код обещания не выполнял).

**Доказан мутацией:** с откаченным фиксом медленный проход зелёный, быстрый — **красный** с
точными именами: `байты есть, видимости нет: alice_face.png, max_face.png, nastya_face.png`.
Полный прогон на починенном коде — **все проверки зелёные** (4 темы×ширины × 5 страниц × 2
скорости).

## Решения, принятые без владельца

1. **Спрашивать кэш служебной `new Image()`, а не переписывать разметку карты.** Альтернатива —
   отказаться от `use:ready` для SVG и рисовать лица сразу — нарушила бы глобальное правило
   владельца о готовности графики. Выбран путь, при котором правило остаётся в силе, а чинится
   его исполнение.
2. **Расширить существующий страж `bug69`, а не заводить новый.** Правило одно на весь проект —
   у него должен быть один страж (канон: «приём один, копий не заводить»).
3. **Второй проход стража удваивает время прогона.** Принято сознательно: без него страж не
   стережёт целый класс дефектов, а быстрый проход дешевле медленного (нет ожидания задержки).
