## Вектор цели

- **Achieve:** человек, пришедший по ссылке ролика `https://ndimspace.app/?utm_source=instagram&…`,
  виден в PostHog со своей площадкой, и ряд эпика «зритель → гость → первая оценка» читается.
- **Maintain:** код из письма (`oobCode`, `apiKey`) и любые другие параметры адреса наружу не
  уходят — ради этого часть адреса и отрезана сегодня · `$process_person_profile: false` ·
  предмет оценки не уходит (№002 В4).
- **Avoid:** передача адреса целиком «чтобы метки доехали» — это вернёт `oobCode` в PostHog.

## Критерии приёмки

1. Situation. Чистый браузер без маркера сессии, боевой хост.
   Action. Открывается `https://ndimspace.app/?utm_source=instagram&utm_medium=reel&utm_campaign=pilot-001`.
   Result. Событие `landing_view` несёт `utm_source=instagram`, `utm_medium=reel`, `utm_campaign=pilot-001`.
   Check. Юнит в `src/lib/data/analytics.test.ts` (стенд-заглушка `runRootScript`) видит три свойства в теле запроса.
2. Situation. Адрес `?mode=signIn&utm_source=google&oobCode=abc`.
   Action. Строка корня исполняется.
   Result. Отправки нет (дверь письма), а в любом отправленном теле нет подстроки `oobCode`.
   Check. Существующий юнит «ссылка из письма — не приход» остаётся зелёным без правки.
3. Мутация «белый список снят, уходит весь `location.search`» роняет юнит адресно.

## Что делает код — дословно

`src/lib/data/root-landing-view.ts:91` — свойства события:

> `properties:{env:env,$process_person_profile:false,$lib:…,$current_url:location.origin+location.pathname,$host:location.hostname,$pathname:location.pathname}`

Шапка того же файла, строки 28–30: «*`$current_url` без query — `oobCode` из адреса письма наружу не
уходит*». Юнит `src/lib/data/analytics.test.ts:735–738` закрепляет это на адресе с
`utm_source=google`: «*query в $current_url не уходит — там бывает oobCode*».

🔑 **Отрезание сделано сознательно и верно по своей причине.** Дефект не в том, что адрес
отрезан, а в том, что вместе с опасным параметром отрезаны и безопасные метки `utm_*`, которые
станут нужны, когда появятся ролики. В день написания строки роликов не было.

## Чего этот разбор НЕ знает

- **Языковой лендинг и остальные экраны** считают событиями SDK `posthog-js`
  (`analytics.ts:347`, `capture_pageview: false`). 🔎 **Прочитано в исходнике** 2026-09-14
  (`node_modules/posthog-js/dist/module.js`, версия 1.422.5): умолчание `save_campaign_params: !0`;
  при старте `save_campaign_params&&this.sessionPersistence.update_campaign_params()`, а та делает
  `this.register(i)` из параметров адреса (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`,
  `utm_term` и др.) — зарегистрированные свойства сессии приклеиваются к событиям. Значит, ссылка
  ролика прямо на `/ru?utm_…` / `/en?utm_…` **по чтению** доносит метку — рабочий путь для пилота
  до лечения корня.
  ✅ **Проверено живьём 2026-09-14 20:22** разовым прибором Playwright на боевом `https://ndimspace.app/ru?utm_source=instagram&utm_medium=reel&utm_campaign=probe-utm`

  `/en?utm_…` доносит метку уже сегодня.**
- 🔍 **Замечено попутно, НЕ проверено — отдельный вопрос приватности:** SDK кладёт в `$current_url` адрес

  с `oobCode`, код уезжает в PostHog. Проверить прибором с перехватом — до того, как лечить корень «по образцу
  SDK».
  🔎 Чтение кода 2026-09-14 (не прогон): `src/routes/profile/+page.svelte:589–591` — сразу после

  Не доказан порядок для `track('signin_wall_view')` (стр. 205, наблюдатель состояния `stand === 'signedout'`):
  если это состояние бывает до стирания адреса, `$current_url` понесёт код. Закрывается прибором с перехватом
  тела на стенде (адрес письма из эмулятора Auth).
- Уходит ли метка дальше главной при переходе внутрь: ссылки главной ведут на адреса без query —
  значит, если корень её не записал, дальше её нет.

## Направление лечения (не начато)

Белый список, а не адрес целиком: из `URLSearchParams(location.search)` в свойства события
копируются только `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` — с
ограничением длины значения. Правка корня — самое опасное место продукта (`researches/67` §7:
отдельный `try`, `csr = true` не включать), выкат только `npm run deploy` через стейдж.

## 🔴 2026-09-15 — дефект стал ЕДИНСТВЕННЫМ путём ролика, и он шире меток: корень теряет и ИСТОЧНИК

**Что изменилось в мире.** Владелец опубликовал ролик пилота в Instagram, TikTok и YouTube и написал:
«*Ссылки utm я не прикладывал, платформы не двали этого способа. Просто в кепшенах добавил ndimspace.app*».
Прежний обход этого бага — ссылка на `/ru?utm_…` — в жизни не применился: зрители приходят на КОРЕНЬ голым адресом.

**Что установлено сегодня (код + данные, не догадка).** Строка `src/lib/data/root-landing-view.ts:91` шлёт в
свойствах только `env`, `$process_person_profile`, `$lib`, `$current_url` (без query), `$host`, `$pathname`.
**Источника захода нет вовсе** — ни `$referrer`, ни `$referring_domain`. Запрос PostHog 2026-09-15 20:29: оба
сегодняшних `landing_view` на `/` (15:51 и 19:51) записаны с источником «—», а тот же посетитель, дошедший до
`/ru`, уже получил `$referring_domain: ndimspace.app` от SDK. То есть корень слеп сразу к двум вещам: к метке
и к площадке, с которой человек пришёл.

**Цена прямо сейчас:** зритель ролика неотличим от любого прямого захода; исход пилота читается только всплеском
по времени против фона 2–5 заходов в сутки (`marketing/hypotheses/001…` → «Исход»).

### Предложение лечения (НЕ сделано — требует выката через дверь)

Добавить к свойствам события ДОМЕН источника: `$referring_domain` из `document.referrer` через
`new URL(document.referrer).hostname`, пусто — `$direct`. Только домен, не адрес целиком: так наружу не уходит
ничего, кроме имени площадки (`l.instagram.com`, `www.youtube.com`, `www.tiktok.com`), а `oobCode` письма живёт
в НАШЕМ адресе, не в чужом referrer. Приёмка по образцу критериев 1–3 выше: юнит видит домен в теле, мутация
«снять домен» роняет юнит адресно, живой прогон на стенде с подставным referrer.

⚠️ Честная граница лечения: голый адрес, НАБРАННЫЙ руками (Instagram и TikTok не делают ссылки в подписи
кликабельными), приходит без referrer в любом браузере — это останется «прямым заходом». Лечение даст источник
только тем, кто КЛИКНУЛ (описание YouTube, ссылка в профиле).
