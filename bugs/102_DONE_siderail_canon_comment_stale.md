# Bug 102 — канонический комментарий в SideRail описывает удалённый компромисс 56px как действующий

**Статус:** ✅ ПОЧИНЕНО 2026-07-31 · **Когда/контекст:** найден 2026-07-31 аудитом Fable 5 после
сессий слабых моделей (ревизия кода + состязательная проверка) · **Серьёзность:** minor

## Симптом

В `src/lib/ui/SideRail.svelte` над правилом `top` стоит охранный комментарий-канон в настоящем
времени: «Запасные 56px — ЗНАЮЩИЙ компромисс… оно НЕИЗБЕЖНО расходится с настоящей высотой…
Поэтому здесь остаётся завышенное значение». Но строкой ниже никакого «завышенного значения» уже
нет — фикс `bugs/67` (коммит `c8b0220`) заменил константу на переменную с честным запасным
значением из медиазапроса. Комментарий описывает состояние кода, которого не существует.

Ожидаемое: комментарии-каноны (в этом проекте они прямо адресованы агентам будущих сессий:
«Не меняй, не прочитав bugs/67») описывают ФАКТИЧЕСКОЕ устройство кода, а не промежуточную
редакцию до фикса.

## Воспроизведение (детерминированное)

1. Открыть `src/lib/ui/SideRail.svelte`, строки 80–89.
2. Прочитать комментарий: он утверждает, что запасное значение — 56px, завышено, и даёт
   расхождение 1px при нулевой прокрутке.
3. Прочитать строку 89: `top: var(--bar-h, var(--bar-h-fallback));` — ни 56px, ни расхождения
   1px в коде нет; запасные значения объявлены в `src/routes/+layout.svelte:177/182`
   (61px узко, 55px от 1024px) и совпадают с замеренной высотой шапки.
4. Сценарий вреда: агент будущей сессии, доверившись канону, либо снова «чинит» несуществующий
   1px, либо возвращает константу «как задокументировано» — ровно та регрессия вероятностного
   флейка `desktop-shell`, которую фикс `bugs/67` закрывал 72 прогонами.

## Криминалистика

Фактический код (`SideRail.svelte:80–89`):

```css
/* ⚠️ Запасные 56px — ЗНАЮЩИЙ компромисс, а не небрежность. Не меняй, не прочитав bugs/67.
   Пока шапка не опубликовала `--bar-h` (это происходит при гидратации, окно ~3 кадра),
   CSS берёт это значение, и оно НЕИЗБЕЖНО расходится с настоящей высотой (55px на 1440).
   ...
   1px невидим человеку, заезд под шапку — виден. Поэтому здесь остаётся завышенное
   значение, а настоящее лечение — убрать асинхронную публикацию, а не крутить константу. */
top: var(--bar-h, var(--bar-h-fallback));
```

Фактические запасные значения (`src/routes/+layout.svelte:177–183`):

```css
--bar-h-fallback: 61px;
...
@media (min-width: 1024px) { :global(html) { --bar-h-fallback: 55px; } }
```

Факты из состязательной проверки (закрытые линии опровержения):

1. **Комментарий действительно врёт против кода.** Он в настоящем времени утверждает «остаётся
   завышенное значение… расхождение 1px», а строкой ниже стоит переменная с честными 61px/55px —
   ни 56px, ни 1px в коде больше нет (фикс `c8b0220`, `bugs/67` ПОЧИНЕНО 2026-07-30).
2. **Это упущение, а не решение.** Тот же коммит `c8b0220` обновил аналогичный комментарий в
   `PullToRefresh.svelte` и написал новый канон в `+layout.svelte`, а в SideRail заменил только
   3 CSS-строки, оставив устаревший блок. Текст описывает промежуточное состояние после реверта
   `b66d1ae`. Документа, фиксирующего намеренное сохранение этого текста, нет.
3. **Стражи сценарий не покрывают.** `tools/probe-bug67.mjs` — ручной зонд, ловит лишь возврат
   константы, а флейк `desktop-shell` вероятностный. Сценарий «будущий агент верит
   комментарию-канону» не покрыт ничем.
4. **Смягчение есть, но не опровержение.** Отсылка «прочитай bugs/67» ведёт туда, где написана
   правда, — это оправдывает серьёзность minor, но дефект остаётся.

## Корневая причина

Фикс `bugs/67` менял поведение в трёх файлах, но обход комментариев-канонов о старом поведении
сделал только в двух: `PullToRefresh.svelte` и `+layout.svelte` обновлены, а в `SideRail.svelte`
заменены лишь CSS-строки. Класс дефекта: изменение поведения без синхронизации ВСЕХ канонов,
описывающих старое поведение, — в проекте, где комментарии служат каноном для будущих сессий,
устаревший канон опаснее отсутствующего.
