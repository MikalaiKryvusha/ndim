## Симптом

Живой боевой сервер синхронизации отчитывался версией **2.1.0, сборка 31, собран
2026-08-15T20:08:49Z**. В дереве на 2026-09-08 код `sync-server` ушёл на **13 коммитов вперёд**
(`b095195` … `d404211`, с 2026-08-17 по 2026-08-30). Из них:

| Коммит | Что не доехало в бой |
|---|---|
| `715d561`, `7f558a7` | эпик 60 фаза 1 — прибор замера цены простоя, разбор 2880 холостых операций |
| `874e880`, `c8404c8` | эпик 60 фаза 2 — состояние эскорта на точке, **подписка вместо опроса** |
| `f7f4919` … `1be1d84` | `plans/63` шаги 1–5 — **уборка мёртвых гостей: она УДАЛЯЕТ аккаунты и их следы** |
| `0720d14` | починка гонки с внешней чисткой Auth (обрывала суточный проход) |
| `b095195` | комната измерений панели — один запрос на список |

Три недели работы лежат в стволе и не работают ни у кого.

## Причина

**У веб-приложения дверь есть, у сервера синхронизации — нет.** `npm run deploy` собирает начисто,
проверяет хеш сборки, гоняет смоук под сессией и только потом выкатывает (`AGENT_GUIDE.md` →
«ВЫКАТ В БОЙ», слово владельца 2026-08-15). У сервера синхронизации выкат — это `npm run sync:image`
плюс `docker run` руками, без единых ворот: ни смоука, ни расписки, ни проверки, что выкаченное
вообще поднялось.

Раз ворот нет, нет и напоминания. Никто не забыл — **некому было напомнить**.

🔴 **Второй симптом того же корня, найденный тем же замером:** образ был собран из **несохранённого
дерева** — `builtAt` на семь минут раньше коммита `f6a0c14`, поэтому номер сборки 31 принадлежал
предыдущему коммиту, а код внутри был новее. **Номер сборки врал три недели**, и сверить бой с
историей было нечем. У веб-приложения ровно этот класс закрыт распиской на коммит и отказом
выкатывать грязное дерево (`tools/deploy.mjs:487`, `EXP-0282`).

## Чем это опасно прямо сейчас

Тринадцать коммитов нельзя выкатить «заодно»: среди них код, **удаляющий гостевые аккаунты**, и
переписанный ритм эскорта. Ни то, ни другое в бою не работало ни минуты. Выкатить их вместе с
переездом на PM2 значило бы сделать два изменения одним шагом и потерять ответ на вопрос «что
сломалось». Поэтому `plans/83` поднял бой **старым кодом** — сознательно.

## Направление лечения

1. **Дверь для сервера синхронизации** по образцу двери приложения: расписка на коммит · отказ
   грязному дереву · прогон `npm run test:sync` по тому же коммиту · подъём службы · **проверка
   пульса прибором** (`tools/read-server-pulse.mjs` — он уже есть) · откат одной командой.
   После переезда на PM2 это дешевле, чем было с образом: выкат = сдвинуть замороженную копию на
   новый коммит и перезапустить службу.
2. **Отдельным решением владельца — выкат тринадцати коммитов.** Порциями, а не одним куском:
   первой идёт починка гонки (`0720d14`, чистая), последней — уборка гостей (`plans/63`), у неё
   цена ошибки самая высокая.

## Приёмка

1. Мутация: попытка выката сервера синхронизации на грязном дереве — отказ.
2. Мутация: служба поднялась, но пульс мёртв — дверь красная, а не зелёная.
3. `git -C <замороженная копия> rev-parse HEAD` совпадает с распиской.
