# Bug 54 — «Измерения»: повторный тап по выбранной звезде не снимает оценку и не отменяет отсчёт автосохранения

**Статус:** ✅ DONE (2026-07-28, проверен живым Chrome 60/60 + мутацией; **в бой ещё не
выкачен**) · **Когда/контекст:** 2026-07-27, волна 11 владельца ·
**Кто чинит:** агент сам (канон 1.x известен, решения владельца не требует)

## Симптом

Слово владельца дословно:

> «БАГ на Измерениях — когда установил звезду, не могу её снять и отменить счётчик
> автосохранения оценки. В старом NDim повторный тап по выбранной звезде отменял выделение.
> Нужно вернуть, чтобы повторным тапом по выбранной звезде отменить обратный отсчёт
> сохранения»

Поставил оценку → пошёл отсчёт автосохранения → **передумал, и выхода нет**: тап по той же
звезде ничего не отменяет. В 1.x повторный тап по уже выбранной звезде снимал выделение и
вместе с ним — отсчёт.

## Что нужно (канон 1.x)

Звезда работает как **переключатель**: тап по звезде `N`, когда текущая оценка уже `N`,
снимает оценку и **отменяет запланированное сохранение**. Тап по другой звезде — обычная
смена значения (отсчёт перезапускается).

⚠️ **Первый шаг — разведка, а не код** (`AGENT_GUIDE` шаг 7а): снять по живому 1.x, что
именно делал повторный тап — только снимал выделение до сохранения, или снимал **уже
сохранённую** оценку тоже (то есть равносилен «Убрать оценку» из меню карточки). Это разные
вещи: вторая трогает данные. Источник — `ndim_old/public/scripts/app.js` (обработчик звёзд) +
кадры `design/reference-1x/app-04-измерения-все.png`. Строку — в `researches/12`.

## План проверки

Стенд, живой Chrome: поставить оценку → увидеть отсчёт → тап по той же звезде → оценка снята,
отсчёт **отменён** (в Firestore записи не появилось — проверять по базе эмулятора, а не по
экрану); тап по другой звезде → значение сменилось, отсчёт перезапущен. Обе темы × 390/1440.
Страж проверить на сломанной версии.

## Что сделано (2026-07-28)

**Разведка 1.x — до кода** (как требовал сам баг), записана в `researches/12` → «Жест
звезды: повторный тап». Она ответила на вопрос, который баг ставил ребром:

- вкладка «Все» (не сохранено): повторный тап снимал выделение и прятал кнопку Save
  (`app.js:3759-3770`);
- вкладка «Мой NDim ID» (сохранено): по уже выделенной звезде **не делал ничего** — все
  ветки закрыты условием `checked != "checked"` (`app.js:3856/3870/3884`);
- удаление оценки было **отдельной** операцией (`deleteField`, `app.js:8955`).

**Вывод:** жест звезды отменяет только НЕзаписанное и никогда не трогает сохранённое.

**Фикс** — одна ветка в `pick()` (`src/routes/dims/+page.svelte`), разметка не тронута:
тап по звезде, которая сейчас горит, отменяет отсчёт (роль `hideSaveButton` из 1.x играет
отмена отсчёта — в 2.0 сохраняет время, а не кнопка); если оценка уже сохранена, жест не
делает ничего. Побочно ушла бессмысленная запись в Firestore того же значения.

**Проверка:** новый страж `node tools/verify-bug54.mjs` — **60/60** (обе темы × 390/1440),
смотрит в базу эмулятора, а не на экран, и ждёт ДОЛЬШЕ отсчёта. **Мутация:** ветка отмены
отключена → 3 провала, включая главный — «в базе оказалось 7», то есть оценка записывается
и отменить её нечем (буквальный симптом владельца).

## Решения, принятые без владельца

1. **Тап по уже СОХРАНЁННОЙ звезде не удаляет оценку** — делает ничего. Основание: прямое
   поведение 1.x (таблица выше). Альтернатива «повторный тап удаляет» дала бы второй,
   необъявленный путь удаления рядом с «Убрать оценку» и позволяла бы стереть оценку
   случайным касанием. Если владелец захочет иначе — это одна строка.
2. **Отсчёт на ДРУГОЙ карточке при этом не отменяется**: тап, который ничего не изменил, не
   должен отменять чужое намерение сохранить.
3. **Страж ждёт устойчивого состояния плашки отсчёта**, а не снимает мгновение: плашка
   ездит переходом `slide`, и мгновенный замер дал 3 ложных провала на верном коде.
