## Симптом

`node tools/review.mjs queue <новый документ>` ответил «всего накоплено: 10», хотя ждущих владельца
интервью на тот момент был ОДИН. В `interviews/decisions/queue.json` лежали девять документов,
отвеченных владельцем 4–5 сентября: №060, 061, 068, 070, 071, 072, 074, 076, 077.

Подними я пачку не глядя — владелец открыл бы страницу «Накопилось: 11», где девять вопросов он уже
закрыл своей рукой. Для человека, который дважды за час ругался на сломанный контур вычитки, это
выглядело бы третьей поломкой подряд.

## Причина

Очередь — простой список в `interviews/decisions/queue.json`. `queue` в него ДОПИСЫВАЕТ
(`tools/review.mjs:1300`), а вынимает из него только успешный проход пачки. Ответ, данный ЛЮБЫМ
другим путём — страницей одного документа, правкой файла руками, ответом в чате с последующим
разносом — очередь не трогает вовсе. Признак «отвечено» у проекта есть и надёжен (его читает
`npm run questions`), но очередь его не спрашивает.

## Обход, применённый сейчас

Девять записей вычищены руками, в очереди осталось два настоящих вопроса; страница поднята и
отвечает 200. **Это обход, а не починка:** следующий агент наступит на то же.

## Лечение (не начато)

Одна строка смысла: **пачка обязана спрашивать признак «отвечено» перед показом**, а не доверять
списку. То есть `batch` фильтрует очередь тем же способом, каким `npm run questions` считает
ждущих, и заодно вычищает отвеченные из файла — тогда список перестаёт быть второй правдой рядом с
самими документами (канон: «пару лучше УБРАТЬ, чем сторожить»).

## Приёмка

1. Мутация: положить в очередь отвеченный документ → `batch` его не показывает и убирает из файла.
2. Мутация: положить неотвеченный → показывает.
3. Живой прогон `node --test tools/review-batch.test.mjs` остаётся зелёным.
