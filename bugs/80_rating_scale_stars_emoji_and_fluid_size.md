### Замер ДО правки (покадрово, `test-results/pulse/`)

**Смайлик: анимации у него НЕТ ВОВСЕ.** Трасса выбранного лица — **одно состояние за 150
кадров**. «Пульсацией» читается его ПОЯВЛЕНИЕ: ряд вырастает с 6.9px до 22px за 8 кадров
(≈140 мс, `MOTION.fast`) и дальше не меняется. На таком хронометраже подсветка успевает
мигнуть, а не проявиться.

**Ореол действительно тёмный.** Замер в тёмной теме: `drop-shadow(color(srgb 0.427 0.518 0.627
/ 0.45))` — серо-синий `--faint` на фоне `#060b14`. Отсюда «тёмный смайлик».

**Карточка растворяется на месте.** `fly` гасит непрозрачность ТЕМ ЖЕ прогрессом, что и сдвиг,
а прогресс идёт по `cubicOut` — быстро в начале. Трасса: за первые ~230 мс непрозрачность падала
**1 → 0.2**, пока карточка проходила едва половину пути. Формально «улёт 640 мс», а человек видел
растворение и невидимый доезд.

### Что сделано

| Правка | Было | Стало |
|---|---|---|
| Появление ряда смайликов и строки отсчёта | `MOTION.fast` 140 мс | `MOTION.base` **240 мс** |
| Переход выбранного лица (масштаб, свечение) | `.15s` | `--motion-base` **240 мс** |
| Ореол выбранного лица | `--faint` 45% (в тёмной теме — тёмное пятно) | **золото звезды** `--star` 60%, радиус 5→7px |
| Длительность улёта (`MOTION.gesture` + CSS-зеркало) | 640 мс | **900 мс** |
| Кривая улёта | `fly`: непрозрачность = прогресс сдвига | свой переход `flyAway`: **полная непрозрачность бо́льшую часть пути**, гаснет в последней трети |

## Причина

### (а) Звезда в таблице и звезда в «Измерениях» — разные объекты

Таблица рисует одну звезду глифом:

```
DocBlocks.svelte:76      <i aria-hidden="true">★</i>
DocBlocks.svelte:174     .grades .mark i { font-style: normal; font-size: 17px; line-height: 1; color: var(--star); }
```

Токен `--star` — `#e8a516` в светлой теме и `#ffc93d` в тёмной (`src/routes/+layout.svelte:36` и `:93`).

Действующая реализация оценки на «Измерениях» устроена иначе:

```
src/routes/dims/+page.svelte:1215   <i>{mine !== null && value <= mine ? '★' : '☆'}</i><b>{value}</b>
src/routes/dims/+page.svelte:1535   font-size: 27px; line-height: 1;
src/routes/dims/+page.svelte:1542   .st.fill i { color: #f5a524; }
src/routes/dims/+page.svelte:1545   .st.peak i { color: #ffc247; filter: drop-shadow(0 0 6px rgba(255, 194, 71, .45)); transform: scale(1.12); }
src/routes/dims/+page.svelte:1548   .st.zero i { color: var(--faint); … }
```

Разница по трём осям сразу: **размер** (17px против 27px), **цвет** (токен `--star` против
захардкоженных `#f5a524`/`#ffc247` — сами карточки токен не используют) и **форма подачи**
(в таблице всегда закрашенная «★», в карточке есть пара «★/☆» и заливка 0…N).

> **Гипотеза, не факт.** Что именно владелец называет «новой реализацией», из его фразы однозначно
> не следует. Два чтения: (1) вид звёзд карточек «Измерений» — тогда работа в том, чтобы таблица
> говорила тем же языком; (2) векторный набор `bugs/17` — но **звезды оценки в наборе нет**:
> в `src/lib/ui/icons.ts:68` есть только декоративная `stars` (bootstrap `moon-stars.svg`), звёзды
> оценки во всём 2.0 — юникод-глифы. Разводится словом владельца (см. «⛔ Ждёт владельца»).
>
> Побочно: в 1.x звезда в этой таблице была **тремя разными файлами** — `star_zero.svg` (0),
> `star_full.svg` (1…9), `star_ten.svg` (10) (`researches/12_1x_behavior_inventory.md:324`).
> Возможно, «старые звёздочки» — про этот вид; в 2.0 их нет, стоит глиф.

Слово владельца получено — это п. 8 волны.

Самый сильный аргумент за реализацию нашёлся в собственном тексте продукта. Руководство

То есть страница руководства **уже сейчас отсылает к элементу, которого в карточке нет**.

### (в) Размеры жёсткие; приём флюидного масштабирования в проекте ЕСТЬ, но применён не сюда

Это прямой ответ на вопрос владельца про золотой стандарт индустрии. Стандартный приём —
**CSS `clamp(минимум, гибкая-часть, максимум)`** (fluid type scale), и он **в проекте уже живёт,
причём в том же самом компоненте**, что и шкала:

```
DocBlocks.svelte:151   width: auto; height: auto; max-width: 100%; max-height: clamp(180px, 40vw, 300px);
DocBlocks.svelte:156   .art.logo img { max-height: clamp(60px, 16vw, 100px); }
```

Обе формулы — дословно перенесённые из 1.x (`researches/12:320-321`), то есть та самая «топорная
эмпирика» владельца в 2.0 уже стоит и работает. Третье упоминание — `BottomNav.svelte:58`:
комментарий с формулой панели 1.x `clamp(24px, 2vw, 28px)`. Полный список `clamp` в `src/` — ровно
эти три места.

Верная формулировка причины: **приём есть, но применён только к картинкам**; текст, звёзды, цифры и
смайлики шкалы остались на константах (таблица выше). Это не «в проекте нет флюидного
масштабирования» — так было бы неправдой.

Две оговорки, которые надо держать в голове при фиксе:

1. **`vw` меряет окно, а не колонку.** Колонка документа ограничена `DocShell.svelte:68` (458px)
   и `:90` (820px), поэтому `vw`-член на широком экране «врёт» относительно реальной ширины текста.
   Практического ожога сегодня нет: в живых формулах `clamp` упирается в потолок, и `vw`-член
   реально работает примерно на ширинах 450–750px. **Отдельно отмечу как урок разведки:** первичный
   числовой пример «на 1440px 40vw = 576px при колонке 820px» вводил в заблуждение — потолок 300px
   срабатывает раньше. Мысль верная, иллюстрация была неверной.
2. **Атрибуты `width`/`height` у `<svg>` ничему не мешают.** `DocBlocks.svelte:28`
   `<svg viewBox="0 0 16 16" width={size} height={size} …>` — это *презентационные* атрибуты, их
   перебивает любое авторское CSS-правило (`.grades .mark svg { width: clamp(…) }`). Атрибут при
   этом остаётся полезен как резерв места. Первичная разведка называла атрибут блокером фикса — **это
   опровергнуто каскадом**, блокера нет.
