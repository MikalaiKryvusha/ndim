# Bug 109 — «новые измерения» в бою не находятся никогда: запрос ищет поле, которого у боевых документов нет

**Статус:** ✅ ЗАКРЫТ 2026-08-14 (был: 🔴 OPEN) · **ВОСПРОИЗВЕДЁН 2026-08-02** · латентный в бою (сработает, как только в
каталоге появится новое измерение) · найден чтением кода при разведке эпика `ideas/29`
(`researches/29` §2.6) · **Версия/сборка:** 2.0, сервер синхронизации билд 20 ·
**Класс:** расхождение формы данных между стендом и боем — дефект, который стенд увидеть не может
по построению.

## ✅ ЗАМЕР [TESTED: 2026-08-02 · `sync-server/measure-dims-index.mjs` на эмуляторе Firestore]

Прибор посеял каталог в **боевой** форме (`time.created` как `Timestamp`), создал новое измерение
прямо перед циклом и прочитал результат:

```
space/stats.newDims: []
space/stats.dims:    15
```

Ни одного нового измерения не найдено — при том, что одно было создано секундой раньше.
Гипотеза подтверждена: запрос ищет плоское поле `created`, которого у документов боевой формы
нет вовсе.

🔑 **И вот почему это не поймал бы ни один существующий тест:** прибор специально сеет боевую
форму. Сид стенда (`tools/seed-dev.mjs:297`) сеет ПЛОСКОЕ `created` — на нём тот же запрос
работает, и все проверки зелены на сломанном в бою продукте.

---

## Симптом (какой он будет, когда сработает)

Владелец (или ИИ-агент эпика `ideas/29`) заводит новое измерение. Виджет «Сегодня» на экране
«Пространство» о нём **молчит** — и будет молчать всегда, сколько бы измерений ни добавили.

Бейдж «Новое 🔥» на карточке измерения при этом работает: его считает клиент, и он понимает обе
формы поля (`src/lib/model/feed.ts:232` — `createdAt`).

## Криминалистика

Сервер синхронизации ищет свежие измерения так (`sync-server/index.mjs:319–322`):

```js
const [count, fresh] = await Promise.all([
  catalog.count().get(),
  catalog.where('created', '>=', now - NEW_DIM_WINDOW_MS).get(),   // ← ПЛОСКОЕ поле
]);
```

А боевые документы каталога несут **вложенное** `time.created` (Timestamp) — это форма 1.x:
`adminCreateDim` писал `time: { created: serverTimestamp(), updated: serverTimestamp() }`
(живой код 1.x, `app.js:9646`). Миграция каталога добавляла только `title`, `stars`, `rates`,
`rating` и поля `time` не трогала (`tools/migrate/05-dims-catalog.mjs`).

👉 Значит запрос в бою **не находит ни одного документа никогда**, и `newDims` всегда пуст.

Проект об этом расхождении знает — и в двух местах написал это прямо:

- `src/lib/model/schema.ts:239`: «В бою — `time.created` (Timestamp), на стенде — плоское `created`
  (миллисекунды). Оба обличья понимает `model/feed.ts` → `createdAt`»;
- `src/lib/model/feed.test.ts:199`: «Бой (Admin SDK): Timestamp как `{ seconds }`. Стенд: плоское
  число. Оба обличья — настоящие».

То есть **клиент** научили обеим формам, а **запрос сервера синхронизации** — нет.

### 🔴 Почему ни один тест этого не ловит

`tools/seed-dev.mjs:297` кладёт измерения стенда с ПЛОСКИМ полем:

```js
await db.doc(`dims/${dimId}`).set({ ...dim, created });
```

На стенде форма другая, чем в бою, — значит запрос там работает, и все проверки зелены на
сломанном в бою продукте. Это не дыра в конкретном тесте, а **ложь фикстуры**: стенд моделирует
данные, которых в бою не существует.

## Радиус поражения

- Виджет «Сегодня» на экране «Пространство» — строка о новых измерениях (единственный потребитель
  `newDims`).
- **Ценность эпика `ideas/29`**: смысл пополнения каталога наполовину в том, чтобы люди ЗАМЕТИЛИ
  новое. Молчащий виджет обесценивает работу агента и владельца.
- Снимки дней и тренды дефект **не задевает**: они считают число измерений, а не список новых.
- Сегодня в бою симптом невидим, потому что после миграции 2026-07-12 **ни одного нового измерения
  не заводили** — заводить их нечем (`researches/29` §2.1: админского экрана в 2.0 нет вовсе).

## Гипотеза о причине (в терминах фикса)

Запрос писался под стендовую фикстуру, а не под боевую форму данных. Правильный фикс — две вещи
сразу, иначе он не проверяем:

1. **Сделать стенд честным**: сеять часть измерений в боевой форме `time.created`. Без этого
   любой фикс останется недоказуемым, а страж — украшением.
2. Искать свежие измерения по той форме, что реально лежит в бою (и, по возможности, по обеим —
   как это уже делает клиентский `createdAt`).
