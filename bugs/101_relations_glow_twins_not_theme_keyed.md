# Bug 101 — свечения сильной связи в «Связях» не ключуются темой: на «Бумаге» они рисуют тень

**Статус:** 🔴 OPEN · **Когда/контекст:** найден 2026-07-31 аудитом Fable 5 после сессий слабых
моделей (ревизия кода + состязательная проверка) · **Серьёзность:** minor

## Симптом

Светлая тема «Бумага» (дефолт, владелец смотрит десктоп именно в ней), экран «Связи», карточка
человека с сильной связью (уровень `lv3`, метрика похожести ≥60%). Ожидается: бирюзовое значение
метрики читается чисто, свечения в светлой теме нет — так закреплено физикой bugs/80. Наблюдалось
бы: вокруг бирюзового текста и мини-бара — размытое пятно того же цвета на чисто белом фоне
карточки. Бирюза `#1fa8c9` имеет светлоту ~0.46, то есть пятно **темнее** белого фона `#ffffff`
и читается не свечением, а грязной тенью — ровно тот механизм, из-за которого владелец три захода
возвращал bugs/80.

## Воспроизведение (детерминированное)

1. Открыть приложение в светлой теме «Бумага».
2. Перейти на экран «Связи».
3. Найти карточку с сильной связью: `strengthLevel(value)` (`src/lib/relations.ts:170`)
   возвращает `'lv3'` при метрике ≥60%, класс вешается в
   `src/routes/relations/+page.svelte:333`.
4. Смотреть на значение метрики и мини-бар: вокруг них цветной ореол темнее фона.

## Криминалистика

Фактический код `src/routes/relations/+page.svelte:522–531` (цитата по факту):

```css
/* «яркость связи»: слабая гаснет, средняя синяя, сильная — циан и светится */
.lv1 b { color: var(--faint); }
.lv2 b { color: var(--primary); }
.lv3 b { color: #1298bd; text-shadow: 0 0 14px rgba(31, 168, 201, 0.45); }
.lv3 .mini i {
  background: linear-gradient(90deg, var(--primary), #1fa8c9);
  box-shadow: 0 0 8px rgba(31, 168, 201, 0.55);
}
```

`text-shadow` и `box-shadow` — литеральные, **вне блока темы**, срабатывают в обеих темах.

При этом правило bugs/80 в `src/routes/+layout.svelte:37–46` сформулировано универсально и
закреплено токеном:

```css
/* Свечение читается свечением, только если оно СВЕТЛЕЕ того, что за ним. На «Бумаге»
   фон карточки — чистый #ffffff … любой цветной ореол здесь неизбежно ТЕМНЕЕ фона,
   то есть рисует тень, а не свет. Поэтому в светлой теме свечения нет … */
--glow: transparent;
```

Токен `--glow`, заведённый ровно для этого знания, в «Связях» не используется.

Состязательная проверка закрыла линии опровержения:

- **«Утверждено владельцем»** — комментарий «сильная — циан и светится» (`relations.ts:167`,
  утверждение макета S4 от 2026-07-11) сделан **до** третьего захода bugs/80 (2026-07-30);
  документа, санкционирующего свечение именно в светлой теме, нет. Находка совместима с решением
  владельца: свечение остаётся — но в тёмной теме.
- **«Страж бы поймал»** — verify-bug80 не упоминает relations/lv3, покрытия нет.
- **«Это уже вычистили»** — коммит `2d93562` честно заявляет: «искал drop-shadow по src/ —
  2 места… третьего вхождения нет» — grep шёл только по `drop-shadow`, близнецы на
  `text-shadow`/`box-shadow` уцелели. Grep подтверждает: «Связи» — единственное оставшееся
  место с цветным свечением без привязки к теме.

## Корневая причина

Обход последствий bugs/80 (коммит `2d93562`) искал только `drop-shadow`, тогда как то же
физическое явление — «цветной ореол темнее белого фона читается тенью» — реализуется и через
`text-shadow`, и через `box-shadow`. Свечения `lv3` были написаны при реализации макета S4 до
того, как физика была понята и закреплена токеном `--glow`, и остались вне механизма темы.
