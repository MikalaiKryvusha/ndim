# Bug 96 — пин высоты улетающей карточки переживает отмену оценки во время улёта

**Статус:** ✅ ПОЧИНЕНО И ПОДТВЕРЖДЕНО В БОЮ 2026-07-31 — выкат состоялся выкатом hosting (в бою с ~09:00)
**Когда/контекст:** найден 2026-07-31 аудитом Fable 5 после сессий слабых моделей (ревизия кода +
состязательная проверка) · **Серьёзность:** major

## Симптом

Вкладка «Все» экрана измерений (`/dims`). Человек оценивает карточку, она начинает улетать
вправо (700 мс), и в это окно он жмёт «Отменить» в тосте. Карточка возвращается в ленту — но
**навечно обрезанной**: с inline-стилями `height: 246px` и `overflow: hidden`, поставленными
на её DOM-узел при старте улёта.

Последствия конкретные:

- pending снят (`pending = null`), натуральная высота карточки ~219px → под контентом ~27px
  пустоты, прибитой фикс-высотой;
- раскрытие описания («deep») и любой рост контента дальше 246px **обрезаются** —
  `overflow: hidden` + фиксированная высота;
- лечится только пересозданием узла: смена вкладки или поиск. Сама лента карточку не чинит.

Ожидаемое: отменённая оценка возвращает карточку ровно такой, какой она была до жеста.

## Воспроизведение (детерминированное)

1. Вкладка «Все», выбрать карточке оценку — стартует отсчёт, затем `commit()` (или сразу
   «Сохранить сейчас»).
2. Карточка получает пин высоты и начинает улёт (700 мс, `MOTION.gesture`); тост
   «Отменить оценку» появляется в тот же тик.
3. В первые ~0,7 с (на стенде ~650 мс — оба `await` быстрее окна: второй — гарантированный
   кэш-хит, платит только `removeRating`) нажать «Отменить».
4. Карточка возвращается в начало ленты с прибитыми `height: 246px; overflow: hidden`.
5. Раскрыть описание — низ обрезан; снизу карточки видна лишняя пустота.

Окно узкое, но жест «оценил → тут же отменил» — штатный сценарий тоста (bugs/54), и владелец —
QA, гоняющий именно его.

## Криминалистика

`src/routes/dims/+page.svelte`, `commit()` (строки 565–572) — пин ставится синхронно, первым
действием:

```ts
const willFly = submitted === '' && tab === 'all';
const pinned = willFly
  ? (document.querySelector(`article.dim[data-dim="${dimId}"]`) as HTMLElement | null)
  : null;
if (pinned !== null) {
  pinned.style.height = `${pinned.getBoundingClientRect().height}px`;
  pinned.style.overflow = 'hidden';
}
```

Снимается пин **только на пути ошибки сохранения** (строки 582–585) — других мест, трогающих
эти стили, в проекте нет. Комментарий над кодом (строки 562–563) фиксирует допущение автора:

> Стиль ставится на узел, который вот-вот будет удалён, поэтому убирать его нужно только
> на пути ошибки — иначе карточка осталась бы с прибитой высотой навсегда.

А `cancelRating()` (строка 660) возвращает карточку **с тем же ключом** `card.id`:

```ts
shown = [card, ...shown.filter((item) => item.id !== dimId)];
```

Закрытые линии опровержения (состязательная проверка):

- **«Svelte создаст новый DOM-узел».** Нет: проверено по установленному Svelte 5.56
  (`node_modules/svelte/.../each.js`) — outroing-элементы остаются в items-карте each-блока, и
  повторное добавление того же ключа выполняет `resume_effect`: **воскрешается тот же узел со
  всеми inline-стилями**.
- **«Тост появляется позже окна».** Нет: `showUndo()` зовётся в тот же тик, что старт улёта,
  кнопка тоста зовёт `cancelRating()` напрямую.
- **«Это задокументированное решение».** Нет: bugs/80 описывает пин и замеры, но сценарий
  отмены во время полёта нигде не упомянут; комментарий в коде рассматривает только путь
  ошибки, считая, что узел всегда умирает.

## Корневая причина

`commit()` ставит на узел карточки «стили смертника» в расчёте, что узел покинет DOM навсегда.
Расчёт неверен: механика отмены (bugs/54) может воскресить outro-узел по тому же ключу
each-блока, и Svelte по устройству возвращает **тот же самый** элемент — с прибитыми стилями.
Дефект родился на стыке двух порознь верных решений: синхронный пин высоты из bugs/80 (жалоба
«соседние не дожидаются») и возврат карточки в ленту из bugs/54.

## План фикса

1. В `cancelRating()` после воскрешения карточки очищать inline `height`/`overflow` на узле
   `article.dim[data-dim="${dimId}"]` (после того как Svelte вернул его в поток) — [NOT-TESTED].
2. Рассмотреть общее место: очистка пина при любом добавлении карточки с ключом, на чьём узле
   остались закреплённые стили, — если п. 1 окажется недостаточно, гипотеза [NOT-TESTED].
3. Радиус класса: поискать по проекту другие inline-стили, ставящиеся «навсегда» на узлы
   each-блоков с воскрешаемыми ключами — [NOT-TESTED].
4. Страж: сценарий «оценил → отменил в первые 500 мс → карточка раскрывается, высота
   натуральная» в `verify-bug80`; мутация — убрать очистку, страж обязан покраснеть.
