## Симптом

На публичной странице каталога строка «Теги» / «Tags» перечисляет теги **на обоих языках сразу**,
и одинаково — и на русском адресе, и на английском.

Снято с боя 2026-08-16, `/ru/dimension/harry-potter-and-the-sorcerer-s-stone-dqjageon`:

```
Теги → кино фильм movie film фэнтези волшебство fantasy magic
```

Та же карточка, `/en/dimension/harry-potter-and-the-sorcerer-s-stone-dqjageon`:

```
Tags → кино фильм movie film фэнтези волшебство fantasy magic
```

Списки **побайтово одинаковы**. То есть англоязычный человек видит четыре кириллических тега,
русскоязычный — четыре латинских, и оба видят вдвое больше тегов, чем существует понятий.

## Замер, а не впечатление

`node` по `src/lib/content/dims-build.json` (полный каталог, 2026-08-16):

| Что | Число |
|---|---:|
| Объектов в каталоге | 5111 |
| С тегами | 5108 |
| **С кириллицей И латиницей в ОДНОМ списке** | **5104 (99,9 %)** |
| Только кириллица | 4 |
| Только латиница | 0 |
| Тегов всего (с повторами) | 43 011 |
| из них кириллических | 21 386 |
| из них латинских | 21 625 |

Почти точное равенство 21 386 ≈ 21 625 — не совпадение: теги лежат **парами перевода**
(`кино`+`movie`, `фильм`+`film`, `фэнтези`+`fantasy`). То есть на каждой странице половина строки
«Теги» — это перевод второй половины, показанный рядом с ней.

Примеры из замера:

```
perfect-stranger-00s8ckka  → [кино, фильм, триллер, movie, film, thriller]
the-queen-s-gambit-01tckmb5 → [кино, фильм, movie, film, телесериал, TV series, драма, drama, …]
anne-of-green-gables-03w5egcy → [book, книга, novel, роман, classic, классика, coming-of-age, взросление]
```

## Причина — найдена чтением кода, одна строка

`src/routes/[lang=lang]/dimension/[slug]/+page.server.ts:152`

```ts
tags: dim.tags,
```

Все остальные двуязычные поля карточки проходят через `pick(поле, lang)` — `title`, `description`,
`type`, `author` (строки 93–94, 148–149). **`tags` — единственное, которое не проходит**, и не
может: в модели каталога оно объявлено плоским списком, а не парой языков.

`src/lib/content/dims-source.ts:36`

```ts
readonly tags: readonly string[];      // ← не { ru, en }, как у соседних полей
```

То есть это не описка в шаблоне, а **пробел в модели данных**: у тега нет языка, потому что языку
негде храниться. Класс тот же, что у `bugs/108`/`109` и `bugs/116` — «1.x знал о поле, 2.0 его не
узнал»: в 1.x теги были поисковым индексом, где двуязычность **полезна** (ищут на любом языке), и
поле переехало в 2.0 как есть, а на публичную страницу его вывели как список для чтения.

🔑 **Отсюда главное для того, кто возьмётся чинить:** двуязычный список — это правильные ДАННЫЕ
для поиска и неправильная ВИТРИНА. Чинить надо показ, а не данные.

## Чем это опасно

1. **Английская страница выглядит недоделанной.** Владелец решил (поправка 2026-08-03), что все
   языки равнозначно главные и ни один не «перевод второго сорта». Кириллица в теговой строке
   английской страницы прямо этому противоречит — и стоит на 5104 страницах.
2. **Строка вдвое длиннее нужного.** У «Дома Дракона» 12 тегов вместо 6, у «The Sims Online» — 10
   вместо 5. На телефоне 390px это лишняя строка-две в досье над самым важным блоком.
3. ⚠️ **Ни один страж этого не ловит.** `verify-dimension-pages`, `verify-catalog-hubs` и
   `e2e/no-jargon.spec.ts` судят содержание и запреты; «текст не на том языке» — класс, у которого
   в проекте прибора нет вовсе. Ровно как в `EXP-0136`: проверки поведения не видят дефект, для
   которого у них нет меры.

## Направления лечения (ни одно не выбрано — нужен замер и слово владельца)

| Путь | Что делает | Чем платит |
|---|---|---|
| **А. Разделить показ по алфавиту** | На `/ru` показывать теги с кириллицей, на `/en` — с латиницей | Дёшево, одна функция, данных не трогает. Ломается на тегах-именах собственных (`FIFA`, `Halo`), которые латиницей законны и по-русски |
| **Б. Пары в данных** | Завести `tags: { ru: [], en: [] }` и разложить существующие 43 011 | Честно и навсегда. Но это правка ДАННЫХ каталога — территория `plans/30`/`plans/44` и слово владельца |
| **В. Убрать строку тегов с публичной страницы** | Теги остаются поисковым индексом, наружу не выходят | Самое дешёвое; но теги — это факт об объекте, а фаза 3 как раз добавляет странице фактов, а не убирает |

🔴 **Чего делать НЕ надо:** «чинить» это правкой боевых данных на ходу. Каталог наполняет владелец
(интервью №010, Р11), а комнаты «Измерения» для этого ещё нет (`plans/44`) — правка мимо неё была
бы ровно тем, что владелец запретил.
