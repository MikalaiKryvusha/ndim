# Баг NEW — `process.exit()` после сетевого вызова роняет процесс: данные верны, код возврата мусорный

> **Создан:** 2026-08-28, смена 8, dev-3 · **Родитель:** остаток суда №4 по «Зрение» Ф2
> (`qa/team-verdicts.md`, пункт 3 неотсуженного) · **Статус:** 🟢 ПРИЧИНА НАЙДЕНА, ФИКС В ВЕТКЕ
> `ndim_dev3` (`87b5953`), ждёт вердикта QA · **Исходящее:** живое доказательство класса — судье
> по пункту 3 остатка суда №4

## Симптом

Прибор консолей ходит в сеть, печатает **полный и верный** вывод — и умирает на выходе:

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 76
```

Код возврата при этом **мусорный**: 127 в одном наблюдении, 9 в другом. Данные на экране есть,
поэтому человек читает прогон как успешный; скрипт, ворота или цикл, судящие по коду, читают его
как провал. Расхождение 127/9 — одна и та же смерть процесса, по-разному подобранная оболочкой.

🔴 **Опаснее всего то, что симптом выглядит как успех.** Ошибка печатается ПОСЛЕ всего полезного
вывода, и глаз оператора до неё не доходит.

## Криминалистика — один вызов, два хвоста, живой боевой токен

Опыт поставлен 2026-08-28 после выдачи токена Яндекса. Вызов один и тот же и **только читающий**
(`--quota`, квоты не расходует), токен один, машина одна. Разница ровно в хвосте прибора.

| Хвост | Где | Прогонов | Assertion | Код возврата |
|---|---|---|---|---|
| `main(...).then((code) => process.exit(code), …)` | `main`, дерево на `f74289f` | 3 | **3 из 3** | **127** |
| `settleExit(main(...))` | ветка `ndim_dev3`, `87b5953` | 3 | **0 из 3** | **0** |

**Это не «везение», а детерминированное поведение:** на пути Яндекса старый хвост роняет процесс
каждый раз. Вывод (вердикт квоты, права хоста, статистика) печатается полностью в обоих случаях —
то есть работа прибора исправна, портится только её ЗАВЕРШЕНИЕ.

Первое наблюдение класса — раньше и на другом приборе: `tools/indexnow-submit.mjs`, отказ
предохранителя печатался правильно и уходил кодом **127** вместо 1 (2026-08-28, до этого суда).
Тогда же выяснилось, что **дренирования тела ответа НЕ ХВАТАЕТ** — сокет держит пул соединений.

## Причина

`process.exit()` завершает процесс немедленно, не давая циклу событий закрыть живые дескрипторы.
После `fetch` в пуле соединений остаётся сокет; libuv на Windows ловит дескриптор в состоянии
закрытия и падает по assertion. Код возврата, который прибор честно вычислил, до вызывающего не
доезжает — вместо него приходит код аварийного завершения.

**Класс, а не случай.** Он воспроизводится на любом приборе, который: (1) ходит в сеть по HTTP и
(2) завершается `process.exit()`. На момент починки таких приборов консолей было пять; три несли
`process.exit()`, два — верную редакцию, и держались они не устройством, а тем, что их правили
последними. Судья QA назвал это дословно: «*везение, а не устройство*».

## Фикс — устройством, а не пятой копией комментария

`tools/lib/exit-code.mjs` — один хвост на все сетевые приборы:

```js
export function settleExit(promise) {
	return promise.then(
		(code) => { process.exitCode = code; },
		(error) => { console.error(`🔴 ${error.message}`); process.exitCode = 1; },
	);
}
```

`process.exitCode` выставляет код и **даёт циклу событий закрыться самому** — процесс уходит
штатно, код доезжает честным. На него сведены все пять приборов консолей:
`probe-search-console` · `console-snapshot` · `yandex-snapshot` · `bing-snapshot` ·
`indexnow-submit`.

**Почему модуль, а не правило в головах:** пока хвост существовал пятью копиями, три копии
разъехались. Забыть общий хвост нельзя — писать нечего.

## Чем стережётся

`tools/exit-after-fetch.test.mjs` — **в воротах** `npm run test:tools`, а не рядом с ними.
Четыре проверки: пол корпуса (пропавшее имя краснеет, а не уменьшает число осмотренных молча) ·
само правило · хвост на месте · дрейф (новый прибор консолей мимо списка).
Доказан четырьмя мутациями, адресаты названы ДО прогона; три совпали с предсказанием точно,
мутация «пол корпуса» вышла шире (каскад от чтения пропавшего файла), причина названа.

🔴 **Граница корпуса замерена, а не объявлена.** Первая редакция признака — «прибор ходит в сеть
→ `process.exit()` запрещён» — опровергнута замером: под неё попадают **72 прибора** из 196
(корпус `tools/*.mjs` без тестов и оснастки, база `3fd94fd`), и **59 из них зовут
`process.exit()`**. Правило в этой ширине покрасило бы красным исправный корпус чужих ролей.
У браузерных приборов устройство другое — они закрывают соединение явно (`browser.close()`) до
всякого `exit()`, и доказанного дефекта там нет. Корпус сужен до приборов, говорящих HTTP с
консолями поисковиков.

## Что этот баг говорит о МУТАЦИЯХ — урок дороже самого дефекта

Мутации по новому стражу все четыре покраснели, и ни одна не поймала бы этот дефект: страж судит
ИСХОДНИК (есть ли `process.exit()` в тексте), а дефект живёт в ПОВЕДЕНИИ процесса при живом
сокете. Поймал его первый живой прогон на боевом токене — и поймал в чужой копии, где фикса нет.

**Правило отсюда:** у дефекта завершения процесса статический страж стережёт только повторение
причины; сам симптом наблюдается лишь живым прогоном. Одно другого не заменяет, и объявлять класс
закрытым по зелёному стражу нельзя.
