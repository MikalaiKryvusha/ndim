## Симптом

Одна и та же команда `npm test` в двух рабочих копиях одного коммита даёт РАЗНОЕ число тестов, и
обе объявляют себя зелёными:

| где | вывод |
|---|---|
| копия разработчика | `tests 322 · pass 322 · fail 0` |
| свежий worktree QA | `tests 318 · pass 318 · fail 0` |

Ни строки «пропущено», ни предупреждения: `skipped 0` в обоих случаях. Прогон на 4 теста короче
выглядит ТОЧНО так же успешно, как полный.

## Причина — условное объявление вместо объявленного пропуска

`src/lib/content/catalog-neighbours.test.ts:127` и `src/lib/content/catalog-hub.test.ts:267`:

```js
const BUILD = new URL('./dims-build.json', import.meta.url);
const full = existsSync(BUILD) ? (JSON.parse(readFileSync(BUILD, 'utf8')) as NeighbourItem[]) : null;

if (full) {
  test('боевой каталог: соседи есть у КАЖДОГО объекта, и их ровно восемь', () => { … });
  test('боевой каталог: сосед НИКОГДА не из чужого вида — слияние видов запрещено', () => { … });
}
```

`src/lib/content/dims-build.json` — артефакт сборки и он в `.gitignore` (строка 67). В свежем
worktree его нет, `if (full)` ложно, и четыре теста (по два в каждом файле) **не объявляются
вовсе**. `node --test` не может сообщить о том, чего ему не объявили.

Проверено числом: объявлений `test(` в `src/**/*.test.ts` — **322**; прогнано — **318**.
Расхождение целиком приходится на эти два файла (по 2 в каждом), остальные 18 файлов сходятся
один-в-один.

## Чем это опасно

Пропадают самые дорогие проверки набора — те, что судят каталог из 5 111 объектов («у КАЖДОГО
объекта ровно восемь соседей», «сосед никогда не из чужого вида»). Их и писали ради боя, а не
ради фикстуры из девяти строк — так сказано в их же комментарии. Сессия в чистом worktree
(а команда worktree — это ровно такие сессии) получает зелёный прогон БЕЗ них и не узнаёт об
этом. Это тот же класс, за который в проекте уже платили: проверка, которая молча не выполняется,
неотличима от выполненной.

## Воспроизведение (30 секунд)

```
rm -f src/lib/content/dims-build.json   # или просто взять свежий worktree
npm test                                # tests 318, skipped 0
npm run build                           # артефакт появляется
npm test                                # tests 322, skipped 0
```

## Критерий приёмки починки (что будет ВИДНО работающим)

1. Без `dims-build.json` тесты **объявляются** и печатаются как ПРОПУЩЕННЫЕ с причиной:
   `test('боевой каталог: …', { skip: 'нет src/lib/content/dims-build.json — сначала npm run build' }, …)`.
2. Общее число тестов не зависит от наличия артефакта: `tests 322` в обоих случаях, а разница
   видна в строке `skipped` (0 или 4).
3. Прогон в чистом worktree печатает причину пропуска ВСЛУХ — сессия не может принять неполный
   набор за полный.
4. Проверка починки — мутацией окружения, а не кода: удалить артефакт, прогнать, увидеть
   `skipped 4` и причину; вернуть, прогнать, увидеть `skipped 0`.

## ✅ СТАТУС: DONE (2026-08-22 ~02:05 +03:00)

**Починено ролью `qa`.** Критерий приёмки, записанный выше, исполнен целиком и проверен
**мутацией окружения**, как в нём и было сказано:

| Прогон | Было | Стало |
|---|---|---|
| артефакт ЕСТЬ | `tests 359 · skipped 0` | `tests 363 · skipped 0` |
| артефакта НЕТ | `tests 355 · skipped 0` ← молча короче | `tests 363 · skipped 5` + причина у каждого |

Причина печатается строкой прогона: `# нет src/lib/content/dims-build.json — сначала npm run build`.

### Замер уточнил сам баг: у класса ДВА лица, а не одно

Запись выше называла только первое. Прогон нашёл второе, и оно опаснее:

| Лицо | Где было | Что печатал без артефакта |
|---|---|---|
| **не объявлен вовсе** — `if (full) { test(…) }` | `catalog-neighbours` (2) · `catalog-hub` (2) | ничего: прогон просто короче |
| **объявлен, но выходит вхолостую** — `if (!full) return` | `catalog-hub` (1) | 🔴 **`pass`** — засчитывал непроверенное как проверенное |

Отсюда 5 пропусков вместо ожидавшихся 4.

### Что сделано

1. Все пять тестов объявляются ВСЕГДА и получают `{ skip: NO_BUILD }` — форма родная для
   `node --test`, поэтому общее число тестов больше не зависит от артефакта.
2. 🔒 **Заведён страж класса** — `src/lib/content/dims-build-skip.test.ts` (4 проверки, живёт
   внутри `npm test`, поэтому его запуск не зависит ни от чьей памяти и ни от какого реестра).
   Он судит КОД со снятыми комментариями и несёт контроль прибора первым: печатает, сколько
   файлов осмотрел и сколько из них зависят от каталога (24 и 3).
3. Внутри развёрнутых тестов добавлено утверждение инварианта `assert.ok(full, …)` — оно и
   документирует «тело без артефакта не исполняется», и возвращает сужение типа, которое прежде
   давала обёртка `if (full)`.

### Доказательства стража — мутациями

- Вернул обёртку `if (full) {` → покраснело **ровно правило 1**, адресат назван до прогона.
- Прогон по НАСТОЯЩЕМУ доисправленному коду обоих файлов → покраснели **оба** правила, каждое
  на своём файле. Это сильнее синтетической мутации: страж доказан на том самом дефекте.
- Первая редакция стража дала **три ложных срабатывания** (разбор в комментарии · файл, который
  артефакт лишь упоминает · сам страж) и была переписана: комментарии снимаются до разбора, а
  зависимость определяется по коду. Класс известен — `EXP-0163` (страж судит прозу) и `EXP-0081`
  (фильтр находит сам себя). Оба промаха и их лечение записаны в шапке стража.

### Решения, принятые без владельца

1. **Общий модуль-помощник для загрузки артефакта НЕ заводился.** Он был бы «починкой по форме»,
   но модуль, читающий 17 МБ каталога, — ровно та мина, что уже стоила проекту `EXP-0136`
   (универсальный загрузчик унёс каталог в браузерный бандл). Три локальные константы дешевле и
   безопаснее одной общей двери. Пересмотреть дёшево.
2. **`dim-kind.test.ts` не тронут.** Он вырождается на запасной срез ЧЕСТНО — печатает об этом
   вслух и проверяет срез по-настоящему. Дефект здесь — молчание, а не сама ветка «артефакта
   нет», и страж это различает.
