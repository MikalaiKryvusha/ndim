# Bug 98 — проверка «тёмная тема применена» проходит на прозрачном фоне: вакуум на своём же дефекте

**Статус:** ✅ ПОЧИНЕНО 2026-07-31 · **Когда/контекст:** найден 2026-07-31 аудитом Fable 5 после
сессий слабых моделей (ревизия кода + состязательная проверка) · **Серьёзность:** minor

## Симптом

Страж боя `tools/verify-prod-b4.mjs` содержит проверку «фон соответствует теме — доказывает, что
тема реально применилась». На деле в тёмной половине матрицы она **зеленеет ровно на том дефекте,
который сторожит**: если CSS темы вовсе не применился и фон `body` остался прозрачным дефолтом
браузера (`rgba(0, 0, 0, 0)`), все тёмные комбинации проходят как «тема dark применена».

Ожидаемое поведение стража: непримененная тема = провал в **обеих** темах. Фактическое: краснеет
только светлая половина матрицы (4 из 8 комбинаций) — тихий отказ CSS, случившийся только в
тёмной фазе прогона, даёт **полностью зелёный** прогон.

## Воспроизведение (детерминированное)

1. Смоделируйте непримененную тему: единственное, что красит `body`, —
   `:global(body){background: var(--bg)}` в `+layout.svelte`; уберите это правило (или сымитируйте
   сломанный бандл CSS / пустой ответ 200 на стилях / перенос фона с `body` на другой элемент).
2. `getComputedStyle(document.body).backgroundColor` теперь отдаёт `'rgba(0, 0, 0, 0)'`.
3. Прогоните `node tools/verify-prod-b4.mjs` (или подставьте эту строку в проверку мутацией).
4. Наблюдайте: `/\d+/g` даёт `['0','0','0','0']` → `slice(0,3)` = `[0,0,0]` → `lum = 0` →
   для `theme === 'dark'` утверждение `lum < 120` истинно — все тёмные проверки зелёные.

## Криминалистика

Фактический код (`tools/verify-prod-b4.mjs:74–78`):

```js
// Фон соответствует теме — доказывает, что тема реально применилась.
const bg = await page.evaluate(() => getComputedStyle(document.body).backgroundColor);
const rgb = bg.match(/\d+/g)?.slice(0, 3).map(Number) ?? [0, 0, 0];
const lum = (rgb[0] + rgb[1] + rgb[2]) / 3;
ok(theme === 'light' ? lum > 140 : lum < 120, `${tag}: тема ${theme} применена (фон ${bg})`);
```

Две дыры в одном выражении:

- **Альфа выбрасывается.** `rgba(0, 0, 0, 0)` — четыре числа, `slice(0, 3)` оставляет `[0,0,0]`,
  прозрачность не отличима от честного чёрного.
- **Фолбэк `?? [0, 0, 0]` загоняет туда же любой неразобранный ответ** (`transparent` без цифр,
  пустая строка) — снова «идеально тёмный» фон.

Факты состязательной проверки (закрытые линии опровержения):

1. Сценарий возможен и конкретен: дефолт UA у `body` прозрачен, а единственный источник фона —
   правило `background: var(--bg)` в `+layout.svelte` (строка ~186). Сломанный бандл CSS, пустой
   200 на стилях или перенос фона с `body` дают ровно `rgba(0, 0, 0, 0)`.
2. Документированного решения владельца, оправдывающего такую проверку, нет; тепловая проверка
   мутацией стража не доказана.
3. Частичное покрытие есть: при **тотальном** отказе CSS краснеет светлая половина матрицы — это
   оправдывает severity = minor, но не устраняет вакуум: отказ только в тёмной фазе тихий.

Собственный канон проекта (`EXPERIENCE.md`, EXP-0070, EXP-0074): «признак, который зеленеет
всегда, доказывает ровно ничего» — этот класс квалифицирован как дефект стража.

## Корневая причина

Проверка измеряет **светлоту**, а не **применённость**: неявное допущение «фон всегда разобран и
непрозрачен» нигде не проверяется. Прозрачный фон численно совпадает с чёрным, поэтому тёмная
ветвь утверждения (`lum < 120`) удовлетворяется в точности тем состоянием, которое проверка
должна ловить. Происхождение по git-истории в вердикте не названо — гипотеза: проверка написана
под «нормальный» бой, где фон всегда покрашен, и на мутанте «тема не применилась» не гонялась.

## План фикса

1. [NOT-TESTED] Парсить фон полноценно: матчить `rgb(a)` со всеми компонентами, включая альфу;
   неразобранный ответ — **провал всегда**, без фолбэка `?? [0,0,0]`.
2. [NOT-TESTED] Требовать `альфа === 1` (или отсутствие альфы): прозрачный фон = провал в обеих
   темах, до всякого сравнения светлоты.
3. [NOT-TESTED] Только после этого сравнивать светлоту с порогами тем, как сейчас.
4. [NOT-TESTED] Мутация для приёмки: подать в проверку строку `'rgba(0, 0, 0, 0)'` — обе темы
   обязаны покраснеть.
