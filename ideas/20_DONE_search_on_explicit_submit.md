# Idea 20 — Поиск измерений: только по явному вводу, не по каждой букве

**Статус:** ✅ РЕАЛИЗОВАНО 2026-07-28 (проверено живым Chrome + мутацией; **в бой ещё не
выкачено**) · **Когда:** 2026-07-27, волна 13 (чат, со скриншотом кнопок поиска и 💡)

## Слово владельца (дословно)

> запиши в идеи - поиск делать только по явному вводу по кнопке ИСКАТЬ, или по вводу с
> Android клавиатуры, или Enter на десктопе.
>
> Николай в оригинальном NDim так и делал, явный ввод на начало поиска. Сейчас исщет по
> каждой букве - это неувжение к ограниченному ресурсу Firestore.

## Разбор

Сейчас (`bugs/50`) поиск на «Измерениях» стартует по мере ввода с паузой 250 мс — дебаунс
экономит дребезг, но каждый промежуточный запрос всё равно ходит в Firestore (догрузка
найденных карточек). Канон 1.x — поиск начинается ТОЛЬКО по явному действию человека.

Сделать:
1. Кнопка «Искать» у строки поиска (вид — по месту, это не развилка макетов: кнопка была
   в 1.x) + сабмит формы: Enter на десктопе и действие «поиск» Android-клавиатуры
   (`enterkeyhint="search"`, событие submit).
2. Посимвольный запуск поиска убрать; дебаунс становится не нужен.
3. Пустой ввод по-прежнему не ищет (тост 1.x «Введите текст для поиска» — снят в
   researches/12, `app.js:9230`).
4. Стражу `verify-bug50` обновить предмет: «ввод букв БЕЗ сабмита не порождает запросов
   Firestore» — это и есть новая экономия (класс EXP-0061: страж следит за поведением,
   не за литералами).

## Что сделано (2026-07-28)

Все четыре пункта закрыты:

1. ✅ Поле поиска стало **формой**; кнопка «Искать» рядом с полем + `enterkeyhint="search"`.
   Сабмит — одна дверь на все три способа владельца: кнопка, Enter на десктопе, клавиша
   поиска Android-клавиатуры.
2. ✅ Посимвольный запуск убран: введён `submitted` — запрос, по которому ИЩУТ, отдельно от
   `search` — того, что печатают. Эффект поиска читает только `submitted`. Дебаунс 250 мс
   удалён за ненадобностью.
3. ✅ Пустой ввод не ищет: кнопка погашена, а опустевшее поле возвращает ленту (локально,
   без запросов).
4. ✅ Страж `verify-bug50` получил новый предмет — **счёт реальных обращений к базе**.

**Замер экономии (живой Chrome, стенд):** набор запроса из 5 букв — **0 запросов** к
Firestore; отправка — **2**. До фикса тот же набор стоил **3 запроса** (доказано мутацией
«поиск снова по каждой букве»). То есть каждая набранная буква действительно стоила денег.

**Проверка:** `node tools/verify-bug50.mjs` — всё зелёное, обе темы × 390/1440 + английский
экран. Попутно страж вылечен от двух собственных дефектов: он вводил текст без отправки
(гниль от смены канона, класс EXP-0056) и определял открытость ящика поиска по видимости
поля — а Playwright считает обрезанный родителем элемент видимым, поэтому страж «печатал»
в схлопнутый ящик.

**Найдено попутно:** `bugs/72` — каретка в поле поиска сбрасывается в начало, посимвольный
ввод даёт «икшоК» вместо «Кошки». Дефект **старше** этой работы (доказано прогоном на HEAD),
причина не найдена, заведён отдельно с полной криминалистикой.

## Решения, принятые без владельца

1. **Опустевшее поле возвращает ленту** (не оставляет старую выдачу). Иначе пустое поле
   рядом с результатами прошлого запроса читается как «лента врёт» — та же логика, по
   которой закрытие ящика поиска очищает запрос.
2. **Кнопка при пустом вводе погашена**, а не показывает тост «Введите текст» (как в 1.x):
   человек и так видит пустое поле, а погашенная кнопка честнее сообщения об ошибке.
3. **Закрытие ящика поиска сбрасывает и отправленный запрос** — иначе спрятанный поиск
   продолжал бы держать ленту в состоянии выдачи.
