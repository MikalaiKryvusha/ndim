## Слово владельца — дословно

> «уже вижу бутылочное горлышко - один стенд с которым сразу несколько ролей хотят работать -
> идёт конкуренция за стенд. Значит мало нам одного стенда! Нужно расширять тестовый парк.»

## Контекст, в котором сказано

Первый запуск команды NDIM_WORKTREE_DEV_TEAM: пять ролей в git worktree, стенд один на машину
(эмуляторы 8181/9099/9199 · `vite preview` 4173 · e2e), доступ — по замку статус-доски. За
первый вечер замок последовательно держали dev-2 → dev-3 → dev-1, QA с двумя стендовыми
работами ждал очереди, живая приёмка правок вида стояла за замком. Конкуренция — не гипотеза,
а наблюдение первого же вечера.

## Суть

У каждой роли — свой изолированный стенд в её worktree: свой набор портов (эмуляторы, preview),
своя базa эмулятора, свой сид. Замок доски остаётся только для настоящих синглтонов машины
(Docker-контейнеры сервера синхронизации, боевая и стейдж базы, общий Chrome CDP — по итогам
разведки).

## Известные точки сопротивления (проверить разведкой, не решать памятью)

- Порты жёстко вшиты в неизвестное число мест: `stand.mjs`, `firebase.json` (секция emulators),
  `playwright.config.ts`, стражи и зонды (`?as=guest`-двери, `verify-*`), досье окружения
  (8080 занят `llama-swap`, эмулятор на 8181 — уже прецедент подвинутого порта).
- Память машины: один стенд уже умирает от нехватки памяти (`bugs/134`, обход
  `NODE_OPTIONS=--max-old-space-size=6144`); N стендов разом — это N×память, потолок надо
  замерить, а не предположить.
- e2e требует ПОГАШЕННОГО стенда (`EXP-0027`) — правило сформулировано про единственный стенд,
  при парке его формулировка меняется на «своего стенда».
- `emulators:exec` и `--project demo-*` изоляции портов не дают — порт один на машину.

## Чего идея НЕ просит

- Не отменяет замок для настоящих синглтонов (бой, стейдж, Docker, выкат).
- Не требует второй машины: парк живёт на этой же, пока хватает памяти (замер решит).
