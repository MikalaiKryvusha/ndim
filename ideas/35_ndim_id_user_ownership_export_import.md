## Слово владельца (дословно, 2026-08-14)

> Так же нужно запланировать идею:
>
> NDim ID - это труд пользователя, поэтому это является владением пользователя. NDim ID
> принадлежит пользователю, сообщаем об этом явно в наших политиках. Мы даем возможность им
> управлять, пополнять, изменять. Можно удалить его путем удаления учетной записи пользователя.
> Так же даем и делаем инструментарий, через который в приложении NDim Space NDim ID можно как
> экспортировать во внешний JSON файл, так и импортировать его из внешнего NDim ID JSON файла.
> Наделяем NDim ID некой очерченной предметностью и субъектностью. Он по прежднему существует в
> виде баз данных NDIm ID, но по желанию человек его может выкачать в удобном формате JSON,
> чтобы как-то там с ним работать самостоятельно. Или чтобы импортировать его в свой како-то
> новый аккаунт.

## Вектор цели (по `REQUIREMENTS_FRAMEWORK.md`)

- **Achieve:** NDim ID обретает очерченную предметность и принадлежит человеку: (1) владение
  явно названо в политиках продукта; (2) в приложении есть экспорт NDim ID во внешний JSON-файл
  и импорт из такого файла (в т.ч. в новый аккаунт); (3) управление, пополнение и изменение —
  уже существующие механики — осмыслены как управление СВОИМ владением; (4) удаление NDim ID =
  удаление учётной записи (каскад `plans/20` уже существует и стережётся
  `verify-account-delete`).
- **Maintain:** приватность — экспорт отдаёт человеку ТОЛЬКО его собственные данные (его оценки,
  его профиль), ничего о других людях и никаких чисел похожести (№002 В4, №018 В4); канон
  честности политик (правится ИСТОЧНИК `researches/06`, не сгенерированный `docs.ts`);
  правила текста продукта (без «навсегда»).
- **Avoid:** сочинять текст политик за владельца (правка политик — его артефакт, вычитка
  обязательна) · превращать импорт в дыру (импорт пишет только в СВОЙ аккаунт, только
  валидированные значения — границы из `schema.ts`) · выдумывать формат «стандарта» — формат
  наш, версионированный, но честно свой.

## Критерии приёмки (Scale · Meter · Target)

1. **Владение названо.** Scale: тексты политик · Meter: вычитка владельцем построчно ·
   Target: пункт о принадлежности NDim ID пользователю стоит в политике, источник —
   `researches/06`, регенерация `extract-docs`.
2. **Экспорт.** Scale: путь человека в приложении · Meter: живой Chrome + проверка файла ·
   Target: человек скачивает JSON со своим NDim ID (оценки + профиль), файл читается обратно.
3. **Импорт.** Scale: путь человека · Meter: живой Chrome, стенд, тесты правил · Target:
   JSON-файл импортируется в свой (в т.ч. новый) аккаунт; чужие/битые значения отвергаются
   валидацией; ничего чужого не читается и не пишется.
4. **Круговой инвариант.** Scale: экспорт → импорт в чистый аккаунт → экспорт · Meter:
   автоматический тест · Target: второй экспорт эквивалентен первому (без потерь).
5. Всё новое `[NOT-TESTED]` до прогона; стражи доказываются мутациями.
