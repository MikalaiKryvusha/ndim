Ниже эпик на пополнение пространства NDim измерениями

- нужно реализовать Admin Panel для админских аккаунтов.
Раньше она была частью клиентского приложения. Сейчас можно было бы отделить, чтобы клиенты себе не качали попусту этот код.
Но kotkrinik должен иметь возможность из клиентского приложения открывать админскую панель - обычные клиенты не должны иметь этой возможности

- Нужно в админскую панель добавить инструменты по управлению Измерениями пространства NDIM. CRUD с удобным интерфейсом просмотра измерений, как объектов. форму ручного создания Измерений, для пополнения базы измерений.

- Нужно реализовать машинерию, по которой ИИ агенты, типа Claude, которые в этом проекте ведут разработку Ndim, могли формировать для себя список всех имеющихся измерений - чтобы видеть, что уже есть, и чего добавлять не нужно. И чтобы могли ходить в интернет, находить самые популярные объекты культуры, которых ещё нет в Пространстве NDim - формировать в БД пополняющийся список приоритетных кандидотов измерений.

- Нужна маширения, по которой ИИ агенты, типа Claude, которые в этом проекте ведут разработку Ndim, могли бы брать из БД  список приоритетных кандидотов измерений и по шаблону, по примеру того, как уже ведутся измерения в пространстве NDim - выполнять в сети поиск и создавать в БД измерения-кандидаты на вычитку владельцем. Чтобы владелец в свободное время заходил в Админ Панель - Менеджер Измерений и наглядно в UI интерфесе вычитывал бы кандидатов, быстро их вручную мог редактировать, по одной кнопке одобрять, или отклонять, или оставить пометку в поле комментария и вернуть ИИ агенту на доработку по своему комментарию - так мы автоматизируем поиск и создание измерений ИИ агентами и повысим скорость их добавления в пространство NDim.

- В оригинальном ndim Николай делал механизм синхронизации dims_list по кнопке. Он выполнял это редко, когда накапливалось много новых измерений - он экономил запросы в Firestore, так как обновление dims_list требовало множества запросов, чтобы перелопатить измерения.
Нужно подумать, можно ли это следать лучше, чтобы не перелопачивать всю БД. И чтобы экономить запросы к БД.

- Запускать ИИ агента на создание измерений-кандидатов должен владелец по команде. Вероятно, это буден новый локальный KAIF навык. Результаты работы ИИ агента оседают в БД Firestore, что потом владелец будет вручную одобрять, комменрировать, отклонять.
