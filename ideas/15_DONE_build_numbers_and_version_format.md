# Idea 15 — Номера сборок и единый формат версии для приложения и сервера синхронизации

**Статус:** ✅ РЕАЛИЗОВАНО 2026-07-27 (это не предложение агента, а **прямое требование
владельца** — одобрения не ждало) · **Источник:** волна 11, чат 2026-07-27

## Слово владельца дословно

> «Приложение 2.0.0 — где номер сборки??? каждый коммит должен автоматически повышать номер
> сборки! Если нужно для этого настроить хук VS Code — настраиваем.
> И не пишем минорную цифру версии, если она = 0 — то есть пока просто 2.0 (в скобках целый
> номер сборки, например 123)»

> «У сервера синхронизации убрать билд dev. Тоже пишем ему версию и в скобках номер сборки —
> каждый комит кода сервера синхронизации повышает номер сборки на +1»

> «Дата сборки должна быть И по коду приложения И по коду сервера — 27 июля 2026 г. И нужно
> добавить время, часы и минуты к каждой дате сборки!»

## Что сделано

| Требование | Реализация |
|---|---|
| Номер сборки приложения растёт с каждым коммитом | `__APP_BUILD__` = `git rev-list --count HEAD`, вычисляется в `vite.config.ts` при сборке |
| Номер сборки сервера растёт с каждым коммитом ЕГО кода | `git rev-list --count HEAD -- calculator` → `--build-arg CALC_BUILD` при сборке образа (`npm run calc:image`) |
| Формат «2.0 (123)», нулевой патч не пишем | `versionLabel()` в `src/lib/ui/format.ts`, один на все экраны |
| Убрать «билд dev» у сервера | `SERVER_BUILD = Number(env.CALC_BUILD) \|\| null`; нет номера — нет и скобок |
| Дата сборки с часами и минутами, у обоих | `builtAt` до минут в `vite.config.ts` и `CALC_BUILT_AT` в образе; на экранах `dateTime()` вместо `dateOnly()` |

Показывают: подвал `/menu`, `/menu/about`, виджет «Версии» на `/space`.

## Почему СЧЁТЧИК КОММИТОВ, а не git-хук

Владелец предложил хук — и это рабочий путь, но у него три изъяна, которых нет у счётчика:

1. **Хук надо ставить каждому клону.** Хуки не версионируются вместе с кодом; на новой машине
   или в CI он молча не сработает, и номер тихо застынет — худший вид дефекта.
2. **Хук пишет номер в файл, файл надо коммитить.** Каждый коммит порождал бы второй коммит
   (или `--amend`, ломающий уже отправленную историю).
3. **Номер стал бы вторым источником истины** и рано или поздно разошёлся бы с историей.

`git rev-list --count HEAD` даёт то же самое: растёт ровно на 1 с каждым коммитом, не хранится
нигде, не требует установки и не может соврать. Для сервера — тот же счётчик, но по пути
`calculator/`, то есть буквально «каждый коммит кода сервера синхронизации».

**Цена, которую надо знать:** номер выводится из ИСТОРИИ, а не из момента сборки. Пересборка
без новых коммитов даст тот же номер (это верно), а сборка из архива без `.git` — 0, и тогда
скобок не будет вовсе (честное отсутствие вместо выдуманного числа, PHILOSOPHY).
