PostHog ровно одно событие `landing_view` с контуром, и не считается ли при этом тот, кто
приходом не является: вошедший, гость, ссылка из письма, наш прибор, стенд.

## 1. Основание ожиданий — откуда взято каждое «должно»

| Ожидание | Источник |
|---|---|
| Приход на главную считается ТОЛЬКО PostHog, Firestore не трогается | интервью №078 В1 = Г: «*только аналитикой постхог, мы свою БД фаерстор не грузим запросами*» |
| Главная остаётся без единого файла кода | замер №078: 5 запросов, 39 КБ, кода 0; `plans/81` — корень мгновенный; `csr = false` |
| Имя события — `landing_view` из белого списка | `ANALYTICS_EVENTS`; паритет со своей воронкой (`FUNNEL_STEPS`) |
| Событие несёт контур `env` ∈ prod · stage; стенд молчит | слово владельца 2026-08-29 (один проект PostHog, контуры различает свойство); `contourOf` |
| Вошедший и гость не считаются | `bugs/08.1` (лендинг считает только тех, у кого сессии нет); дверь корня уводит их внутрь по маркеру `ndim-session` |
| Ссылка из письма не считается и уходит в `/profile` с нетронутым query | контракт корня «ссылки из писем входят через корень» (`plans/81`, боевой выкат 2026-07-12) |
| Прибор под меткой человеком не считается | `probeMarked()` · `tools/lib/probe-mark.mjs` · `bugs/202` |
| Предмет оценки наружу не уходит | инвариант №002 В4 — на главной оценок нет; свойства закрыты списком |
| Личных профилей не заводим | `person_profiles: 'never'` у SDK → `$process_person_profile: false` у строки |
| Транспорт — публичный API `POST /i/v0/e/`, тело `text/plain` | документация PostHog (docs/api/capture); проба 2026-09-12: преполёт 200, POST `{"status":"Ok"}` |

**Пути карты, которые набор закрывает:** `NDIM-PUBLIC-014` (позитив) · `NDIM-PUBLIC-015`
(негатив).

### Что сознательно НЕ покрыто — и почему

- **Блокировщики рекламы** режут `posthog.com` целиком — ровно так же, как SDK на лендинге.
  Не меряем; эталон сверки прихода на главную — Search Console (клики на `/` за сутки).
- **Склейка человека «главная → /ru»**: событие корня не ставит метку `claimStep` своей
  воронки (иначе оно гасило бы и Firestore-счёт на `/ru`, а владелец велел главной Firestore
  не трогать). Второе `landing_view` от SDK на `/ru` различимо по `$lib` и `$pathname`.
- **Приём чужим сервисом до выката** недостижим по построению — проверяется слоем С на стейдже.
- **Стенд** (`localhost`) — только отрицательный контроль: там строка молчит по построению.

## 4. Чек-лист прогона — по порядку

1. Стенд ПОГАШЕН (проверить процессами, не логом) — иначе e2e даст ложные красные.
2. `node --test src/lib/data/analytics.test.ts` → все зелёные; ГЛ-01…ГЛ-12 слоя Ю.
3. Мутация: снять строки маркера и метки в `rootLandingViewScript()` → ГЛ-03 и ГЛ-04 красные;
   вернуть файл (`git diff --stat` пустой по этим строкам).
4. `npm run e2e -- e2e/root-landing-view.spec.ts e2e/root.spec.ts` → 2 проекта × 6 кейсов
   нового спека + 3 старых, ноль провалов.
5. `npm run guards` → все ворота зелёные (в том числе карта путей: сводка 170 сошлась).
6. Стенд ПОДНЯТ (`npm run stand`) → `npm run deploy -- --stage` → дверь зелёная.
7. ГЛ-13: свежий браузер на стейдж без метки прибора; через минуту — MCP PostHog: событие
   найдено. **Это след прогона: одно событие `env = stage` в общем ряду; оно так и называется.**
8. Отчёт — `qa/reports/2026-09-12_root-landing-view.md`, строка в реестре.
9. Вопрос владельцу о бое — страницей интервью, с адресами пунктов 1–8.
