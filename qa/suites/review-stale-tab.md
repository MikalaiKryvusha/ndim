# Набор «старая вкладка контура вычитки» — страница не принимает ответы в пустоту

> **Создан:** 2026-09-25 (dev-1, постановка №3 Менеджера) · **Родитель:** `plans/NEW_review_contour_stale_tab.md` ·
> `bugs/NEW_review_page_stale_tab_accepts_answers.md` (S1) · **Статус:** живой набор · **Исходящее:** —

**Основание ожиданий.** Слово владельца: «*так какого хуя страницу переписали, новую блять открыли и старую ОСТАВИЛИ!!!!
… вот я в сторой блять и отвечал!*». Критерии — постановка №3 Менеджера (плашка за ≤ 15 с и блок ввода · черновик
переезжает · законное закрытие с отказом) и контракт KAIF 2.7 `_interactive-contour-spec.md` §4–§5 (замок, прежний адрес,
`--close` с порогом 180 с). Зазор редакции — наш (агент KAIF: OW6 эпика 2.8).

**Техники.** Переходы состояний страницы (жива → сервер умер → сервер ожил · жива → документ переписан → новая редакция ·
жива → закрыта агентом) · таблица решений команды `close` (странице < 180 с · печатал < 180 с · черновик не сохранён ·
тишина) · граничное значение пульса (два промаха подряд, ≤ 15 с) · угадывание ошибок по бегу бага (документ переписан при
мёртвом сервере и поднят заново — сценарий №097).

**Покрыто:** все три корня бага — вкладка переживает сервер молча · новый `open` плодит вторую вкладку · нет законной
команды закрытия; плюс зазор редакции. **Сознательно не покрыто:** троттлинг таймеров СКРЫТОЙ вкладки (headless-страница
всегда видима — проверка `visibilitychange` делается принудительным событием, настоящий фон не воспроизводится); два
разных браузера (страница живёт в одном); голос и окно браузера (`--no-open --no-signal`); пачка (`review batch`) — замок
у неё не заведён (редакцию её страницы документов несут).

| № | Кейс | Стартовое состояние → шаги | Ожидаемо |
|---|---|---|---|
| РС-01 | Сервер убит → плашка и блок ввода | фикстура из трёх вопросов открыта (`open`, постоянный порт), владелец отметил В2 и написал текст → процесс страницы убит | за ≤ 15 с плашка «Сервер агента замолчал — эта страница больше не принимает ответы.» · страница под ней `inert` (клик по варианту не меняет выбор) · на плашке ответы текстом и «Скопировать» |
| РС-02 | Возврат на вкладку — проверка сразу | РС-01 до плашки: сервер убит, затем событие `visibilitychange` (видима) | плашка за ≤ 3 с после события (не ждёт очередного пульса) |
| РС-03 | Подъём заново — та же вкладка оживает | РС-01 → `open` того же документа без `--port` | «Прежняя страница … поднимаю на её же адресе» · адрес тот же · плашка снята, «Связь восстановлена» · отметки владельца на местах · «Прежняя вкладка ожила на этом адресе — новое окно браузера не открываю» (одно окно на документ, суд p3 п. 3) |
| РС-04 | Второй `open` при живой странице | РС-03 → ещё раз `open` | «уже открыта: адрес (pid)», код 0, второй сервер не поднят (порт один) |
| РС-05 | Документ переписан при живом сервере | РС-03 → документ переписан (В1 убран, В2 стал В1 с тем же текстом, В3 изменён) | за ≤ 15 с плашка «Документ переписан — эта страница больше не принимает ответы.» с кнопкой «Открыть новую редакцию» · ответ со страницы старой редакции `POST /decision` → 409 `stale` |
| РС-06 | Новая редакция: черновик переехал | РС-05 → «Открыть новую редакцию» | вопрос о языке (был В2, стал В1) — ответ на месте · ответ на изменённый вопрос о строках — блоком «Черновик прошлой редакции» с текстом, на чужой вопрос не сел |
| РС-07 | Сценарий №097 целиком | страница открыта, ответ отмечен → процесс убит → документ переписан → в замке pid ЖИВОГО чужого процесса (Windows переиспользует PID) → `open` заново | замок с живым чужим pid не принят за живую страницу — страница поднята («не работает», суд p3 п. 1) · старая вкладка на том же адресе получает «Документ переписан» (а не молча принимает ответы) → новая редакция с переносом по РС-06 |
| РС-08 | `close` отказывает, пока владелец пишет | живая страница, ввод меньше 180 с назад | `close` печатает адрес · pid · документ, «НЕ ЗАКРЫТО: …» со ВСЕМИ причинами (странице < 180 с · печатал N с назад · черновик не сохранён; суд p3 п. 7 — «печатал» названо), код 4; страница жива и через 12 с (закрытая уходит через 11 с) |
| РС-09 | `close --force` без слова владельца | живая страница | отказ кодом 1: «--force только со словом владельца» — при любом состоянии страницы |
| РС-10 | На СТАРОЙ странице: печатал — отказ; тишина — закрывает, вкладка гаснет | живая страница старше 180 с → владелец печатает → `close`; затем черновик пуст, 180 с тишины → `close` | первый `close` — код 4 «владелец печатал N с назад» без возраста страницы (суд p3 п. 7) · второй — `closed <док>`, код 0 (проба живости `?ping=1` без `i` не «печатал только что», п. 8) · вкладка за ≤ 15 с показывает «Агент закрыл эту страницу — она больше не принимает ответы.» · процесс ушёл |
| РС-11 | Контроль: живой сервер, та же редакция — ответ записывается | фикстура открыта → отметка → «Сохранить» | «Записано» · решение в `interviews/decisions/` · замок снят САМИМ сервером до уборки стража и сервер ушёл сам (суд p3 п. 9; регресс `node tools/verify-bug110.mjs` — 25 проверок) |
| РС-12 | Ответ записан из другой вкладки | две вкладки одного документа · в первой отметка → «Сохранить» → во второй возврат на вкладку | вторая вкладка: «Ответ по этому документу уже записан — эта страница больше не принимает ответы.», а не «Документ переписан… Агент изменил» (суд p3 п. 4) |
| РС-13 | Подъём на порту из замка; одно окно | страница на явном `--port P` (не постоянный порт) → убита → `open` без `--port`; затем вкладка закрыта → страница убита → `open` | подъём на P, а не на постоянном порту (суд p3 п. 2) · «Прежняя вкладка ожила… новое окно не открываю», плашка в ней снята · контроль: вкладки нет — «Прежняя вкладка за 6 с не отозвалась — окно не открываю: --no-open.» (п. 3) · кадр 390 тёмная |
