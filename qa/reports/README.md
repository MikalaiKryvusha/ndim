# Отчёты по исполненным прогонам

> **Создан:** 2026-09-09 · **Родитель:** `TESTING_FRAMEWORK.md` → «ИСПОЛНЕННЫЙ ПРОГОН РОЖДАЕТ
> ОТЧЁТ» · **Статус:** живой реестр — DONE не помечается никогда · **Исходящее:** запрос на
> улучшение методологии отправлен в исток KAIF (`bugs/KAIF/11`); второй — определение слова
> «протестировано» = ручной функциональный прогон, две раздельные строки в карточке (`bugs/KAIF/12`, issue #62).

**Зачем эта директория.** Прогон, о котором кому-то доложено, живёт здесь документом. Вердикт
прибора, строка «зелёное» в записке смены и маркер `[TESTED: …]` в коде остаются законными —
и ни одно из них отчётом не является: их читает только тот агент, который их произвёл.

Повод, по которому директория заведена, записан честно: работу приоритета 0 проверяли двумя
прогонами одного прибора и подавали владельцу как готовую к бою. Его вердикт: «*из этой таблицы я
вижу, что ТЕСТИРОВАНИЯ НЕ БЫЛО*».

## Как завести отчёт

```bash
node tools/verify-test-reports.mjs        # форма отчётов и полнота этого реестра
```

Имя файла — `<ISO-дата>_<короткое-имя-работы>.md`. Первым разделом после шапки идёт
**«Карточка прогона»** с семью обязательными полями:

| Поле | Что в нём |
|---|---|
| **Работа** | что именно проверяли, с адресом плана или бага |
| **Контур** | стенд · стейдж · бой, и чем доказано, что это именно та сборка |
| **Прогонов** | число, метки времени и КОМАНДА каждого прогона |
| **Проверок** | пройдено / провалено; каждый провал назван |
| **Найдено** | дефекты с адресами заведённых документов либо честное «ноль» |
| **Следы** | что прогон оставил в контуре: учётки, записи, кадры |
| **Вердикт** | годится к следующему шагу или нет, и почему |
