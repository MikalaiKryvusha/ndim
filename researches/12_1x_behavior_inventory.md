### Boot-экран: механика целиком (снято 2026-07-29 по коду `ndim-old`, под `bugs/40`)

Строки выше описывали, КАК он выглядит. Здесь — КОГДА он живёт и чем гасится: именно это
владелец назвал «не показывал приложение, пока определяло состояние, а затем красиво
открывало нужный экран, без дёрганых переходов».

| Свойство | Как это сделано в 1.x (дословно по коду) |
|---|---|
| Где лежит | **Статической разметкой в `index.html`** (`#full_screen_loading`, строки 158–184), а не создаётся скриптом |
| Когда виден | **С ПЕРВОГО КАДРА.** CSS `.full_screen_loading { position: absolute; width/height: 100%; background: white; z-index: 200 }` — без `display:none`, то есть экран уже накрывает страницу, когда JS ещё не исполнялся. `openFullScreenLoading()` на `DOMContentLoaded` лишь подтверждает `display = "flex"` (app.js:1786) |
| Состав | лого `NDim_LOGO_v8_196.webp` + «Пространство NDim» / «NDim Space» + кольцо `.loader` |
| ⭐ Чем гасится | **Ничем по таймеру — только принятым решением.** `closeFullScreenLoading()` вызывается в КАЖДОЙ ветке `onAuthStateChanged` (app.js:8216/8238/8251/8313), и всегда ПОСЛЕ того, как нужная страница уже открыта |
| ⭐ Порядок (суть эффекта) | вошедший: `openPage("home_page", false)` → `openNavbar()` → **и только потом** `closeFullScreenLoading()` (app.js:8214–8217). Целевой экран рисуется ПОД щитом, человек не видит ни одного промежуточного состояния — отсюда «красиво открывало» |
| Гость | та же схема: `openPage("ob1_page", true)` → `closeFullScreenLoading()` (app.js:8306–8313) — щит держится и для НЕвошедшего |
| Второй держатель щита | `space_public_metrics_loader_is_working`: пока грузятся публичные метрики, закрытие **блокируется** (app.js:1635). Гасит тот, кто закончил последним — щит снимается по готовности, а не по одному событию |
| Потолок | через **15 секунд** — `too_long_loading`: «Загрузка выполняется необычно долго.<br>Попробуйте перезагрузить страницу.» + кнопка **«Перезагрузить»** (app.js:1569, index.html:169–182). Таймер снимается при закрытии щита |

**Что из этого НЕ переносится дословно и почему** (осознанные отличия 2.0):
- В 1.x всё приложение жило в одном `index.html`, и щит был уместен всегда. В 2.0 корень (`/`) —
  **пререндеренный лендинг с SEO**, и накрывать его щитом у гостя нельзя: гость и краулер обязаны
  получить лендинг сразу. Значит щит поднимается **только при признаке сессии**.
- Признак нужен **синхронно, до первого кадра** (иначе лендинг мелькнёт — это и есть дефект).
  Firebase хранит сессию в IndexedDB, читаемой только асинхронно, поэтому 2.0 ведёт **свой
  маркер в `localStorage`** и читает его тем же скриптом `app.html`, что уже применяет тему.
- Блокировка публичными метриками не переносится: у 2.0 счётчик лендинга — не условие входа.

### Жест звезды: повторный тап (снято 2026-07-28 по коду, под `bugs/54`)

Владелец: «повторный тап по выбранной звезде отменял выделение… нужно вернуть, чтобы
повторным тапом отменить обратный отсчёт сохранения». Разведка отвечает на вопрос, который
баг ставил ребром: **трогал ли повторный тап уже СОХРАНЁННЫЕ данные?** Ответ — нет, никогда.

| Случай 1.x | Обработчик | Что делал повторный тап по ВЫДЕЛЕННОЙ звезде |
|---|---|---|
| Вкладка «Все» — измерение ещё не оценено, выбор не сохранён | `starButtonHandlerAllDims` (`app.js:3752`) | Снимал выделение со ВСЕХ звёзд (`star_empty.svg`) + `hideSaveButton` + `hideEmoji` (`:3759-3770`). Отмена НЕсохранённого выбора |
| Вкладка «Мой NDim ID» — оценка уже сохранена | `starButtonHandlerMyDims` (`app.js:3838`) | **Ничего.** Все три ветки заполнения звёзд закрыты условием `checked != "checked"` (`:3856`, `:3870`, `:3884`) — тап по уже выделенной звезде не проходил ни в одну, функция выходила без изменений |
| Удаление сохранённой оценки | отдельная операция | `user_dims.${dim_id}: deleteField()` (`app.js:8955`) — жестом звезды НЕ вызывалась |

**Канон, из этого выведенный:** звезда отменяет только то, что ещё не записано. Сохранённую
оценку жест звезды не удаляет — для этого в 1.x была отдельная команда, в 2.0 это «Убрать
оценку» в меню карточки и тост «Отменить оценку».

**Адаптация к 2.0** (в 1.x сохраняла КНОПКА Save, в 2.0 — отсчёт 5 секунд, `bugs/21`):
роль `hideSaveButton` играет отмена отсчёта. Повторный тап по звезде, по которой идёт
отсчёт → отсчёт отменён, звёзды вернулись к сохранённому значению (или к «не оценено»).
Повторный тап по сохранённой звезде без отсчёта → ничего, данные не трогаем.
