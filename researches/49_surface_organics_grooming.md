### dev-2 — данные и цена (7 идей + замер)
· «Сегодня в рейтингах» — ноль новых чтений: `newDims` УЖЕ в `space/stats` (~0,4 КБ), цена в
  БАЙТАХ, потолок записей держать · NDSR на внутренних карточках: индекс НЕ несёт
  `stars/rates/rating` — наивно = чтение на карточку (нарушение канона экономии) · решение
  числами (замер Менеджера 2026-08-22): dims_list ≈ 633 КБ из 1024, добавка NDSR ≈ +125 КБ —
  влезает, но съедает треть запаса → **отдельный документ-срез топов** (+1 чтение на сессию,
  кэш гасит; писатель ТОЛЬКО сервер синхронизации — панелью строку индекса не пишем никогда,
  класс `plans/44` шаг 4) · «Позвать на тест» кормит Связи по-настоящему: `saveTestRating` без
  сессии рождает гостя и кладёт оценку ШТАТНЫМ путём (гипотеза «testPairs не кормят Связи»
  опровергнута чтением) · сшивание приглашённого = ЭСКОРТ НОВИЧКА эпика 60 фазы 2 — попутно,
  если поверх него; второй ритм = вразрез · порядок: сперва фаза 2 эпика 60, потом приглашение.

### Дизайнер — UX жителя (7 идей + 2 резки затравки, приняты)
· Оценка прямо из витрины (риск: приватность оценок — своя видна только мне) · пустой старт
  лечится витриной («оцените то, что уже видели») — БЕЗ геймификации, жест-предложение ·
  NDSR после своей оценки (якорение — выше) · «позвать» — жест АДРЕСНЫЙ из карточки человека
  (Связи → конкретному; Профиль → общая ссылка), без наград зовущему · витрина-утилита с
  фильтром «чего я не оценил» (единственная разрешённая GOAL возвращаемость — польза; фильтр
  не вычитает мои оценки на клиенте из всего каталога) · одна карточка объекта, а не две
  (слоями, не заменой: у публичной «стены нет», у внутренней личный слой) · «место в виде»
  словами, не номером («входит в десятку лучших фильмов Пространства») — текст лица, слово
  владельца · РЕЗКИ: виджет = вариант двери (одно решение об одном месте); «NDSR на карточке»
  и «место в виде» — расщепить (якорение ≠ текст лица).
· Факт: тестов ТРИ — «для двоих» только compatibility и love; personality одиночный, жест у
  него «показать результат», не «позвать». Один жест на двоих не проектировать.

### dev-1 — механика оценок и SEO-плечо (7 идей + 2 замера)
· «Позвать» — дострочить МАЛО: личная ссылка пары уже живёт (`testPairs`), нет только ТОЧКИ
  ВХОДА в приложении; движок один (`saveRating` тот же) · разорванный круг — предусловием
  (выше) · «место в виде» внутри: НЕ пересчётом (каталог 16,86 МБ в клиент нельзя, EXP-0136) —
  сервер синхронизации кладёт место в запись `dims_list` (+40–60 КБ, влезает; ⚠️ место меняется
  у многих каждым циклом — мерить цену перезаписи) · оценка прямо с ПУБЛИЧНОЙ карточки: страница
  сейчас НЕ несёт ни одного JS-модуля — клиент привезёт ~554 КБ SDK туда, где ноль; вес судится
  ДО решения · виджет при нуле активных БУДЕТ ПУСТ — честная ветка «пока тихо» обязательна ·
  третий потребитель правила показа оценок — только из общего модуля `dims-rating` (пара
  «истина ↔ зеркало» уже разъезжалась) · топливо круга: 63 % без числа (выше).

### dev-3 — контент как ценность (7 идей + число)
· Плотность первой фазой (хребет, выше) · внутренняя карточка = то же ТЕЛО описания БЕЗ
  витринной обвязки (блок-двери, брендовых повторов) — источник ОДИН, расхождение ловит машина ·
  доля меты едет ВМЕСТЕ с новой поверхностью (прибор готов, предъявляет адресно; на 10 222 —
  выборкой) · ось «новое» стала честной только после фикса скаута (52 % переизданий); у 170
  записей года нет — называть числом на витрине, не выдумывать · текст обёртки теста называет
  ЖЕСТ, а не обещает результат; стража на ОБЕЩАНИЕ нет (verify-test-pages судит структуру) —
  нужен раньше вёрстки приглашения · хаб жителя отвечает на вопрос («что я ещё не оценил») —
  персонализация ломает пререндер, цена архитектурная; «вы не оценили 40» — справка, не
  механика · один вход к приборам качества текстов поверхности; реестр собирает МАШИНА из самих
  приборов (ручной запрещён К4).
