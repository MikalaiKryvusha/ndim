## 4. Перевывод фактов из кода — снова поймал расхождения

Ровно как в вашей KPOT-сессии («caught a fresh falsehood mid-writing»), пересбор с
перевыводом каждого утверждения вскрыл дрейф старого текста:

- английская половина старого README несла числа тестов **173/87/30/70** при актуальных
  **192/97/43/72** — RU и EN половины разошлись и жили каждая своей жизнью;
- «до 250 похожих» перевыведено из `RELATIONS_TOP_LIMIT = 250` (schema.ts), «30 дней» гостя —
  из `GUEST_TTL_DAYS = 30`, показатель 0.7 — из `PROXIMITY_EXPONENT` — теперь у каждого числа
  README есть именованный источник в коде.

Вывод для методики: правило «перевыведи из кода» — не разовая находка KPOT-сессии, а
воспроизводимый механизм; предлагаю закрепить его в портрете/стайлгайде как обязательный шаг
любого README-прохода (у вас он сейчас живёт только в STATUS-записи сессии).

## 5. Предложения стилометрической команде

1. **Выделить «мануальный профиль» приложением к портрету.** Перенос показал, что для жанра
   README/руководств достаточно подмножества: К0.1 + К1–К5 + К10 + «Границы применения» +
   Л8-рамка + правило перевывода. Готовый лист «что брать для мануала» сэкономит следующему
   агенту разведку по трём проектам (я собирал образец из трёх источников: ваш портрет,
   STATUS KPOT, README Unliminium).
2. **Зафиксировать анти-жанр.** Вердикт владельца «устаревший фрод» (KPOT) и его довольная
   реакция на смену жанра здесь — устойчивый сигнал: README-витрина с историей проекта,
   роадмапом и похвалой собственной архитектуре для него то же, что М10/М15 вашего
   анти-портрета, только на уровне документа. Стоит строки в анти-портрете: «README о том,
   „как проект получился“, — не README».
3. **Шапка-витрина - каноничный блок.** Три проекта используют одинаковую: центрированный
   знак → заголовок «ИМЯ — расшифровка» → бейджи языков → ряд shields.io → две половины
   целиком, без эмодзи-флагов (прямое требование владельца, STATUS Unliminium 2026-07-25).
   Это уже фирменный стандарт — ему место в портрете, а не в памяти сессий.
