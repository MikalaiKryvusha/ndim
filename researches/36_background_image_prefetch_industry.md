**Задача яруса 2 дословно** (слово владельца): «те картинки, которые скоро могут понадобится —
в ленивой загрузке в фоне приложения». Сегодняшний потребитель ровно один (инвентарь шага 0):
**полноразмерные персоны лендинга 3 × ~1,2 МБ**, которые открываются зумом по тапу и сейчас
едут «мегабайт на горячую».

## §1. Инструменты платформы — что вообще существует

| Механизм | Что делает | Приоритет | Годится ярусу 2? |
|---|---|---|---|
| `<link rel="prefetch" as="image">` | браузер качает В ПРОСТОЕ в HTTP-кэш | **Lowest** — ниже всего на странице; шлёт `Sec-Purpose: prefetch` | ✅ **да — родной инструмент ровно этой задачи** |
| `<link rel="preload">` | ПРИКАЗ качать сейчас, для текущей страницы | высокий | ❌ нет — это ярус 1; на throttling отбирает канал у LCP (наш замер шага 2) |
| `fetch(url, {priority:'low'})` | то же, что prefetch, но из JS | low (чуть выше prefetch) | запасной путь, если ссылку неудобно вставлять |
| `new Image().src` | обычная загрузка картинки | нормальный приоритет картинки | ⚠️ хуже: конкурирует с содержимым, приоритет не занижен |
| `fetchpriority="low"` на `<img>` | подсказка приоритета УЖЕ загружаемому | понижает | не про фон: элемент должен существовать |
| `requestIdleCallback` | окно простоя main thread | — | ✅ как МОМЕНТ старта (в паре с fallback `setTimeout`: Safari его не имеет) |
| Speculation Rules | префетч/пререндер СЛЕДУЮЩИХ НАВИГАЦИЙ | — | ❌ не про картинки текущей страницы |

Первоисточники: [MDN rel=prefetch](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/prefetch) ·
[web.dev link-prefetch](https://web.dev/articles/link-prefetch) ·
[web.dev fetch-priority](https://web.dev/articles/fetch-priority) ·
[Addy Osmani: Preload, Prefetch and Priorities in Chrome](https://medium.com/reloading/preload-prefetch-and-priorities-in-chrome-776165961bbf) ·

## §2. Правила индустрии, которые нельзя нарушить (все — из первоисточников §1)

1. **Префетч-хинты НЕ кладутся в исходный HTML** — только вставкой ПОСЛЕ загрузки страницы
   (`load` → idle), иначе они конкурируют с критическим путём — ровно то, что уронило бы
   Perf 100, восстановленный `bugs/119`.
2. **Только высоковероятные кандидаты.** Каждый неугаданный файл — оплаченный человеком трафик
   (наш пул это уже знает). Для лендинга вероятность честная: зум — единственный интерактив
   с полноразмерами.
3. **Уважать экономию данных**: `navigator.connection?.saveData === true` → фоновую догрузку
   НЕ запускать (API есть только в Chromium-семействе — отсутствие поля читать как «не знаем»,
   а не «можно»). Источники: [web.dev Save-Data](https://web.dev/articles/optimizing-content-efficiency-save-data) ·
   [MDN Save-Data](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Save-Data) ·
   [WICG Save Data API](https://wicg.github.io/savedata/).
4. **Префетч живёт в HTTP-кэше** — переиспользование зависит от заголовков кэша файла.
   ✅ **ЗАМЕР СНЯТ 2026-08-14 с боя** (`HEAD https://ndimspace.app/img/personas/alice.png`):
   `Cache-Control: max-age=3600` + `ETag`. Час свежести покрывает путь «загрузился → потрогал
   демо → тапнул зум» с запасом; после часа — ревалидация по ETag (304, без повторного
   мегабайта). Prefetch годится без правок хостинга.
5. **Firefox**: prefetch поддержан, но исторически капризен с некэшируемыми ответами; провал
   префетча — не дефект (это подсказка, а не приказ), зум обязан работать и без него.

## §3. Рекомендация для реализации яруса 2 (следующий заход)

Механика — три строки, не подсистема:

```js
// после window.load, в простое, без Save-Data:
if (!navigator.connection?.saveData) requestIdle(() => {
  for (const href of fullPersonaUrls) head.append(<link rel="prefetch" as="image" href>);
});
```

- Момент: `load` → `requestIdleCallback` (fallback `setTimeout(..., 2000)` для Safari).
- Инструмент: `<link rel="prefetch" as="image">` — Lowest-приоритет отдаёт браузер, самим
  дросселировать нечего.
- Границы: только 3 полноразмерные персоны лендинга; Save-Data выключает; ошибка префетча
  молчалива (зум работает как сегодня).
- Страж (шаг 5 `ideas/27`): после `load`+idle в разметке 3 префетч-ссылки; при
  эмулированном Save-Data — ноль; Perf лендинга НЕ просел (LH по канону `EXP-0146`);
  мутация — ссылки в исходном HTML до load = провал.

## §4. Чего НЕ делать

- Не расширять на «все экраны» — ярус 2 включается только по названному кандидату с
  вероятностью использования, а не по списку файлов (риск из `ideas/27` дословно).
- Не брать `new Image()` без нужды — он не занижает приоритет.
- Не считать префетч гарантией: это подсказка; UI не имеет права на неё полагаться.
- Не мерить эффект на другом стенде, чем «до» (`bugs/119`, правило замера).
