# /end-chat — полное завершение: мы прощаемся с этим чатом

Человек закрывает этот чат насовсем; работа продолжится в ДРУГИХ чатах, в ДРУГИХ сессиях агента,
которые стартуют с пустым контекстом. Выполни процедуру завершения **по порядку**, кратко проговаривая
каждый шаг в чате. Не пропускай шаги. Если шаг провалился — остановись, скажи человеку, не продолжай
вслепую.

## Шаг 1. Записать статус и эстафету в STATUS.md

Обнови `STATUS.md`:
- **Что сделано в этом чате** — конкретно, с привязкой к багам, фичам и файлам.
- **Текущая позиция** — что работает, что в процессе, где мы.
- **Эстафета («где продолжить»)** — чеклист, написанный для ЧУЖОГО: следующая сессия не знает ничего
  из того, что знал этот чат. Команды, пути файлов, что проверить первым, открытые вопросы и чьи они.
- Переводи относительные даты в абсолютные (сегодняшнюю дату возьми из контекста или `date`).

Сверься с активными документами багов в `bugs/` и отрази их статус. Если в этом чате родился
переиспользуемый урок — зафиксируй его в `EXPERIENCE.md` (скилл `/experience`) ДО передачи эстафеты.

Если проект ведёт **реестр пар «истина ↔ зеркало»** (`AGENT_GUIDE.md` → «Гигиена документов и
текста»), прогони его команды проверки до передачи эстафеты — эстафета поверх разъехавшейся пары
вручает следующей сессии ложь.

**Стрижка бонсая (STATUS — сводка, а не летопись):** записи, переставшие быть «сейчас», — закрытые
фазы, завершённые сессии, выпущенные релизы — переезжают ДОСЛОВНО в `PROJECT_HISTORY.md` (свежее
сверху; переноси, не переписывай). Затем перечитай остаток `STATUS.md` двумя тестами из его шапки
(«убери эту строку — ошибётся ли следующий агент?» · «читается ли за один присест?»; мягкая цель
~200 строк). Оставь файл таким, каким сам хотел бы его найти.

## Шаг 2. Освежить README (если реальность сдвинулась)

Приведи `README.md` в соответствие с реальностью: статус фаз, работающие фичи, инструкции. README
двуязычный — держи оба языка синхронными. Не выдумывай — отражай только то, что действительно сделано
и проверено.

## Шаг 3. Пересобрать / перегенерировать артефакты

`npm run check` (типы) → `npm test` (юнит) → `npm run build` (сборка). Если сборка падает —
остановись и покажи ошибки, не коммить сломанное состояние. Полный список гейтов — `AGENT_GUIDE.md`
→ «Команды».

## Шаг 4. Закоммитить и запушить (сначала судья)

Прогони `/fable-judge` по завершённым заявлениям этого чата ДО push (канон: судейский проход
предшествует каждому push). Затем:

```bash
npm run kaif:check && git add -A && git commit -m "..." && git push
```

⚠️ **`npm run kaif:check` перед push обязателен** — он падает, если в git попал секрет или ПДн
(здесь это уже случалось однажды; см. `AGENT_GUIDE.md` → «Гейт перед push»).

Стиль сообщения (из `AGENT_GUIDE.md`): `feat:` / `fix:` / `docs:` / `refactor:` / `ci:` + одна строка.
Заверши сообщение трейлером соавторства, канон которого — в `AGENT_GUIDE.md` → «Коммиты».

## Шаг 5. Прощальный доклад

Доложи человеку: что записано, что собрано, хеши коммитов, что запушено, и одним абзацем — эстафету:
главное, что СЛЕДУЮЩЕМУ чату сделать первым. Это и есть прощание.

## Заметки

- Разница в одну строку: **/pause — чат продолжится позже; /end-chat — чат прощается.**
- Если push отклонён (non-fast-forward) — `git pull --rebase`, повтори push, затем расскажи человеку
  о расхождении.
- Сгенерированные артефакты, попавшие в `.gitignore` (сборка, логи), не коммитятся — это нормально.
